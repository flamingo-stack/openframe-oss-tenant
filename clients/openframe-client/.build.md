Build script that forwards required environment variables into the compiled binary at build time, making version strings available via `env!()` macros in the crate.

## Key Components

- **`main()`** — Entry point that registers version variables based on enabled Cargo features. `OPENFRAME_VERSION` is always required; others are conditionally compiled via feature flags.
- **`forward_required(var)`** — Helper that registers a `cargo:rerun-if-env-changed` directive and embeds the variable's value into the binary via `cargo:rustc-env`. Panics at build time if the variable is not set.

## Feature Flags

| Feature | Variable Required |
|---|---|
| *(always)* | `OPENFRAME_VERSION` |
| `openframe-chat-version` | `OPENFRAME_CHAT_VERSION` |
| `meshcentral-agent-version` | `MESHCENTRAL_AGENT_VERSION` |
| `fleetmdm-agent-version` | `FLEETMDM_AGENT_VERSION` |
| `tacticalrmm-agent-version` | `TACTICALRMM_AGENT_VERSION` |
| `osquery-version` | `OSQUERY_VERSION` |

## Usage Example

Set the required variables before building, then access them in code via `env!()`:

```bash
export OPENFRAME_VERSION="1.2.3"
export MESHCENTRAL_AGENT_VERSION="2.0.1"
cargo build --features meshcentral-agent-version
```

```rust
// In your crate source code
const VERSION: &str = env!("OPENFRAME_VERSION");
const AGENT_VER: &str = env!("MESHCENTRAL_AGENT_VERSION");
```

The build will **fail immediately** if a required variable is missing, ensuring version information is never silently absent from a release artifact.
