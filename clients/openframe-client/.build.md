Cargo build script that forwards required environment variables into the compiled binary as compile-time constants, triggering rebuilds when those variables change.

## Key Components

### `main()`
Registers version-related environment variables for forwarding. `OPENFRAME_VERSION` is always required; additional agent/component versions are conditionally included based on Cargo feature flags:

| Feature Flag | Environment Variable |
|---|---|
| *(always)* | `OPENFRAME_VERSION` |
| `openframe-chat-version` | `OPENFRAME_CHAT_VERSION` |
| `meshcentral-agent-version` | `MESHCENTRAL_AGENT_VERSION` |
| `fleetmdm-agent-version` | `FLEETMDM_AGENT_VERSION` |
| `tacticalrmm-agent-version` | `TACTICALRMM_AGENT_VERSION` |
| `osquery-version` | `OSQUERY_VERSION` |

### `forward_required(var: &str)`
Emits two Cargo directives for a given environment variable:
- `cargo:rerun-if-env-changed` — invalidates the build cache when the variable value changes
- `cargo:rustc-env` — embeds the value into the binary, accessible via `env!("VAR_NAME")`

Panics at build time if the variable is not set, enforcing that all version strings are explicitly provided before compilation.

## Usage Example

Set the required variables before building:

```bash
export OPENFRAME_VERSION="1.2.3"
export OPENFRAME_CHAT_VERSION="0.9.1"

cargo build --features openframe-chat-version
```

Access the forwarded values at runtime using the `env!` macro:

```rust
const VERSION: &str = env!("OPENFRAME_VERSION");

fn main() {
    println!("Running OpenFrame v{}", VERSION);
}
```

> If `OPENFRAME_VERSION` (or any enabled feature's variable) is missing at build time, the build will **panic** with a descriptive error, preventing silent version mismatches in release artifacts.
