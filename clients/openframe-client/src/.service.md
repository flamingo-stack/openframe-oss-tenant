Brief description of the service installation, Windows SCM integration, and cross-platform service lifecycle management for the OpenFrame client daemon.

## Key Components

| Item | Description |
|------|-------------|
| `Service` | Main struct providing static methods for service lifecycle management |
| `FULL_SERVICE_NAME` | Public constant `"com.openframe.client"` used as the cross-platform service identifier |
| `windows_service_main` | Windows SCM entry point registered via `define_windows_service!` macro |
| `set_service_status` | Windows-only helper to report service state changes to the SCM |
| `Service::is_installed()` | Cross-platform check for existing service registration |
| `Service::install()` | Async install flow: privilege check, uninstall-if-present, binary copy, config init |

## Usage Example

```rust
use crate::service::{Service, FULL_SERVICE_NAME};
use crate::installation_initial_config_service::InstallConfigParams;

// Check installation state
if Service::is_installed() {
    println!("Service already registered as {}", FULL_SERVICE_NAME);
}

// Install with initial configuration
let params = InstallConfigParams { /* ... */ };
Service::install(params).await?;
```

## Recovery Policy (Windows SCM)

```text
Attempt 1 → restart after 10s
Attempt 2 → restart after 60s
Attempt 3+ → restart after 300s
Reset counter after 1 day of clean operation
```

## Platform Detection Matrix

| OS | Installation Check | Service Identity |
|----|-------------------|-----------------|
| Windows | `sc query com.openframe.client` | Windows SCM |
| macOS | `/Library/LaunchDaemons/com.openframe.client.plist` | launchd |
| Linux | `/etc/systemd/system/com.openframe.client.service` | systemd |

> **Note:** `Service::install()` requires admin/root privileges on all platforms. On Windows, the binary directory is added to the system `PATH` automatically; a terminal restart is required for the change to take effect.
