Cross-platform service lifecycle manager for the OpenFrame client, handling installation, uninstallation, and runtime execution across Windows, macOS, and Linux.

## Key Components

- **`Service`** — Core struct providing static methods for service lifecycle management
- **`windows_service_main`** — Windows SCM entry point registered via `define_windows_service!`, handling stop/shutdown/session-change control events
- **`set_service_status`** — Windows helper to report current `ServiceState` to the SCM
- **`FULL_SERVICE_NAME`** — Public constant `"com.openframe.client"` used as the canonical service identifier across all platforms
- **Recovery constants** — SCM restart delays (`FIRST_RESTART_SERVICE_SECS: 10s`, `SECOND_RESTART_SERVICE_SECS: 60s`, `SUBSEQUENT_RESTART_SERVICE_SECS: 300s`) and a 1-day reset period

## Key Methods

| Method | Description |
|--------|-------------|
| `Service::is_installed()` | Checks platform-native registration (SC query / LaunchDaemon plist / systemd unit) |
| `Service::install(params)` | Copies binary to install location, writes initial config, registers OS service |
| `Service::get_install_location()` | Returns the canonical binary path for the current platform |
| `Service::run(session_rx)` | Async entrypoint that starts the client runtime |

## Usage Example

```rust
// Install the service with initial configuration
let params = InstallConfigParams {
    tenant_id: "acme-corp".into(),
    // ...other params
};
Service::install(params).await?;

// Check installation status before proceeding
if Service::is_installed() {
    println!("OpenFrame client service is registered");
}

// Run directly (non-SCM, e.g. foreground/debug mode)
Service::run(None).await?;
```

## Platform Notes

- **Windows** — Registers with SCM via `windows_service` crate; forwards `SessionChange` events to `WindowsSessionManager` via an unbounded Tokio channel
- **macOS** — Installs as a `/Library/LaunchDaemons/com.openframe.client.plist` LaunchDaemon
- **Linux** — Installs as a `/etc/systemd/system/com.openframe.client.service` systemd unit
- On reinstall, the existing binary is invoked with `uninstall` and a 3-second cleanup grace period is observed before proceeding
