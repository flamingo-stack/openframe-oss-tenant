The root module file for the OpenFrame agent messaging and configuration types, re-exporting all public structs and enums used for agent lifecycle management, tool orchestration, and device communication.

## Key Components

| Export | Description |
|--------|-------------|
| `AgentRegistrationRequest/Response` | Agent registration handshake types |
| `AgentConfiguration` / `InitialConfiguration` | Agent setup and runtime configuration |
| `AgentTokenResponse` | Authentication token response |
| `ToolInstallationResult` / `ToolInstallationMessage` | Tool install lifecycle events |
| `ToolConnectionMessage` / `ToolConnection` | Tool connectivity state |
| `InstalledTool`, `Installation`, `InstalledAsset` | Installed tool inventory types |
| `OpenFrameClientUpdateMessage` / `OpenFrameClientInfo` | OpenFrame client update and metadata |
| `ToolAgentUpdateMessage`, `AssetUpdate` | Tool agent update payloads |
| `MachineHeartbeatMessage` | Device heartbeat signaling |
| `DownloadConfiguration`, `InstallationType` | Download and install strategy config |
| `InstalledAgentMessage` | Agent presence/install notification |
| `UpdateState`, `UpdatePhase` | Update lifecycle state tracking |
| `DeviceTag` | Device tagging/labeling |

## Usage Example

```rust
use openframe_types::{
    AgentRegistrationRequest,
    AgentConfiguration,
    MachineHeartbeatMessage,
    UpdateState,
    UpdatePhase,
    DeviceTag,
};

// Register an agent
let request = AgentRegistrationRequest { /* .. */ };

// Track an ongoing update
let state = UpdateState {
    phase: UpdatePhase::Downloading,
    // ..
};

// Tag the managed device
let tag = DeviceTag { /* .. */ };
```

> All types are re-exported at the crate root, so consumers only need a single `use` path rather than importing from individual submodules.
