Data structure for automating tool installation and management across different platforms, handling downloads, assets, and platform-specific configurations.

## Key Components

- **`ToolInstallationMessage`** - Main message structure containing tool metadata, installation commands, and asset configurations
- **`SessionType`** - Enum defining execution contexts (Service, Console, User)
- **`Asset`** - Represents downloadable tool components with platform-specific configurations
- **`LocalFilenameConfig`** - Platform-specific filename mapping with OS detection
- **`AssetSource`** - Enum for different download sources (Artifactory, Tool API, GitHub)

## Usage Example

```rust
use tool_installation_message::{ToolInstallationMessage, SessionType, Asset, AssetSource};

// Create a tool installation message
let installation_msg = ToolInstallationMessage {
    tool_agent_id: "agent-123".to_string(),
    tool_id: "docker".to_string(),
    tool_type: "container".to_string(),
    version: "24.0.0".to_string(),
    reinstall: false,
    session_type: Some(SessionType::Service),
    download_configurations: None,
    installation_command_args: Some(vec!["install".to_string(), "-y".to_string()]),
    uninstallation_command_args: Some(vec!["remove".to_string()]),
    run_command_args: vec!["docker".to_string(), "run".to_string()],
    tool_agent_id_command_args: None,
    assets: Some(vec![Asset {
        id: "docker-binary".to_string(),
        local_filename_configuration: vec![
            LocalFilenameConfig {
                filename: "docker.exe".to_string(),
                os: "windows".to_string(),
            }
        ],
        source: AssetSource::Github,
        path: Some("/usr/local/bin".to_string()),
        executable: true,
        download_configurations: None,
        version: None,
    }]),
};

// Check if filename config matches current OS
let config = LocalFilenameConfig {
    filename: "docker".to_string(),
    os: "linux".to_string(),
};
let is_compatible = config.matches_current_os();
```
