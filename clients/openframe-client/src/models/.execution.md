Defines the core data types and trait for RMM (Remote Monitoring & Management) script execution, mapping inbound message payloads to normalized `ExecutionRequest` values and outbound `RmmResult` structs.

## Key Components

| Item | Kind | Description |
|---|---|---|
| `ScriptShell` | enum | Supported script runtimes: `Powershell`, `Cmd`, `Bash`, `Python`, `Nushell`, `Shell` |
| `PrivilegeLevel` | enum | Execution privilege: `User` or `Admin` (default) |
| `ScriptSpec` | struct | Reusable script body: code, shell, privilege, args, timeout, env vars |
| `ScriptEnvVar` | struct | Name/value pair with optional `secret` flag |
| `CommandMessage` | struct | One-shot command payload (no env vars or args) |
| `ScriptMessage` | struct | Single script execution payload with full `ScriptSpec` |
| `ScriptScheduleExecutionMessage` | struct | Batch of scripts sharing one `execution_id`; `DURABLE = true` |
| `ExecutionRequest<'a>` | struct | Normalized, lifetime-bound execution unit passed to the runner |
| `RmmResult` | struct | Serialized execution result (stdout, stderr, exit code, timing) |
| `ExecutionMessage` | trait | Common interface: `from_payload`, `execution_id`, `to_requests`, `schedule_id` |

**`ExecutionMessage` constants:**

| Implementor | `KIND` | `RESULT_KIND` | `DURABLE` |
|---|---|---|---|
| `CommandMessage` | `command-execution` | _(same)_ | false |
| `ScriptMessage` | `script-execution` | _(same)_ | false |
| `ScriptScheduleExecutionMessage` | `script-schedule-execution` | `script-execution` | **true** |

## Usage Example

```rust
use crate::execution::{ExecutionMessage, ScriptMessage, ScriptScheduleExecutionMessage};

// Deserialize an inbound message and build execution requests
let msg = ScriptMessage::from_payload(payload)?;
for req in msg.to_requests() {
    println!("Run {} via {:?} (timeout {}s)", req.execution_id, req.shell, req.timeout_secs);
    runner.execute(req).await?;
}

// Batch schedule execution (durable, multiple scripts)
let batch = ScriptScheduleExecutionMessage::from_payload(payload)?;
assert_eq!(ScriptScheduleExecutionMessage::RESULT_KIND, ScriptMessage::KIND);
for req in batch.to_requests() {
    // All requests share the same execution_id and schedule_id
    runner.execute(req).await?;
}
```

> **Defaults:** `timeout_seconds` falls back to **900 s**; missing `privilege_level` defaults to **Admin**; `None` fields on `RmmResult` (`error`, `schedule_id`) are omitted from JSON serialization.
