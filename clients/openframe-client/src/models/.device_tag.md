Defines the `DeviceTag` struct for representing key-multi-value device tags, along with CLI parsing logic that groups repeated keys into a single tag entry.

## Key Components

### `DeviceTag`
A serializable struct representing a single tag with one key and one or more associated values.

| Field | Type | Description |
|-------|------|-------------|
| `key` | `String` | The tag key (e.g., `"site"`) |
| `values` | `Vec<String>` | One or more values for that key |

### `DeviceTag::parse_from_cli`
Parses a list of `key=value` strings (as passed via CLI arguments) into a `Vec<DeviceTag>`. Multiple entries sharing the same key are merged into a single `DeviceTag` with all values collected. Invalid entries (missing `=`, empty keys, or empty/whitespace-only values) are silently skipped.

## Usage Example

```rust
use crate::device_tag::DeviceTag;

let raw = vec![
    "site=CHICAGO".to_string(),
    "site=NEW YORK".to_string(),
    "env=production".to_string(),
    "=nokey".to_string(),   // skipped — empty key
    "broken".to_string(),   // skipped — no '='
];

let tags = DeviceTag::parse_from_cli(raw);
// tags == [
//   DeviceTag { key: "site", values: ["CHICAGO", "NEW YORK"] },
//   DeviceTag { key: "env",  values: ["production"] },
// ]
```

## Parsing Rules

- Input format: `key=value` (first `=` is the delimiter)
- Duplicate keys → values are merged into one `DeviceTag`
- Keys and values are trimmed of surrounding whitespace
- Entries with an empty key, empty value, or whitespace-only value are dropped
- Entries missing `=` are ignored entirely
