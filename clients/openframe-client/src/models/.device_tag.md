Defines the `DeviceTag` data model and its CLI parsing logic for key-value device tag strings used in device filtering operations.

## Key Components

### `DeviceTag` Struct

| Field | Type | Description |
|-------|------|-------------|
| `key` | `String` | Tag key (e.g., `"site"`) |
| `values` | `Vec<String>` | All values associated with the key |

Derives `Debug`, `Clone`, `Serialize`, `Deserialize`, and `PartialEq`.

### `DeviceTag::parse_from_cli`

```rust
pub fn parse_from_cli(raw_tags: Vec<String>) -> Vec<Self>
```

Parses a list of `"key=value"` strings into grouped `DeviceTag` entries. Multiple entries sharing the same key are collapsed into a single `DeviceTag` with multiple values.

**Parsing rules:**
- Entries without `=` are silently ignored
- Keys or values that are empty or whitespace-only are skipped
- Leading/trailing whitespace is trimmed from both key and value

## Usage Example

```rust
use device_tag::DeviceTag;

let raw = vec![
    "site=CHICAGO".to_string(),
    "site=NEW YORK".to_string(),
    "env=production".to_string(),
];

let tags = DeviceTag::parse_from_cli(raw);
// tags[0] => DeviceTag { key: "site", values: ["CHICAGO", "NEW YORK"] }
// tags[1] => DeviceTag { key: "env",  values: ["production"] }
```

This is typically used when accepting `--tag key=value` CLI flags, where a flag may be repeated to specify multiple values for the same key.
