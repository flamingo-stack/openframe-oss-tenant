Defines the data structures for tracking the lifecycle state of an update operation, including phase transitions and metadata.

## Key Components

### `UpdatePhase` (enum)
Represents the sequential stages of an update process:

| Variant | Description |
|---|---|
| `Validating` | Initial validation of the update |
| `Downloading` | Fetching update artifacts |
| `Extracting` | Unpacking downloaded content |
| `PreparingUpdater` | Staging the updater binary |
| `UpdaterLaunched` | Updater process has started |
| `Verifying` | Post-update verification |
| `Completed` | Update finished successfully |
| `RolledBack` | Update failed; system reverted |

### `UpdateState` (struct)
Persisted state snapshot for an in-progress or completed update. Fields:
- `target_version` — semver string of the desired release
- `phase` — current `UpdatePhase`
- `boot_attempts` — incremented on each boot during update (defaults to `0`)
- `started_at` — RFC 3339 timestamp set at construction

### `UpdateState::new(target_version)`
Creates a fresh state record in the `Validating` phase with `started_at` set to the current UTC time.

### `UpdateState::set_phase(&mut self, phase)`
Transitions the state to a new `UpdatePhase`.

## Usage Example

```rust
use update_state::{UpdateState, UpdatePhase};

// Begin a new update workflow
let mut state = UpdateState::new("2.4.1".to_string());
assert_eq!(state.phase, UpdatePhase::Validating);

// Advance through phases
state.set_phase(UpdatePhase::Downloading);
state.set_phase(UpdatePhase::Extracting);

// Serialize to JSON for persistence
let json = serde_json::to_string(&state)?;

// Deserialize back when resuming after reboot
let restored: UpdateState = serde_json::from_str(&json)?;
```
