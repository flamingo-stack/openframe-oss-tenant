Compile-time configuration constants for the update/agent system, defining timeouts, retry behavior, and NATS messaging parameters.

## Key Components

| Constant | Value | Purpose |
|---|---|---|
| `MAX_DOWNLOAD_RETRIES` | `3` | Max retry attempts per download |
| `DOWNLOAD_TIMEOUT_SECS` | `300` | Binary download timeout (5 min) |
| `MIN_BINARY_SIZE_BYTES` | `102,400` | Minimum valid binary size (100 KB) |
| `HTTP_CLIENT_TIMEOUT_SECS` | `120` | Timeout for control-plane requests |
| `DOWNLOAD_CLIENT_TIMEOUT_SECS` | `300` | Timeout for binary download clients |
| `CONSUMER_RETRY_ATTEMPTS_PER_CYCLE` | `5` | Retry attempts before pausing |
| `INITIAL_RETRY_DELAY_MS` | `1,000` | Starting backoff delay (1s) |
| `MAX_RETRY_DELAY_MS` | `30,000` | Backoff ceiling (30s) |
| `CONSUMER_CYCLE_PAUSE_MS` | `30,000` | Pause between retry cycles (30s) |
| `RECONNECTION_DELAY_MS` | `5,000` | Delay before reconnect attempt (5s) |
| `CONSUMER_ACK_WAIT_SECS` | `120` | NATS consumer ack wait window |
| `CONSUMER_MAX_DELIVER` | `10` | Max NATS message delivery attempts |

## Usage Example

```rust
use crate::update_config::{
    MAX_DOWNLOAD_RETRIES,
    DOWNLOAD_TIMEOUT_SECS,
    INITIAL_RETRY_DELAY_MS,
    MAX_RETRY_DELAY_MS,
};

// Build an HTTP client for binary downloads
let client = reqwest::Client::builder()
    .timeout(Duration::from_secs(DOWNLOAD_TIMEOUT_SECS))
    .build()?;

// Exponential backoff within retry loop
for attempt in 0..MAX_DOWNLOAD_RETRIES {
    let delay = (INITIAL_RETRY_DELAY_MS * 2u64.pow(attempt))
        .min(MAX_RETRY_DELAY_MS);
    // ...
}
```

> Two separate HTTP client timeouts exist by design: `HTTP_CLIENT_TIMEOUT_SECS` covers fast control-plane calls (auth, heartbeat), while `DOWNLOAD_CLIENT_TIMEOUT_SECS` allows longer windows for large binary transfers from GitHub or Artifactory.
