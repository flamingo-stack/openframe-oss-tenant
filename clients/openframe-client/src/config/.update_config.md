Configuration constants for the OpenFrame OSS tenant update system, defining timeouts, retry policies, concurrency limits, and behavioral flags for the update pipeline.

## Key Components

| Constant | Value | Purpose |
|---|---|---|
| `MAX_DOWNLOAD_RETRIES` | 3 | Binary download attempt limit |
| `DOWNLOAD_TIMEOUT_SECS` | 300s | Timeout for binary downloads (GitHub, Artifactory) |
| `HTTP_CLIENT_TIMEOUT_SECS` | 120s | Timeout for control-plane operations (auth, heartbeat) |
| `CONSUMER_RETRY_ATTEMPTS_PER_CYCLE` | 5 | NATS consumer retries before pausing |
| `CONSUMER_CYCLE_PAUSE_MS` | 30,000ms | Pause between retry cycles |
| `EXECUTION_MIN_CONCURRENCY` | 4 | Minimum parallel execution slots |
| `OUTBOX_MAX_ENTRIES` | 500 | Durable result outbox capacity |
| `OUTBOX_MAX_PAYLOAD_BYTES` | ~960 KB | Max NATS payload (1 MB minus 64 KB headroom) |
| `BOOT_MARKER_WAIT_SECS` | 90s | Wait for new binary boot confirmation |
| `CRASH_LOOP_MAX_BOOT_ATTEMPTS` | 3 | Unverified boots before marking update failed |
| `ALLOW_DOWNGRADE` | `false` | Refuse updates below the last-known-good anchor |
| `UPDATER_TRANSCRIPTS_KEPT` | 5 | Update attempt logs retained after pruning |
| `CONSUMER_ACK_WAIT_SECS` | 120s | NATS message acknowledgement window |
| `CLIENT_UPDATE_PENDING_TTL_SECS` | 300s | Client-before-tool ordering flag lifetime |
| `PROGRESS_ACK_INTERVAL_SECS` | 60s | In-progress heartbeat interval (within ack window) |

## Usage Example

```rust
use crate::update_config::{
    BOOT_MARKER_WAIT_SECS,
    CRASH_LOOP_MAX_BOOT_ATTEMPTS,
    ALLOW_DOWNGRADE,
};

// Guard against downgrade attempts
if !ALLOW_DOWNGRADE && incoming_version < last_known_good {
    return Err(UpdateError::DowngradeRefused);
}

// Wait for boot marker after applying update
tokio::time::timeout(
    Duration::from_secs(BOOT_MARKER_WAIT_SECS),
    wait_for_boot_marker(),
).await?;
```

## Design Notes

- **Two HTTP clients** are intentional: the shorter `HTTP_CLIENT_TIMEOUT_SECS` (120s) governs lightweight control-plane calls, while `DOWNLOAD_CLIENT_TIMEOUT_SECS` (300s) covers large binary transfers.
- **`UNINSTALL_CONSUMER_MAX_DELIVER` and `RESTART_CONSUMER_MAX_DELIVER`** are set to 20 (vs. 10 for standard consumers) to tolerate deferral behind long-running install operations holding the tool lock.
- **`CLIENT_UPDATE_PENDING_TTL_SECS`** (300s) deliberately exceeds `CONSUMER_ACK_WAIT_SECS` (120s) to ensure the client-before-tool ordering flag survives redelivery gaps.
