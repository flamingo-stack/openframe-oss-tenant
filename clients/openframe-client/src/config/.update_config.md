Centralized configuration constants for the update system, defining timeouts, retry policies, and download parameters used across the update pipeline.

## Key Components

| Constant | Value | Purpose |
|----------|-------|---------|
| `MAX_DOWNLOAD_RETRIES` | `3` | Maximum attempts per binary download |
| `DOWNLOAD_TIMEOUT_SECS` | `300` | Per-download timeout (5 minutes) |
| `MIN_BINARY_SIZE_BYTES` | `102,400` | Minimum valid binary size (100 KB) |
| `HTTP_CLIENT_TIMEOUT_SECS` | `120` | Control-plane HTTP client timeout |
| `DOWNLOAD_CLIENT_TIMEOUT_SECS` | `300` | Binary download HTTP client timeout |
| `CONSUMER_RETRY_ATTEMPTS_PER_CYCLE` | `5` | NATS consumer retries before pausing |
| `INITIAL_RETRY_DELAY_MS` | `1,000` | Starting backoff delay (1 second) |
| `MAX_RETRY_DELAY_MS` | `30,000` | Backoff ceiling (30 seconds) |
| `CONSUMER_CYCLE_PAUSE_MS` | `30,000` | Pause between retry cycles (30 seconds) |
| `RECONNECTION_DELAY_MS` | `5,000` | Delay before reconnect attempt (5 seconds) |
| `CONSUMER_ACK_WAIT_SECS` | `120` | NATS message ACK deadline |
| `CONSUMER_MAX_DELIVER` | `10` | Maximum NATS delivery attempts |

## Usage Example

```rust
use crate::update_config::{
    MAX_DOWNLOAD_RETRIES,
    DOWNLOAD_TIMEOUT_SECS,
    MIN_BINARY_SIZE_BYTES,
    CONSUMER_RETRY_ATTEMPTS_PER_CYCLE,
    INITIAL_RETRY_DELAY_MS,
    MAX_RETRY_DELAY_MS,
};

// Apply exponential backoff using config bounds
let mut delay = INITIAL_RETRY_DELAY_MS;
for attempt in 0..MAX_DOWNLOAD_RETRIES {
    match download_binary(&url, DOWNLOAD_TIMEOUT_SECS).await {
        Ok(bytes) if bytes.len() as u64 >= MIN_BINARY_SIZE_BYTES => break,
        _ => {
            tokio::time::sleep(Duration::from_millis(delay)).await;
            delay = (delay * 2).min(MAX_RETRY_DELAY_MS);
        }
    }
}
```

> Two distinct HTTP client timeouts are intentional: control-plane operations (auth, heartbeat, key fetch) use `HTTP_CLIENT_TIMEOUT_SECS` (120s), while binary downloads from GitHub/Artifactory use the longer `DOWNLOAD_CLIENT_TIMEOUT_SECS` (300s).
