Platform-specific update script module that conditionally exposes OS update scripts and templates for Windows and macOS targets.

## Key Components

| Export | Platform | Description |
|--------|----------|-------------|
| `UPDATE_SCRIPT_WINDOWS` | Windows | PowerShell update script constant |
| `UPDATE_SCRIPT_MACOS` | macOS | Shell update script constant |
| `UPDATER_PLIST_TEMPLATE` | macOS | launchd `.plist` template for the updater daemon |

## Platform Modules

- **`windows`** — compiled only on `target_os = "windows"`
- **`macos`** — compiled only on `target_os = "macos"`

## ASCII Invariant

Both platforms enforce a strict **pure-ASCII** constraint on all exported string constants, validated at test time. On Windows, PowerShell 5.1 reads BOM-less UTF-8 files as ANSI, causing multi-byte characters (e.g. an em-dash's `0x94` byte) to be misinterpreted as smart quotes that can structurally break the script.

## Usage Example

```rust
// Windows — embed the update script at compile time
#[cfg(target_os = "windows")]
use scripts::UPDATE_SCRIPT_WINDOWS;

// macOS — embed both the script and the plist template
#[cfg(target_os = "macos")]
use scripts::{UPDATE_SCRIPT_MACOS, UPDATER_PLIST_TEMPLATE};

#[cfg(target_os = "macos")]
fn install_launch_daemon(version: &str) {
    let plist = UPDATER_PLIST_TEMPLATE.replace("{{VERSION}}", version);
    std::fs::write("/Library/LaunchDaemons/com.example.updater.plist", plist).unwrap();
}
```

## Tests

| Test | Platform | Assertion |
|------|----------|-----------|
| `windows_update_script_is_ascii` | Windows | `UPDATE_SCRIPT_WINDOWS` is pure ASCII |
| `macos_update_script_is_ascii` | macOS | Both `UPDATE_SCRIPT_MACOS` and `UPDATER_PLIST_TEMPLATE` are pure ASCII |
