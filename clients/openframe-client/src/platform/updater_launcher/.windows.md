Handles launching a Windows PowerShell updater process detached from the console, writing the update script to a temporary file and spawning it with the appropriate parameters.

## Key Components

### `launch_updater(params: UpdaterParams) -> Result<()>`

Async function that orchestrates the Windows update process:

- Writes `UPDATE_SCRIPT_WINDOWS` to a UUID-named temp file (`openframe-updater-<uuid>.ps1`) with a **UTF-8 BOM** prefix to prevent Windows PowerShell 5.1 from misreading multi-byte characters as ANSI
- Resolves the PowerShell executable path via `get_powershell_path()`
- Spawns PowerShell with `-ExecutionPolicy Bypass -NoProfile` and passes all `UpdaterParams` fields as named arguments
- Sets the `CREATE_NO_WINDOW` flag (`0x08000000`) so the process runs silently with no console window
- Conditionally appends `-RollbackOnly` when `params.rollback_only` is `true`

## Usage Example

```rust
use crate::platform::windows::launch_updater;
use crate::updater::UpdaterParams;

let params = UpdaterParams {
    binary_path: "/tmp/update.zip".into(),
    service_name: "openframe".into(),
    target_exe: "C:/Program Files/openframe/openframe.exe".into(),
    update_state_path: "C:/ProgramData/openframe/update_state.json".into(),
    target_version: "1.2.3".into(),
    boot_marker_path: "C:/ProgramData/openframe/boot.marker".into(),
    lkg_path: "C:/ProgramData/openframe/lkg/".into(),
    transcript_path: "C:/ProgramData/openframe/update.log".into(),
    rollback_only: false,
};

launch_updater(params).await?;
```

## Notes

- The UTF-8 BOM (`\u{FEFF}`) is critical for PowerShell 5.1 compatibility on older Windows systems
- The child process is intentionally not awaited — the updater is expected to replace the current binary, so the parent process exits after spawning
