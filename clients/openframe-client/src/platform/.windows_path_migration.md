One-time Windows registry migration that repairs the system `PATH` value type from `REG_SZ` back to `REG_EXPAND_SZ`, restoring proper environment variable expansion (e.g. `%SystemRoot%`) that was broken by a previous OpenFrame agent version.

## Key Components

### `run()`

The sole exported function. Safe to call on every startup — performs a no-op if the registry value is already the correct type. Execution flow:

1. Opens `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment` with read/write access.
2. Reads the raw `Path` value and checks its registry type.
3. **Skips** if already `REG_EXPAND_SZ`.
4. **Skips** if the string contains no `%` characters (no variable references to expand).
5. Re-encodes the existing path string as UTF-16 LE and writes it back with type `REG_EXPAND_SZ`.
6. Logs a warning (non-fatal) if the registry operation fails — never panics.

## Usage Example

```rust
// Call once at agent startup, before launching any child processes
// that rely on PATH resolution (ping.exe, ipconfig.exe, etc.)
fn main() {
    windows_path_migration::run();

    // ... rest of agent initialisation
}
```

## Notes

| Condition | Behaviour |
|-----------|-----------|
| Type already `REG_EXPAND_SZ` | No-op, returns immediately |
| Type is `REG_SZ`, no `%` chars | No-op, expansion not needed |
| Type is `REG_SZ` with `%` vars | Rewrites as `REG_EXPAND_SZ` |
| Registry open/write fails | Logs `warn!`, continues startup |

> **Windows only.** This module uses `winreg` and will not compile on non-Windows targets. Wrap call sites with `#[cfg(target_os = "windows")]` if the crate is cross-platform.
