One-time Windows registry migration that repairs the `PATH` environment variable's registry value type from `REG_SZ` back to `REG_EXPAND_SZ`, restoring proper `%variable%` expansion for system tools.

## Key Components

- **`run()`** — Public entry point for the migration. Reads the raw `Path` registry value under `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment`, checks if it was incorrectly written as `REG_SZ`, and rewrites it as `REG_EXPAND_SZ` if unexpanded `%variables%` are detected. Safe to call on every startup; no-ops if the type is already correct.

## Problem Context

Previous OpenFrame versions used `set_value()` which silently downgrades `REG_EXPAND_SZ` to `REG_SZ`. This prevents Windows from expanding `%SystemRoot%` and similar tokens in `PATH`, making standard system tools (`ping.exe`, `ipconfig.exe`, etc.) unreachable from the shell.

## Migration Logic

```text
1. Open HKLM\...\Environment with KEY_READ | KEY_WRITE
2. Read raw bytes of "Path" value
3. If vtype != REG_SZ → already correct, exit
4. If value contains no '%' chars → no expansion needed, exit
5. Re-encode as UTF-16LE + null terminator
6. Write back with vtype = REG_EXPAND_SZ
```

## Usage Example

```rust
// Call once at application startup (e.g., in main.rs or service init)
windows_path_migration::run();

// Non-fatal: failures are logged as warnings and execution continues
```

## Behavior Notes

- Errors are caught internally and emitted as `warn!` — never panics or propagates
- Only rewrites the value when **both** conditions are true: type is `REG_SZ` **and** the string contains `%`
- Requires the process to be running with sufficient privileges to write `HKLM` registry keys
