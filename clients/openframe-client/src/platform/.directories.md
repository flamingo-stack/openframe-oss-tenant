Cross-platform directory management for OpenFrame, providing a unified `DirectoryManager` interface that resolves and configures platform-specific paths for app support, logs, and secured directories across Windows, macOS, and Linux.

## Key Components

- **`DirectoryError`** — Typed error enum covering creation failures, permission denials, validation errors, and missing home directories
- **`get_app_support_directory()`** — Returns the platform-specific app data path (`ProgramData\OpenFrame`, `/Library/Application Support/OpenFrame`, `/var/lib/openframe`)
- **`get_logs_directory()`** — Returns the logs path, respecting the `OPENFRAME_LOG_DIR` environment variable override before falling back to platform defaults
- **`get_secured_directory()`** — Returns an admin/root-only directory path for sensitive data
- **`set_directory_permissions()`** — Applies `755` permissions and appropriate ownership per platform
- **`set_secured_directory_permissions()`** — Applies `700` (owner-only) permissions for secured directories on Linux
- **`DirectoryManager`** — Central struct managing all directory paths with multiple construction modes

## Usage Example

```rust
// Standard system-level usage (requires elevated privileges)
let manager = DirectoryManager::new();

// Development mode: uses user directories to avoid permission issues
let manager = DirectoryManager::for_development();

// With user-specific log directory alongside system directories
let manager = DirectoryManager::with_user_logs_dir();

// Custom paths (e.g., for testing)
let manager = DirectoryManager::with_custom_dirs(
    PathBuf::from("/tmp/openframe/logs"),
    PathBuf::from("/tmp/openframe/app"),
    PathBuf::from("/tmp/openframe/secured"),
);

// OPENFRAME_LOG_DIR env var overrides the default log path
// std::env::set_var("OPENFRAME_LOG_DIR", "/custom/log/path");
let logs_path = get_logs_directory();
```

> **Note:** On Unix systems, `set_directory_permissions` and `set_secured_directory_permissions` invoke `chown` and `chmod` as subprocesses. These operations require root/admin privileges in production deployments.
