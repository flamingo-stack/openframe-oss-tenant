Cross-platform directory management for the OpenFrame agent, providing a unified API to resolve, create, and configure platform-specific paths for app support, logs, and secured storage on Windows, macOS, and Linux.

## Key Components

### Enums
- **`DirectoryError`** — Error variants for directory operations: `CreateFailed`, `PermissionDenied`, `ValidationFailed`, `FixFailed`, `HomeDirectoryNotFound`

### Free Functions
- **`get_app_support_directory()`** — Returns the system app support path (`ProgramData\OpenFrame`, `/Library/Application Support/OpenFrame`, `/var/lib/openframe`)
- **`get_logs_directory()`** — Returns the log directory path, with `OPENFRAME_LOG_DIR` env var override support
- **`get_secured_directory()`** — Returns an admin/root-only secured storage path
- **`set_directory_permissions(path)`** — Applies standard `755` permissions (platform-aware)
- **`set_secured_directory_permissions(path)`** — Applies restrictive `700` permissions for secured directories

### Struct: `DirectoryManager`
- **`new()`** — Initializes with default platform-specific paths
- **`with_custom_dirs(logs, app_support, secured)`** — Initializes with explicit paths
- **`with_user_logs_dir()`** — Adds a per-user log path alongside system paths
- **`for_development()`** — Uses only user-space directories to avoid permission issues during development
- **`is_development_mode()`** — Detects whether the manager is in dev mode
- **`get_user_logs_directory()`** — Resolves the platform-appropriate user-scoped log path

## Usage Example

```rust
use crate::platform::directories::DirectoryManager;

// Production: system-level directories
let manager = DirectoryManager::new();

// Development: user-space only (avoids needing root/admin)
let dev_manager = DirectoryManager::for_development();

// Custom paths (e.g., for testing or containerized environments)
let custom = DirectoryManager::with_custom_dirs(
    PathBuf::from("/tmp/openframe/logs"),
    PathBuf::from("/tmp/openframe/app"),
    PathBuf::from("/tmp/openframe/secured"),
);
```

> **Note:** `get_logs_directory()` respects the `OPENFRAME_LOG_DIR` environment variable, enabling log path overrides without recompilation — useful for containerized or test deployments.
