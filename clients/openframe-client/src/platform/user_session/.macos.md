macOS-specific utilities for detecting the current console user and launching processes in their GUI session context.

## Key Components

### `ConsoleUser`
A struct holding the `username` (String) and `uid` (u32) of the currently logged-in console user.

### Public Functions

| Function | Description |
|---|---|
| `get_console_user()` | Reads `/dev/console` ownership via `stat` to identify the logged-in user; filters out `root` and system accounts (prefixed with `_`) |
| `launch_as_user()` | Launches an executable as the console user; tries `launchctl asuser` first, falls back to `sudo -u` |
| `is_gui_session_ready()` | Checks whether the user's GUI session is active by verifying `Dock` and `Finder` are running via `pgrep` |
| `is_process_running()` | Checks if a process is already running by path using `pgrep -f` |

### Private Helpers

- **`launch_via_launchctl()`** — Spawns the process under the user's launchd session; detects `.app` bundles and uses `open -a` for those, otherwise invokes the executable directly
- **`launch_via_sudo()`** — Fallback launcher using `sudo -u <username>`
- **`extract_app_bundle_path()`** — Walks ancestor paths to find a `.app` bundle root for a given executable path

## Usage Example

```rust
use macos::{get_console_user, launch_as_user, is_gui_session_ready};

async fn start_agent() -> anyhow::Result<()> {
    let user = get_console_user().expect("No console user logged in");

    // Wait for GUI to be ready before launching
    if is_gui_session_ready(user.uid).await {
        let child = launch_as_user(
            "/Applications/MyApp.app/Contents/MacOS/MyApp",
            &["--background".to_string()],
            &user,
        ).await?;

        println!("Launched with PID: {:?}", child.id());
    }

    Ok(())
}
```

> **Note:** This module shells out to `stat`, `id`, `pgrep`, `launchctl`, and `sudo`. It must run as `root` (or with appropriate privileges) for `launchctl asuser` and `sudo -u` to succeed.
