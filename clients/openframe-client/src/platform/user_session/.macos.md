Provides macOS-specific utilities for identifying the console user and launching processes in the correct user session context, supporting both `.app` bundles and plain executables.

## Key Components

### `ConsoleUser`
A struct holding the `username` and `uid` of the currently logged-in console user.

### `get_console_user() -> Option<ConsoleUser>`
Reads `/dev/console` ownership via `stat` to identify the active GUI user. Filters out `root` and system accounts (prefixed with `_`).

### `launch_as_user(executable, args, user) -> Result<Child>`
Launches a process in the target user's session. Tries `launchctl asuser` first, falling back to `sudo -u` on failure.

### `is_gui_session_ready(uid) -> bool`
Checks whether `Dock` and `Finder` are running for the given UID — used to verify the GUI session is fully initialized before launching UI processes.

### `is_process_running(executable_path) -> bool`
Uses `pgrep -f` to check if a process is already running by executable path.

### Internal helpers
- `launch_via_launchctl` — spawns via `launchctl asuser`, using `open -a` for `.app` bundles
- `launch_via_sudo` — fallback spawner using `sudo -u <username>`
- `extract_app_bundle_path` — walks path ancestors to find the `.app` bundle root

## Usage Example

```rust
use macos::{get_console_user, is_gui_session_ready, launch_as_user};

if let Some(user) = get_console_user() {
    if is_gui_session_ready(user.uid).await {
        let child = launch_as_user(
            "/Applications/MyApp.app/Contents/MacOS/MyApp",
            &[],
            &user,
        )
        .await?;
        println!("Launched PID: {:?}", child.id());
    }
}
```
