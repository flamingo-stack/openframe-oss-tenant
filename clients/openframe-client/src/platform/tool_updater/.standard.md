Implements the standard tool update strategy via `StandardToolUpdater`, which handles the full lifecycle of updating a managed tool binary: stop, backup, download, finalize, and rollback.

## Key Components

- **`StandardToolUpdater`** — Concrete implementation of the `ToolUpdater` trait for standard (non-special-case) tools, wrapping `ToolUpdaterDeps` for service/path access.
- **`prepare`** — Stops the running tool process and creates a binary backup before any update is applied.
- **`apply`** — Downloads and writes the new binary to the resolved agent path.
- **`finalize`** — Cleans up the backup file and logs that the tool will auto-restart via the run manager.
- **`rollback`** — Restores the backed-up binary if the update fails, reverting to the previous working state.

## Usage Example

```rust
use crate::updater::standard::StandardToolUpdater;
use crate::updater::{ToolUpdater, ToolUpdaterDeps};

let deps = ToolUpdaterDeps { /* ... */ };
let updater = StandardToolUpdater::new(deps);

// Orchestrated update flow
let ctx = updater.prepare(&installed_tool).await?;

match updater.apply(&installed_tool, &download_config, &ctx).await {
    Ok(_) => {
        updater.finalize(&installed_tool, &ctx).await?;
    }
    Err(e) => {
        // Restore previous binary on failure
        updater.rollback(&installed_tool, &ctx).await?;
        return Err(e);
    }
}
```

> **Note:** After `finalize`, the tool is expected to auto-restart through the run manager — no explicit restart call is required in the update orchestrator.
