Implements the `GuiAppToolUpdater`, which manages the full lifecycle of updating macOS GUI application bundles (`.app`) as part of the Flamingo/OpenFrame tool update pipeline.

## Key Components

**`GuiAppToolUpdater`** — Main struct implementing the `ToolUpdater` trait with four async lifecycle methods:

| Method | Responsibility |
|--------|---------------|
| `prepare` | Stops the running GUI app process, waits 2 seconds for graceful shutdown |
| `apply` | Removes the old `.app` bundle, downloads and extracts the new version to `/Applications` |
| `finalize` | Resolves command arg placeholders, writes macOS preferences via `bundle_id`, then relaunches the app as the console user |
| `rollback` | Logs a warning — no backup is maintained; reinstallation from server is required |

**Notable behaviors:**
- Waits in a loop for a console user session before launching (handles pre-login states)
- Special-cases `openframe-chat` tool to pass `--background` flag on relaunch
- Preference args are resolved through `command_params_resolver` before writing (e.g., `${client.serverUrl}` placeholders)
- Validates the new `.app` bundle exists at the expected path before reporting success

## Usage Example

```rust
use crate::updaters::gui_app::GuiAppToolUpdater;
use crate::updaters::{ToolUpdater, ToolUpdaterDeps};

let updater = GuiAppToolUpdater::new(deps);

// Lifecycle: prepare → apply → finalize
let ctx = updater.prepare(&installed_tool).await?;
updater.apply(&installed_tool, &download_config, &ctx).await?;
updater.finalize(&installed_tool, &ctx).await?;
```

> **Rollback note:** This updater does not create backups. If `apply` fails mid-way, users must reinstall the tool from the Flamingo server.
