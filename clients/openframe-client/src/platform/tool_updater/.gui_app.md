Implements the `GuiAppToolUpdater`, which manages the full lifecycle of updating macOS GUI application bundles (`.app`) as part of the Flamingo/OpenFrame tool update pipeline.

## Key Components

**`GuiAppToolUpdater`** — Main struct implementing the `ToolUpdater` trait with four lifecycle stages:

| Method | Responsibility |
|--------|---------------|
| `prepare` | Stops the running GUI app process, waits 2 seconds for clean shutdown |
| `apply` | Removes the old `.app` bundle, downloads and extracts the new version into `/Applications` |
| `finalize` | Waits for an active console user, writes resolved preferences via bundle ID, then relaunches the app as that user |
| `rollback` | Logs a warning — no backup strategy exists; reinstall from server is required |

**Special case — `openframe-chat`**: During `finalize`, this tool receives a `--background` flag on launch; all other GUI apps using a bundle ID pass args via preferences instead.

## Usage Example

```rust
use crate::updaters::gui_app::GuiAppToolUpdater;
use crate::updaters::{ToolUpdater, ToolUpdaterDeps};

let updater = GuiAppToolUpdater::new(deps);

// Lifecycle driven by the update orchestrator:
let ctx = updater.prepare(&tool).await?;
updater.apply(&tool, &config, &ctx).await?;
updater.finalize(&tool, &ctx).await?;
```

## Notes

- Expects `Installation::GuiApp { executable_path, bundle_id }` — panics with a bail if the installation variant is wrong.
- Placeholder resolution (e.g. `${client.serverUrl}`) in `run_command_args` is attempted before writing preferences; failures are soft-warned, not fatal.
- Launch failures during `finalize` are logged as errors but do **not** propagate — the update itself is considered complete.
- `find_app_bundle_path` resolves both `.app` root paths and deep binary paths to their bundle root.
