Implements the `GuiAppToolUpdater`, which handles the full lifecycle of updating macOS GUI application bundles — stopping the running app, replacing the bundle, writing preferences, and relaunching under the console user session.

## Key Components

| Item | Description |
|------|-------------|
| `GuiAppToolUpdater` | Struct implementing the `ToolUpdater` trait for GUI `.app` bundle updates |
| `prepare()` | Stops the running GUI process and signals a restart is needed |
| `apply()` | Removes the old `.app` bundle from `/Applications` and downloads/extracts the new version |
| `finalize()` | Waits for a console user session, resolves command args, writes macOS preferences via bundle ID, then relaunches the app as the user |
| `rollback()` | Logs a warning; no backup restore is available — user must reinstall manually |

## Usage Example

```rust
let updater = GuiAppToolUpdater::new(deps);

// Prepare: stops the GUI process
let ctx = updater.prepare(&installed_tool).await?;

// Apply: removes old bundle, installs new one to /Applications
updater.apply(&installed_tool, &download_config, &ctx).await?;

// Finalize: resolves args, writes preferences, relaunches as console user
updater.finalize(&installed_tool, &ctx).await?;
```

## Notes

- Only handles `Installation::GuiApp` variants — bails early for other installation types.
- After install, validates the new `.app` exists at the expected path before completing `apply()`.
- The `openframe-chat` tool receives a `--background` launch flag automatically during finalize.
- When a `bundle_id` is present, run arguments are resolved (e.g. `${client.serverUrl}` placeholders) and written as macOS preferences before launch.
- Rollback is a no-op with a warning; this updater does not maintain a backup path.
