Entry point for the tool update and migration subsystem, defining the core `ToolUpdater` trait, shared utilities, and orchestration logic for the prepare → apply → finalize/rollback lifecycle.

## Key Components

| Item | Description |
|------|-------------|
| `ToolUpdater` | Async trait defining the 4-phase update lifecycle: `prepare`, `apply`, `finalize`, `rollback` |
| `UpdateContext` | Carries per-update state (backup path, restart flag) across lifecycle phases |
| `ToolUpdaterDeps` | Dependency bundle (download service, kill service, run manager, directory manager, command resolver) |
| `create_updater()` | Factory that returns the correct `ToolUpdater` impl based on `Installation` type |
| `run_update()` | Orchestrates a full update with automatic rollback on failure |
| `run_migration()` | Orchestrates installation-type migration (e.g. Standard → Service) with rollback |
| `backup_binary()` | Creates a `.backup` copy of an existing binary before replacement |
| `download_and_write_binary()` | Downloads from GitHub and writes an executable to the target path |
| `cleanup_backup()` | Removes the backup file after a successful update |
| `restore_from_backup()` | Copies the backup back to the target path during rollback |
| `UnsupportedToolUpdater` | Non-macOS stub that immediately bails on prepare/apply (no-op finalize/rollback) |

## Usage Example

```rust
// Run a standard tool update with automatic rollback on failure
let deps = ToolUpdaterDeps {
    github_download_service,
    tool_kill_service,
    tool_run_manager,
    directory_manager,
    command_params_resolver,
};

run_update(&installed_tool, &download_config, deps.clone()).await?;

// Migrate a tool from Standard to Service installation type
let new_installation = run_migration(
    &installed_tool,
    &download_config,
    InstallationType::Service,
    deps,
).await?;
```
