Orchestrates tool update and migration lifecycle across installation types (`Standard`, `GuiApp`, `Service`), providing a phased prepare → apply → finalize → rollback pattern with shared binary helpers.

## Key Components

| Item | Description |
|------|-------------|
| `ToolUpdater` | Core async trait defining the 4-phase update lifecycle |
| `UpdateContext` | Carries per-update state (backup path, restart flag) |
| `ToolUpdaterDeps` | Dependency bundle injected into all updater implementations |
| `create_updater()` | Factory that returns the correct `Arc<dyn ToolUpdater>` for an `Installation` type |
| `run_update()` | Drives the full update flow with automatic rollback on failure |
| `run_migration()` | Drives installation-type migration (e.g. `Standard` → `Service`) with rollback |
| `UnsupportedToolUpdater` | Non-macOS stub that bails immediately on unsupported GUI app updates |
| `backup_binary()` | Copies existing binary to `.backup` before overwriting |
| `download_and_write_binary()` | Downloads from GitHub, extracts, and writes executable to target path |
| `cleanup_backup()` | Removes the `.backup` file after a successful update |
| `restore_from_backup()` | Copies `.backup` back to target path during rollback |

## Usage Example

```rust
// Run a standard tool update with automatic rollback on failure
let deps = ToolUpdaterDeps {
    github_download_service,
    tool_kill_service,
    tool_run_manager,
    directory_manager,
    command_params_resolver,
};

run_update(&installed_tool, &download_config, deps.clone()).await?;

// Migrate a tool from Standard to Service installation type
let new_installation = run_migration(
    &installed_tool,
    &download_config,
    InstallationType::Service,
    deps,
).await?;
```

> **Platform note:** `GuiAppToolUpdater` is compiled only on macOS (`#[cfg(target_os = "macos")]`). On other platforms, GUI app installations fall back to `StandardToolUpdater`.
