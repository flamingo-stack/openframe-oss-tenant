Implements the `ToolUpdater` trait for tools installed as system services, handling the full update lifecycle: stop service → backup → download → restart, with special handling for macOS `.app` bundles.

## Key Components

### `ServiceToolUpdater`
The primary struct implementing `ToolUpdater` for service-managed tools.

- **`new(deps: ToolUpdaterDeps) -> Self`** — Constructs the updater with injected dependencies.
- **`resolve_executable_path(tool) -> PathBuf`** — Resolves the actual binary path, supporting absolute paths, relative paths (joined to the agent directory), and default agent paths.
- **`is_app_bundle_download(config) -> bool`** — Detects whether the download target is a macOS `.app` bundle by checking for `.app/` in the target filename.

### Trait Implementation (`ToolUpdater`)

| Method | Behavior |
|--------|----------|
| `prepare` | Stops the system service, kills any lingering processes, waits 2s, backs up the binary (skips backup for `.app` bundles) |
| `apply` | On macOS `.app` bundles: removes old bundle and extracts full archive; otherwise performs a standard single-binary replacement |
| `finalize` | Cleans up backup, then restarts the service via the system service manager |
| `rollback` | Restores binary from backup; warns and no-ops if no backup exists (`.app` bundle case) |

## Usage Example

```rust
let updater = ServiceToolUpdater::new(deps);

// Prepare (stop service, backup)
let ctx = updater.prepare(&installed_tool).await?;

// Apply new binary or .app bundle
updater.apply(&installed_tool, &download_config, &ctx).await?;

// Finalize (cleanup backup, restart service)
updater.finalize(&installed_tool, &ctx).await?;

// On failure, rollback
updater.rollback(&installed_tool, &ctx).await?;
```

> **macOS Note:** `.app` bundle updates skip backup (protected/oversized) and use full archive extraction instead of single-binary replacement. Rollback for `.app` bundles requires a server reinstall.
