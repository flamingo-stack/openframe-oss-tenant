Implements the `ToolUpdater` trait for system-service-managed tools, handling the full update lifecycle (prepare → apply → finalize → rollback) including special macOS `.app` bundle handling.

## Key Components

- **`ServiceToolUpdater`** — Main struct wrapping `ToolUpdaterDeps`, constructed via `ServiceToolUpdater::new(deps)`
- **`resolve_executable_path`** — Resolves the tool binary path from either an absolute path, a relative `Service`-installation path, or the default agent directory
- **`is_app_bundle_download`** — Detects whether a `DownloadConfiguration` targets a macOS `.app` bundle by inspecting `target_file_name`
- **`prepare`** — Stops the running service and any managed processes, waits 2 seconds, then backs up the binary (skips backup for `.app` bundles)
- **`apply`** — On macOS with `.app` bundles: removes the old bundle and extracts the full archive; otherwise performs a standard single-binary download and write
- **`finalize`** — Cleans up the backup file and restarts the service via `system_service::start_service`
- **`rollback`** — Restores the binary from backup; logs a warning if no backup exists (`.app` bundle case requires server reinstall)

## Usage Example

```rust
let updater = ServiceToolUpdater::new(deps);

// Prepare: stop service, backup binary
let ctx = updater.prepare(&installed_tool).await?;

// Apply: download and write new binary (or extract .app bundle on macOS)
updater.apply(&installed_tool, &download_config, &ctx).await?;

// Finalize: clean up backup, restart service
updater.finalize(&installed_tool, &ctx).await?;

// On failure: restore previous binary from backup
updater.rollback(&installed_tool, &ctx).await?;
```

> **Note:** `.app` bundle backup is intentionally skipped on macOS — bundles are system-protected and oversized. Rollback for app bundles requires a server-side reinstall.
