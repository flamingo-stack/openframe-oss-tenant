Implements the `ToolUpdater` trait for tools installed as system services, handling the full update lifecycle: stop service → backup → download → restart, with rollback support.

## Key Components

**`ServiceToolUpdater`** — Main struct wrapping `ToolUpdaterDeps` that orchestrates service-based tool updates.

**`resolve_executable_path`** — Resolves the actual binary path from the tool's `Installation::Service` config, supporting both absolute paths and paths relative to the agent directory.

**`is_app_bundle_download`** — Detects macOS `.app` bundle targets by inspecting `DownloadConfiguration.target_file_name`.

**`ToolUpdater` impl** — Four-phase update pipeline:
- `prepare` — Stops the service and any managed processes, waits 2 seconds, then backs up the binary (skips backup for macOS `.app` bundles)
- `apply` — On macOS with `.app` bundles: removes old bundle and extracts the full archive; otherwise performs a standard single-binary download and write
- `finalize` — Cleans up the backup and restarts the service via `system_service::start_service`
- `rollback` — Restores from backup; warns and exits early if no backup exists (`.app` bundle case)

## Usage Example

```rust
use crate::updater::service::ServiceToolUpdater;

let updater = ServiceToolUpdater::new(deps);

// Execute the update pipeline
let ctx = updater.prepare(&installed_tool).await?;
updater.apply(&installed_tool, &download_config, &ctx).await?;
updater.finalize(&installed_tool, &ctx).await?;

// On failure, roll back
updater.rollback(&installed_tool, &ctx).await?;
```

> **Note:** The `.app` bundle path skips backup and rollback — a failed update on macOS bundles requires a full reinstall from the server. The `prepare` step always waits 2 seconds after stopping the service to allow file handles to be released before writing the new binary.
