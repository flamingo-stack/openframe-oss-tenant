Implements the `ServiceToolUpdater` struct, which handles the full update lifecycle (prepare, apply, finalize, rollback) for tools installed as system services, including special handling for macOS `.app` bundles.

## Key Components

### `ServiceToolUpdater`

The primary struct implementing the `ToolUpdater` trait for service-based tool installations.

| Method | Description |
|--------|-------------|
| `new(deps)` | Constructs a new updater with injected dependencies |
| `resolve_executable_path` | Resolves the binary path from `InstalledTool`, supporting absolute paths, relative paths, and default agent paths |
| `is_app_bundle_download` | Detects if a `DownloadConfiguration` targets a macOS `.app` bundle via path inspection |

### `ToolUpdater` Trait Implementation

| Method | Description |
|--------|-------------|
| `prepare` | Stops the service and any managed processes, waits 2 seconds, then creates a binary backup (skipped for `.app` bundles) |
| `apply` | On macOS, removes the old `.app` bundle and extracts the full archive; otherwise performs a standard single-binary replacement |
| `finalize` | Starts the system service and cleans up the backup file |
| `rollback` | Restores the binary from backup and attempts to restart the service; warns if no backup exists (`.app` bundle case) |

## Usage Example

```rust
use crate::updater::{ServiceToolUpdater, ToolUpdaterDeps};

let updater = ServiceToolUpdater::new(deps);

// Orchestrated by the update engine:
let ctx = updater.prepare(&installed_tool).await?;
let new_installation = updater.apply(&installed_tool, &download_config, &ctx).await?;
updater.finalize(&installed_tool, &ctx).await?;

// On failure:
updater.rollback(&installed_tool, &ctx).await?;
```

> **Note:** `.app` bundle rollback is not supported — if no backup exists, the tool must be reinstalled from the server. Service stop/restart failures are logged as warnings and treated as non-fatal to avoid blocking the update pipeline.
