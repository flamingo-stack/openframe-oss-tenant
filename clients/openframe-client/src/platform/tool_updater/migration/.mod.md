Defines the migration framework for transitioning installed tools between different installation types (e.g., `Standard` → `GuiApp`).

## Key Components

### `MigrationContext`
A shared state struct passed between migration lifecycle methods, tracking whether the old installation was cleaned up (`old_cleaned`) and whether the tool needs to be restarted post-migration (`needs_start`).

### `ToolMigrator` (trait)
Async trait defining the migration lifecycle:

| Method | Description |
|---|---|
| `from_type` / `to_type` | Declares the migration path |
| `prepare` | Pre-migration checks; returns a `MigrationContext` |
| `migrate` | Performs the actual installation change |
| `finalize` | Post-migration cleanup or activation |
| `rollback` | Optional rollback (default: logs a warning, returns `Ok`) |

### `create_migrator`
Factory function that returns the appropriate `Arc<dyn ToolMigrator>` for a given `from`/`to` type pair. Returns `None` if no migration is needed (same type). Currently supports:
- `Standard → GuiApp` on macOS and Windows only

### `needs_migration`
Convenience check — returns `true` if the current `Installation` type differs from the target `InstallationType`.

## Usage Example

```rust
let migrator = create_migrator(&current_installation, InstallationType::GuiApp, deps)?;

if let Some(migrator) = migrator {
    let ctx = migrator.prepare(&tool).await?;
    let new_installation = migrator.migrate(&tool, &config, &ctx).await?;
    migrator.finalize(&tool, &new_installation, &ctx).await?;
}
```

## Notes

- The `StandardToGuiAppMigrator` implementation is gated behind `#[cfg(any(target_os = "macos", windows))]` — unsupported migration paths bail with an error at runtime.
- Adding new migration paths requires implementing `ToolMigrator` and registering the match arm in `create_migrator`.
