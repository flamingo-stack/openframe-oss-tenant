Defines the migration framework for transitioning installed tools between different installation types (e.g., `Standard` → `GuiApp`).

## Key Components

### `MigrationContext`
A state-tracking struct passed through migration phases, carrying flags:
- `old_cleaned` — whether the previous installation was removed
- `needs_start` — whether the tool requires a post-migration start

### `ToolMigrator` (trait)
Async trait defining the lifecycle of a migration operation:

| Method | Description |
|--------|-------------|
| `prepare` | Pre-migration checks and setup; returns a `MigrationContext` |
| `migrate` | Performs the actual installation of the new type |
| `finalize` | Post-migration cleanup and activation |
| `rollback` | Attempts to undo the migration (default: no-op with warning) |

### `create_migrator`
Factory function that resolves the correct `ToolMigrator` implementation for a given `from → to` type pair. Returns `None` if no migration is needed (same type). Currently supports:
- `Standard → GuiApp` on macOS and Windows via `StandardToGuiAppMigrator`

### `needs_migration`
Helper that checks whether a current `Installation` differs from a target `InstallationType`.

## Usage Example

```rust
let migrator = create_migrator(&current_installation, InstallationType::GuiApp, deps)?;

if let Some(migrator) = migrator {
    let ctx = migrator.prepare(&tool).await?;
    let new_installation = migrator.migrate(&tool, &config, &ctx).await
        .or_else(|e| {
            migrator.rollback(&tool, &ctx);
            Err(e)
        })?;
    migrator.finalize(&tool, &new_installation, &ctx).await?;
}
```

> Adding a new migration path requires implementing `ToolMigrator` and registering the `(from, to)` match arm in `create_migrator`.
