Defines the migration framework for transitioning installed tools between different installation types (e.g., `Standard` → `GuiApp`).

## Key Components

- **`MigrationContext`** — Shared state passed between migration phases; tracks whether the old installation was cleaned up (`old_cleaned`) and whether the tool needs to be restarted post-migration (`needs_start`).

- **`ToolMigrator` trait** — Async trait defining the lifecycle of a migration:
  - `prepare` — Pre-migration checks and setup, returns a `MigrationContext`
  - `migrate` — Performs the actual installation type transition
  - `finalize` — Post-migration cleanup and validation
  - `rollback` — Best-effort undo; logs a warning by default if not overridden

- **`create_migrator()`** — Factory function that resolves the correct `ToolMigrator` implementation for a given `from → to` path. Returns `None` if no migration is needed, errors on unsupported paths.

- **`needs_migration()`** — Utility predicate to check if the current installation type differs from the target.

- **`StandardToGuiAppMigrator`** — Concrete migrator (macOS/Windows only) for the `Standard → GuiApp` path, gated via `#[cfg(any(target_os = "macos", windows))]`.

## Usage Example

```rust
use crate::updater::migrations::{create_migrator, needs_migration};

// Check if migration is required before proceeding
if needs_migration(&current_installation, target_type) {
    let migrator = create_migrator(&current_installation, target_type, deps)?
        .expect("Migration path must be supported");

    let ctx = migrator.prepare(&tool).await?;

    match migrator.migrate(&tool, &download_config, &ctx).await {
        Ok(new_installation) => {
            migrator.finalize(&tool, &new_installation, &ctx).await?;
        }
        Err(e) => {
            migrator.rollback(&tool, &ctx).await?;
            return Err(e);
        }
    }
}
```
