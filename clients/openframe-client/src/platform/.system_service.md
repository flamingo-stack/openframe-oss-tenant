Cross-platform service lifecycle manager providing start, stop, and status verification operations for system services across macOS (launchctl), Linux (systemctl), and Windows (SCM/Windows Service Control Manager).

## Key Components

| Function | Description |
|---|---|
| `start_service(service_name)` | Starts a service using the platform-native tool (`launchctl load`, `systemctl start`, or Windows SCM with retry logic) |
| `stop_service(service_name, allow_delete)` | Stops a service cross-platform; on Windows, escalates through graceful stop → force-kill by PID → force-kill by image path → optional SCM delete |
| `verify_service_running(service_name)` | Confirms a service reached `RUNNING` state after install (Windows-only; no-op on macOS/Linux) |
| `service_clear_for_install(service_name)` | Returns `true` if the service is absent or stopped and safe to (re)install over; always `true` on non-Windows |

**Windows-only internal helpers:**

- `try_start_service_windows` — raw SCM start, treats `ERROR_SERVICE_ALREADY_RUNNING` as success
- `wait_for_service_running_windows` — polls SCM until `Running` state or timeout
- `stop_service_windows` — graceful SCM stop with configurable timeout
- `force_stop_service_windows` — escalating force-kill via `taskkill` (PID or image path)

## Usage Example

```rust
use your_crate::system_service::{start_service, stop_service, verify_service_running};

// Start a service
start_service("com.example.myagent").await?;

// Stop before reinstall (allow_delete = true only on install/uninstall paths)
stop_service("com.example.myagent", true).await?;

// Stop during update (do NOT allow SCM delete — service won't be re-registered)
stop_service("com.example.myagent", false).await?;

// Confirm service reached RUNNING after install (Windows: polls SCM; others: no-op)
verify_service_running("com.example.myagent").await?;
```

> **`allow_delete` safety note:** Pass `true` only from install/reinstall/uninstall flows that recreate the service registration afterward. Update and restore flows must pass `false` — a SCM delete without re-registration bricks the tool.
