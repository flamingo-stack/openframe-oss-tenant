Utilities for safely reading and sanitizing command output from async streams, enforcing a 10 MiB size cap and producing clean UTF-8 strings.

## Key Components

| Item | Kind | Description |
|---|---|---|
| `MAX_OUTPUT_SIZE` | Constant | Hard cap of 10 MiB (`10 * 1024 * 1024` bytes) applied to all output reads |
| `read_capped` | Async function | Reads up to `MAX_OUTPUT_SIZE` bytes from an optional `AsyncRead` source; drains and discards any remaining bytes if the cap is hit |
| `clean_string` | Function | Converts a byte slice to a `String`, enforcing the size cap, stripping null bytes (`\x00`), and silently dropping invalid UTF-8 sequences |

## Usage Example

```rust
use tokio::process::Command;

let mut child = Command::new("ls")
    .arg("-la")
    .stdout(std::process::Stdio::piped())
    .spawn()?;

// Read stdout with a 10 MiB cap
let stdout_bytes = read_capped(child.stdout.take()).await;

// Convert raw bytes to a clean UTF-8 string
let output = clean_string(&stdout_bytes);
println!("{}", output);
```

## Behavior Notes

- **Cap enforcement**: If output reaches `MAX_OUTPUT_SIZE`, a `tracing::warn!` is emitted and the remainder of the stream is fully drained to avoid blocking the child process.
- **Null stripping**: `clean_string` removes all `\x00` bytes before UTF-8 decoding, which is common with some command outputs on Windows.
- **Invalid UTF-8**: Invalid byte sequences are silently dropped (not replaced); valid UTF-8 replacement characters (`\u{FFFD}`) already present in the input are preserved as-is.
- **Mid-codepoint truncation**: When truncating to `MAX_OUTPUT_SIZE`, `clean_string` walks back to a valid codepoint boundary to avoid splitting a multi-byte character.
