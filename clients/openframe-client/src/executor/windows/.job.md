Windows Job Object wrapper that manages process lifecycle via the Win32 Job Objects API, enabling kill-on-close semantics and whole-process-tree termination.

## Key Components

### `JobHandle`
A RAII wrapper around a Win32 `HANDLE` to a Job Object. Automatically closes the handle on drop via `CloseHandle`.

**Private constructor — `create() -> Option<HANDLE>`**
Creates a new anonymous Job Object and configures it with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, so all assigned processes are killed when the last handle is closed. Logs a warning (non-fatal) if the limit flag cannot be set.

**`for_pid(pid: u32) -> Self`**
Opens an existing process by PID with `PROCESS_TERMINATE | PROCESS_SET_QUOTA` rights and assigns it to the job. Returns a no-op `JobHandle(None)` if the PID is `0`, the job cannot be created, or `OpenProcess` fails.

**`for_handle(process: HANDLE) -> Self`**
Assigns an already-open process handle to a new job. Useful when the caller holds the handle from `CreateProcess` or similar.

**`terminate(&self)`**
Immediately terminates all processes in the job via `TerminateJobObject` with exit code `1`. This kills the entire process tree, not just the root process.

## Usage Example

```rust
// Attach to an existing process by PID and kill it (and its children) later
let job = JobHandle::for_pid(child_pid);
// ... do work ...
job.terminate(); // kills entire process tree

// Or attach using an already-open HANDLE (e.g. from CreateProcess)
let job = JobHandle::for_handle(process_handle);
// Dropping `job` also kills all processes if KILL_ON_JOB_CLOSE was set
```

> **Note:** All unsafe Win32 calls are isolated inside the `JobHandle` implementation. Failures degrade gracefully — termination falls back to single-process kill with a `tracing::warn!` log rather than panicking.
