NATS JetStream push consumer that listens for OpenFrame client update messages on the `CLIENT_UPDATE` stream and dispatches them to `OpenFrameClientUpdateService` for processing.

## Key Components

| Item | Description |
|------|-------------|
| `OpenFrameClientUpdateListener` | Main struct holding NATS connection, update service, and config service references |
| `start()` | Spawns a background `tokio` task with an infinite reconnect loop |
| `listen()` | Inner loop that creates the JetStream consumer and processes the message stream, handling NATS reconnection signals |
| `handle_message()` | Deserializes `OpenFrameClientUpdateMessage` JSON payloads, delegates to the update service, and ACKs on success; leaves unACKed on processing failure for redelivery |
| `create_consumer()` | Retry loop (exponential backoff, configurable cycles/attempts) that creates or retrieves an existing durable push consumer |
| `build_consumer_configuration()` | Assembles `push::Config` with `DeliverPolicy::New`, ACK wait, max deliver limits, and machine-scoped subjects |

**Stream:** `CLIENT_UPDATE`  
**Filter subject:** `machine.all.client-update`  
**Deliver subject:** `machine.<machine_id>.client-update.inbox`  
**Durable name:** `machine_<machine_id>_client-update_consumer_v2`

## Usage Example

```rust
let listener = OpenFrameClientUpdateListener::new(
    nats_connection_manager,
    openframe_client_update_service,
    config_service,
);

// Spawns a self-healing background task; hold the handle to monitor/abort
let _handle = listener.start().await?;
```

On NATS disconnect, the listener pauses for `RECONNECTION_DELAY_MS` before retrying. Consumer creation uses exponential backoff up to `MAX_RETRY_DELAY_MS`, cycling indefinitely until a consumer is obtained. Malformed messages are ACKed immediately to avoid poison-pill redelivery loops; failed processing leaves messages unACKed for JetStream redelivery up to `CONSUMER_MAX_DELIVER`.
