A NATS JetStream push consumer that listens for tool agent update messages on the `TOOL_UPDATE` stream, with automatic reconnection and retry logic.

## Key Components

| Item | Description |
|------|-------------|
| `ToolAgentUpdateListener` | Main struct holding NATS connection, update service, and config service |
| `start()` | Spawns a background `tokio` task with an infinite reconnect loop |
| `listen()` | Establishes JetStream connection and drives the message consumption loop |
| `handle_message()` | Deserializes payload, delegates to `ToolAgentUpdateService`, and acks on success |
| `create_consumer()` | Creates or retrieves a durable push consumer with exponential backoff retry |
| `build_consumer_configuration()` | Constructs `push::Config` with machine-scoped filter/deliver subjects and durable name |

**NATS subjects** (machine-scoped):

| Role | Pattern |
|------|---------|
| Filter | `machine.all.tool.*.update` |
| Deliver | `machine.{id}.tool.update.inbox` |
| Durable name | `machine_{id}_tool_update_consumer` |

## Usage Example

```rust
let listener = ToolAgentUpdateListener::new(
    nats_connection_manager,
    tool_agent_update_service,
    config_service,
);

// Spawns a self-healing background task
let handle = listener.start().await?;

// Optionally await the handle (runs indefinitely)
handle.await?;
```

**Retry behavior:** Each consumer creation cycle retries up to `CONSUMER_RETRY_ATTEMPTS_PER_CYCLE` times with exponential backoff (capped at `MAX_RETRY_DELAY_MS`). After exhausting a cycle, it pauses `CONSUMER_CYCLE_PAUSE_MS` before the next cycle. On listener failure, the outer loop waits `RECONNECTION_DELAY_MS` before reconnecting.

> **Ack strategy:** Messages are acked only after successful processing. Failed processing leaves the message unacked, allowing JetStream to redeliver up to `CONSUMER_MAX_DELIVER` times.
