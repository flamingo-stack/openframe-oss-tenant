A NATS JetStream push-consumer listener that subscribes to tool agent update messages on the `TOOL_UPDATE` stream, processes them via `ToolAgentUpdateService`, and handles reconnection/retry logic automatically.

## Key Components

**`ToolAgentUpdateListener`** — Main struct holding:
- `nats_connection_manager` — Manages NATS client connections
- `tool_agent_update_service` — Processes deserialized update messages
- `config_service` — Retrieves the local machine ID for consumer scoping

**Core Methods:**
- `start()` — Spawns a background `tokio` task with an infinite reconnect loop
- `listen()` — Establishes JetStream context, creates the consumer, and polls the message stream
- `handle_message()` — Deserializes `ToolAgentUpdateMessage` JSON, delegates to the update service, and ACKs on success; leaves unACKed on failure for redelivery
- `create_consumer()` — Creates or retrieves a durable push consumer with exponential backoff retry across configurable cycles; handles `consumer name already in use` gracefully
- `build_consumer_configuration()` — Assembles `push::Config` with `DeliverPolicy::New`, ACK wait, and max deliver limits

**Subject Pattern:**
- Filter subject: `machine.all.tool.*.update`
- Deliver inbox: `machine.<machine_id>.tool.update.inbox`
- Durable name: `machine_<machine_id>_tool_update_consumer`

## Usage Example

```rust
let listener = ToolAgentUpdateListener::new(
    nats_connection_manager,
    tool_agent_update_service,
    config_service,
);

// Spawns a self-healing background task
let handle = listener.start().await?;

// Optionally await the handle
handle.await?;
```

> Messages that fail processing are intentionally left unACKed, allowing JetStream to redeliver them up to `CONSUMER_MAX_DELIVER` times based on the consumer configuration.
