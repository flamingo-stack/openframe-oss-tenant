Async NATS JetStream push consumer that subscribes to tool agent update messages on the `TOOL_UPDATE` stream, deserializes them, and dispatches processing through the `ToolAgentUpdateService` with automatic reconnection and retry logic.

## Key Components

| Item | Description |
|------|-------------|
| `ToolAgentUpdateListener` | Main struct holding NATS connection, update service, config, and run manager |
| `start()` | Spawns a background `tokio` task with an infinite reconnect loop |
| `listen()` | Inner loop that creates the JetStream consumer and drives the message stream |
| `handle_message()` | Deserializes `ToolAgentUpdateMessage` JSON and gates dispatch via `park_or_dispatch` |
| `dispatch()` | Calls `ToolAgentUpdateService::process_update`; acks on success, leaves unacked for redelivery on failure |
| `create_consumer()` | Creates or recovers a durable push consumer with exponential backoff across retry cycles |
| `build_consumer_configuration()` | Builds `push::Config` with `DeliverPolicy::New`, configurable ack-wait, and per-machine subject routing |

**Subject routing** (machine-scoped):
- Filter: `machine.all.tool.*.update`
- Deliver inbox: `machine.<id>.tool.update.inbox`
- Durable name: `machine_<id>_tool_update_consumer`

## Usage Example

```rust
let listener = ToolAgentUpdateListener::new(
    nats_connection_manager,
    tool_agent_update_service,
    config_service,
    tool_run_manager,
);

// Spawns a self-healing background task; hold the handle to track completion
let handle = listener.start().await?;
handle.await?;
```

## Retry Behaviour

Consumer creation uses a two-level retry strategy controlled by constants in `update_config`:

```text
Cycle N:
  attempt 1..CONSUMER_RETRY_ATTEMPTS_PER_CYCLE
    → exponential backoff: INITIAL_RETRY_DELAY_MS × 2^n  (capped at MAX_RETRY_DELAY_MS)
  all attempts exhausted → sleep CONSUMER_CYCLE_PAUSE_MS → Cycle N+1

Stream error / normal exit → sleep RECONNECTION_DELAY_MS → restart listen()
```
