A gate function that either dispatches a NATS JetStream message immediately or parks it during a pending client update, keeping the message alive via periodic `Progress` acks until the update completes.

## Key Components

### `park_or_dispatch`

The sole export — an async function that accepts:

| Parameter | Description |
|---|---|
| `manager` | `ToolRunManager` used to poll `is_client_update_pending()` |
| `message` | The NATS JetStream `Message` to dispatch or park |
| `label` | Human-readable string for log context |
| `dispatch` | A one-shot async closure executed when the message is finally handled |

**Behaviour:**

- If no client update is pending, `dispatch(message)` is called inline and returns immediately.
- If an update **is** pending, a background `tokio::spawn` task loops, sending `AckKind::Progress` to the NATS server every `PROGRESS_ACK_INTERVAL_SECS` seconds, preventing the message from timing out and being redelivered.
- Once `is_client_update_pending()` returns `false`, the spawned task calls `dispatch(message)` and exits.
- If a `Progress` ack fails, the task abandons the park and logs a warning, allowing NATS natural redelivery to take over.

## Usage Example

```rust
park_or_dispatch(
    manager.clone(),
    nats_message,
    "RunToolRequest".to_string(),
    |msg| async move {
        handle_run_tool_request(msg).await;
    },
)
.await;
```

## Notes

- `PROGRESS_ACK_INTERVAL_SECS` is sourced from [`update_config`](https://github.com/flamingo-stack/openframe-oss-tenant/blob/main/src/config/update_config.rs) and must be shorter than the NATS server's `ack_wait` to avoid premature redelivery.
- The parking loop runs in a detached `tokio::spawn`, so `park_or_dispatch` returns immediately when parking is required — the caller is not blocked.
