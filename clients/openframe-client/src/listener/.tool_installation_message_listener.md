Listens for tool installation messages from a NATS JetStream subject and delegates installation to `ToolInstallationService`, with automatic reconnection and retry logic.

## Key Components

**`ToolInstallationMessageListener`** — Core struct holding:
- `nats_connection_manager` — Manages the NATS client connection
- `tool_installation_service` — Handles the actual tool installation logic
- `config_service` — Retrieves the machine ID used to scope NATS subjects

**Key Methods:**

| Method | Description |
|--------|-------------|
| `start()` | Spawns a background `tokio` task that runs `listen()` in an infinite loop with auto-reconnect on failure |
| `listen()` | Establishes the JetStream consumer and drives the message stream loop |
| `handle_message()` | Deserializes payload into `ToolInstallationMessage`, calls `install()`, and ACKs on success; leaves unACKed on failure for redelivery |
| `create_consumer()` | Creates or retrieves a durable push consumer with exponential backoff retry across cycles |
| `build_consumer_configuration()` | Builds the `push::Config` with machine-scoped filter/deliver subjects and durable name |

**NATS Subject Pattern:**
```text
Filter:  machine.{machine_id}.tool-installation
Deliver: machine.{machine_id}.tool-installation.inbox
Durable: machine_{machine_id}_tool-installation_consumer
```

## Usage Example

```rust
let listener = ToolInstallationMessageListener::new(
    nats_connection_manager,
    tool_installation_service,
    config_service,
);

// Spawns a self-healing background task
let handle = listener.start().await?;
handle.await?;
```

> Malformed messages are immediately ACKed to prevent infinite redelivery loops. Failed installations are intentionally left unACKed, allowing JetStream to redeliver up to `CONSUMER_MAX_DELIVER` times.
