NATS JetStream push consumer that listens for tool installation messages scoped to a specific machine, handling deserialization, dispatch, and resilient consumer lifecycle management.

## Key Components

- **`ToolInstallationMessageListener`** — Main struct holding references to the NATS connection manager, installation service, agent configuration, and tool run manager.
- **`start()`** — Spawns a background `tokio` task with an infinite reconnect loop, restarting `listen()` after a configurable delay on failure.
- **`listen()`** — Inner loop that acquires a NATS client, creates or recovers a durable push consumer, and dispatches incoming messages. Handles NATS reconnection signals via `subscribe_reconnect()`.
- **`handle_message()`** — Deserializes the raw NATS payload into a `ToolInstallationMessage`. ACKs malformed messages immediately to prevent infinite redelivery, then calls `park_or_dispatch` for valid ones.
- **`dispatch()`** — Delegates to `ToolInstallationService::install()`. ACKs on success; leaves unacked for JetStream redelivery on failure.
- **`create_consumer()`** — Resilient consumer provisioning with exponential backoff retry cycles. Recovers existing consumers when a name-collision error (`10013`) is detected.
- **Subject helpers** — `build_filter_subject`, `build_deliver_subject`, and `build_durable_name` scope all subjects to the machine ID (e.g., `machine.<id>.tool-installation`).

## Usage Example

```rust
let listener = ToolInstallationMessageListener::new(
    nats_connection_manager,
    tool_installation_service,
    config_service,
    tool_run_manager,
);

// Spawns a self-healing background task
let _handle = listener.start().await?;
```

The listener subscribes to `machine.<machine_id>.tool-installation` and routes messages through `park_or_dispatch`, ensuring ordered per-tool processing without blocking the consumer loop.
