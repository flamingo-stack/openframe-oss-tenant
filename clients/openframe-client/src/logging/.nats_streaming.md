Manages NATS JetStream log streaming for the OpenFrame agent, handling connection lifecycle, log source discovery, and batched log publishing to a remote NATS server over WebSocket.

## Key Components

### `NatsLogConnection`
Wraps an `async_nats` JetStream context. Handles WebSocket connection with tenant authentication headers (`x-tenant-domain`, `x-initial-key`, `x-machine-id`), automatic reconnect callbacks, and publishing serialized `LogBatchMessage` batches to the `agents.logs` subject with acknowledgment confirmation.

### `LogStreamingRunManager`
Orchestrates the full streaming lifecycle. Resolves server host, tenant domain, hostname, and file paths on construction, then spawns a background Tokio task on `start()` that:
1. Polls for a valid initial key before connecting
2. Establishes the NATS connection with retry loop
3. Builds the initial `LogSourceRegistry` (OpenFrame log file)
4. Spawns source discovery for dynamically installed tools (e.g., MeshCentral)
5. Runs the main `log_streaming_loop`

### `log_streaming_loop`
Ticks every 60 seconds, reads up to 50 log entries from all registered sources, and publishes a `LogBatchMessage`. On publish failure, rolls back source offsets for retry. On success, commits offsets and persists file position.

### `spawn_source_discovery` / `create_meshcentral_source`
Background task that polls every 30 seconds for MeshCentral installation. Once detected, registers a `FileLogSource` for its log file and exits.

## Usage Example

```rust
let manager = LogStreamingRunManager::new(
    &initial_config_service,
    &agent_config_service,
    &installed_tools_service,
    &directory_manager,
)?;

manager.start().await?;
```

## Constants

| Constant | Value | Purpose |
|----------|-------|---------|
| `BATCH_INTERVAL_SECS` | 60s | Log publish cadence |
| `MAX_LOGS_PER_BATCH` | 50 | Max entries per publish |
| `RECONNECT_DELAY_SECS` | 5s | NATS reconnect backoff |
| `SOURCE_DISCOVERY_INTERVAL_SECS` | 30s | Tool discovery poll rate |
