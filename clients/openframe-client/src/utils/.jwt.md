Lightweight JWT utility for extracting the `exp` (expiration) claim from a token's payload without performing signature verification.

## Key Components

| Item | Description |
|------|-------------|
| `token_exp_unix(token: &str) -> Option<i64>` | Public function that decodes the JWT payload and returns the `exp` claim as Unix epoch seconds, or `None` if the token is malformed or missing the claim |
| `ExpClaim` | Private deserialization struct targeting only the `exp` field from the JWT payload JSON |

## Behavior & Validation

The function enforces strict structural correctness before decoding:

- **Requires exactly three segments** (`header.payload.signature`) — tokens with fewer or more parts return `None`
- **Base64url-decodes** the payload using `URL_SAFE_NO_PAD`, tolerating trailing `=` padding
- **Deserializes only `exp`** via `serde_json` — extra claims are ignored, missing `exp` returns `None`
- Signature is **never verified** — suitable only for non-security-critical use cases such as proactive token refresh checks

## Usage Example

```rust
use crate::jwt::token_exp_unix;

fn is_token_expired(token: &str) -> bool {
    let now = std::time::SystemTime::now()
        .duration_since(std::time::UNIX_EPOCH)
        .unwrap()
        .as_secs() as i64;

    match token_exp_unix(token) {
        Some(exp) => exp < now,
        None => true, // treat malformed tokens as expired
    }
}
```

> **Security note:** This function skips signature verification entirely. Never use it to authenticate or authorize — use it only for expiry pre-checks (e.g., deciding when to refresh a token before making an outbound request).
