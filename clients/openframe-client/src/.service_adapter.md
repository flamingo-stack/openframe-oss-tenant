Cross-platform service installation and lifecycle management adapter that wraps the `service_manager` crate to provide a unified API for installing, uninstalling, starting, and stopping system services across macOS (launchd), Windows (SCM), and Linux (systemd).

## Key Components

- **`RecoveryConfig`** — Windows SCM failure-action settings (restart delays, reset period, non-crash failure handling)
- **`ServiceConfig`** — Unified service descriptor covering identity, process control, environment, logging, resource limits, and platform-specific options
- **`CrossPlatformServiceManager`** — Main struct wrapping a `ServiceConfig`; exposes builder-style setters and the core lifecycle methods

### Main Methods

| Method | Description |
|--------|-------------|
| `new()` / `with_config()` | Construct a manager from parameters or a full `ServiceConfig` |
| `install()` | Register the service with the native daemon manager and start it |
| `uninstall()` | Stop, wait for termination, clean up files, then deregister |
| `start()` / `stop()` | Send start/stop commands via the native service manager |

## Usage Example

```rust
use std::path::PathBuf;

let mut manager = CrossPlatformServiceManager::new(
    "agent",
    "OpenFrame Agent",
    "OpenFrame background agent service",
    PathBuf::from("/usr/local/bin/openframe-agent"),
);

manager
    .set_stdout_path(PathBuf::from("/var/log/openframe/agent.log"))
    .set_stderr_path(PathBuf::from("/var/log/openframe/agent.err"))
    .set_working_directory(PathBuf::from("/var/lib/openframe"))
    .set_restart_throttle(30)
    .set_file_limit(1024);

manager.install()?;
// Service is now registered as com.openframe.agent and running

manager.stop()?;
manager.uninstall()?;
```

> **Platform notes:** On macOS a full launchd plist is generated via the `plist` crate. On Windows, SCM recovery actions are applied post-install when a `RecoveryConfig` is provided. Uninstall gracefully ignores SCM error codes `1060` (not found) and `1072` (marked for deletion).
