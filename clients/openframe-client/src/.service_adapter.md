Cross-platform service installation and lifecycle management adapter that wraps the `service_manager` crate to provide a unified API for installing, starting, stopping, and uninstalling system services on macOS (launchd), Windows (SCM), and Linux (systemd).

## Key Components

### Structs

- **`RecoveryConfig`** — Windows SCM failure/recovery action settings (restart delays, reset period, non-crash failure handling)
- **`ServiceConfig`** — Full service configuration including binary path, environment variables, logging paths, identity (user/group), resource limits, and platform-specific options
- **`CrossPlatformServiceManager`** — Primary manager struct; wraps `ServiceConfig` and drives all lifecycle operations

### Methods on `CrossPlatformServiceManager`

| Method | Description |
|---|---|
| `new(...)` | Construct with minimal required fields |
| `with_config(config)` | Construct from a full `ServiceConfig` |
| `set_stdout_path` / `set_stderr_path` | Configure log file paths |
| `set_working_directory` | Override the service working directory |
| `set_user` / `set_group` | Set service identity |
| `set_restart_throttle` | Seconds between restart attempts |
| `set_file_limit` / `set_exit_timeout` | Resource limits |
| `install()` | Install + start the service; applies platform-specific plist/SCM config |
| `uninstall()` | Stop then remove the service; tolerates already-deleted state on Windows |
| `start()` / `stop()` | Service lifecycle control |

## Usage Example

```rust
use std::path::PathBuf;

let mut mgr = CrossPlatformServiceManager::new(
    "agent",
    "OpenFrame Agent",
    "OpenFrame background agent service",
    PathBuf::from("/usr/local/bin/openframe-agent"),
);

mgr.set_stdout_path(PathBuf::from("/var/log/openframe/agent.log"))
   .set_stderr_path(PathBuf::from("/var/log/openframe/agent.err"))
   .set_working_directory(PathBuf::from("/var/lib/openframe"))
   .set_user("openframe")
   .set_restart_throttle(15);

// Install and auto-start the service
mgr.install()?;

// Later, clean removal
mgr.uninstall()?;
```

Services are registered under the `com.openframe.<name>` label on all platforms. On Windows, optional `RecoveryConfig` is applied via SCM failure actions after installation.
