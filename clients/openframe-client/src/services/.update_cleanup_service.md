Handles post-update filesystem cleanup by removing stale executable backups and temporary update artifacts left behind by the OpenFrame auto-updater.

## Key Components

### `UpdateCleanupService`
A cloneable service struct holding the current executable's path, used as a reference point for locating cleanup targets.

| Method | Description |
|---|---|
| `new() -> Result<Self>` | Constructs the service by resolving the current executable path |
| `cleanup_all()` | Public entry point; runs both cleanup routines and logs total files removed |
| `cleanup_all_old_backups()` | Scans the executable's directory for `.backup.`-suffixed copies and removes them |
| `cleanup_temp_update_leftovers()` | Scans the OS temp directory for `openframe-update-*` directories and `openframe-updater-*.ps1/.sh` scripts older than `TEMP_LEFTOVER_MIN_AGE_SECS` |

## Usage Example

```rust
use update_cleanup_service::UpdateCleanupService;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let cleanup = UpdateCleanupService::new()?;
    // Runs silently if nothing to clean; logs removed file count otherwise
    cleanup.cleanup_all().await;
    Ok(())
}
```

## Notes

- **Age guard:** Temp leftovers younger than `TEMP_LEFTOVER_MIN_AGE_SECS` (defined in `crate::config::update_config`) are intentionally skipped to avoid removing in-progress update files.
- **Non-fatal:** Individual removal failures emit `warn!` logs but never propagate errors, keeping startup paths clean.
- Both cleanup routines are `async` for consistency with the broader async runtime but perform synchronous `std::fs` I/O internally.
