Manages the lifecycle of tool connection processing for installed MSP tools, orchestrating agent ID resolution, deduplication of concurrent runs, and reliable message publishing with retry logic.

## Key Components

### `ToolConnectionProcessingManager`

The central struct managing tool connection workflows. Holds shared state via `Arc<RwLock<HashSet<String>>>` to track in-flight tool processing and prevent duplicate concurrent runs.

| Field | Description |
|---|---|
| `installed_tools_service` | Retrieves the list of installed tools |
| `params_processor` | Resolves command argument placeholders |
| `tool_connection_publisher` | Publishes connection messages to the broker |
| `config_service` | Provides machine identity (`machine_id`) |
| `tool_connection_service` | Persists tool connection records |
| `running_tools` | Concurrent-safe set of in-progress tool IDs |

### Key Methods

- **`run()`** — Iterates all installed tools and initiates connection processing for any without an existing connection record.
- **`run_new_tool(installed_tool)`** — Entry point for a freshly installed tool; guards against duplicate processing.
- **`process_tool(tool)`** — Spawns a background `tokio` task with a retry loop that resolves the agent tool ID via subprocess, then publishes and persists the connection.
- **`try_mark_running(tool_id)`** — Atomic check-and-insert to prevent duplicate processing.
- **`clear_running_tool(tool_id)`** — Removes a tool from the in-flight set after completion or external cancellation.

## Usage Example

```rust
let manager = ToolConnectionProcessingManager::new(
    installed_tools_service,
    params_processor,
    tool_connection_publisher,
    config_service,
    tool_connection_service,
);

// Process all installed tools on startup
manager.run().await?;

// Process a single newly installed tool
manager.run_new_tool(installed_tool).await?;

// Release a tool from the running set after external handling
manager.clear_running_tool("tool-abc-123").await;
```

> **Note:** `process_tool` spawns a detached `tokio::spawn` loop with a 15-second retry delay (`RETRY_DELAY_SECONDS`) on any failure — subprocess timeout, empty output, publish failure, or persistence error. The loop exits only on a fully successful publish + save.
