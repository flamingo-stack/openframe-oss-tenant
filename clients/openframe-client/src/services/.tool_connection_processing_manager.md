Manages the lifecycle of tool connection processing, orchestrating agent ID resolution, command execution, and connection publishing for installed MSP tools.

## Key Components

### `ToolConnectionProcessingManager`

Main struct coordinating tool connection workflows with the following dependencies:

- `InstalledToolsService` – retrieves installed tools
- `ToolCommandParamsResolver` – resolves command argument placeholders
- `ToolConnectionMessagePublisher` – publishes connection events
- `AgentConfigurationService` – provides machine identity
- `ToolConnectionService` – persists connection records
- `ToolRunManager` – detects in-progress tool updates
- `running_tools: Arc<RwLock<HashSet<String>>>` – deduplicates concurrent processing
- `wake_signals: Arc<RwLock<HashMap<String, Arc<Notify>>>>` – lets `run_new_tool` nudge a live loop into an immediate re-publish

### Key Constants

| Constant | Value | Purpose |
|---|---|---|
| `RETRY_DELAY_SECONDS` | `15` | Standard retry interval |
| `AGENT_ID_MAX_FAST_RETRIES` | `5` | Failures before degraded backoff |
| `AGENT_ID_DEGRADED_BACKOFF_SECONDS` | `300` | Backoff delay after repeated failures |
| `REPUBLISH_INTERVAL_SECONDS` | `3600` | Cadence of the periodic re-resolve + re-publish |

### Public Methods

- **`run()`** – Spawns a resolve/publish loop for every installed tool on startup, skipping in-flight tools
- **`run_new_tool(installed_tool)`** – Processes a single newly installed tool; if its loop is already alive (reinstall), wakes it for an immediate re-publish instead

### Private Methods

- **`try_mark_running(tool_id)`** – Atomically marks a tool as running and registers its wake handle, returning it (or `None` if already in flight)
- **`process_tool(tool)`** – Spawns a loop that resolves the agent ID via command execution (with 15s timeout), publishes and persists the `ToolConnection`, then repeats hourly (or when woken) so a re-keyed agent heals without a restart; exits when the tool is uninstalled

## Usage Example

```rust
let manager = ToolConnectionProcessingManager::new(
    installed_tools_service,
    params_resolver,
    connection_publisher,
    config_service,
    connection_service,
    run_manager,
);

// On agent startup – process all installed tools
manager.run().await?;

// On new tool installation event
manager.run_new_tool(newly_installed_tool).await?;
```

The agent ID resolution loop defers processing while a tool update is in progress, backs off exponentially after `AGENT_ID_MAX_FAST_RETRIES` consecutive failures, and transitions to a 5-minute degraded interval to avoid tight spinning on persistently unhealthy agents.
