Manages the lifecycle of tool connection processing for installed MSP tools, orchestrating command execution, agent ID resolution, and connection message publishing with retry logic.

## Key Components

**`ToolConnectionProcessingManager`** — Core struct managing concurrent tool connection workflows via a shared `running_tools` set (Arc<RwLock<HashSet>>).

**Key methods:**

| Method | Description |
|--------|-------------|
| `new(...)` | Constructs manager with injected services |
| `run()` | Iterates all installed tools and initiates connection processing for unregistered ones |
| `run_new_tool(tool)` | Initiates connection processing for a single newly installed tool |
| `process_tool(tool)` | Spawns an async retry loop that resolves `agent_tool_id`, publishes the connection message, and persists the record |
| `try_mark_running(tool_id)` | Atomically marks a tool as in-progress; returns `false` if already running |
| `clear_running_tool(tool_id)` | Removes a tool from the in-progress set |

**Constants:**
- `RETRY_DELAY_SECONDS = 15` — Backoff interval for all retry paths

## Usage Example

```rust
let manager = ToolConnectionProcessingManager::new(
    installed_tools_service,
    params_resolver,
    connection_publisher,
    config_service,
    tool_connection_service,
);

// Process all installed tools on startup
manager.run().await?;

// Process a single newly installed tool
manager.run_new_tool(installed_tool).await?;

// Release a tool slot after external completion
manager.clear_running_tool("tool-id-123").await;
```

## Behavior Notes

- Skips tools where a connection record already exists in `ToolConnectionService`
- If `tool_agent_id_command_args` is empty, uses an empty string as `agent_tool_id`
- Command execution is bounded by a **15-second timeout**; failures, timeouts, and empty output all trigger a retry loop
- Connection is persisted via `ToolConnectionService::save` only after a successful publish
