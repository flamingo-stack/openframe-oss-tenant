Orchestrates the update lifecycle for tool agents, handling version checks, binary downloads, installation type migrations, asset updates, and state persistence across Standard and legacy (Artifactory) installation paths.

## Key Components

### `ToolAgentUpdateService` (struct)
The primary service struct, holding injected dependencies for downloading, filesystem management, process control, and state publishing.

**Dependencies injected via `new()`:**
- `GithubDownloadService` — fetches binaries from GitHub releases
- `ToolAgentFileClient` — legacy Artifactory download client
- `InstalledToolsService` — persists/retrieves tool installation records
- `ToolKillService` — stops running tool processes before updates
- `ToolRunManager` — manages update state flags and restarts
- `DirectoryManager` — resolves agent binary paths
- `AgentConfigurationService` — agent configuration access
- `InstalledAgentMessagePublisher` — publishes post-update status events
- `ToolCommandParamsResolver` — resolves runtime command parameters

### Key Methods

| Method | Description |
|--------|-------------|
| `process_update` | Entry point; checks versions, sets updating flag, delegates to `do_updates` |
| `do_updates` | Coordinates tool and asset update ordering; stops tool once before asset-only updates |
| `do_tool_update` | Handles GitHub-based updates including installation-type migration detection |
| `do_legacy_update` | Artifactory fallback path for `Standard` installs without download configs |
| `do_asset_update` | Updates individual assets, reusing executable flags from existing install records |

## Usage Example

```rust
let svc = ToolAgentUpdateService::new(
    github_download_service,
    tool_agent_file_client,
    installed_tools_service,
    tool_kill_service,
    tool_run_manager,
    directory_manager,
    config_service,
    installed_agent_publisher,
    command_params_resolver,
);

// Triggered by an inbound update message (e.g. from MQTT/queue)
svc.process_update(update_message).await?;
```

> **Note:** `process_update` is idempotent — if the tool and all assets are already at the target versions, it returns early without stopping or restarting any processes.
