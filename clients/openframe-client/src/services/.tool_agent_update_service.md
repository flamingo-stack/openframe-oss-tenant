Service responsible for orchestrating tool agent updates, including downloading new binaries, managing process lifecycle, and maintaining installation state.

## Key Components

- **`ToolAgentUpdateService`** - Main service struct that coordinates the update process using multiple specialized services
- **`process_update()`** - Public method that processes update messages and determines if an update is needed
- **`do_update()`** - Private method that performs the actual update workflow including backup, download, and file operations
- **Dependencies** - Integrates with GitHub download service, file client, installation tracking, process management, and messaging services

## Usage Example

```rust
use crate::services::tool_agent_update_service::ToolAgentUpdateService;
use crate::models::tool_agent_update_message::ToolAgentUpdateMessage;

// Initialize the service with all required dependencies
let update_service = ToolAgentUpdateService::new(
    github_download_service,
    tool_agent_file_client,
    installed_tools_service,
    tool_kill_service,
    tool_run_manager,
    directory_manager,
    config_service,
    installed_agent_publisher,
);

// Process an update message
let update_message = ToolAgentUpdateMessage {
    tool_agent_id: "my-tool".to_string(),
    version: "1.2.3".to_string(),
    download_configurations: vec![],
};

update_service.process_update(update_message).await?;
```

The service handles the complete update lifecycle: version checking, process stopping, binary backup, downloading new versions (via GitHub or legacy Artifactory), file permissions, and state persistence. It supports both modern GitHub-based downloads with OS-specific configurations and legacy Artifactory downloads as fallback.
