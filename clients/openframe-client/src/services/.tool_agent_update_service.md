Handles automated tool agent updates with safe binary replacement and rollback capabilities. This service coordinates the complete update lifecycle including stopping running processes, downloading new binaries, and maintaining system consistency.

## Key Components

- **`ToolAgentUpdateService`** - Main service orchestrating tool agent updates
- **`process_update()`** - Entry point for processing update messages with version validation
- **`do_update()`** - Internal method handling the complete update workflow
- **Dependency injection** - Uses multiple services for GitHub downloads, file operations, process management, and messaging

## Usage Example

```rust
use tool_agent_update_service::ToolAgentUpdateService;
use crate::models::tool_agent_update_message::ToolAgentUpdateMessage;

// Initialize the service with all required dependencies
let update_service = ToolAgentUpdateService::new(
    github_download_service,
    tool_agent_file_client,
    installed_tools_service,
    tool_kill_service,
    tool_run_manager,
    directory_manager,
    config_service,
    installed_agent_publisher,
);

// Process an update message
let update_message = ToolAgentUpdateMessage {
    tool_agent_id: "my-tool".to_string(),
    version: "v2.0.0".to_string(),
    download_configurations: vec![],
};

match update_service.process_update(update_message).await {
    Ok(()) => println!("Update completed successfully"),
    Err(e) => eprintln!("Update failed: {:#}", e),
}
```

The service provides robust error handling with automatic backup creation and cleanup, supports both modern GitHub releases and legacy Artifactory downloads, and ensures proper file permissions on Unix systems. Updates are coordinated through the `ToolRunManager` to prevent conflicts with running processes.
