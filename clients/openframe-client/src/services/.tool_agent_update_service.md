Service responsible for updating tool agents to new versions by downloading, backing up current versions, and replacing binaries while ensuring proper permissions and state management.

## Key Components

**ToolAgentUpdateService** - Main service struct that orchestrates tool agent updates
- `process_update()` - Processes update messages and validates update requirements
- `do_update()` - Performs the actual update process including download, backup, and replacement
- `new()` - Constructor that initializes all dependencies and ensures directory structure

**Dependencies:**
- `GithubDownloadService` - Downloads new agent binaries from GitHub releases
- `ToolAgentFileClient` - Legacy fallback for downloading from Artifactory
- `InstalledToolsService` - Manages installed tool records
- `ToolKillService` - Stops running tool processes during updates
- `ToolRunManager` - Tracks update status to prevent concurrent operations
- `DirectoryManager` - Manages file paths and directory structure

## Usage Example

```rust
use crate::services::ToolAgentUpdateService;
use crate::models::tool_agent_update_message::ToolAgentUpdateMessage;

// Initialize the service with all dependencies
let update_service = ToolAgentUpdateService::new(
    github_download_service,
    tool_agent_file_client,
    installed_tools_service,
    tool_kill_service,
    tool_run_manager,
    directory_manager,
    config_service,
    installed_agent_publisher,
);

// Process an update message
let update_message = ToolAgentUpdateMessage {
    tool_agent_id: "my-tool".to_string(),
    version: "1.2.0".to_string(),
    download_configurations: vec![/* config */],
};

update_service.process_update(update_message).await?;
```

The service handles the complete update lifecycle: validation, process termination, binary backup, new version download, file replacement with proper Unix permissions, database updates, and status publishing.
