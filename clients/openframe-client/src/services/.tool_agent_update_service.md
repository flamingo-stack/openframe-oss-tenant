Orchestrates the update process for tool agents, managing version checks, binary downloads, and safe rollback mechanisms. Handles both GitHub-based downloads and legacy Artifactory methods while ensuring proper file permissions and process management.

## Key Components

- `ToolAgentUpdateService` - Main service coordinating tool agent updates
- `process_update()` - Validates update requirements and initiates update process
- `do_update()` - Executes the complete update workflow with backup and rollback support

## Dependencies

The service integrates with multiple components:
- `GithubDownloadService` - Downloads binaries from GitHub releases
- `ToolAgentFileClient` - Legacy Artifactory-based downloads
- `InstalledToolsService` - Manages tool installation records
- `ToolKillService` - Safely stops running tool processes
- `ToolRunManager` - Tracks tool update states
- `DirectoryManager` - Handles file system operations

## Usage Example

```rust
use crate::services::ToolAgentUpdateService;
use crate::models::tool_agent_update_message::ToolAgentUpdateMessage;

// Initialize service with required dependencies
let update_service = ToolAgentUpdateService::new(
    github_service,
    file_client,
    installed_tools_service,
    kill_service,
    run_manager,
    directory_manager,
    config_service,
    publisher,
);

// Process an update message
let update_message = ToolAgentUpdateMessage {
    tool_agent_id: "my-tool".to_string(),
    version: "2.0.0".to_string(),
    download_configurations: vec![/* configs */],
};

update_service.process_update(update_message).await?;
```

The service implements a robust update workflow: version validation → process stopping → binary backup → download → file replacement → permission setting → database update → cleanup → notification publishing.
