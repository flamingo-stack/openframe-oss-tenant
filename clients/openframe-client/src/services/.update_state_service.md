Manages persistence of update state to disk, providing atomic read/write/clear operations for tracking in-progress software updates across restarts.

## Key Components

### `UpdateStateService`

A cloneable service struct that handles serialization and file I/O for `UpdateState` data, stored as JSON in the secured directory.

| Method | Description |
|---|---|
| `new(directory_manager)` | Constructs the service, resolving the state file path and ensuring the secured directory exists |
| `load()` | Reads and deserializes the state file; returns `None` if no file is present |
| `save(state)` | Atomically writes state via a `.json.tmp` temp file before renaming into place |
| `clear()` | Removes the state file if it exists |
| `has_incomplete_update()` | Returns `true` if a state file exists, indicating a pending recovery |
| `get_state_file_path()` | Returns the resolved state file path as a `String` |

## Usage Example

```rust
use crate::services::update_state_service::UpdateStateService;
use crate::platform::directories::DirectoryManager;
use crate::models::update_state::UpdateState;

let dir_manager = DirectoryManager::new()?;
let service = UpdateStateService::new(dir_manager)?;

// Persist update state before rebooting
let state = UpdateState {
    target_version: "1.2.3".to_string(),
    phase: UpdatePhase::Downloading,
    // ...
};
service.save(&state).await?;

// On next startup, check for incomplete updates
if service.has_incomplete_update().await? {
    let state = service.load().await?.unwrap();
    // resume recovery...
}

// Clear after successful completion
service.clear().await?;
```

> **Atomic writes:** `save()` writes to a `.json.tmp` sibling file first, then renames it, preventing partial/corrupt state files on crash or power loss.
