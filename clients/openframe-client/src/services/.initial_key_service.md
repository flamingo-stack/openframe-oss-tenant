Handles background fetching and persistence of a missing initial registration key, designed as a legacy upgrade path for agents that lack an initial key in their local configuration.

## Key Components

- **`InitialKeyService`** — Main service struct holding an HTTP client, base URL, and references to `InitialConfigurationService` and `AgentConfigurationService`
- **`ensure_initial_key()`** — Entry point that checks if the key is missing; if so, spawns a background task that retries indefinitely until the key is fetched and saved
- **`fetch_registration_secret()`** — Authenticated GET request to `/clients/agent/registration-secret/active`, returning the active registration key as a `String`
- **`is_key_missing()`** — Thin wrapper around `InitialConfigurationService::is_initial_key_missing()`, defaulting to `false` on error
- **`RegistrationSecretResponse`** — Private deserialization struct for the API response payload
- **`RETRY_INTERVAL_SECS`** — Constant (60s) controlling the backoff delay between failed fetch attempts

## Usage Example

```rust
use std::sync::Arc;
use reqwest::Client;

let service = Arc::new(InitialKeyService::new(
    Client::new(),
    "https://api.example.com".to_string(),
    initial_config_service,
    agent_config_service,
));

// Call at startup; no-op if key already present,
// otherwise spawns a background retry loop
service.ensure_initial_key().await;
```

## Notes

- `ensure_initial_key` takes `Arc<Self>` to allow the spawned `tokio` task to hold a shared reference across the async boundary
- Failures log via `tracing::error` and retry every 60 seconds without blocking the caller
- The service exits the retry loop immediately after a successful save, keeping resource usage minimal
