Handles tenant deactivation lifecycle for the OpenFrame client agent: detects gateway `410 Gone` responses, backs off, stops managed tools, and triggers a detached self-uninstall after the tenant has remained gone for a configurable wall-clock window.

## Key Components

| Item | Description |
|------|-------------|
| `DeactivationService` | Primary struct managing detection state, suspension flag, and command dispatch |
| `Phase` | Internal FSM states: `Healthy` → `Suspended` |
| `DeactivationCommand` | Channel messages: `StopTools`, `RestartTools`, `Uninstall` |
| `State` | Mutable inner state: consecutive 410 count, `gone_since` timestamp, backoff, uninstall flag |
| `GONE_MARKER_FILE` | Persisted RFC-3339 timestamp in the secured directory, survives restarts |

**Key thresholds:**

| Constant | Value | Purpose |
|----------|-------|---------|
| `STOP_TOOLS_AFTER_CONSECUTIVE_GONE` | 5 | 410s before suspension |
| `UNINSTALL_AFTER` | 2 hours | Wall-clock gone duration before self-uninstall |
| `POST_RESTART_GRACE` | 1 hour | Minimum uptime before honoring deadline |
| `PROBE_BACKOFF_MAX` | 30 minutes | Exponential backoff ceiling |

## Usage Example

```rust
// Construct once, share via Arc
let svc = DeactivationService::new(&directory_manager);

// Start the supervisor after the tool manager is available
svc.clone().start(tool_run_manager);

// Feed every gateway response status
svc.on_gateway_status(StatusCode::GONE).await;      // records 410
svc.on_gateway_status(StatusCode::OK).await;        // clears state

// Gate outbound calls while suspended
if !svc.is_suspended() {
    make_outbound_call().await;
}

// Exponential delay between suspension probes
let delay = svc.next_probe_delay().await;
tokio::time::sleep(delay).await;

// Manually trigger uninstall (e.g. from a backend decommission message)
svc.request_uninstall().await;
```

## Notes

- **Platform:** Active only on macOS and Windows (`ENABLED` compile-time flag); Linux self-uninstall is unsupported.
- **Persistence:** The `tenant_gone_since` marker file survives reboots but requires a fresh live 410 to advance toward uninstall — a stale marker alone cannot trigger removal.
- **Clock safety:** `POST_RESTART_GRACE` uses `Instant` (monotonic) to prevent a forwarded system clock from shortcutting the deadline.
- **Idempotent uninstall:** `request_uninstall` sets a boolean flag before sending the command, making all callers safe to call concurrently.
