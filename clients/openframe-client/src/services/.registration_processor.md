Orchestrates the agent registration lifecycle by checking for an existing machine ID and retrying registration indefinitely until successful.

## Key Components

### `RegistrationProcessor` (struct)

A cloneable processor that coordinates between the registration and configuration services.

| Field | Type | Description |
|---|---|---|
| `registration_service` | `AgentRegistrationService` | Handles the actual registration API call |
| `config_service` | `AgentConfigurationService` | Reads/writes local agent configuration (e.g., machine ID) |

### Methods

- **`new(registration_service, config_service) -> Self`** — Constructs a new processor with the required service dependencies.
- **`process() -> Result<()>`** — Entry point. Skips registration if a `machine_id` already exists; otherwise enters a retry loop with 60-second backoff until registration succeeds.
- **`attempt_registration() -> Result<AgentRegistrationResponse>`** — Private helper that delegates a single registration attempt to `AgentRegistrationService`.

## Usage Example

```rust
let processor = RegistrationProcessor::new(
    registration_service,
    config_service,
);

// Blocks until registered or panics on unrecoverable error.
// Skips silently if already registered.
processor.process().await?;
```

## Behavior Notes

- **Idempotent**: If `config_service.get_machine_id()` returns a non-empty value, `process()` returns `Ok(())` immediately without making any network calls.
- **Retry loop**: On failure, logs the error and waits **60 seconds** before retrying — loops indefinitely until success.
- **No max retries**: Designed for resilient startup scenarios where the registration endpoint may be temporarily unavailable.
