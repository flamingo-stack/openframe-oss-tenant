Manages persistent agent configuration by reading and writing `AgentConfiguration` data to a secured JSON file on disk, with serialized write access to prevent concurrent update races.

## Key Components

| Item | Kind | Description |
|------|------|-------------|
| `AgentConfigurationService` | Struct | Core service holding the config file path and an async write lock |
| `new()` | Constructor | Initializes the service using a `DirectoryManager`, ensuring the secured directory exists |
| `save_registration_data()` | Async method | Persists `machine_id`, `client_id`, and `client_secret` atomically |
| `update_tokens()` | Async method | Persists `access_token` and `refresh_token` atomically |
| `get_machine_id()` | Sync method | Returns the stored machine ID |
| `get_client_credentials()` | Async method | Returns `(client_id, client_secret)` as a tuple |
| `get_access_token()` | Async method | Returns the current access token |
| `get_refresh_token()` | Async method | Returns the current refresh token |
| `get()` (private) | Sync method | Deserializes config from disk, returning `Default` if file absent |
| `save()` (private) | Async method | Serializes config to pretty JSON via atomic file write |

## Usage Example

```rust
use crate::platform::directories::DirectoryManager;
use crate::services::AgentConfigurationService;

let dir_manager = DirectoryManager::new()?;
let config_svc = AgentConfigurationService::new(dir_manager)?;

// Store registration credentials after initial enrollment
config_svc
    .save_registration_data(
        "machine-abc123".into(),
        "client-xyz".into(),
        "super-secret".into(),
    )
    .await?;

// Update tokens after an OAuth refresh
config_svc
    .update_tokens("new-access-token".into(), "new-refresh-token".into())
    .await?;

// Retrieve credentials for an outbound API call
let (client_id, client_secret) = config_svc.get_client_credentials().await?;
let access_token = config_svc.get_access_token().await?;
```

> **Concurrency note:** All mutating methods acquire `write_lock` before performing a read-modify-write cycle, preventing field-level data loss when multiple async tasks update configuration simultaneously. Writes use `atomic_write` to avoid partial file corruption.
