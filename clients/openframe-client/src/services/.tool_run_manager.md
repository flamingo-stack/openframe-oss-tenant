Manages the lifecycle of tool processes across Windows and Unix platforms, handling process launching, session detection, retry logic, and cross-session execution (including launching processes in active user sessions from a Windows service context).

## Key Components

- **`get_active_user_session()`** *(Windows only)* — Enumerates Windows Terminal Services sessions to find the best active user session (preferring RDP over Console), handling both interactive and service (`session 0`) contexts.
- **`launch_process_in_console_session()`** *(Windows only)* — Launches a process in the physical console session using `WTSQueryUserToken` + `CreateProcessAsUserW` with `DETACHED_PROCESS | CREATE_NO_WINDOW`.
- **`launch_process_in_user_session()`** *(Windows only)* — Public wrapper that resolves the active session via `get_active_user_session()` and delegates to `launch_process_in_target_session`.
- **`launch_process_in_target_session()`** *(Windows only)* — Core Windows session-launch logic: queries and duplicates a user token (`DuplicateTokenEx` → primary token), builds the command line, configures `STARTUPINFOW` with `winsta0\default` desktop, and calls `CreateProcessAsUserW`. Includes a fallback retry without desktop specification on failure.

**Supporting dependencies used:**
- `ToolCommandParamsResolver` — resolves runtime command parameters
- `ToolKillService` — terminates managed tool processes
- `InstalledToolsService` — queries installed tool records
- `system_service` — platform-level service utilities

## Usage Example

```rust
// Launch a tool in the active Windows user session from a service
#[cfg(windows)]
let (pid, handle) = launch_process_in_user_session(
    "C:\\Program Files\\MyTool\\tool.exe",
    &["--config".to_string(), "config.yaml".to_string()],
)?;
info!("Tool launched with PID: {}", pid);
```

## Notes

- Session 0 isolation (Windows Vista+) is handled by enumerating WTS sessions when the current process runs as a service.
- RDP sessions are prioritized over Console sessions when multiple active sessions exist.
- Uses `RETRY_DELAY_SECONDS = 5` for retry loops in the broader run manager logic.
