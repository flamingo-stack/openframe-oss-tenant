Manages the lifecycle of tool processes across platforms, handling launching, monitoring, and termination of installed MSP tools with Windows-specific support for session-aware process creation.

## Key Components

### Constants
- `RETRY_DELAY_SECONDS` — Delay between retry attempts when a tool process fails

### Windows-Only Helpers
- `to_wide(s: &str) -> Vec<u16>` — Converts a Rust string to a null-terminated UTF-16 wide string for Windows API calls
- `get_active_user_session() -> Option<u32>` — Enumerates WTS sessions to find the best active user session (prefers RDP over Console, skips session 0 / service sessions)
- `wcslen(ptr: *const u16) -> usize` — Unsafe helper to measure null-terminated wide string length
- `launch_process_in_console_session(command_path, args) -> Result<(u32, HANDLE)>` — Spawns a process in the physical console session via `WTSGetActiveConsoleSessionId` + `CreateProcessAsUserW`
- `launch_process_in_user_session(command_path, args) -> Result<(u32, HANDLE)>` — Full session-aware launcher: detects active user session → queries user token → duplicates to primary token → calls `CreateProcessAsUserW` with `winsta0\default` desktop context

### Dependencies (used by the manager)
- `InstalledToolsService` — Resolves and tracks installed tools
- `ToolCommandParamsResolver` — Builds resolved command arguments per tool
- `ToolKillService` — Handles graceful/forceful process termination

## Usage Example

```rust
// Windows: launch a tool in the active user's desktop session
#[cfg(windows)]
let (pid, handle) = launch_process_in_user_session(
    "C:\\Program Files\\MyTool\\mytool.exe",
    &["--config".to_string(), "C:\\config.toml".to_string()],
)?;
info!("Tool running as PID {} in user session", pid);
```

## Notes

- On Windows, session 0 isolation means services cannot launch GUI/interactive processes directly. This module handles token duplication and `CreateProcessAsUserW` to correctly place processes in an active user session.
- Uses `DETACHED_PROCESS | CREATE_NO_WINDOW` for background tools and `CREATE_NEW_PROCESS_GROUP` for interactive/GUI tools.
- Session selection prioritizes active RDP sessions over Console, then by highest session ID.
