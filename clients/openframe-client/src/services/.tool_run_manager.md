Manages the execution of tool processes across different platforms, with specialized Windows session handling for GUI applications launched from services.

## Key Components

- **`get_active_user_session()`** (Windows) - Detects active user sessions by enumerating Windows Terminal Services sessions
- **`launch_process_in_user_session()`** (Windows) - Launches processes in active user sessions using Windows API token duplication
- **`launch_process_in_console_session()`** (Windows) - Alternative launcher for console session processes
- **Session Detection Logic** - Prioritizes RDP sessions over console sessions and filters out service/listen sessions
- **Token Management** - Handles Windows security tokens for cross-session process creation

## Usage Example

```rust
use crate::tool_run_manager::*;

// Windows-specific: Launch a GUI tool in the active user session
#[cfg(windows)]
async fn launch_gui_tool() -> Result<()> {
    let command_path = "C:\\Program Files\\MyTool\\tool.exe";
    let args = vec![
        "--config".to_string(),
        "production.json".to_string()
    ];
    
    // Launch in user session (handles service-to-user context switching)
    let (pid, handle) = launch_process_in_user_session(command_path, &args)?;
    info!("Tool launched with PID: {}", pid);
    
    // Process handle can be used for monitoring/cleanup
    Ok(())
}

// Cross-platform: Basic process management
async fn run_tool_command() -> Result<()> {
    let mut cmd = Command::new("my-tool");
    cmd.args(&["--daemon", "--port", "8080"]);
    cmd.stdout(Stdio::piped());
    
    let child = cmd.spawn().context("Failed to spawn tool process")?;
    // Handle process lifecycle...
    Ok(())
}
```

This module is essential for OpenFrame's tool management system, ensuring GUI tools launched by Windows services appear correctly in the user's desktop session rather than running invisibly in the service context.
