This module manages the execution of tools in user sessions, handling cross-platform process launching with special Windows session management for GUI applications.

## Key Components

- **`get_active_user_session()`** - Windows-specific function to detect active user sessions, with support for both console and RDP sessions
- **`launch_process_in_console_session()`** - Launches processes in the physical console session on Windows
- **`launch_process_in_user_session()`** - Advanced Windows process launcher that creates processes in active user sessions with proper token handling
- **Session Management** - Comprehensive Windows Terminal Services integration for multi-user environments
- **Cross-platform Support** - Conditional compilation for Windows-specific functionality

## Usage Example

```rust
use crate::tool_run_manager::*;

#[cfg(windows)]
async fn launch_gui_tool() -> Result<()> {
    // Launch a tool in the active user session
    let (pid, handle) = launch_process_in_user_session(
        "C:\\Program Files\\MyTool\\tool.exe",
        &["--arg1".to_string(), "value1".to_string()]
    )?;
    
    info!("Tool launched with PID: {}", pid);
    Ok(())
}

#[cfg(windows)]
async fn get_current_session() -> Option<u32> {
    // Get the active user session ID
    get_active_user_session()
}
```

The module includes extensive Windows session enumeration, token duplication for proper security context, and handles both console and RDP sessions. It provides detailed logging for debugging session detection and process creation issues.
