Manages the execution of external tools on different platforms with special handling for Windows user session management and process launching.

## Key Components

- **get_active_user_session()** - Windows-specific function to detect and select the best active user session (prefers RDP over console sessions)
- **launch_process_in_console_session()** - Launches processes in the physical console session on Windows
- **launch_process_in_user_session()** - Launches processes in active user sessions with proper token handling and desktop assignment
- **RETRY_DELAY_SECONDS** - Constant defining retry delay for failed operations
- **Windows utility functions** - Helper functions for wide string conversion and string length calculation

## Usage Example

```rust
use crate::tool_run_manager::*;
use tokio::process::Command;

// Launch a tool in the active user session (Windows)
#[cfg(windows)]
async fn launch_calculator() -> Result<()> {
    let command_path = "C:\\Windows\\System32\\calc.exe";
    let args = vec![];
    
    match launch_process_in_user_session(command_path, &args) {
        Ok((pid, handle)) => {
            info!("Calculator launched with PID: {}", pid);
            Ok(())
        }
        Err(e) => {
            error!("Failed to launch calculator: {}", e);
            Err(e)
        }
    }
}

// Cross-platform tool execution with retry logic
async fn execute_tool_with_retry(tool: &InstalledTool) -> Result<()> {
    for attempt in 1..=3 {
        match try_execute_tool(tool).await {
            Ok(()) => return Ok(()),
            Err(e) => {
                warn!("Tool execution attempt {} failed: {}", attempt, e);
                if attempt < 3 {
                    sleep(Duration::from_secs(RETRY_DELAY_SECONDS)).await;
                }
            }
        }
    }
    Err(anyhow::anyhow!("Tool execution failed after 3 attempts"))
}
```

The module provides robust cross-platform tool execution with sophisticated Windows session management, including active session detection, user token handling, and proper process isolation for both console and GUI applications.
