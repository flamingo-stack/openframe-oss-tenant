Manages the execution and lifecycle of external tools within user sessions on Windows systems, providing secure process launching and monitoring capabilities.

## Key Components

- **Session Management**: `get_active_user_session()` - Detects and selects the best active Windows user session for process execution
- **Process Launching**: `launch_process_in_user_session()` and `launch_process_in_console_session()` - Create processes with proper user context and token impersonation
- **Security Handling**: Token duplication and user impersonation for secure cross-session process creation
- **Utility Functions**: `to_wide()` for Windows Unicode string conversion, `wcslen()` for wide string length calculation

## Usage Example

```rust
// Launch a tool in the active user session
let (pid, handle) = launch_process_in_user_session(
    "C:\\Program Files\\MyTool\\tool.exe",
    &["--arg1".to_string(), "--arg2".to_string()]
)?;

// Or launch in console session specifically
let (pid, handle) = launch_process_in_console_session(
    "notepad.exe", 
    &[]
)?;

// Detect active session for manual handling
if let Some(session_id) = get_active_user_session() {
    println!("Active session: {}", session_id);
}
```

The module handles Windows Terminal Services session enumeration, user token management, and secure process creation across different user contexts. It prioritizes RDP sessions over console sessions and includes comprehensive logging for debugging session detection and process launching issues.
