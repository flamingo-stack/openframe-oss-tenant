Manages the execution of tools in Windows user sessions, handling process creation, session detection, and user impersonation for running applications with proper desktop access.

## Key Components

- **`get_active_user_session()`** - Detects active user sessions using Windows Terminal Services API
- **`launch_process_in_user_session()`** - Creates processes in user sessions with proper token impersonation
- **`launch_process_in_console_session()`** - Launches processes in the physical console session
- **`to_wide()` / `wcslen()`** - Windows string conversion utilities for Unicode handling

## Usage Example

```rust
use crate::tool_run_manager::*;

// Get the active user session ID
if let Some(session_id) = get_active_user_session() {
    println!("Active session found: {}", session_id);
    
    // Launch a tool in the user session
    let command_path = r"C:\Program Files\MyTool\tool.exe";
    let args = vec!["--param".to_string(), "value".to_string()];
    
    match launch_process_in_user_session(command_path, &args) {
        Ok((pid, handle)) => {
            println!("Process launched with PID: {}", pid);
            // Process handle can be used for monitoring
        }
        Err(e) => {
            eprintln!("Failed to launch process: {}", e);
        }
    }
}

// Alternative: Launch in console session
let (pid, handle) = launch_process_in_console_session(
    r"C:\Windows\System32\notepad.exe",
    &["file.txt".to_string()]
)?;
```

This module is essential for MSP tools that need to run applications with full desktop access and proper user context, particularly important for GUI applications and tools that require interactive desktop features.
