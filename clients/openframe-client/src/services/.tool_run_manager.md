Manages the execution and lifecycle of tools in different Windows session contexts, providing functionality to launch processes as different users and handle session-aware tool execution.

## Key Components

- **`ToolRunManager`** - Main service for managing tool execution across Windows sessions
- **Session Management Functions** - Windows-specific functions for detecting active user sessions and launching processes in user contexts
- **Process Launching** - Methods for launching tools in console sessions and user sessions with proper token handling
- **Tool Lifecycle** - Integration with installed tools service, command parameter resolution, and kill management

## Usage Example

```rust
use crate::services::tool_run_manager::ToolRunManager;
use crate::models::installed_tool::InstalledTool;

async fn launch_user_tool() -> Result<()> {
    let tool_run_manager = ToolRunManager::new().await?;
    
    let tool = InstalledTool {
        name: "notepad".to_string(),
        path: "C:\\Windows\\System32\\notepad.exe".to_string(),
        // ... other fields
    };
    
    // Launch tool in active user session
    let result = tool_run_manager
        .launch_in_user_session(&tool, &["document.txt".to_string()])
        .await?;
    
    println!("Tool launched with PID: {}", result.0);
    Ok(())
}
```

The service handles Windows-specific complexities like session enumeration, token duplication, and proper process creation flags to ensure tools launch in the correct user context with appropriate permissions and visibility.
