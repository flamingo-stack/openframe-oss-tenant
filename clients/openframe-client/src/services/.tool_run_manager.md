This tool run manager provides process management capabilities for launching tools in Windows user sessions, with automatic retry mechanisms and session detection.

## Key Components

- **`get_active_user_session()`** - Detects active Windows Terminal Services sessions, preferring RDP over console sessions
- **`launch_process_in_user_session()`** - Launches processes in detected user sessions with proper token handling
- **`launch_process_in_console_session()`** - Alternative launcher using physical console session
- **Session Management** - Windows-specific session enumeration and user token management
- **Process Creation** - Handles command-line building, argument quoting, and process isolation

## Usage Example

```rust
use crate::tool_run_manager::*;

// Launch a tool in the active user session
async fn launch_notepad() -> Result<()> {
    let command_path = "C:\\Windows\\System32\\notepad.exe";
    let args = vec!["myfile.txt".to_string()];
    
    #[cfg(windows)]
    {
        let (pid, handle) = launch_process_in_user_session(command_path, &args)?;
        info!("Launched notepad with PID: {}", pid);
        // Process handle can be used for monitoring/cleanup
    }
    
    Ok(())
}

// Detect active session for service applications
#[cfg(windows)]
fn check_user_session() -> Option<u32> {
    if let Some(session_id) = get_active_user_session() {
        println!("Active user session found: {}", session_id);
        Some(session_id)
    } else {
        println!("No active user session detected");
        None
    }
}
```

The manager handles Windows service scenarios where tools need to run in user context, manages session tokens, and provides fallback mechanisms for different session types.
