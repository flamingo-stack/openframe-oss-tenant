This file manages the lifecycle of running tools in the Flamingo/OpenFrame platform, handling cross-platform process execution with special support for Windows session management.

## Key Components

- **`get_active_user_session()`** (Windows) - Detects and returns the active user session ID by enumerating Windows Terminal Services sessions
- **`launch_process_in_console_session()`** (Windows) - Launches processes in the physical console session using `WTSGetActiveConsoleSessionId`
- **`launch_process_in_user_session()`** (Windows) - Launches processes in the detected active user session with proper token duplication
- **Helper functions** - `to_wide()` for Windows string conversion, `wcslen()` for string length calculation
- **Constants** - `RETRY_DELAY_SECONDS` for retry logic timing

## Usage Example

```rust
use anyhow::Result;

// Windows: Launch a tool in the active user session
#[cfg(windows)]
fn launch_tool() -> Result<()> {
    let command_path = "C:\\Tools\\MyTool.exe";
    let args = vec!["--config".to_string(), "production".to_string()];
    
    match launch_process_in_user_session(command_path, &args) {
        Ok((pid, handle)) => {
            println!("Tool launched successfully with PID: {}", pid);
            // Process handle can be used for monitoring/cleanup
            Ok(())
        }
        Err(e) => {
            println!("Failed to launch tool: {}", e);
            Err(e)
        }
    }
}

// Get active session for monitoring
#[cfg(windows)]
fn check_active_session() -> Option<u32> {
    if let Some(session_id) = get_active_user_session() {
        println!("Active user session detected: {}", session_id);
        Some(session_id)
    } else {
        println!("No active user session found");
        None
    }
}
```

The manager integrates with `InstalledToolsService`, `ToolCommandParamsResolver`, and `ToolKillService` to provide complete tool lifecycle management with proper Windows session handling for GUI applications.
