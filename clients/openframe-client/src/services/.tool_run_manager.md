Manages the execution and lifecycle of installed tools across Windows and Unix systems, with specialized support for Windows session handling and user token management.

## Key Components

- **`get_active_user_session()`** (Windows) - Detects and selects the best active user session from Windows Terminal Services
- **`launch_process_in_user_session()`** (Windows) - Launches processes with proper user tokens and session context
- **`launch_process_in_console_session()`** (Windows) - Alternative launcher for console-based sessions
- **Session Management** - Handles Windows RDP, console, and service sessions with priority-based selection
- **Process Token Handling** - Manages user token duplication and security context for cross-session execution

## Usage Example

```rust
use crate::services::tool_run_manager::ToolRunManager;
use crate::models::installed_tool::InstalledTool;

// Initialize the tool run manager
let tool_manager = ToolRunManager::new();

// Launch a tool in the active user session (Windows)
#[cfg(windows)]
{
    let tool = InstalledTool::new("notepad.exe", "/path/to/notepad.exe");
    let args = vec!["document.txt".to_string()];
    
    match launch_process_in_user_session(&tool.path, &args) {
        Ok((pid, handle)) => {
            info!("Tool launched with PID: {}", pid);
            // Handle process lifecycle
        }
        Err(e) => error!("Failed to launch tool: {}", e),
    }
}

// Cross-platform tool execution with retry logic
let mut retries = 3;
while retries > 0 {
    match tool_manager.execute_tool(&installed_tool, &params).await {
        Ok(result) => break,
        Err(e) => {
            warn!("Tool execution failed, retrying in {} seconds: {}", RETRY_DELAY_SECONDS, e);
            sleep(Duration::from_secs(RETRY_DELAY_SECONDS)).await;
            retries -= 1;
        }
    }
}
```

The manager provides robust cross-platform tool execution with Windows-specific session awareness, making it suitable for service-based applications that need to launch GUI tools in user contexts.
