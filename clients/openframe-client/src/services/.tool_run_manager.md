This module manages tool execution with Windows session handling and process lifecycle management for the Flamingo AI-powered MSP platform. It provides asynchronous tool launching, process monitoring, and Windows-specific session management for running tools in user contexts.

## Key Components

- **`get_active_user_session()`** - Detects and returns active Windows Terminal Services session ID
- **`launch_process_in_console_session()`** - Launches processes in the physical console session
- **`launch_process_in_user_session()`** - Launches processes in the active user session with proper token duplication
- **Windows session management functions** - Handle WTS enumeration, token management, and process creation
- **Helper utilities** - Wide string conversion (`to_wide()`) and string length calculation (`wcslen()`)

## Usage Example

```rust
use crate::tool_run_manager::*;

// Launch a tool in the active user session (Windows)
#[cfg(windows)]
async fn run_tool_example() -> Result<()> {
    let command_path = r"C:\Tools\example.exe";
    let args = vec!["--config".to_string(), "config.json".to_string()];
    
    match launch_process_in_user_session(command_path, &args) {
        Ok((pid, handle)) => {
            println!("Tool launched successfully with PID: {}", pid);
            // Process handle can be used for monitoring
            Ok(())
        }
        Err(e) => {
            eprintln!("Failed to launch tool: {}", e);
            Err(e)
        }
    }
}

// Get active user session for monitoring
#[cfg(windows)]
fn check_active_session() {
    if let Some(session_id) = get_active_user_session() {
        println!("Active user session: {}", session_id);
    } else {
        println!("No active user session found");
    }
}
```

The module includes comprehensive Windows session detection, preferring RDP sessions over console sessions, and handles service-to-user process launching with proper security token management. It provides detailed logging for troubleshooting session and process creation issues.
