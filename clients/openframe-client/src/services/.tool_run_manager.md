Manages the execution of installed tools as processes with Windows session handling and user context switching. This service coordinates tool launches, process monitoring, and proper user session detection for GUI applications running from system services.

## Key Components

- **Session Detection**: `get_active_user_session()` - Finds active user sessions on Windows systems
- **Process Launching**: `launch_process_in_user_session()` and `launch_process_in_console_session()` - Launches tools in appropriate user contexts
- **Token Management**: Windows security token duplication for proper user impersonation
- **Service Integration**: Works with `InstalledToolsService`, `ToolCommandParamsResolver`, and `ToolKillService`

## Usage Example

```rust
use crate::services::tool_run_manager::ToolRunManager;

// Launch a tool in the active user session (Windows)
#[cfg(windows)]
let (pid, handle) = launch_process_in_user_session(
    "C:\\Program Files\\MyTool\\tool.exe",
    &vec!["--arg1".to_string(), "value1".to_string()]
)?;

// The manager handles session detection and user token management automatically
info!("Tool launched with PID: {}", pid);

// For cross-platform compatibility, the service also provides
// standard async process spawning with proper stdio handling
```

The service includes sophisticated Windows Terminal Services integration to detect active user sessions, handle RDP connections, and properly launch GUI applications from system services with full user context preservation.
