This file manages the execution of tools as separate processes, handling cross-platform process creation with special Windows session management for service contexts.

## Key Components

- **`get_active_user_session()`** (Windows) - Detects active user sessions for service-to-user process launching
- **`launch_process_in_console_session()`** (Windows) - Launches processes in the physical console session
- **`launch_process_in_user_session()`** (Windows) - Launches processes in active user sessions with proper token duplication
- **Session Management** - Handles Windows Terminal Services enumeration and session selection
- **Process Isolation** - Creates processes with appropriate flags for GUI/service contexts

## Usage Example

```rust
use crate::tool_run_manager::*;

// On Windows, launch a tool in the active user session
#[cfg(windows)]
let (pid, handle) = launch_process_in_user_session(
    "C:\\Tools\\mytool.exe",
    &["--arg1".to_string(), "value".to_string()]
)?;

// Cross-platform process execution would typically use:
let mut cmd = Command::new("tool_path");
cmd.args(["--param", "value"])
   .stdout(Stdio::piped())
   .stderr(Stdio::piped());
let child = cmd.spawn()?;
```

The manager handles complex Windows session scenarios like:
- Service processes launching GUI applications
- RDP vs Console session priority
- Token duplication for user impersonation
- Proper desktop assignment (`winsta0\default`)

Critical for MSP automation where tools must run in user contexts even when launched from system services.
