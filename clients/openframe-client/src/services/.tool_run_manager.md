Manages the execution and lifecycle of external tools as separate processes, with platform-specific Windows session handling for service-to-user process launching.

## Key Components

- **`ToolRunManager`** - Main service for managing tool execution lifecycle
- **Windows Session Management** - Platform-specific functions for launching processes in active user sessions:
  - `get_active_user_session()` - Detects active Windows Terminal Services sessions
  - `launch_process_in_user_session()` - Launches processes with proper user context
  - `launch_process_in_console_session()` - Alternative console-based process launching
- **Process Lifecycle Management** - Handles tool startup, monitoring, and cleanup
- **Retry Logic** - Built-in retry mechanism with configurable delays

## Usage Example

```rust
use crate::services::tool_run_manager::ToolRunManager;
use crate::models::installed_tool::InstalledTool;

// Initialize the tool run manager
let tool_manager = ToolRunManager::new(
    installed_tools_service,
    params_resolver,
    kill_service
);

// Run a tool with parameters
let tool = InstalledTool {
    name: "my-tool".to_string(),
    command: "/path/to/tool".to_string(),
    // ... other fields
};

let args = vec!["--param1".to_string(), "value1".to_string()];
match tool_manager.run_tool(&tool, args).await {
    Ok((pid, handle)) => {
        println!("Tool started with PID: {}", pid);
    }
    Err(e) => {
        eprintln!("Failed to start tool: {}", e);
    }
}
```

The manager automatically handles platform differences, ensuring tools launched from Windows services can properly interact with the active user session through Windows Terminal Services APIs.
