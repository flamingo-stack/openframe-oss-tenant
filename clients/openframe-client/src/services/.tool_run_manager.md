Manages the lifecycle of tool processes, handling cross-platform process spawning (with special Windows session management for service contexts), retry logic, and process monitoring for installed MSP tools.

## Key Components

- **`get_active_user_session()`** *(Windows-only)* — Detects the active Windows Terminal Services session, preferring RDP sessions over console, falling back to highest session ID
- **`launch_process_in_console_session()`** *(Windows-only)* — Spawns a process in the physical console session (session 0 bypass) using `WTSGetActiveConsoleSessionId` + `CreateProcessAsUserW`
- **`launch_process_in_user_session()`** *(Windows-only)* — Public entry point that resolves the active user session and delegates to `launch_process_in_target_session`
- **`launch_process_in_target_session()`** *(Windows-only)* — Full token duplication pipeline (`WTSQueryUserToken` → `DuplicateTokenEx` → `CreateProcessAsUserW`) targeting a specific session ID with desktop assignment (`winsta0\default`)

### Constants

| Name | Value | Purpose |
|------|-------|---------|
| `RETRY_DELAY_SECONDS` | `5` | Pause between process restart attempts |

### Dependencies

- `InstalledToolsService` — tool registry lookups
- `ToolCommandParamsResolver` — resolves runtime command parameters
- `ToolKillService` — process termination handling
- `WindowsSessionManager` / `windows_helpers` — Windows-specific session utilities

## Usage Example

```rust
#[cfg(windows)]
use crate::services::tool_run_manager::launch_process_in_user_session;

// Launch a tool binary in the active user's Windows session
// (works correctly when the calling process runs as a Windows service)
let args = vec!["--config".to_string(), "agent.toml".to_string()];
match launch_process_in_user_session("C:\\Tools\\agent.exe", &args) {
    Ok((pid, handle)) => {
        info!("Tool started with PID {}", pid);
        // handle is a Win32 HANDLE; close when done
    }
    Err(e) => error!("Failed to launch tool: {}", e),
}
```

> **Note:** `launch_process_in_user_session` is designed for Windows service contexts where the calling process runs in Session 0 and needs to spawn interactive processes in the logged-in user's desktop session. On non-Windows targets, cross-platform process spawning is handled via `tokio::process::Command`.
