This module provides cross-platform process management functionality for launching tools as child processes, with specialized Windows support for running processes in active user sessions.

## Key Components

- **`ToolRunManager`** - Main service for managing tool execution lifecycle
- **Windows Session Management** - Functions for detecting active user sessions and launching processes with proper privileges
- **Process Lifecycle** - Handles process spawning, monitoring, and cleanup
- **Cross-platform Support** - Unified interface with platform-specific implementations

### Core Functions

- `get_active_user_session()` - Detects active Windows user sessions (Windows only)
- `launch_process_in_user_session()` - Launches processes in detected user sessions (Windows only)
- `launch_process_in_console_session()` - Alternative launcher for console sessions (Windows only)
- Process monitoring and retry logic with configurable delays

### Dependencies

- `InstalledToolsService` - Tool installation management
- `ToolCommandParamsResolver` - Command parameter resolution
- `ToolKillService` - Process termination handling
- Windows APIs for session management and process creation

## Usage Example

```rust
use crate::services::tool_run_manager::ToolRunManager;
use crate::models::installed_tool::InstalledTool;

// Initialize the tool run manager
let mut run_manager = ToolRunManager::new(
    installed_tools_service,
    params_resolver,
    kill_service,
);

// Launch a tool process
let tool = InstalledTool {
    name: "my-tool".to_string(),
    path: "/usr/local/bin/my-tool".to_string(),
    // ... other fields
};

let args = vec!["--config".to_string(), "production".to_string()];
let result = run_manager.launch_tool(&tool, args).await?;

// Monitor process execution
match result {
    Ok((pid, handle)) => {
        println!("Tool launched successfully with PID: {}", pid);
        // Process monitoring logic
    }
    Err(e) => {
        eprintln!("Failed to launch tool: {}", e);
        // Retry logic with RETRY_DELAY_SECONDS
    }
}
```

The module includes comprehensive Windows session detection logic to ensure tools run with appropriate user privileges and desktop access, making it suitable for MSP automation scenarios where tools need to interact with user desktops.
