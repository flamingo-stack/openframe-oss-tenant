Manages process execution for tools in user sessions with Windows Terminal Services integration and cross-platform support. Handles session detection, token management, and process lifecycle for running tools in appropriate user contexts.

## Key Components

- **Session Management** - `get_active_user_session()` detects active Windows Terminal Services sessions
- **Process Launchers** - `launch_process_in_user_session()` and `launch_process_in_console_session()` for different execution contexts
- **Token Management** - Duplicates and manages Windows security tokens for user impersonation
- **Service Integration** - `InstalledToolsService`, `ToolCommandParamsResolver`, `ToolKillService` for tool lifecycle

## Usage Example

```rust
use crate::tool_run_manager::*;

#[cfg(windows)]
fn launch_tool_in_user_session() -> Result<()> {
    // Get active user session
    let session_id = get_active_user_session()
        .context("No active user session found")?;
    
    // Launch process with arguments
    let command_path = "notepad.exe";
    let args = vec!["document.txt".to_string()];
    
    let (pid, handle) = launch_process_in_user_session(command_path, &args)?;
    info!("Tool launched with PID: {}", pid);
    
    Ok(())
}

// Cross-platform tool execution
async fn run_tool_async() -> Result<()> {
    let mut command = Command::new("my-tool");
    command.args(&["--param", "value"])
           .stdout(Stdio::piped())
           .stderr(Stdio::piped());
    
    let child = command.spawn()
        .context("Failed to spawn tool process")?;
    
    Ok(())
}
```

The manager provides Windows-specific session handling for running tools in user desktop contexts while maintaining cross-platform compatibility through Tokio's process management.
