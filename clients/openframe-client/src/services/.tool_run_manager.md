This file manages the execution of tools across different operating systems, with specialized Windows session handling for proper user context execution.

## Key Components

- **`get_active_user_session()`** - Windows-specific function that detects and returns the active user session ID by enumerating Terminal Services sessions
- **`launch_process_in_console_session()`** - Launches processes in the physical console session using Windows APIs
- **`launch_process_in_user_session()`** - Comprehensive Windows process launcher that creates processes in the active user session with proper token handling
- **Session management utilities** - Helper functions for wide string conversion and session enumeration on Windows
- **Cross-platform abstractions** - Conditional compilation for Windows-specific functionality

## Usage Example

```rust
use crate::services::tool_run_manager::*;
use anyhow::Result;

#[tokio::main]
async fn main() -> Result<()> {
    // On Windows, launch a tool in the active user session
    #[cfg(windows)]
    {
        let command_path = r"C:\Program Files\MyTool\tool.exe";
        let args = vec!["--config".to_string(), "production".to_string()];
        
        match launch_process_in_user_session(command_path, &args) {
            Ok((pid, handle)) => {
                println!("Tool launched successfully with PID: {}", pid);
                // Process handle can be used for monitoring
            }
            Err(e) => {
                eprintln!("Failed to launch tool: {}", e);
            }
        }
    }
    
    Ok(())
}
```

The manager handles complex Windows session scenarios including service contexts, RDP sessions, and console sessions, ensuring tools run with proper user privileges and desktop access.
