Manages the execution and lifecycle of external tools within user sessions on Windows systems, handling process creation, session detection, and cross-platform compatibility.

## Key Components

- **Active User Session Detection**: Comprehensive Windows session enumeration to find the best active user session (prioritizes RDP over console sessions)
- **Process Launching**: Cross-platform process creation with Windows-specific user session impersonation using `CreateProcessAsUserW`
- **Session Management**: Handles both service and interactive contexts, automatically detecting whether running as a system service
- **Tool Integration**: Works with `InstalledTool`, `InstalledToolsService`, and `ToolCommandParamsResolver` for complete tool management

## Usage Example

```rust
use crate::services::tool_run_manager::ToolRunManager;

// The manager handles Windows session detection automatically
let session_id = get_active_user_session().unwrap_or_else(|| {
    panic!("No active user session found");
});

// Launch a tool in the user session (Windows)
let (pid, handle) = launch_process_in_user_session(
    "C:\\Tools\\my_tool.exe",
    &["--param1".to_string(), "value1".to_string()]
)?;

// Or use console session specifically
let (pid, handle) = launch_process_in_console_session(
    "C:\\Tools\\console_tool.exe", 
    &["--verbose".to_string()]
)?;
```

The manager prioritizes RDP sessions over console sessions and filters out system sessions and listeners, ensuring tools run in the appropriate user context for GUI applications and system integrations.
