Manages the lifecycle of periodic machine heartbeat publishing, spawning a background Tokio task that sends heartbeats at a fixed interval with timeout protection.

## Key Components

| Item | Description |
|------|-------------|
| `MachineHeartbeatRunManager` | Cloneable struct that owns a `MachineHeartbeatPublisher` and drives the heartbeat loop |
| `HEARTBEAT_INTERVAL` | 60-second tick interval between heartbeat publishes |
| `HEARTBEAT_TIMEOUT` | 30-second timeout per publish attempt before logging a NATS disconnect warning |
| `new(publisher)` | Constructor accepting a `MachineHeartbeatPublisher` instance |
| `start()` | Spawns a detached async loop; errors are logged but do not terminate the loop |

## Usage Example

```rust
use crate::services::machine_heartbeat_publisher::MachineHeartbeatPublisher;
use crate::services::machine_heartbeat_run_manager::MachineHeartbeatRunManager;

#[tokio::main]
async fn main() {
    let publisher = MachineHeartbeatPublisher::new(/* nats_client */).await?;
    let manager = MachineHeartbeatRunManager::new(publisher);

    // Spawns background task; returns immediately
    manager.start();

    // Application continues while heartbeats run in the background
    tokio::signal::ctrl_c().await?;
}
```

## Behavior Notes

- The background task runs **indefinitely** — it does not expose a shutdown handle
- A failed publish logs an error but keeps the loop alive for the next tick
- A timeout (30 s) logs a NATS disconnection warning, distinguishing network issues from publish errors
- `MachineHeartbeatRunManager` is `Clone`, so it can be passed across service boundaries before `start()` is called
