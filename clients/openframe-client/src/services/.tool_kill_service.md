Process termination service for installed tools and assets, handling graceful shutdown with fallback to force kill across different installation types (GUI app, standard executable, system service).

## Key Components

| Item | Description |
|------|-------------|
| `ToolKillService` | Main service struct (cloneable, stateless) |
| `stop_tool()` | Stops all processes matching a tool ID pattern |
| `stop_asset()` | Stops all processes matching an asset ID + tool ID pattern |
| `stop_installed_tool()` | Dispatches stop logic based on `Installation` variant |
| `stop_for_installation()` | Handles `GuiApp`, `Standard`, and `Service` installation types |
| `is_installed_tool_running()` | Checks if any process matching an installed tool's patterns is alive |
| `collect_matching_processes()` | Scans live processes via `sysinfo`, matching cmdline or exe path |
| `stop_process_with_retry()` | Graceful → force kill pipeline with configurable retries |
| `wait_for_process_exit()` | Polls process existence until timeout |
| `build_tool_cmd_pattern()` | Builds OS-aware path pattern (`tool\agent` / `tool/agent`) |

Configuration constants (`FORCE_KILL_TIMEOUT_SECS`, `GRACEFUL_SHUTDOWN_TIMEOUT_SECS`, `MAX_KILL_RETRIES`, `PROCESS_CHECK_INTERVAL_MS`) are sourced from `crate::config::service_stop`.

## Usage Example

```rust
use crate::services::tool_kill_service::ToolKillService;

let kill_svc = ToolKillService::new();

// Stop all processes for a tool by ID
kill_svc.stop_tool("my-monitoring-tool").await?;

// Stop processes for a specific asset
kill_svc.stop_asset("asset-123", "my-monitoring-tool").await?;

// Stop using full installation metadata (handles service, GUI, or standard)
let tool: InstalledTool = /* loaded from registry */;
kill_svc.stop_installed_tool(&tool, /* allow_delete */ true).await?;

// Check if a tool is currently running before attempting install
if kill_svc.is_installed_tool_running(&tool).await {
    kill_svc.stop_installed_tool(&tool, false).await?;
}
```

For `Service` installations, `system_service::stop_service` is called first, with a fallback to path-based process kill for any detached child processes.
