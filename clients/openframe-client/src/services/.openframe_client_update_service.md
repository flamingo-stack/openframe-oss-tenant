Orchestrates the complete OpenFrame client update workflow from version validation through binary deployment.

## Key Components

### OpenFrameClientUpdateService
Main service struct that coordinates the update process with thread-safe execution control.

**Fields:**
- `client_info_service` - Manages client status and version information
- `github_download_service` - Handles downloading releases from GitHub
- `update_state_service` - Tracks update progress and state persistence
- `update_in_progress` - Mutex preventing concurrent updates

**Key Methods:**
- `process_update()` - Entry point for update requests with race condition protection
- `execute_update()` - Core update workflow execution
- `create_temp_archive()` - Platform-specific binary preparation (ZIP on Windows, direct binary on Unix)
- `parse_version()` - Semantic version parsing with "v" prefix support
- `is_valid_version()` - Basic version format validation

## Usage Example

```rust
use anyhow::Result;

// Initialize the service with required dependencies
let update_service = OpenFrameClientUpdateService::new(
    client_info_service,
    github_download_service,
    update_state_service,
);

// Process an update request
let message = OpenFrameClientUpdateMessage {
    version: "v1.2.3".to_string(),
    download_configurations: vec![/* download configs */],
};

match update_service.process_update(message).await {
    Ok(_) => println!("Update launched successfully"),
    Err(e) => eprintln!("Update failed: {}", e),
}
```

The service implements a comprehensive update pipeline: validates version format → downloads binary from GitHub → creates platform-specific archive → launches updater script → transfers control to external updater process. Includes robust error handling with automatic state cleanup and prevents concurrent updates through mutex protection.
