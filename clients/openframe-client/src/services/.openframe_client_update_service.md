This service orchestrates the OpenFrame client self-update process, managing version validation, binary downloads, and platform-specific update execution with comprehensive safety checks and state tracking.

## Key Components

- **OpenFrameClientUpdateService** - Main service coordinating the update workflow
- **process_update()** - Entry point handling concurrent update protection and validation
- **execute_update()** - Core update logic managing download, extraction, and updater launch
- **create_temp_archive()** - Platform-specific binary preparation (ZIP on Windows, direct file on Unix)
- **Version validation utilities** - Semver parsing and format validation helpers

## Usage Example

```rust
use openframe_client_update_service::OpenFrameClientUpdateService;
use crate::models::openframe_client_update_message::OpenFrameClientUpdateMessage;

// Initialize the service with required dependencies
let update_service = OpenFrameClientUpdateService::new(
    client_info_service,
    github_download_service,
    update_state_service,
);

// Process an update request
let update_message = OpenFrameClientUpdateMessage {
    version: "v1.2.3".to_string(),
    download_configurations: vec![/* platform configs */],
};

// Execute update with built-in safety checks
match update_service.process_update(update_message).await {
    Ok(_) => println!("Update launched successfully"),
    Err(e) => eprintln!("Update failed: {}", e),
}
```

The service includes race condition protection via mutex locking, comprehensive error handling with state cleanup, and platform-aware binary preparation. Updates are tracked through multiple phases (Downloading, Extracting, PreparingUpdater, UpdaterLaunched) with persistent state management for recovery scenarios.
