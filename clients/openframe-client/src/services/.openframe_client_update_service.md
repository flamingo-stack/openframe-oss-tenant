Orchestrates automated client updates for OpenFrame applications by handling version validation, binary downloads, and launching platform-specific update processes. This service ensures thread-safe updates with proper state tracking and error recovery.

## Key Components

- **`OpenFrameClientUpdateService`** - Main service for processing client update requests
- **`process_update`** - Entry point that validates requests and prevents concurrent updates
- **`execute_update`** - Core update logic handling download, extraction, and launcher execution
- **`create_temp_archive`** - Platform-specific binary preparation (ZIP on Windows, direct file on Unix)
- **`parse_version`** / **`is_valid_version`** - Semantic version validation utilities

## Usage Example

```rust
use openframe_client_update_service::OpenFrameClientUpdateService;
use crate::models::openframe_client_update_message::OpenFrameClientUpdateMessage;

// Initialize the update service
let update_service = OpenFrameClientUpdateService::new(
    client_info_service,
    github_download_service,
    update_state_service,
);

// Process an update request
let update_message = OpenFrameClientUpdateMessage {
    version: "v1.2.3".to_string(),
    download_configurations: vec![/* download configs */],
};

match update_service.process_update(update_message).await {
    Ok(()) => println!("Update process initiated successfully"),
    Err(e) => eprintln!("Update failed: {}", e),
}
```

The service uses a mutex-protected update lock to prevent race conditions, validates semantic versions, downloads binaries from GitHub releases, and launches platform-specific updater scripts that handle the actual binary replacement and service restart.
