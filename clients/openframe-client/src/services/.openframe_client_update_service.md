Orchestrates the full lifecycle of an OpenFrame client self-update: version validation, downgrade protection, binary download/extraction, temporary archive creation, and delegating to the platform-specific updater launcher.

## Key Components

### `OpenFrameClientUpdateService`

The primary struct managing the update pipeline with the following injected dependencies:

| Field | Purpose |
|---|---|
| `client_info_service` | Reads/writes current client version and update status |
| `github_download_service` | Resolves OS-specific download config and fetches binaries |
| `update_state_service` | Persists update phase transitions for crash recovery |
| `last_known_good_service` | Manages the LKG anchor used for downgrade guard |
| `tool_run_manager` | Gates updates when tool operations are in-flight |
| `update_in_progress` | `Arc<Mutex<bool>>` preventing concurrent update races |

### Key Methods

- **`process_update`** — Public entry point; acquires the update mutex, defers if tool ops are running, releases lock on completion or error
- **`process_update_internal`** — Validates semver format, enforces downgrade guard against the LKG anchor, initializes `UpdateState`, and transitions `ClientUpdateStatus`
- **`execute_update`** — Drives the phased pipeline: `Downloading → Extracting → PreparingUpdater → UpdaterLaunched`, with cleanup on each failure point
- **`create_temp_archive`** *(Windows, truncated)* — Packages the downloaded binary into a ZIP for the updater script

## Usage Example

```rust
let svc = OpenFrameClientUpdateService::new(
    client_info_service,
    github_download_service,
    update_state_service,
    last_known_good_service,
    tool_run_manager,
);

let msg = OpenFrameClientUpdateMessage {
    version: "1.4.2".to_string(),
    download_configurations: vec![/* OS-specific configs */],
};

svc.process_update(msg).await?;
```

> The service signals shutdown via `tool_run_manager.signal_shutdown()` after successfully launching the updater — the calling process should expect termination.
