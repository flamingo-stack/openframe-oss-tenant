Orchestrates client update process for OpenFrame applications with version validation, concurrent update protection, and platform-specific binary deployment. Manages the complete update lifecycle from download to service restart.

## Key Components

- **OpenFrameClientUpdateService** - Main service for processing client update requests
- **process_update()** - Entry point with race condition protection using mutex
- **process_update_internal()** - Core update logic with version validation
- **execute_update()** - Handles download, extraction, and updater launch
- **create_temp_archive()** - Platform-specific binary preparation (ZIP on Windows, direct file on Unix)
- **parse_version()** / **is_valid_version()** - Semver version validation utilities

## Usage Example

```rust
use openframe_client_update_service::OpenFrameClientUpdateService;
use openframe_client_update_message::OpenFrameClientUpdateMessage;

// Initialize service with dependencies
let update_service = OpenFrameClientUpdateService::new(
    client_info_service,
    github_download_service,
    update_state_service,
);

// Process update request
let message = OpenFrameClientUpdateMessage {
    version: "v1.2.3".to_string(),
    download_configurations: vec![/* OS-specific configs */],
};

// This will validate version, download binary, and launch updater
match update_service.process_update(message).await {
    Ok(_) => println!("Update process initiated successfully"),
    Err(e) => eprintln!("Update failed: {}", e),
}
```

The service ensures only one update can run at a time, validates semver versions, tracks update state through multiple phases, and handles platform-specific deployment (ZIP archives on Windows, direct binaries on Unix).
