Manages the OpenFrame client's self-update process by orchestrating version validation, file downloads, and platform-specific updater launches. Implements race condition protection and comprehensive error handling for safe automatic updates.

## Key Components

### OpenFrameClientUpdateService
- **`new()`** - Creates service with dependencies for client info, GitHub downloads, and update state management
- **`process_update()`** - Main entry point handling update requests with race condition protection
- **`execute_update()`** - Orchestrates the complete update workflow from download to updater launch
- **`create_temp_archive()`** - Platform-specific temporary file creation (ZIP for Windows, binary for Unix)
- **`parse_version()`** - Validates and parses semantic version strings
- **`is_valid_version()`** - Basic version format validation

### Update Workflow
1. **Race Protection** - Prevents concurrent updates using async mutex
2. **Version Validation** - Ensures semver compatibility and format correctness
3. **Download Phase** - Downloads and extracts binary from GitHub releases
4. **Preparation** - Creates platform-appropriate temporary files for updater
5. **Launch** - Executes platform-specific updater script and stops current service

## Usage Example

```rust
use crate::services::openframe_client_update_service::OpenFrameClientUpdateService;
use crate::models::openframe_client_update_message::OpenFrameClientUpdateMessage;

// Initialize service with dependencies
let update_service = OpenFrameClientUpdateService::new(
    client_info_service,
    github_download_service,
    update_state_service,
);

// Process an update request
let update_message = OpenFrameClientUpdateMessage {
    version: "v1.2.3".to_string(),
    download_configurations: vec![/* platform configs */],
};

// This will handle the complete update process
match update_service.process_update(update_message).await {
    Ok(()) => println!("Update process initiated successfully"),
    Err(e) => eprintln!("Update failed: {:#}", e),
}
```

The service automatically handles cleanup on failures and ensures only one update can run at a time. After launching the updater, the current service instance will be terminated and restarted with the new version.
