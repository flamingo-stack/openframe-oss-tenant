Service for managing OpenFrame client application updates via NATS messaging. Handles version validation, binary downloads from GitHub, extraction, and launching platform-specific update scripts with race condition protection and comprehensive error handling.

## Key Components

### Main Service
- **`OpenFrameClientUpdateService`** - Core service with update lock protection
- **`process_update()`** - Public entry point with race condition protection
- **`process_update_internal()`** - Internal update logic with version validation
- **`execute_update()`** - Handles download, extraction, and updater launch

### Helper Methods
- **`create_temp_archive()`** - Creates temporary archives (ZIP on Windows, direct binary on Unix)
- **`parse_version()`** - Parses semver version strings with prefix support
- **`is_valid_version()`** - Basic version format validation

### Dependencies
- Uses `OpenFrameClientInfoService` for status tracking
- Uses `GithubDownloadService` for binary downloads
- Uses `UpdateStateService` for persistent state management
- Uses platform-specific `updater_launcher` for update execution

## Usage Example

```rust
use openframe_client_update_service::OpenFrameClientUpdateService;
use openframe_client_update_message::OpenFrameClientUpdateMessage;

// Initialize service with dependencies
let update_service = OpenFrameClientUpdateService::new(
    client_info_service,
    github_download_service,
    update_state_service,
);

// Process update request
let message = OpenFrameClientUpdateMessage {
    version: "v1.2.3".to_string(),
    download_configurations: vec![/* configs */],
};

match update_service.process_update(message).await {
    Ok(_) => println!("Update launched successfully"),
    Err(e) => eprintln!("Update failed: {}", e),
}
```

The service ensures only one update can run at a time, validates version formats using semver, and handles cleanup on failures. After launching the updater, the current service is terminated and restarted with the new version.
