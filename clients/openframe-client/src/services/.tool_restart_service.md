Orchestrates safe, lock-guarded restarts of installed tools, handling both OS-managed service installs and supervised process installs with panic- and cancellation-safe cleanup.

## Key Components

### `RestartOutcome`
Enum returned by restart operations with three variants:
- `Restarted` — tool was found and successfully restarted
- `NotInstalled` — tool agent ID not found in the registry
- `Busy` — tool lock could not be acquired (concurrent operation in progress)

### `UpdatingGuard`
RAII guard that clears the `updating` flag and releases the tool lock exactly once, even if the restart future is cancelled or panics. Uses `Drop` to spawn an async cleanup task on the current Tokio runtime handle.

### `ToolRestartService`
Primary service struct (cloneable) that coordinates restart logic across three dependencies:
- `InstalledToolsService` — looks up tool metadata by agent ID
- `ToolKillService` — stops the running tool process or OS service
- `ToolRunManager` — manages the per-tool mutex, updating flag, and supervised process lifecycle

#### Methods
| Method | Description |
|---|---|
| `restart_guarded` | Public entry point; acquires the tool lock, sets the updating flag, then drives restart with panic recovery via `catch_unwind` |
| `restart_by_tool_agent_id` | Resolves the tool from the registry and delegates to `restart_tool` |
| `restart_tool` | Stops the tool, then either restarts the OS service (with retry logic) or re-registers supervision with the run manager |

## Usage Example

```rust
let svc = ToolRestartService::new(
    installed_tools_service,
    tool_kill_service,
    tool_run_manager,
);

match svc.restart_guarded("my-agent-id").await? {
    RestartOutcome::Restarted    => info!("Tool restarted successfully"),
    RestartOutcome::NotInstalled => warn!("Tool not found in registry"),
    RestartOutcome::Busy         => warn!("Tool locked by concurrent operation"),
}
```

> **Note:** For `Installation::Service` installs, a failed `start_service` call is treated as success if the tool is already running (e.g. re-launched by an OS supervisor). For supervised process installs, the run-manager loop handles relaunch automatically once the updating flag clears.
