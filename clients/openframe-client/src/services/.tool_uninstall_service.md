Handles the uninstallation lifecycle for managed tools, including process termination, command execution, and post-uninstall cleanup across platforms.

## Key Components

### `ToolUninstallService`

The primary struct providing two public/private uninstall methods:

| Method | Visibility | Description |
|---|---|---|
| `new()` | `pub` | Constructor injecting required services and directory manager |
| `uninstall_all()` | `pub async` | Iterates all installed tools and uninstalls each; fails fast on first error |
| `uninstall_tool()` | `private async` | Full uninstall lifecycle for a single tool |
| `stop_tool_process()` | `private async` | Delegates to `ToolKillService` to stop the tool before removal |
| `cleanup_tool_processes()` | `private async` | Kills any lingering processes by executable path post-uninstall |
| `cleanup_gui_app_bundle()` | `private async` | macOS-only: removes `.app` bundles for `GuiApp` installations |

### Platform-specific behavior

- **macOS** — calls `remove_app_bundle()` for `GuiApp` installations after uninstall
- **Windows** — logs file lock diagnostics via `log_file_lock_info()` when the uninstall command fails to execute

## Usage Example

```rust
let service = ToolUninstallService::new(
    installed_tools_service,
    command_params_resolver,
    tool_kill_service,
    directory_manager,
);

// Uninstall all tracked tools (fail-fast on any error)
service.uninstall_all().await?;
```

## Notes

- **Fail-fast design** — `uninstall_all()` and `uninstall_tool()` both return `Err` immediately on any failure; no partial success state is retained
- **Fleet/osqueryd workaround** — tools whose `tool_agent_id` contains `"fleet"` trigger an explicit `osqueryd` stop before uninstall, noted in-code as a known dirty solution pending a cleaner fix
- Tools with no `uninstallation_command_args` skip command execution and proceed directly to GUI bundle cleanup
- Missing executables are warned and skipped rather than errored, allowing cleanup to proceed
