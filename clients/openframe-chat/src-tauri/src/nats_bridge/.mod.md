NATS bridge module that owns the user-scoped NATS WebSocket connection for the OpenFrame desktop agent, managing OS notification subscriptions and on-demand JetStream chat stream consumers.

## Key Components

### Types

| Type | Description |
|------|-------------|
| `ConnectionState` | Enum: `Connecting`, `Connected`, `Disconnected` — serialized as lowercase |
| `NatsStatus` | Current connection state + cumulative reconnect count |
| `NatsEvent` | JetStream message envelope: `dialogId`, `streamSeq`, `payload` |
| `NatsBridge` | Public handle (cheaply `Clone`able via `Arc<Inner>`) |
| `Inner` | All mutable state behind locks: NATS client, dialog consumers, event channel, notification gate |

### `NatsBridge` Methods

| Method | Description |
|--------|-------------|
| `new(app, server_url, token_source, machine_id)` | Constructs the bridge; initialises macOS notification delegate on that platform |
| `start()` | Spawns the connect/reconnect loop. Idempotent — subsequent calls are no-ops via `AtomicBool` CAS |
| `status()` | Returns a snapshot `NatsStatus` |
| `register_event_channel(channel)` | Replaces the active WebView IPC channel; old channel is silently dropped |

### Internal helpers

- `current_client(inner)` — async read-lock accessor returning a cloned `Client` option
- `mask_token` — re-exported from `connection` for logging/display use outside the module

### Sub-modules

- `connection` — connect/reconnect/auth lifecycle
- `dialogs` — JetStream `OrderedConsumer` management per dialog
- `notifications` — core NATS subscription on `machine.<machineId>.notification`
- `macos_un` / `windows_toast` — platform-specific OS notification dispatch (conditional compilation)

## Usage Example

```rust
// Initialise and start the bridge at app startup
let bridge = NatsBridge::new(
    app.handle(),
    server_url_state,
    token_source,
    Some("machine-abc123".to_string()),
);
bridge.start(); // idempotent; safe to call multiple times

// Register the WebView IPC channel after the window loads
bridge.register_event_channel(channel).await;

// Query current status for the frontend
let status: NatsStatus = bridge.status().await;
```

> Resume on WebSocket reconnect is fully bridge-owned: `DialogState` tracks `last_delivered_stream_seq` so new `OrderedConsumer`s resume from the correct point without requiring any acknowledgement from the WebView.
