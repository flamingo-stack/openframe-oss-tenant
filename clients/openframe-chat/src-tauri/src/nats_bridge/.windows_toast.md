Builds and dispatches Windows toast notifications using protocol-activation, enabling clicks on Action Center toasts to reach both running and cold-launched app instances via the `openframe-chat://` URI scheme.

## Key Components

### `show(app_id, title, body, uri)` → `windows::core::Result<()>`
Constructs a raw XML toast payload and dispatches it via the Windows Runtime notification API. Key behaviors:
- Uses `activationType="protocol"` so both body clicks and the **Open** button invoke the provided `uri` (e.g., `openframe-chat://notify/...`) rather than an in-process handler
- Audio is silenced to match legacy notification behavior
- Body element is omitted entirely when `body` is empty

### `escape_xml(value)` → `String`
Internal XML sanitizer that escapes the five standard XML entities (`&`, `<`, `>`, `"`, `'`) before interpolating user-supplied strings into the toast XML template.

## Usage Example

```rust
windows_toast::show(
    "com.flamingo.openframe",
    "New message from Alice",
    "Hey, are you available for a call?",
    "openframe-chat://notify?ticket=12345",
)?;
```

A warm click (app already running) forwards the URI through single-instance argv forwarding. A cold click launches the app with the URI in `argv`. Both paths are handled by `NatsBridge::handle_notification_uri`.

## Notes

- Replaces `tauri-winrt-notification`, which only supports foreground (in-process) activation — toasts left in the Action Center after process exit became unclickable with that approach.
- Requires the `windows` crate with features: `Data_Xml_Dom`, `UI_Notifications`.
