Manages JetStream `OrderedConsumer` instances per open dialog, routing chat chunk messages from NATS subjects (`chat.<dialogId>.message`) to the WebView's event channel, with resume-on-reconnect and automatic failure-driven consumer recreation.

## Key Components

### `DialogState`
Tracks per-dialog subscription state:
- `initial_opt_start_seq` — replay start point from the WebView (e.g. history fetch)
- `last_delivered_stream_seq` — highest delivered sequence; used to compute resume position on reconnect
- `task` — the live router `JoinHandle`; `None` means no active consumer
- `generation` — monotonic counter to prevent replaced router tasks from clearing the active task on exit

### `NatsBridge` Methods
- **`subscribe_dialog(dialog_id, opt_start_seq)`** — Idempotent subscribe. Inserts `DialogState` if not present, re-emits `nats:subscribed` for already-live consumers, and falls back to `schedule_consumer_recreate` on failure.
- **`unsubscribe_dialog(dialog_id)`** — Removes state and aborts the router task.

### Internal Functions
- **`create_and_store_consumer`** — Resolves the start sequence, creates a named ephemeral `OrderedConsumer` with `DeliverPolicy::ByStartSequence`, spawns the router task under the dialogs write-lock, and emits `nats:subscribed`.
- **`compute_start_seq`** — Computes `max(initial, last_delivered) + 1`; returns `None` for live-tail (triggers tail-floor calculation).
- **`dialog_router`** — Async task that drains the JetStream message stream, deduplicates by `stream_seq` under the dialogs lock, and sends `NatsEvent` to the shared event channel.
- **`emit_subscribed`** — Emits `nats:subscribed` to the `main` WebView window.

## Usage Example

```rust
// Subscribe to a dialog (e.g. on WebView load or reconnect)
bridge.subscribe_dialog("dialog-abc123".to_string(), Some(42)).await;

// Resume from last known position — compute_start_seq handles the max logic:
// opt_start_seq=Some(42), last_delivered=Some(50) → resumes at seq 51

// Unsubscribe when the dialog is closed
bridge.unsubscribe_dialog("dialog-abc123").await;
```

> **Reconnect safety:** Live-tail subscriptions use `DeliverPolicy::ByStartSequence` with a concrete floor rather than `DeliverPolicy::New`, ensuring messages published during a reconnect gap are replayed. Deduplication under the write-lock prevents out-of-order delivery when old and new consumers briefly overlap.
