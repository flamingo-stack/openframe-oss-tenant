Defines the feature flag registry for the Flamingo/OpenFrame platform, providing type-safe flag names, default values, and associated types for controlling experimental or in-progress features at runtime.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `FEATURE_FLAG_NAMES` | `readonly string[]` | Const tuple of all valid feature flag identifiers |
| `FeatureFlagName` | `type` | Union type derived from `FEATURE_FLAG_NAMES` entries |
| `DEFAULT_FEATURE_FLAGS` | `Record<FeatureFlagName, boolean>` | Default (all `false`) state for every flag |
| `FeatureFlags` | `type` | Shape of a feature flag state map |

### Current Flags

| Flag | Default | Description |
|------|---------|-------------|
| `thinking` | `false` | Mingo AI reasoning/thinking mode |
| `batch-approval` | `false` | Bulk ticket/action approval workflow |
| `ai-streaming-jetstream` | `false` | NATS JetStream-backed AI response streaming |

## Usage Example

```typescript
import {
  DEFAULT_FEATURE_FLAGS,
  FeatureFlags,
  FeatureFlagName,
} from './features';

// Merge persisted overrides with safe defaults
function resolveFlags(overrides: Partial<FeatureFlags>): FeatureFlags {
  return { ...DEFAULT_FEATURE_FLAGS, ...overrides };
}

// Type-safe flag check
function isEnabled(flags: FeatureFlags, name: FeatureFlagName): boolean {
  return flags[name];
}

const flags = resolveFlags({ thinking: true });
console.log(isEnabled(flags, 'thinking')); // true
console.log(isEnabled(flags, 'batch-approval')); // false
```

> To add a new flag, append its key to `FEATURE_FLAG_NAMES` and provide a default value in `DEFAULT_FEATURE_FLAGS`. TypeScript will enforce consistency across all usages automatically.
