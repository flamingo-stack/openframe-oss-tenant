Provides a single source of truth for NATS WebSocket URL construction and auth-token lifecycle management for the `openframe-chat` client, consolidating token state, URL building, and reconnection logic into one reusable hook.

## Key Components

- **`CHAT_NATS_CLIENT_CONFIG`** — Static NATS client identity constants (`name`, `user`, `pass`)
- **`CHAT_NATS_RECONNECTION_BACKOFF`** — Reconnection timing constants (`fastRetries`, `fastRetryDelayMs`)
- **`ChatNatsConfig`** — Interface describing the hook's return shape (`getWsUrl`, `onBeforeReconnect`, `apiBaseUrl`, `token`)
- **`useChatNatsConfig()`** — Core hook; subscribes to `tokenService` updates, exposes a memoized config object consumed by `useConnectionStatus` and `useChat`

## Usage Example

```typescript
import { useChatNatsConfig, CHAT_NATS_CLIENT_CONFIG } from './useChatNatsConfig';

function ChatProvider() {
  const { getWsUrl, onBeforeReconnect, token } = useChatNatsConfig();

  useEffect(() => {
    const wsUrl = getWsUrl(); // null until token + apiBaseUrl are loaded
    if (!wsUrl) return;

    const client = connect({
      ...CHAT_NATS_CLIENT_CONFIG,
      servers: wsUrl,
    });

    return () => client.close();
  }, [getWsUrl]);

  return <>{token ? <Chat /> : <Connecting />}</>;
}
```

## Notes

- Token state remains synchronized across all hook consumers because `tokenService` is a module-level singleton with its own pub/sub — no prop-drilling or context required
- `getWsUrl` returns `null` while credentials are still loading, preventing premature connection attempts
- `onBeforeReconnect` calls `tokenService.refreshToken()` automatically before each NATS reconnect, ensuring stale tokens are never reused
