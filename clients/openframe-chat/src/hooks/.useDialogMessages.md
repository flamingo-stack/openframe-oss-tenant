Fetches and processes paginated dialog message history for a given dialog ID, transforming raw GraphQL message nodes into structured UI-ready messages with approval handling.

## Key Components

- **`useDialogMessages(dialogId, options)`** — Main hook that combines infinite pagination, message processing, and approval state management
- **`UseDialogMessagesOptions`** — Configuration interface supporting `enabled` flag, `onApprove`/`onReject` callbacks, and `approvalStatuses` map
- **`historicalMessages`** — Processed `Message[]` array with tool titles applied and Fae avatar injected, ready for rendering
- **`escalatedApprovals`** — Map of pending client-facing approvals keyed by request ID, including command, explanation, approval type, and tool calls
- **`initialOptStartSeq`** — Highest `lastChunkStreamSeq` across all loaded pages, used to seed optimistic streaming continuity
- **`reset`** — Removes all cached dialog message queries from the React Query client

## Usage Example

```typescript
const {
  historicalMessages,
  escalatedApprovals,
  hasNextPage,
  isFetchingNextPage,
  fetchNextPage,
  isLoading,
  initialOptStartSeq,
  reset,
} = useDialogMessages(dialogId, {
  enabled: true,
  approvalStatuses,
  onApprove: async (requestId) => {
    await approveRequest(requestId);
  },
  onReject: async (requestId) => {
    await rejectRequest(requestId);
  },
});

// Load older messages on scroll
if (hasNextPage && !isFetchingNextPage) {
  fetchNextPage();
}

// Clear cache on dialog close
useEffect(() => () => reset(), [dialogId]);
```

## Notes

- Pages are fetched in batches of **50** and reversed in-memory so oldest messages appear first
- Only `CLIENT` approval type is surfaced to the UI; batch approvals are gated behind the `batch-approval` feature flag
- The `thinking` feature flag controls whether extended reasoning chunks are included in the message fetch
