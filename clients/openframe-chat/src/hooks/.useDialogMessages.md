Fetches and processes paginated dialog messages for a conversation thread, transforming raw GraphQL data into structured UI-ready messages with approval state management.

## Key Components

- **`useDialogMessages(dialogId, options)`** — Main hook that orchestrates infinite pagination, message processing, and approval escalation
- **`UseDialogMessagesOptions`** — Configuration interface supporting enable toggling, approval/rejection callbacks, and per-request approval status tracking
- **`historicalMessages`** — Processed `Message[]` array with tool titles applied and Fae avatar injected, ready for rendering
- **`escalatedApprovals`** — `Map` of approval requests requiring client-side action (`CLIENT` display type), optionally batched via feature flag
- **`initialOptStartSeq`** — Highest `lastChunkStreamSeq` across all loaded pages, used to seed optimistic streaming continuity
- **`reset`** — Clears all cached query data for `dialog-messages`

## Usage Example

```typescript
const {
  historicalMessages,
  escalatedApprovals,
  hasNextPage,
  isFetchingNextPage,
  fetchNextPage,
  isLoading,
  reset,
} = useDialogMessages(dialogId, {
  enabled: isOpen,
  approvalStatuses: { 'req-123': 'APPROVED' },
  onApprove: async (requestId) => {
    await approveToolCall(requestId);
  },
  onReject: async (requestId) => {
    await rejectToolCall(requestId);
  },
});

// Load older messages
if (hasNextPage && !isFetchingNextPage) {
  fetchNextPage();
}

// On dialog close, purge cache
reset();
```

## Notes

- Pages are fetched in reverse cursor order (oldest-first after reversal) using `endCursor` pagination with a default page size of **50**
- The `thinking` and `batch-approval` feature flags gate extended reasoning content and batched approval UI respectively
- The hook is **disabled by default** (`enabled ?? false`); callers must explicitly opt in
