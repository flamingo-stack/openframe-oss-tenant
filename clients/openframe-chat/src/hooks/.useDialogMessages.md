Fetches and processes paginated historical chat messages for a dialog, transforming raw GraphQL message nodes into structured UI-ready message objects with approval state, resolver names, and assistant branding overlays.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `useDialogMessages` | Hook | Primary hook managing infinite-scroll message pagination and message processing |
| `UseDialogMessagesOptions` | Interface | Configuration options including approval callbacks and resolver name overlays |

### Returned Values

| Field | Type | Description |
|-------|------|-------------|
| `historicalMessages` | `Message[]` | Processed messages with approval state and branding applied |
| `latestAssistantModel` | `object \| null` | Model provenance of the newest assistant message (name, provider, context window) |
| `escalatedApprovals` | `Map` | Approval requests requiring client-side action |
| `initialOptStartSeq` | `number` | Highest stream sequence seen across fetched pages; seeds optimistic streaming |
| `rawHistoryIds` | `Set<string>` | Persisted MongoDB IDs for deduplication against realtime synthetic messages |
| `reset` | `() => void` | Clears all cached query data for dialog messages |

## Usage Example

```typescript
const {
  historicalMessages,
  latestAssistantModel,
  hasNextPage,
  isFetchingNextPage,
  fetchNextPage,
  escalatedApprovals,
  reset,
} = useDialogMessages(dialogId, {
  enabled: true,
  approvalStatuses: { 'req-123': 'APPROVED' },
  resolvedByNames: { 'req-123': 'Alice' },
  onApprove: async (requestId) => {
    await approveToolCall(requestId);
  },
  onReject: async (requestId) => {
    await rejectToolCall(requestId);
  },
});

// Load older messages on scroll
if (hasNextPage && !isFetchingNextPage) {
  fetchNextPage();
}
```

## Notes

- Pages are fetched newest-first and reversed before processing so messages render in chronological order.
- `resolvedByNames` overlays resolver display names onto approval segments immediately from live `APPROVAL_RESULT` chunks, avoiding stale nameless status pills before the next refetch.
- Batched approvals (`batch-approval` feature flag) are supported via `processHistoricalMessages`.
