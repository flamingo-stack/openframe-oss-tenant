Provides a React Query hook for fetching AI assistant appearance and configuration settings, with connection-aware cache keying and readiness gating based on live token and API URL state.

## Key Components

### `aiSettingsQueryKey(apiBaseUrl)`
Generates a scoped React Query cache key tied to the active API base URL, preventing stale settings from a previous connection being served after credentials change.

### `useApiConnectionState()`
A shared hook that tracks live token and API URL readiness by subscribing to `tokenService` updates. Returns `{ isReady, apiBaseUrl }` and reacts to credential changes (including drops).

### `useAiSettingsQuery({ enabled })`
The primary query hook. Fetches `AiSettingsResponse` (client assistant appearance and quick actions) from `/chat/graphql`. Combines the caller's `enabled` flag with `connection.isReady` so the query never fires without valid credentials.

**Query behaviour:**
- `staleTime`: 60 seconds — minimises redundant fetches while ensuring admin edits land without a restart
- `refetchOnWindowFocus` / `refetchOnReconnect`: `true` — picks up changes passively
- `retry`: 1 — one automatic retry on failure
- Returns `null` when no settings record exists yet

## Usage Example

```typescript
import { useAiSettingsQuery } from './hooks/useAiSettingsQuery';

function ClientAssistantShell({ isVisible }: { isVisible: boolean }) {
  const { data, isLoading, isError } = useAiSettingsQuery({ enabled: isVisible });

  if (isLoading) return <Spinner />;
  if (isError)   return <ErrorBanner />;
  if (!data)     return <DefaultAssistant />;

  return (
    <AssistantShell
      appearance={data.clientView}
      quickActions={data.clientAiConfig}
    />
  );
}
```

> **Cache isolation:** Each unique `apiBaseUrl` gets its own cache entry, so switching tenants or servers triggers a fresh fetch rather than serving the previous tenant's settings.
