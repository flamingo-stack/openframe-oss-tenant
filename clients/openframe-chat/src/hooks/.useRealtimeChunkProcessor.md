Feeds raw NATS chunks into the core library's shared stream reducer and forwards the reducer's observations to the callbacks `useChat` already implements. Replaces the hook of the same name that the library used to ship.

## Why it lives here now

The library's `useRealtimeChunkProcessor` carried its own ~490-line chunk parser and segment accumulator. The chat unification deleted it: `createChatStreamReducer` is now the single owner of every accumulation rule — segment routing, EXECUTING→EXECUTED merging, approval flips, participant dedup, the direct-mode barrier, stream phase — fed by the one wire decoder, `decodeNatsChunk`. This desktop client was the last consumer of the removed hook.

What remains here is **only** a callback shim. Nothing in the file accumulates anything.

## Key Components

| Export | Purpose |
|---|---|
| `useRealtimeChunkProcessor(options)` | Returns `{ processChunk, reset }` |
| `RealtimeChunkCallbacks` | The host's callback bundle; names match reducer effect names one-for-one |
| `UseRealtimeChunkProcessorOptions` | `callbacks`, `displayApprovalTypes?`, `approvalStatuses?`, `initialState?`, `batchApprovalsEnabled?`, `isDirectMode?` |

## Hot path

```
chunk → decodeNatsChunk → reducer.apply(event) → onEffect → callbacks
```

The reducer publishes each observation as a `ChatReducerEffect` — a sink the library added precisely for callback-contract consumers. Because the effect names (`onStreamStart`, `onSegmentsUpdate`, `onApprovalResolved`, `onToolExecuted`, `onAgentBusy`, …) match the host's callbacks exactly, the shim is a forward rather than a translation: a new effect only needs adding to `RealtimeChunkCallbacks` to reach the host.

## Key Behaviors

- **Late-bound callbacks** — reducer creation options are consulted once, so both the effect sink and the approve/reject stamps read through a ref. Otherwise the first render's callbacks would be frozen for the reducer's whole life.
- **Resumed dialog** — `initialState` seeds the per-turn kernel one-shot, with `resumed: true`, so a chunk arriving with no preceding `turn-start` appends to the restored bubble instead of replacing it through the cold-start path.
- **Approval statuses** — merged as a command when they arrive (history can resolve after the reducer exists). The merge is state-monotonic in the reducer: a resolved status is never downgraded back to `pending`.
- **`reset()`** — drops the per-turn kernel and re-arms seeding (dialog switch, Stop).

## Deliberately not built on `useChatStreamReducer`

That hook and `createChatDialogStore` exist to **own** the thread and hand it back as state. This client keeps its thread in `useChatMessages` (React state, merged with React Query history in `useChat`), so it needs the reducer as a pure event machine and takes its output through effects. A dialog store would add an LRU registry and a second copy of the thread with no consumer.
