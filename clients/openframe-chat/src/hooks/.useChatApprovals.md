Manages chat approval workflows for AI-driven command authorization in the OpenFrame tenant interface, handling approval/rejection lifecycle, optimistic UI updates, escalated technician approvals, and historical message status synchronization.

## Key Components

### State
| State | Type | Description |
|---|---|---|
| `approvalStatuses` | `Record<string, 'pending' \| 'approved' \| 'rejected'>` | Tracks per-request approval state |
| `resolvedByNames` | `Record<string, string>` | Resolver display names for historical approval card overlays |
| `pendingApprovalRequests` | `Record<string, ApprovalData>` | Escalated requests awaiting technician action |
| `awaitingTechnicianResponse` | `boolean` | Indicates an escalated approval is in-flight |

### Returned Functions

| Function | Description |
|---|---|
| `handleApproveRequest(requestId)` | Optimistically flips status to `approved`, then POSTs to `/chat/api/v1/approval-requests/:id/approve` |
| `handleRejectRequest(requestId)` | Same pattern as approve but sends `{ approve: false }` |
| `updateApprovalStatusInMessages(messages, requestId, status)` | Mutates `approval_request` segments within a message array for live bubbles |
| `handleEscalatedApproval(requestId, data)` | Registers an escalated request and sets technician-awaiting flag |
| `handleEscalatedApprovalResult(requestId, approved, data)` | Resolves an escalated approval, produces an `approval_request` `MessageSegment` |
| `applyResolvedStatus(requestId, status, resolvedByName?)` | Syncs APPROVAL_RESULT-driven status into historical dialog bubbles |
| `clearApprovals()` | Resets all approval state |

## Usage Example

```typescript
const {
  approvalStatuses,
  handleApproveRequest,
  handleRejectRequest,
  updateApprovalStatusInMessages,
  applyResolvedStatus,
  clearApprovals,
} = useChatApprovals();

// Approve a pending request (optimistic update fires immediately)
await handleApproveRequest('req-abc-123');

// Overlay resolved status onto historical messages from a resumed dialog
applyResolvedStatus('req-abc-123', 'approved', 'Jane Smith');

// Patch approval segments in a live message list
const updated = updateApprovalStatusInMessages(messages, 'req-abc-123', 'approved');
```

> **Optimistic update note:** Status is flipped to `approved`/`rejected` _before_ the API call completes. This prevents incoming `MESSAGE_START` stream events from overwriting the approval card while the backend streams its continuation response.
