Manages chat approval request state and actions for the Mingo AI technician chat interface, handling approval/rejection flows for commands that require explicit authorization before execution.

## Key Components

### State
| State | Type | Description |
|-------|------|-------------|
| `approvalStatuses` | `Record<string, 'pending' \| 'approved' \| 'rejected'>` | Tracks status per `requestId` |
| `pendingApprovalRequests` | `Record<string, ApprovalData>` | Stores escalated approvals awaiting technician response |
| `awaitingTechnicianResponse` | `boolean` | Flags when a human escalation is in progress |

### Exported Functions
| Function | Description |
|----------|-------------|
| `handleApproveRequest(requestId)` | Optimistically flips status to `approved`, then POSTs to approval endpoint |
| `handleRejectRequest(requestId)` | Optimistically flips status to `rejected`, then POSTs to approval endpoint |
| `updateApprovalStatusInMessages(messages, requestId, status)` | Mutates assistant message segments to reflect resolved status |
| `handleEscalatedApproval(requestId, data)` | Registers an escalated (technician-required) approval request |
| `handleEscalatedApprovalResult(requestId, approved, data)` | Resolves an escalated approval and returns a typed `MessageSegment` |
| `applyResolvedStatus(requestId, status)` | Syncs approval status for historical/resumed dialog bubbles |
| `clearApprovals()` | Resets all approval state |

## Usage Example

```typescript
const {
  approvalStatuses,
  awaitingTechnicianResponse,
  handleApproveRequest,
  handleRejectRequest,
  updateApprovalStatusInMessages,
  applyResolvedStatus,
  clearApprovals,
} = useChatApprovals();

// Approve a pending command request
await handleApproveRequest('req_abc123');

// Sync status for a resumed dialog approval segment
applyResolvedStatus('req_abc123', 'approved');

// Update approval segments inside existing message history
const updated = updateApprovalStatusInMessages(messages, 'req_abc123', 'approved');

// Reset on dialog close
clearApprovals();
```

> **Note:** Approval status is flipped **optimistically** before the API call completes. This prevents incoming `MESSAGE_START` stream events from overwriting the approval card UI while the backend streams the continuation response.
