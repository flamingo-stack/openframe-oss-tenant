Manages chat approval request state and actions for Mingo AI's command approval workflow, handling optimistic UI updates, approval/rejection API calls, and status synchronization across live and historical message bubbles.

## Key Components

**State**
- `approvalStatuses` — map of `requestId → 'pending' | 'approved' | 'rejected'`
- `pendingApprovalRequests` — map of escalated requests awaiting technician action
- `awaitingTechnicianResponse` — boolean flag for escalated approval UX

**Handlers**
- `handleApproveRequest(requestId)` — optimistically marks approved, then POSTs to `/chat/api/v1/approval-requests/:id/approve` with `{ approve: true }`
- `handleRejectRequest(requestId)` — same flow with `{ approve: false }`
- `updateApprovalStatusInMessages(messages, requestId, status)` — immutably patches `approval_request` segments in a message array
- `handleEscalatedApproval(requestId, data)` — registers an escalated approval and sets awaiting flag
- `handleEscalatedApprovalResult(requestId, approved, data)` — resolves escalation, returns a fully-formed `MessageSegment`
- `applyResolvedStatus(requestId, status)` — syncs status into the map for historical/resumed-dialog bubbles (no-op if already set)
- `clearApprovals()` — resets all approval state

## Usage Example

```typescript
const {
  approvalStatuses,
  handleApproveRequest,
  handleRejectRequest,
  updateApprovalStatusInMessages,
  applyResolvedStatus,
} = useChatApprovals();

// Optimistic approve from a UI button
await handleApproveRequest('req_abc123');

// Sync a status received from a streamed APPROVAL_RESULT event
applyResolvedStatus('req_abc123', 'approved');

// Patch approval segments in a message list before rendering
const patched = updateApprovalStatusInMessages(messages, 'req_abc123', 'approved');
```

> **Note:** Approval status is flipped optimistically *before* the API call completes. This prevents incoming `MESSAGE_START` stream events from overwriting the approval card while the response is in-flight.
