Manages the lifecycle of AI command approval requests within the Flamingo chat interface, tracking approval/rejection states and handling both direct and escalated (technician-reviewed) approval flows.

## Key Components

**State**
- `approvalStatuses` — Map of `requestId → 'pending' | 'approved' | 'rejected'`
- `pendingApprovalRequests` — Map of unresolved escalated approvals awaiting technician response
- `awaitingTechnicianResponse` — Boolean flag indicating an escalated approval is in-flight

**Functions**

| Function | Description |
|---|---|
| `handleApproveRequest` | Optimistically marks a request as `approved`, then POSTs to `/chat/api/v1/approval-requests/:id/approve` |
| `handleRejectRequest` | Same as above but sends `{ approve: false }` |
| `updateApprovalStatusInMessages` | Patches `approval_request` segments within a message array with the latest status |
| `handleEscalatedApproval` | Registers an approval that requires technician review |
| `handleEscalatedApprovalResult` | Resolves an escalated approval, builds a completed `MessageSegment`, and clears it from pending |
| `applyResolvedStatus` | Applies a server-driven status flip to historical (resumed-dialog) approval bubbles |
| `clearApprovals` | Resets all approval state |

## Usage Example

```typescript
const {
  approvalStatuses,
  awaitingTechnicianResponse,
  handleApproveRequest,
  handleRejectRequest,
  updateApprovalStatusInMessages,
  applyResolvedStatus,
} = useChatApprovals();

// Approve a pending command
await handleApproveRequest('req-abc123');

// Sync status into a historical message list
const updated = updateApprovalStatusInMessages(messages, 'req-abc123', 'approved');

// Apply a server-resolved status to historical bubbles
applyResolvedStatus('req-abc123', 'approved');
```

> **Note:** Approval status is flipped optimistically **before** the fetch completes. This prevents incoming `MESSAGE_START` stream events from overwriting the approval card UI while the backend begins streaming the continuation response.
