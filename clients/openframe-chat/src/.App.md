Root application component that bootstraps the OpenFrame tenant app, wiring together React Query, feature flags, NATS notifications, connection status monitoring, and the Tauri native window focus workaround.

## Key Components

| Export / Symbol | Description |
|---|---|
| `App` (default export) | Root component; composes all providers and renders `ChatView` |
| `NatsNotificationsFlag` | Internal component that enables NATS notifications once feature flags are loaded |
| `queryClient` | Singleton `QueryClient` configured with 60s stale time, no window-focus refetch, and 1 retry |
| Tauri focus manager patch | Replaces react-query's `visibilitychange` listener with Tauri's `onFocusChanged` to fix WebView2 (Windows) focus events |

## Provider Tree

```text
QueryClientProvider
  └─ FeatureFlagsProvider
       ├─ NatsNotificationsFlag   (side-effect only, renders null)
       └─ FeatureFlagsGate
            └─ DebugModeProvider
                 └─ ChatView
Toaster                           (outside query scope)
```

## Usage Example

```typescript
// main.tsx — standard Vite/Tauri entry point
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
```

## Notes

- **`data-app-type` attribute** — set on `<html>` at mount from `NEXT_PUBLIC_APP_TYPE` (defaults to `"flamingo"`); used for CSS theme scoping.
- **Tauri-only patch** — the `focusManager.setEventListener` block only runs when `isTauri` is `true`; it is a no-op in browser builds.
- **`NatsNotificationsFlag`** must be rendered inside `FeatureFlagsProvider` because it reads `flags.notifications` before activating the Rust-backed notification service.
