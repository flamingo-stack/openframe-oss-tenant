The main chat interface view component for the Fae client-facing assistant, orchestrating message rendering, ticket management, AI dialog state, and real-time connection handling via NATS and GraphQL.

## Key Components

| Export / Hook | Purpose |
|---|---|
| `ChatView` | Root view component rendering the full chat UI |
| `toTokenUsageData` | Converts `DialogTokenUsage` → `TokenUsageData` for display |
| `isTerminalTicket` | Predicate that detects resolved/archived ticket states |
| `STATUS_POLL_INTERVAL_MS` | 15-second polling interval for active ticket status |

### Internal State

- **`currentModel`** — Active AI model name, provider, and context window
- **`activeTicketId` / `previewTicketId`** — Tracks which ticket is open or being previewed
- **`faeFormTicket`** — Stores metadata for tickets created via the Fae form flow
- **`isDialogClosed`** — Flags when the AI dialog has been terminated
- **`quickActionPreview`** — Ghost-text preview of a hovered quick-action chip label
- **`tokenUsage`** — Live token consumption data displayed in the chat header

### Key Hooks Used

- `useChat` — Core message stream, send, stop, history pagination, quick actions
- `useTickets` — Ticket list, detail fetching, and dialog ID resolution
- `useConnectionStatus` — Online/disconnected guard for message sends
- `useAssistantBranding` / `useApplyAiAppearance` — Fae visual identity
- `useMspOrganization` — MSP company name, logo, and website for header branding

## Usage Example

```typescript
// Rendered as the top-level route in the Fae client shell
import { ChatView } from './views/ChatView';

export function App() {
  return <ChatView />;
}
```

### Message Pre-processing

Pending approval segments are filtered from the message list (they render in the sticky footer instead) and duplicate `approval_request`/`approval_batch` segments are deduplicated by `requestId` before rendering:

```typescript
// Internally applied via useMemo before passing messages to ChatContainer
const processedMessages = useMemo(() => {
  const seenApprovalIds = new Set<string>();
  // ... filters pending approvals and dedupes by requestId
  return filteredMessages;
}, [messages]);
```

### Ticket Polling

Active ticket status is polled every 15 seconds and stops automatically once the ticket reaches a terminal state (`RESOLVED` or `ARCHIVED`):

```typescript
const { data: activeTicket } = useQuery({
  queryKey: ['active-ticket-state', activeTicketId],
  refetchInterval: query =>
    query.state.data && isTerminalTicket(query.state.data)
      ? false
      : STATUS_POLL_INTERVAL_MS,
});
```
