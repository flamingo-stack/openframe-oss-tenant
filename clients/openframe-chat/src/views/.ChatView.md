Renders the main chat interface for Fae (the client-facing AI assistant), orchestrating message display, ticket management, dialog resumption, and real-time connection state.

## Key Components

| Export / Symbol | Description |
|---|---|
| `ChatView` | Primary exported component — composes the full chat UI including header, message list, input, and modals |
| `toTokenUsageData` | Utility that maps internal `DialogTokenUsage` to the shared `TokenUsageData` shape |
| `processedMessages` | Memoized pipeline that strips pending approvals and deduplicates `approval_request` / `approval_batch` segments |
| `displayMessages` | Injects a synthetic "Fae Form" confirmation bubble when a ticket was created via FAE_FORM without a dialog |
| `handleTicketClick` | Loads ticket details, sets active-ticket header state, and either resumes an existing dialog or enters preview-polling mode |
| `useChat` | Core hook wiring NATS streaming, history pagination, quick actions, and metadata/token callbacks |
| `useConnectionStatus` | Provides live connection `status`, `serverUrl`, and AI config for header display |
| `useTickets` | Supplies ticket list, detail fetching, and dialog-ID lookup |
| `useWelcomeScreen` | Gates rendering behind a one-time welcome flow |

## Usage Example

```typescript
// Mount inside the Fae widget shell — no props required;
// all state is managed internally via hooks and services.
import { ChatView } from './views/ChatView';

export function FaeWidget() {
  return (
    <QueryClientProvider client={queryClient}>
      <ChatView />
    </QueryClientProvider>
  );
}
```

## Behavior Notes

- **Welcome gate** — renders `<WelcomeScreen>` until `completeWelcome()` is called; skipped on subsequent loads.
- **Preview polling** — when a ticket has no dialog yet, a 5-second interval polls `ticketGraphQlService.getTicket` until a `dialog.id` appears, then calls `resumeDialog`.
- **Token usage** — hydrated from `dialogGraphQlService.getDialogTokenUsage` on dialog load; updated in real-time via the `onTokenUsage` callback.
- **Disconnected state** — `isDisconnected` disables input and reflects `status !== 'connected'` from `useConnectionStatus`.
