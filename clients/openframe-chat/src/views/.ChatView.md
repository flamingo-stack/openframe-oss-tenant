Renders the main chat interface for the Fae client-facing AI assistant, managing conversation state, ticket integration, model display, and connection status within the Flamingo/OpenFrame platform.

## Key Components

| Export / Symbol | Description |
|---|---|
| `ChatView` | Primary view component orchestrating the full chat UI |
| `toTokenUsageData` | Utility to normalize `DialogTokenUsage` into `TokenUsageData` |
| `processedMessages` | Memoized pipeline filtering/deduplicating approval segments |
| `handleTicketClick` | Loads ticket details and resumes or previews an associated dialog |
| `handleNewChat` | Resets all chat state and invalidates the tickets query cache |
| `displayMessages` | Merges synthetic FAE-form messages with processed chat history |

## Usage Example

```typescript
// Rendered at the top-level route for the Fae client portal
import { ChatView } from './views/ChatView';

export default function App() {
  return <ChatView />;
}
```

## Key Behaviors

- **Welcome gate** — shows `WelcomeScreen` on first launch; proceeds to chat after `completeWelcome()`
- **Ticket integration** — supports creating tickets via `NewTicketModal`, clicking existing tickets to resume dialogs, and polling for dialog assignment on FAE-form tickets
- **Approval deduplication** — pending `approval_request` segments are hidden from the bubble list (rendered in the sticky footer instead); duplicate approval segments sharing a `requestId` are collapsed to the first occurrence
- **Token usage** — fetched from `dialogGraphQlService` on dialog load and updated live via `useChat` callbacks
- **Model display** — reflects the active AI model/provider reported by the streaming metadata or the server `aiConfiguration`
- **FAE-form synthetic message** — when a ticket was submitted via form (no dialog yet), a placeholder assistant bubble is injected until the real dialog is available
