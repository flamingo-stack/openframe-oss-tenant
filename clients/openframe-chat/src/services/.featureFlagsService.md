Singleton service that fetches feature flag configurations from a GraphQL API, using Bearer token authentication managed by `tokenService`.

## Key Components

- **`FeatureFlagResponse`** — Interface representing a single flag with `name: string` and `enabled: boolean`
- **`FeatureFlagsService`** (class) — Lazily initializes a `GraphQLClient` and exposes methods to query feature flags
  - `initializeClient()` — Creates or reuses a `GraphQLClient` pointed at `{baseUrl}/chat/graphql`, injecting the current Bearer token on every call
  - `request<T>()` — Generic wrapper that initializes the client and executes a GraphQL document
  - `fetchFeatureFlags(names?)` — Public method that waits for the token to be ready, then queries `feFeatureFlags`; returns `null` on error
- **`featureFlagsService`** — Exported singleton instance

## Usage Example

```typescript
import { featureFlagsService } from './featureFlagsService';

// Fetch all feature flags
const allFlags = await featureFlagsService.fetchFeatureFlags();

// Fetch specific flags by name
const flags = await featureFlagsService.fetchFeatureFlags([
  'new-dashboard',
  'beta-reporting',
]);

if (flags) {
  const isDashboardEnabled = flags.find(f => f.name === 'new-dashboard')?.enabled;
  console.log('New dashboard enabled:', isDashboardEnabled);
}
```

> **Note:** `fetchFeatureFlags` returns `null` on any error (network, auth, etc.) rather than throwing, so always guard against a `null` response before iterating results.
