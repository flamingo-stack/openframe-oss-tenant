Manages feature flag retrieval for the Flamingo platform by querying a GraphQL endpoint with Bearer token authentication.

## Key Components

- **`FeatureFlagResponse`** — Interface representing a single feature flag with `name` and `enabled` fields.
- **`FeatureFlagsService`** — Singleton class that handles GraphQL client initialization and feature flag fetching.
  - `initializeClient()` — Lazily initializes the `GraphQLClient`, attaching the current Bearer token to request headers. Reuses the existing client if already initialized.
  - `request<T>()` — Generic private wrapper for executing GraphQL queries through the initialized client.
  - `fetchFeatureFlags(names?)` — Public method that fetches one or more feature flags by name. Returns `null` on error.
- **`featureFlagsService`** — Pre-exported singleton instance for use across the application.

## Usage Example

```typescript
import { featureFlagsService } from './featureFlagsService';

// Fetch specific feature flags by name
const flags = await featureFlagsService.fetchFeatureFlags(['new-dashboard', 'ai-chat']);

if (flags) {
  const isDashboardEnabled = flags.find(f => f.name === 'new-dashboard')?.enabled;
  console.log('New dashboard enabled:', isDashboardEnabled);
}

// Fetch all feature flags (no filter)
const allFlags = await featureFlagsService.fetchFeatureFlags();
```

> **Note:** The service depends on `tokenService` to resolve both the API base URL (`/chat/graphql`) and the current Bearer token. Ensure the token is available before calling `fetchFeatureFlags`, as the method internally calls `tokenService.ensureTokenReady()` before making the request.
