Singleton service for fetching feature flags from the Flamingo GraphQL API using authenticated requests.

## Key Components

- **`FeatureFlagResponse`** — Interface describing a feature flag with `name` (string) and `enabled` (boolean) fields
- **`FeatureFlagsService`** — Private class managing a lazy-initialized `GraphQLClient` with Bearer token auth
  - `initializeClient()` — Lazily creates or reuses the GraphQL client, pulling the API base URL and token from `tokenService`
  - `request<T>()` — Generic wrapper for executing GraphQL documents against the initialized client
  - `fetchFeatureFlags(names?)` — Public method to query one or more feature flags by name; returns `null` on error
- **`featureFlagsService`** — Exported singleton instance

## Usage Example

```typescript
import { featureFlagsService } from './featureFlagsService';

// Fetch all feature flags
const allFlags = await featureFlagsService.fetchFeatureFlags();

// Fetch specific flags by name
const flags = await featureFlagsService.fetchFeatureFlags(['new-dashboard', 'ai-copilot']);

if (flags) {
  const isCopilotEnabled = flags.find(f => f.name === 'ai-copilot')?.enabled ?? false;
}
```

## Notes

- The client is lazily initialized on first use; subsequent calls reuse the existing instance while refreshing the `Authorization` header with the latest token
- Returns `null` (instead of throwing) when the GraphQL request fails, so callers should handle both `null` and an empty array `[]`
- Depends on `tokenService` for both the API base URL (`/chat/graphql`) and the current Bearer token
