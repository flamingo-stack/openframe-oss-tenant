Manages authentication token and API base URL state for a Tauri desktop application, bridging Rust backend credentials to the frontend via Tauri commands and events.

## Key Components

**`TokenService` (class)**
- `requestToken()` — Fetches token from Rust via `get_token` invoke; returns cached value on failure
- `refreshToken()` — Force-fetches token bypassing cache; intended for use before NATS reconnections
- `getCurrentToken()` — Returns the currently cached token
- `onTokenUpdate(callback)` — Subscribes to token changes; fires immediately if token exists; returns unsubscribe function
- `initApiUrl()` — Fetches server URL from Rust via `get_server_url` and normalizes it
- `getCurrentApiBaseUrl()` — Returns the currently cached API base URL
- `onApiUrlUpdate(callback)` — Subscribes to API URL changes; returns unsubscribe function
- `ensureTokenReady()` — Throws if neither token nor API URL can be resolved; use as a pre-flight guard

**`tokenService`** — Exported singleton instance

## Usage Example

```typescript
import { tokenService } from './tokenService';

// Guard before making authenticated requests
await tokenService.ensureTokenReady();

// One-time read
const token = tokenService.getCurrentToken();
const apiUrl = tokenService.getCurrentApiBaseUrl();

// React to live token updates (e.g. token rotation)
const unsubscribe = tokenService.onTokenUpdate((token) => {
  myApiClient.setAuthHeader(`Bearer ${token}`);
});

// Later, clean up
unsubscribe();

// Force-refresh before a NATS reconnect
const freshToken = await tokenService.refreshToken();
```

> **Note:** `VITE_TOKEN` and `VITE_SERVER_URL` environment variables can seed the service at startup without a Tauri invoke round-trip, useful for local development.
