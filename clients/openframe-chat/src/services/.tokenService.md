Manages authentication token and API base URL state for a Tauri desktop application, bridging Rust backend values to the frontend via Tauri commands and events.

## Key Components

**`TokenService` (class)**
- `requestToken()` — Fetches token via Tauri `get_token` command; returns cached value on failure
- `refreshToken()` — Bypasses cache to force-fetch a fresh token from Rust (used before NATS reconnection)
- `getCurrentToken()` — Returns the currently cached token
- `onTokenUpdate(callback)` — Subscribes to token changes; fires immediately if token already exists; returns unsubscribe function
- `getCurrentApiBaseUrl()` — Returns the currently cached API base URL
- `onApiUrlUpdate(callback)` — Subscribes to API URL changes; returns unsubscribe function
- `ensureTokenReady()` — Throws if either token or API URL cannot be resolved; use before making authenticated requests
- `initTokenListener()` — Listens for `token-update` Tauri events emitted from Rust

**`tokenService`** — Singleton instance exported for app-wide use

## Usage Example

```typescript
import { tokenService } from './tokenService';

// Ensure both token and API URL are ready before connecting
await tokenService.ensureTokenReady();

// One-time reads
const token = tokenService.getCurrentToken();
const apiUrl = tokenService.getCurrentApiBaseUrl();

// Subscribe to token changes (e.g., on refresh/rotation)
const unsubscribe = tokenService.onTokenUpdate((newToken) => {
  console.log('Token updated, reconnecting...');
  reconnectNats(newToken);
});

// Later: clean up subscription
unsubscribe();
```

> **Environment fallback:** During development, set `VITE_TOKEN` and `VITE_SERVER_URL` in your `.env` file to seed the service without a running Rust backend.
