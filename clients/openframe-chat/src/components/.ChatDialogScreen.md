Thin wrapper component that renders the Fae client-facing chat message list by forwarding conversation state to `ChatMessageList` from the OpenFrame frontend core library, with Fae-specific assistant identity and client-safe approval card rendering locked in.

## Key Components

### `ChatDialogScreen`

A presentational component that configures `ChatMessageList` for the end-client (Fae) chat context:

- **`assistantType="fae"`** — Renders the assistant identity as Fae rather than the technician-facing Mingo AI persona.
- **`approvalVariant="client"`** — Displays title-only approval cards with Approve/Reject actions or status pills; suppresses command/script details that should never be visible to end clients.
- **`autoScroll={true}`** — Hardcoded to keep the view pinned to the latest message.

### `ChatDialogScreenProps`

| Prop | Type | Description |
|---|---|---|
| `messages` | `Message[]` | Ordered list of chat messages to render |
| `dialogId` | `string?` | Identifier for the active conversation |
| `isTyping` | `boolean` | Shows the assistant typing indicator |
| `isLoadingHistory` | `boolean` | Shows a loading state while fetching history |
| `hasNextPage` | `boolean` | Whether older messages can be paginated |
| `isFetchingNextPage` | `boolean` | Loading state for pagination requests |
| `onLoadMore` | `() => void` | Callback triggered to load the previous page |

## Usage Example

```typescript
<ChatDialogScreen
  messages={messages}
  dialogId={activeDialogId}
  isTyping={isAssistantTyping}
  isLoadingHistory={isLoadingHistory}
  hasNextPage={hasNextPage}
  isFetchingNextPage={isFetchingNextPage}
  onLoadMore={fetchNextPage}
/>
```

> **Note:** `assistantType` and `approvalVariant` are intentionally not exposed as props — they are hardcoded to enforce the client-safe Fae experience and prevent accidental exposure of technician-level content.
