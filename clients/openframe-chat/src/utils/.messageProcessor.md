Transforms raw GraphQL dialog messages into chat-ready `Message` objects for the Fae client-facing assistant UI.

## Key Components

**`processHistoricalMessages(messages, onApprove?, onReject?)`**
Main export that orchestrates the conversion pipeline. Accepts raw `GraphQlMessage[]` from the dialog service and optional approval/rejection callbacks for interactive messages, returning a normalized `Message[]` array ready for chat display.

**Internal pipeline steps:**
1. Maps `GraphQlMessage[]` → `HistoricalMessage[]` (core-compatible shape)
2. Delegates to `processHistoricalMessagesWithErrors` with Fae-specific config (`assistantName`, `assistantAvatar`, `chatTypeFilter: CLIENT`)
3. Re-maps output to final `Message[]`, attaching `faeAvatar` to all `assistant` and `error` role messages

## Usage Example

```typescript
import { processHistoricalMessages } from './messageProcessor';
import { fetchDialogMessages } from '../services/dialogGraphQLService';

const rawMessages = await fetchDialogMessages(dialogId);

const chatMessages = processHistoricalMessages(
  rawMessages,
  async (requestId) => {
    await approveRequest(requestId);
  },
  async (requestId) => {
    await rejectRequest(requestId);
  },
);

// chatMessages is ready for the chat component
renderChat(chatMessages);
```

## Notes

- Avatar is statically bound to the Fae assistant image asset (`fae-avatar.png`) for both `assistant` and `error` roles; human/user roles receive `undefined`
- Filtering is hardcoded to `CHAT_TYPE.CLIENT`, so only client-facing messages pass through
- Error handling is delegated entirely to `processHistoricalMessagesWithErrors` from `@flamingo-stack/openframe-frontend-core`
