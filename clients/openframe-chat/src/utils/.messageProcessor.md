Transforms raw GraphQL dialog messages into a normalized chat display format consumable by the Fae client-facing chat UI.

## Key Components

### `processHistoricalMessages(messages, onApprove?, onReject?)`

Maps `GraphQlMessage[]` → `Message[]` through a two-stage pipeline:

1. **Normalize** — Strips GraphQL-specific fields into `HistoricalMessage` shape
2. **Process** — Delegates to `processHistoricalMessagesWithErrors` with Fae-specific config (name, type, avatar, `CLIENT` chat type filter)
3. **Enrich** — Attaches `faeAvatar` to `assistant` and `error` role messages

| Parameter | Type | Description |
|-----------|------|-------------|
| `messages` | `GraphQlMessage[]` | Raw messages from the dialog GraphQL service |
| `onApprove` | `(requestId?) => Promise<void>` | Optional approval callback for actionable messages |
| `onReject` | `(requestId?) => Promise<void>` | Optional rejection callback for actionable messages |

## Usage Example

```typescript
import { processHistoricalMessages } from './messageProcessor';

const rawMessages = await dialogGraphQLService.getMessages(dialogId);

const chatMessages = processHistoricalMessages(
  rawMessages,
  async (requestId) => { await approveRequest(requestId); },
  async (requestId) => { await rejectRequest(requestId); },
);

// chatMessages is ready for rendering in the chat UI
// assistant/error roles will have faeAvatar attached
```

> **Note:** The `chatTypeFilter` is hardcoded to `CHAT_TYPE.CLIENT`, meaning only client-facing messages are included in the output. Server-side or internal message types are filtered out automatically.
