Vite configuration file for the OpenFrame OSS Tenant app, defining build settings, dev server options, plugin setup, and environment variable handling for a React + Tauri application.

## Key Components

| Setting | Description |
|---|---|
| `plugins` | Enables React with HMR via `@vitejs/plugin-react` |
| `resolve.alias` | Shims `next/image` to a local compatibility layer at `src/shims/next-image.tsx` |
| `define` | Injects `NODE_ENV` and `NEXT_PUBLIC_APP_TYPE` (defaults to `"flamingo"`) into the client bundle |
| `build` | Outputs to `dist/assets`, no sourcemaps, clears output dir on each build |
| `server` | Dev server on `127.0.0.1:3003` with `strictPort` enforced |
| `envPrefix` | Exposes `VITE_`, `TAURI_`, and `NEXT_PUBLIC_` prefixed env vars to client code |

## Usage Example

```bash
# Start the dev server
npm run dev
# → Serves at http://127.0.0.1:3003

# Build for production
npm run build
# → Output written to dist/

# Override app type at build time
NEXT_PUBLIC_APP_TYPE=openframe npm run build
```

## Notes

- The `next/image` alias allows shared components originally written for Next.js to work in this Vite/Tauri context without modification.
- `strictPort: true` prevents silent port fallback — the server will error if `3003` is already in use, which is important in Tauri desktop app contexts where the port is hardcoded.
- `clearScreen: false` preserves Tauri CLI output in the terminal during development.
