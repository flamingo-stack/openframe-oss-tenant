Spring Boot application entry point for the OpenFrame client tenant service, bootstrapping the application context with a configured component scan across core platform packages.

## Key Components

- **`@SpringBootApplication`** — Enables auto-configuration, component scanning, and Spring Boot defaults
- **`@ComponentScan`** — Explicitly scans the following base packages:
  - `com.openframe.data` — Data layer (Cassandra, repositories)
  - `com.openframe.client` — Client-specific beans and services
  - `com.openframe.core` — Core platform utilities
  - `com.openframe.security` — Security configuration
  - `com.openframe.kafka.producer` — Kafka message producers
- **`excludeFilters`** — Excludes `CassandraHealthIndicator` from auto-registration, allowing custom health check wiring
- **`main()`** — Standard Spring Boot launcher via `SpringApplication.run()`

## Usage Example

Run the application locally via Maven or the built JAR:

```bash
# Run via Maven
./mvnw spring-boot:run

# Or run the packaged JAR
java -jar target/client-application.jar
```

To pass Spring profiles or override properties at startup:

```bash
java -jar target/client-application.jar \
  --spring.profiles.active=dev \
  --server.port=8081
```

## Notes

- The explicit `basePackages` list is required because the application entry point lives in `com.openframe.client`, which would not automatically scan sibling packages like `com.openframe.data` or `com.openframe.security` without this configuration.
- `CassandraHealthIndicator` is excluded to prevent duplicate or premature health check bean registration — a custom indicator is expected to be registered elsewhere in the data layer.
