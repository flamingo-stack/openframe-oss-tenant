Defines the Relay GraphQL query and paginated fragment for fetching unread notifications in the notifications drawer component.

## Key Components

- **`notificationsDrawerRelayQuery`** — Root GraphQL query that spreads the drawer fragment with `$first` (Int, required) and `$after` (String, optional) pagination arguments
- **`notificationsDrawerRelayFragment`** — Refetchable fragment on `Query` with built-in cursor-based pagination support (`@refetchable`), defaulting to 30 notifications per page. Fetches only unread notifications (`filter: { read: false }`) via a `@connection`-tracked list

### Notification Fields Returned

| Field | Description |
|---|---|
| `id` | Unique identifier |
| `severity` | Alert level |
| `title` / `description` | Display content |
| `createdAt` | Timestamp |
| `read` | Read status |
| `context.__typename` / `context.type` | Contextual metadata |

## Usage Example

```typescript
import { usePreloadedQuery, useRefetchableFragment } from 'react-relay';
import {
  notificationsDrawerRelayQuery,
  notificationsDrawerRelayFragment,
} from './notifications-drawer-relay';

// Load query at route level
const queryRef = loadQuery(environment, notificationsDrawerRelayQuery, {
  first: 30,
});

// Inside component — supports pagination refetch
const [data, refetch] = useRefetchableFragment(
  notificationsDrawerRelayFragment,
  queryRef
);

// Load next page
refetch({ first: 30, after: data.notifications.pageInfo.endCursor });
```

> **Connection key:** `NotificationsList_notifications` — used by Relay's store to track pagination state. Filters `filter` and `search` are included as connection filter keys.
