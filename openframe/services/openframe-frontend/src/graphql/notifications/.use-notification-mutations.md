Provides a unified React hook encapsulating the three notification GraphQL mutations (mark read, mark all read, delete) with optimistic UI updates and toast error feedback.

## Key Components

### `useNotificationMutations(options)`

Main exported hook accepting a `UseNotificationMutationsOptions` object.

| Option | Type | Description |
|--------|------|-------------|
| `filterPairs` | `NotificationConnectionPair[]` | Relay connection pairs used to scope store updaters |
| `onError` | `(operation: NotificationMutation, err: Error) => void` | Optional per-operation error callback |
| `onMarkAllReadCompleted` | `() => void` | Optional callback fired after mark-all-read succeeds |

### Returned Values

| Value | Type | Description |
|-------|------|-------------|
| `markRead` | `(id: string) => void` | Marks a single notification as read |
| `markAllRead` | `() => void` | Marks all notifications as read |
| `removeNotification` | `(id: string) => void` | Deletes a notification |
| `isMarkingAllRead` | `boolean` | Relay in-flight state for the mark-all-read mutation |

### `NotificationMutation` (type)

Union string literal `'markRead' | 'markAllRead' | 'delete'` used to identify which operation triggered an error.

## Usage Example

```typescript
import { useNotificationMutations } from './use-notification-mutations';

function NotificationPanel({ connectionPairs }) {
  const { markRead, markAllRead, removeNotification, isMarkingAllRead } =
    useNotificationMutations({
      filterPairs: connectionPairs,
      onMarkAllReadCompleted: () => console.log('All cleared'),
      onError: (operation, err) =>
        console.error(`Mutation "${operation}" failed:`, err),
    });

  return (
    <div>
      <button onClick={markAllRead} disabled={isMarkingAllRead}>
        Mark All Read
      </button>
      <button onClick={() => markRead('notif-123')}>Mark Read</button>
      <button onClick={() => removeNotification('notif-123')}>Delete</button>
    </div>
  );
}
```

All three mutations apply both an `optimisticUpdater` and a server `updater` built from `notifications-helpers`, ensuring the Relay store reflects changes immediately while awaiting server confirmation.
