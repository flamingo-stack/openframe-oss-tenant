Client-side React component that triggers GraphQL schema introspection once the user's authentication state is verified server-side, ensuring introspection only runs against an authenticated session.

## Key Components

- **`GraphQlIntrospectionInitializer`** — Headless React component (returns `null`) that manages the lifecycle of GraphQL introspection initialization
- **`useAuthSession`** — Hook providing `isAuthenticated` and `isReady` flags from a server-verified auth session
- **`initializeGraphQlIntrospection`** — Library function that performs the actual GraphQL schema introspection
- **`hasInitialized` ref** — Guards against duplicate introspection calls across re-renders; resets on logout to allow re-initialization on subsequent login

## Behavior

| Condition | Action |
|-----------|--------|
| `isReady && isAuthenticated && !hasInitialized` | Runs introspection once |
| `!isAuthenticated && hasInitialized` | Resets the guard (enables re-init on next login) |
| Introspection failure | Logs error, does not throw |

## Usage Example

Mount once at the application root, typically inside an authenticated layout:

```typescript
// app/(authenticated)/layout.tsx
import { GraphQlIntrospectionInitializer } from '@/components/graphql-introspection-initializer';

export default function AuthenticatedLayout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <GraphQlIntrospectionInitializer />
      {children}
    </>
  );
}
```

> The component intentionally avoids `localStorage` for auth checks — introspection is deferred until `useAuthSession` confirms a valid server-side session, preventing stale credential issues.
