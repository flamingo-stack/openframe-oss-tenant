A read-only customer table component with client-side search filtering, designed to display a pre-fetched list of assigned customers within a detail view or assignment context.

## Key Components

- **`CustomersAssignedTable`** — Main exported component that renders a searchable, filterable table of assigned customers
- **`useDebounce`** — Debounces the search input by 300ms to avoid excessive re-filtering on keystrokes
- **`useMemo` filter** — Filters customers by `name` or `contact.email` using the debounced search term
- **`CustomersSearchInput`** — Shared search input component from the customers table columns module
- **`CustomersTableBody`** — Shared table body renderer, configured with `skeletonRows={3}` and a contextual empty state message

## Props

| Prop | Type | Required | Description |
|------|------|----------|-------------|
| `customers` | `Customer[]` | ✅ | Pre-fetched list of assigned customers to display |
| `isLoading` | `boolean` | ❌ | Shows skeleton rows while data is loading |

## Usage Example

```typescript
import { CustomersAssignedTable } from './customers-assigned-table';
import { useCustomers } from '@/app/(app)/customers/hooks/use-customers';

export function TechnicianDetailPanel({ technicianId }: { technicianId: string }) {
  const { customers, isLoading } = useCustomers({ assignedTo: technicianId });

  return (
    <CustomersAssignedTable
      customers={customers}
      isLoading={isLoading}
    />
  );
}
```

> **Note:** This component performs filtering entirely on the client side. It expects the parent to own data fetching — pass all assigned customers up front via the `customers` prop.
