Utility module that normalizes raw entity IDs into Relay-compliant global IDs, providing a temporary shim until `ai-agent`'s `Ticket` type is updated to return proper Relay global IDs natively.

## Key Components

- **`RELAY_TYPE_NAME`** — Maps `AssignmentItemType | AssignmentTargetType` enum values to their Relay type name strings (e.g., `DEVICE → "Machine"`, `TICKET → "Ticket"`)
- **`KNOWN_RELAY_TYPES`** — Immutable set of valid Relay type name strings used for validation during decode
- **`btoaUtf8`** / **`atobUtf8`** — Cross-environment Base64 encode/decode helpers supporting both browser (`window.btoa/atob`) and Node.js (`Buffer`)
- **`decodeGlobalId(value)`** — Decodes a Base64 string and validates it matches the `TypeName:rawId` Relay format; returns `null` if invalid or unknown type
- **`toGlobalId(type, rawId)`** — Encodes a raw ID into the Relay global ID format: `base64("TypeName:rawId")`
- **`ensureGlobalId(type, value)`** *(exported)* — Idempotent normalization: returns `value` unchanged if already a valid Relay global ID, otherwise encodes it as one

## Usage Example

```typescript
import { ensureGlobalId } from './relay-id';

// Raw MongoDB ObjectId → encoded as Relay global ID
const globalId = ensureGlobalId('TICKET', '507f1f77bcf86cd799439011');
// → btoa("Ticket:507f1f77bcf86cd799439011")

// Already a Relay global ID → returned unchanged (idempotent)
const same = ensureGlobalId('TICKET', globalId);
// → globalId (no double-encoding)

// Use in assignment mutations
const input = {
  targetId: ensureGlobalId('ORGANIZATION', orgId),
  itemId: ensureGlobalId('DEVICE', deviceId),
};
```

> **Note:** This module is a temporary workaround. Once `ai-agent`'s `TicketDataFetcher` is updated to return proper Relay global IDs, all callers of `ensureGlobalId` for `TICKET` should be removed and this module retired.
