Provides a React context and provider that builds and manages NATS WebSocket connection configuration, wiring together authentication state, access tokens, and base URL resolution for real-time messaging.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `NatsAppConfig` | Interface | Shape of the context value: WS URL getter, reconnect handler, revision string, auth state, and user ID |
| `NatsAppConfigProvider` | Component | Context provider — wrap your app tree to make NATS config available |
| `useNatsAppConfig` | Hook | Consumes the context; throws if used outside the provider |

### Internal helpers

- **`getApiBaseUrl()`** — resolves the tenant host URL from runtime env or `window.location.origin`
- **`getAccessToken()`** — safely reads the access token from `localStorage` (SSR-safe)
- **`useNatsAppConfigState()`** — core hook that derives all config state; handles token sync via `StorageEvent` and auth changes

## Usage Example

```typescript
// 1. Mount the provider near the app root
import { NatsAppConfigProvider } from './nats-app-config';

export function AppLayout({ children }: { children: ReactNode }) {
  return (
    <NatsAppConfigProvider>
      {children}
    </NatsAppConfigProvider>
  );
}

// 2. Consume in any child component
import { useNatsAppConfig } from './nats-app-config';

function NatsConsumer() {
  const { getWsUrl, onBeforeReconnect, urlRevision, isAuthenticated } = useNatsAppConfig();

  // urlRevision changes whenever auth/token/URL state changes,
  // signalling the NATS client to reconnect
  useEffect(() => {
    const url = getWsUrl();
    if (!url) return;
    // pass url to your NATS WebSocket client...
  }, [urlRevision]);
}
```

## Notes

- `urlRevision` is a pipe-delimited string encoding all connection-relevant state; consumers should watch it to detect when a reconnect is needed
- `onBeforeReconnect` calls `apiClient.me()` to validate the session before reconnecting; a 401 triggers a forced logout via the API client's own interceptor
- Token sync is only active when `runtimeEnv.enableDevTicketObserver()` is `true` (dev/ticket-observer mode)
