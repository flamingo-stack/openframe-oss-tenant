Manages server-loaded feature flags with environment variable fallbacks, providing a typed interface for checking feature availability across the Flamingo/OpenFrame platform.

## Key Components

- **`FEATURE_FLAG_NAMES`** — Const array of all flag names recognized by the backend. Only flags listed here are returned by the `feFeatureFlags` GraphQL query.
- **`getFlagValue(flagName, envFallback)`** — Internal helper that reads from the Zustand `useFeatureFlagsStore`. Falls back to the provided default if the store hasn't loaded or the flag is absent.
- **`featureFlags`** — Main export. A typed const object grouping each feature flag under a camelCase namespace with an `enabled()` method.
- **`FeatureFlagKey`** — Utility type derived from `keyof typeof featureFlags` for type-safe flag references.

## Available Flags

| Flag Key | Backend Name |
|---|---|
| `subscription` | `billings` |
| `thinking` | `thinking` |
| `knowledgeBase` | `knowledge-base` |
| `notifications` | `notifications` |
| `ticketsBoard` | `tickets-board` |
| `batchApproval` | `batch-approval` |
| `aiStreamingJetstream` | `ai-streaming-jetstream` |
| `debugNatsChunks` | `debug-nats-chunks` |

## Usage Example

```typescript
import { featureFlags, FeatureFlagKey } from '@/utils/feature-flags';

// Check a single flag
if (featureFlags.knowledgeBase.enabled()) {
  // render knowledge base UI
}

// Type-safe flag key usage
function isEnabled(flag: FeatureFlagKey): boolean {
  return featureFlags[flag].enabled();
}
```

> **Note:** Flags default to `false` until the store is populated by the `feFeatureFlags` GraphQL query. Ensure the store is hydrated at app bootstrap before relying on flag values in critical render paths.
