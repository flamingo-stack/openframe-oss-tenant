A centralized feature flag system that controls the availability of features across the Flamingo/OpenFrame application based on runtime environment configuration.

## Key Components

- **`featureFlags`** - Main feature flags object containing all available features
- **`organizationImages`** - Feature flag for organization logo/image functionality with granular controls for upload and display
- **`ssoAutoAllow`** - Feature flag controlling SSO domain auto-allowance
- **`scriptSchedule`** - Feature flag for script scheduling capabilities  
- **`FeatureFlagKey`** - Type definition for all available feature flag keys

## Usage Example

```typescript
import { featureFlags, type FeatureFlagKey } from './feature-flags'

// Check if organization images are enabled
if (featureFlags.organizationImages.enabled()) {
  // Show organization image upload UI
  renderImageUpload()
}

// Check specific sub-features
if (featureFlags.organizationImages.uploadEnabled()) {
  enableUploadButton()
}

// Check SSO auto-allow feature
if (featureFlags.ssoAutoAllow.enabled()) {
  autoAllowDomainSSO()
}

// Dynamic feature checking
const checkFeature = (key: FeatureFlagKey) => {
  return featureFlags[key].enabled()
}

// Usage in components
const showScriptScheduling = featureFlags.scriptSchedule.enabled()
```

The feature flags are driven by the runtime environment configuration, allowing for easy feature toggling without code changes across different deployment environments.
