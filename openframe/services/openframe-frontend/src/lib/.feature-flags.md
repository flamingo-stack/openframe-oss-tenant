Centralized feature flag management module that reads server-loaded flags from the Zustand store (`feFeatureFlags` GraphQL query) with environment-variable fallbacks when the store hasn't hydrated.

## Key Components

- **`FEATURE_FLAG_NAMES`** — Readonly tuple of all server-known flag identifiers that must be explicitly requested via the `feFeatureFlags` GraphQL query
- **`getFlagValue`** — Internal helper that resolves a flag from the store when loaded, falling back to an env-var default otherwise
- **`featureFlags`** — Exported const object providing typed `.enabled()` accessors for each feature flag
- **`FeatureFlagKey`** — Utility type representing valid keys of the `featureFlags` object

## Available Flags

| Key | Server Name |
|-----|-------------|
| `subscription` | `billings` |
| `thinking` | `thinking` |
| `knowledgeBase` | `knowledge-base` |
| `notifications` | `notifications` |
| `ticketsBoard` | `tickets-board` |
| `batchApproval` | `batch-approval` |
| `aiStreamingJetstream` | `ai-streaming-jetstream` |
| `debugNatsChunks` | `debug-nats-chunks` |
| `mingoSidebar` | `mingo-sidebar` |
| `ticketStatuses` | `ticket-statuses` |

## Usage Example

```typescript
import { featureFlags, FeatureFlagKey } from '@/lib/feature-flags';

// Check a specific flag before rendering a feature
if (featureFlags.knowledgeBase.enabled()) {
  renderKnowledgeBasePanel();
}

// Use the type for dynamic flag lookups
function isEnabled(key: FeatureFlagKey): boolean {
  return featureFlags[key].enabled();
}

// In a React component
function TicketsBoardTab() {
  if (!featureFlags.ticketsBoard.enabled()) return null;
  return <BoardView />;
}
```

> **Note:** Flags default to `false` until the `feFeatureFlags` GraphQL query resolves and hydrates the store. Ensure the query runs early in the app lifecycle to avoid flash-of-disabled-feature issues.
