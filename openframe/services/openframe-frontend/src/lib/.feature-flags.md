Centralizes feature flag resolution for the Flamingo/OpenFrame platform, reading server-loaded flag values from the feature flags store with environment variable fallbacks.

## Key Components

- **`FEATURE_FLAG_NAMES`** — Typed const array of all known server-side flag identifiers; must be passed to the `feFeatureFlags` GraphQL query so the backend returns them
- **`getFlagValue(flagName, envFallback)`** — Internal resolver that checks the Zustand store first (if loaded), then falls back to the provided env-var default
- **`featureFlags`** — Main export; a typed const object with camelCase namespaced entries, each exposing an `enabled(): boolean` method
- **`FeatureFlagKey`** — Utility type derived from `keyof typeof featureFlags` for type-safe flag access

## Usage Example

```typescript
import { featureFlags, FeatureFlagKey } from '@/lib/feature-flags';

// Check a single flag
if (featureFlags.knowledgeBase.enabled()) {
  renderKnowledgeBasePanel();
}

// Type-safe dynamic lookup
function isFeatureEnabled(key: FeatureFlagKey): boolean {
  return featureFlags[key].enabled();
}

// Guard a route or component
const showTicketsBoard = featureFlags.ticketsBoard.enabled();
const showBatchApproval = featureFlags.batchApproval.enabled();
```

> All flags default to `false` when the store hasn't loaded or the flag is absent — ensuring safe opt-in behavior with no accidental feature exposure.
