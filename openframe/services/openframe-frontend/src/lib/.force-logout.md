Handles forced user logout by clearing authentication tokens from localStorage, resetting the auth store state, and optionally redirecting to a login page based on the current app mode.

## Key Components

### Interfaces
- **`ForceLogoutOptions`** — Configuration object for logout behavior, with optional `reason`, `shouldRedirect` flag, and `redirectPath`

### Functions
- **`forceLogout(options?)`** — Orchestrates full logout: clears tokens, resets auth store, and redirects unless already on an auth page or in SaaS tenant mode
- **`hasStoredTokens()`** — Returns `true` if any auth tokens exist in localStorage (SSR-safe)
- **`clearStoredTokens()`** — Removes both access and refresh tokens from localStorage without triggering a redirect

## Usage Example

```typescript
import { forceLogout, hasStoredTokens, clearStoredTokens } from '@/lib/force-logout';

// Force logout with redirect to default auth path
await forceLogout();

// Force logout with custom redirect, e.g. after session expiry
await forceLogout({
  reason: 'session_expired',
  shouldRedirect: true,
  redirectPath: '/auth/login',
});

// Logout without redirect (e.g. during background cleanup)
await forceLogout({ shouldRedirect: false });

// Check if tokens exist before making an authenticated request
if (!hasStoredTokens()) {
  console.warn('No active session found');
}

// Clear tokens without full logout flow (e.g. on account switch)
clearStoredTokens();
```

## Notes

- All functions are **SSR-safe** and exit early when `window` is undefined
- `forceLogout` dynamically imports the auth store to avoid circular dependencies
- In **SaaS tenant mode**, redirect is suppressed even if `shouldRedirect` is `true`
- Each operation is wrapped in `try/catch` to ensure partial failures don't block the full logout flow
