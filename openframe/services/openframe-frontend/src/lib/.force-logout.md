Utility module for programmatically logging out users by clearing authentication tokens, resetting auth store state, and optionally redirecting to the appropriate login page.

## Key Components

### `ForceLogoutOptions` Interface
Configuration options for the `forceLogout` function:
- `reason` — Optional string describing why the logout was triggered
- `shouldRedirect` — Whether to redirect after logout (defaults to `true`)
- `redirectPath` — Custom redirect path; falls back to `getDefaultRedirectPath`

### `forceLogout(options?)`
Async function that performs a full logout sequence:
1. Removes `ACCESS_TOKEN_KEY` and `REFRESH_TOKEN_KEY` from `localStorage`
2. Dynamically imports and calls `logout()` from the auth store
3. Redirects to the appropriate auth page (skipped in SaaS tenant mode or if already on an auth page)

### `hasStoredTokens()`
Returns `true` if either an access or refresh token exists in `localStorage`. Safe to call in SSR contexts (returns `false` on the server).

### `clearStoredTokens()`
Removes both auth tokens from `localStorage` without triggering a store reset or redirect. Useful for lightweight token cleanup without a full logout flow.

## Usage Example

```typescript
import { forceLogout, hasStoredTokens, clearStoredTokens } from '@/lib/force-logout';

// Force logout with redirect to custom path
await forceLogout({ reason: 'session_expired', redirectPath: '/auth/login' });

// Force logout without redirecting
await forceLogout({ shouldRedirect: false });

// Check if tokens exist before making an authenticated request
if (!hasStoredTokens()) {
  await forceLogout();
}

// Clear tokens only (e.g., on account switch)
clearStoredTokens();
```

> **Note:** All functions are SSR-safe — they no-op when `window` is undefined, making them safe to import in server-side contexts.
