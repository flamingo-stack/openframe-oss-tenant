Manages file downloads over the MeshCentral WebSocket protocol, handling chunked binary transfers with acknowledgment, progress tracking, and browser-side file saving.

## Key Components

### `DownloadTask` Interface
Tracks the state of a single download operation, including chunked binary data, transfer progress, and lifecycle status (`pending` → `negotiating` → `downloading` → `completed` / `failed` / `cancelled`).

### `FileDownloader` Class
Core download manager. Key methods:

| Method | Description |
|---|---|
| `downloadFile(remotePath, fileName?, fileSize?)` | Initiates a download, sends start request, returns `downloadId` |
| `handleControlMessage(message)` | Routes JSON control messages (`start`, `cancel`, `error`) from the server |
| `handleBinaryChunk(data, isFinal)` | Processes incoming binary chunks; reads 4-byte big-endian header to detect final chunk |
| `saveFile(downloadId)` | Assembles chunks into a `Blob` and triggers browser download via anchor click |
| `cancelDownload(downloadId)` | Cancels an in-progress download and notifies the server |
| `resetActiveDownload()` | Unsticks a timed-out or hung active download |
| `clearAll()` | Clears all tracked downloads and resets state |

## Usage Example

```typescript
const downloader = new FileDownloader(
  (data) => socket.send(data),           // sendMessage
  (progress) => console.log(progress),   // onProgress
  (fileName, reason) => alert(`Server cancelled ${fileName}: ${reason}`) // onServerCancel
);

// Start a download
const downloadId = downloader.downloadFile('/remote/path/report.pdf', 'report.pdf', 204800);

// Route incoming WebSocket messages
socket.onmessage = (event) => {
  if (typeof event.data === 'string') {
    downloader.handleControlMessage(JSON.parse(event.data));
  } else {
    // Binary chunk — isFinal is derived from the 4-byte header internally
    downloader.handleBinaryChunk(new Uint8Array(event.data), false);
  }
};

// Cancel if needed
downloader.cancelDownload(downloadId);
```

> **Protocol note:** Each binary frame carries a 4-byte big-endian header. Bit 0 of that integer signals the final chunk; the remaining bytes are file payload. An `ack` control message is sent after every non-final chunk.
