Provides a WebSocket-based tunnel connection to MeshCentral agents for remote access protocols like terminal and desktop connections. The tunnel handles connection lifecycle, authentication, handshake protocols, and bidirectional data transfer with automatic reconnection capabilities.

## Key Components

### Types
- **`TunnelState`** - Connection state enum (0: stopped, 1: connecting, 2: open, 3: connected)
- **`TunnelOptions`** - Configuration options including terminal dimensions and login requirements
- **`TunnelCallbacks`** - Event handlers for data, state changes, and control messages

### Main Class
- **`MeshTunnel`** - Core tunnel manager with connection lifecycle, handshake handling, and message routing
  - `start()` - Initiates WebSocket connection with authentication
  - `stop()` - Cleanly closes connection and clears timers
  - `sendText()`/`sendBinary()` - Send data through tunnel
  - `sendCtrl()` - Send control messages for tunnel management
  - `reconnect()` - Manually trigger reconnection
  - `getState()`/`isConnected()` - Connection status queries

## Usage Example

```typescript
const tunnel = new MeshTunnel({
  authCookie: 'your-auth-cookie',
  nodeId: 'target-device-id',
  protocol: 1, // Terminal protocol
  options: { cols: 80, rows: 24 },
  onData: (data) => console.log('Received:', data),
  onStateChange: (state) => console.log('State changed:', state),
  onConsoleMessage: (msg) => console.log('Console:', msg),
  onRequestPairing: (relayId) => {
    // Send pairing request through control connection
    controlSocket.send(`pair:${relayId}`);
  }
});

// Start the tunnel
tunnel.start();

// Send terminal commands
tunnel.sendText('ls -la\n');

// Clean shutdown
tunnel.stop();
```

The tunnel automatically handles WebSocket reconnection, authentication token refresh, and maintains a latency monitoring heartbeat every 10 seconds.
