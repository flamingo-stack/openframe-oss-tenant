High-level WebSocket tunnel manager for MeshCentral remote access connections, handling protocol negotiation, state management, and data transmission for terminal and desktop sessions.

## Key Components

- **`TunnelState`** - Type alias defining connection states (0: stopped, 1: connecting, 2: open, 3: connected)
- **`TunnelOptions`** - Configuration interface for terminal dimensions and authentication requirements
- **`MeshTunnel`** - Main class managing WebSocket connections to MeshCentral relay servers
- **Connection Management** - Automatic reconnection, authentication token handling, and state synchronization
- **Protocol Handlers** - Message parsing for control commands, binary data, and text transmission
- **Latency Monitoring** - Built-in RTT (round-trip time) measurement via periodic ping/pong

## Usage Example

```typescript
import { MeshTunnel, TunnelOptions } from './meshcentral-tunnel'

// Configure tunnel options for terminal session
const options: TunnelOptions = {
  cols: 80,
  rows: 24,
  requireLogin: true
}

// Create and start tunnel connection
const tunnel = new MeshTunnel({
  authCookie: 'your-auth-cookie',
  nodeId: 'target-node-id',
  protocol: 1, // 1=terminal, 2=desktop
  options,
  onData: (data) => {
    console.log('Received:', data)
  },
  onStateChange: (state) => {
    console.log('State changed:', state)
  },
  onConsoleMessage: (msg) => {
    console.log('Console:', msg)
  },
  onRequestPairing: (relayId) => {
    // Handle pairing request for reconnection
    console.log('Pairing requested for:', relayId)
  }
})

tunnel.start()

// Send terminal commands
tunnel.sendText('ls -la\n')

// Send binary data
tunnel.sendBinary(new Uint8Array([1, 2, 3]))

// Check connection status
if (tunnel.isConnected()) {
  console.log('Tunnel is active')
}

// Clean shutdown
tunnel.stop()
```
