Manages WebSocket tunnel connections to MeshCentral agents for remote access protocols like terminal/desktop sessions. This class handles connection lifecycle, authentication, protocol handshakes, and bidirectional data streaming with automatic reconnection support.

## Key Components

- **`MeshTunnel`** - Main tunnel management class with connection lifecycle control
- **`TunnelState`** - Connection state enum (0: stopped, 1: connecting, 2: open, 3: connected)
- **`TunnelOptions`** - Configuration options for terminal dimensions and login requirements
- **`TunnelCallbacks`** - Event handlers for data, state changes, and control messages

## Usage Example

```typescript
import { MeshTunnel } from './meshcentral-tunnel'

// Create a terminal tunnel
const tunnel = new MeshTunnel({
  authCookie: 'your-auth-cookie',
  nodeId: 'target-device-id',
  protocol: 1, // Terminal protocol
  options: {
    cols: 80,
    rows: 24,
    requireLogin: false
  },
  onData: (data) => {
    // Handle terminal output
    console.log('Terminal output:', data)
  },
  onStateChange: (state) => {
    console.log('Connection state:', state)
    if (state === 3) {
      console.log('Tunnel connected and ready')
    }
  },
  onConsoleMessage: (msg) => {
    console.log('Console message:', msg)
  },
  onRequestPairing: (relayId) => {
    // Handle pairing request on reconnect
    console.log('Pairing requested for relay:', relayId)
  }
})

// Start the connection
tunnel.start()

// Send terminal input
tunnel.sendText('ls -la\n')

// Send binary data
const binaryData = new Uint8Array([1, 2, 3, 4])
tunnel.sendBinary(binaryData)

// Check connection status
if (tunnel.isConnected()) {
  console.log('Tunnel is ready for communication')
}

// Stop the tunnel
tunnel.stop()
```

The tunnel automatically handles WebSocket reconnection, authentication token refresh, and protocol-specific handshake sequences. It supports both text and binary data transmission for various MeshCentral protocols.
