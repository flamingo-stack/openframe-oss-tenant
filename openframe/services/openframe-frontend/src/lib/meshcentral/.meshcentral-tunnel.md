MeshTunnel manages secure WebSocket tunnels to MeshCentral agents for remote device access, handling authentication, connection lifecycle, and binary/text data streaming with automatic reconnection.

## Key Components

- **MeshTunnel**: Main class that establishes and manages WebSocket tunnels to MeshCentral nodes
- **TunnelState**: Type defining tunnel states (0=stopped, 1=connecting, 2=open, 3=connected)
- **TunnelOptions**: Configuration options for tunnel behavior (terminal dimensions, login requirements)
- **TunnelCallbacks**: Event handlers for data, state changes, and control messages

## Usage Example

```typescript
const tunnel = new MeshTunnel({
  authCookie: 'session_cookie',
  nodeId: 'mesh_node_id',
  protocol: 1,
  options: { cols: 80, rows: 24 },
  onData: (data) => {
    console.log('Received data:', data)
  },
  onStateChange: (state) => {
    console.log('Tunnel state:', state)
  },
  onConsoleMessage: (msg) => {
    console.log('Console:', msg)
  }
})

// Start the tunnel
tunnel.start()

// Send text data
tunnel.sendText('ls -la\n')

// Send binary data
tunnel.sendBinary(new Uint8Array([0x1b, 0x5b, 0x41]))

// Check connection status
if (tunnel.isConnected()) {
  console.log('Tunnel is ready')
}

// Stop the tunnel
tunnel.stop()
```

The tunnel automatically handles WebSocket reconnection, handshake protocols, and maintains persistent connections with latency monitoring through periodic RTT messages.
