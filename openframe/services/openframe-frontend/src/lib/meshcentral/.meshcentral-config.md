Provides MeshCentral WebSocket connection configuration utilities, resolving base host/port and building properly-schemed WebSocket URLs for the MeshCentral proxy integration.

## Key Components

- **`MeshUrlParts`** — Type describing WebSocket URL parts (`baseHostPort` and `scheme`)
- **`getMeshBaseHostPort()`** — Resolves the MeshCentral base host/port by stripping protocols from the tenant host URL, routing through the `/ws/tools/meshcentral-server` proxy path
- **`getMeshWsScheme()`** — Returns `'wss'` always (HTTPS-aware but defaults to secure WebSocket regardless)
- **`buildWsUrl(path)`** — Constructs a full WebSocket URL, falling back to `window.location.host` or `localhost` when no tenant host is configured
- **`MESH_USER` / `MESH_PASS`** — MeshCentral credentials sourced from `NEXT_PUBLIC_MESH_USER` and `NEXT_PUBLIC_MESH_PASS` environment variables

## Usage Example

```typescript
import { buildWsUrl, getMeshWsScheme, getMeshBaseHostPort } from './meshcentral-config';

// Build a WebSocket URL for a specific MeshCentral path
const wsUrl = buildWsUrl('/control.ashx');
// → "wss://yourtenant.flamingo.run/ws/tools/meshcentral-server/control.ashx"

// Get base host/port for manual URL construction
const base = getMeshBaseHostPort();
// → "yourtenant.flamingo.run/ws/tools/meshcentral-server"

// Get the WebSocket scheme
const scheme = getMeshWsScheme();
// → "wss"
```

> **Note:** `MESH_USER` and `MESH_PASS` are public env variables intended for development defaults. Override via `NEXT_PUBLIC_MESH_USER` and `NEXT_PUBLIC_MESH_PASS` in production environments.
