Provides configuration utilities for establishing WebSocket connections to the MeshCentral server, including URL construction and credential management for the OpenFrame platform.

## Key Components

- **`MeshUrlParts`** — Type definition for WebSocket URL components (`baseHostPort` and `scheme`)
- **`getMeshBaseHostPort()`** — Resolves the MeshCentral host/port from the tenant host URL, stripping any protocol prefix
- **`getMeshWsScheme()`** — Determines the WebSocket scheme (`ws` or `wss`) based on the current browser protocol; always returns `wss`
- **`buildWsUrl(path)`** — Constructs a full WebSocket URL for a given path, falling back to the proxy path (`/ws/tools/meshcentral-server`) or `localhost` when no base is configured
- **`MESH_USER`** / **`MESH_PASS`** — MeshCentral credentials sourced from `NEXT_PUBLIC_MESH_USER` and `NEXT_PUBLIC_MESH_PASS` environment variables, with insecure defaults for development

## Usage Example

```typescript
import { buildWsUrl, getMeshWsScheme, MESH_USER, MESH_PASS } from './meshcentral-config';

// Build a WebSocket URL for a MeshCentral relay path
const wsUrl = buildWsUrl('/meshrelay.ashx');
// → "wss://your-tenant.example.com/ws/tools/meshcentral-server/meshrelay.ashx"

// Use credentials when authenticating
console.log(MESH_USER); // "mesh@openframe.io" (or from env)
console.log(MESH_PASS); // "meshpass@1234" (or from env)
```

## Notes

> ⚠️ The default values for `MESH_USER` and `MESH_PASS` are hardcoded fallbacks intended for development only. Always override these via `NEXT_PUBLIC_MESH_USER` and `NEXT_PUBLIC_MESH_PASS` environment variables in production deployments.
