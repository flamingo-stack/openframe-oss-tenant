Configuration types, constants, and controller class for MeshCentral remote desktop session settings — quality, scaling, frame rate, and input options.

## Key Components

- **`RemoteSettingsConfig`** — Interface defining all configurable session parameters
- **`QUALITY_OPTIONS`** — JPEG quality presets (10–100), mapped to human-readable labels
- **`SCALING_OPTIONS`** — Display scaling presets using MeshCentral's internal encoding (`256`=25% → `2048`=200%)
- **`FRAME_RATE_OPTIONS`** — FPS presets (`smooth`/30fps → `very slow`/2fps) with millisecond intervals
- **`DEFAULT_SETTINGS`** — Baseline config: 50% quality, 100% scaling, 10 FPS
- **`RemoteDesktopSettings`** — Stateful class that serializes settings into MeshCentral's binary WebSocket protocol (command `0x0005`, 10-byte big-endian payload)

## Usage Example

```typescript
import { RemoteDesktopSettings, DEFAULT_SETTINGS } from './remote-settings';

const rdSettings = new RemoteDesktopSettings({
  ...DEFAULT_SETTINGS,
  quality: 80,
  frameRate: 'fast',
  scaling: 1024,
});

// Attach an active MeshCentral WebSocket tunnel
rdSettings.setWebSocket(tunnelWs);

// Push settings to the remote session
rdSettings.applySettings();

// Estimate current bandwidth usage (KB/s)
const kbps = rdSettings.estimateBandwidth();
console.log(`Estimated bandwidth: ${kbps} KB/s`);

// Resolve milliseconds for a given frame rate label
const ms = RemoteDesktopSettings.getFrameRateMs('smooth'); // 33
```

## Notes

- `applySettings()` writes a 10-byte binary frame: 4-byte header (`0x0005` command + message length) followed by encoding type, quality, scaling, and frame timer — all big-endian
- `estimateBandwidth()` is a heuristic estimate; actual throughput depends on screen content and network conditions
- Mouse button swap, keyboard map, and scroll inversion are stored in state but are not included in the binary payload — they are expected to be handled separately by the UI layer
