Configures and exports the singleton Relay environment for client-side GraphQL operations, handling authentication headers, token refresh, and forced logout on auth failures.

## Key Components

- **`getAuthHeaders()`** — Reads a Bearer token from `localStorage` (only in dev/ticket-observer mode) to build auth headers
- **`getGraphqlUrl()`** — Resolves the GraphQL endpoint from tenant host config or `window.location.origin`
- **`executeFetch()`** — Core `fetch` wrapper that POSTs GraphQL queries with JSON body and cookie credentials
- **`fetchRelay`** — Relay `FetchFunction` that mirrors `apiClient` auth logic: attaches auth headers, handles `401` via token refresh with one retry, calls `forceLogout` on failure, and detects trial-expired GraphQL errors
- **`getRelayEnvironment()`** — Returns a singleton `Environment` on the client (with GC/cache tuning) or a fresh SSR-safe instance on the server
- **`resetRelayEnvironment()`** — Nullifies the singleton, triggering re-creation on next access (intended for logout flows)

## Usage Example

```typescript
import { getRelayEnvironment, resetRelayEnvironment } from './environment';

// Provide environment to React Relay tree
const env = getRelayEnvironment();
<RelayEnvironmentProvider environment={env}>
  <App />
</RelayEnvironmentProvider>

// On logout, clear cached store and in-flight queries
resetRelayEnvironment();
```

## Notes

- SSR always receives a **new** (non-singleton) environment with `isServer: true`
- Client store is configured with a 20-entry GC buffer and 5-minute query cache TTL
- Token refresh logic is identical for both "refresh already in-flight" and "first refresh" paths — they share the same outcome branch
