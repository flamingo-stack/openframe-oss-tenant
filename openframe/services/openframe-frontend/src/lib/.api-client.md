Centralized API client that handles authenticated HTTP requests with automatic token refresh, cookie-based and header-based auth, and request queuing during token refresh cycles.

## Key Components

- **`ApiClient`** — Singleton class managing all HTTP communication
- **`request<T>`** — Core method handling auth headers, 401 retry logic, and response parsing
- **`getAuthHeaders()`** — Injects `Bearer` token from `localStorage` when DevTicket mode is enabled
- **`buildUrl()`** — Resolves relative paths against the configured tenant host URL
- **`drainQueue()`** — Replays queued requests after a token refresh completes
- **`forceLogout()`** — Delegates to the unified logout utility on unrecoverable auth failure
- **`ApiResponse<T>`** — Normalized response envelope with `data`, `error`, `status`, and `ok`
- **`ApiRequestOptions`** — Extends `RequestInit` with `skipAuth` flag and typed headers

## Usage Example

```typescript
import { apiClient } from './api-client';

// GET request with typed response
const { data, error, ok } = await apiClient.get<User[]>('/api/users');

// POST with body
const result = await apiClient.post<Ticket>('/api/tickets', {
  title: 'New Issue',
  priority: 'high',
});

// Skip auth for public endpoints
const publicData = await apiClient.get('/api/health', { skipAuth: true });

// External API call (absolute URL, bypasses tenant host resolution)
const external = await apiClient.external<WeatherData>('https://api.example.com/weather');

// Access the current user
const { data: me } = await apiClient.me();
```

> **Auth behavior:** Cookie-based auth is always active via `credentials: 'include'`. Header-based `Bearer` token injection is enabled only when the `enableDevTicketObserver` runtime flag is set. On a `401`, the client attempts one silent token refresh before forcing logout.
