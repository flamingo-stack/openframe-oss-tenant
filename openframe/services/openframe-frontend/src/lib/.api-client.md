Centralized API client that handles authenticated HTTP requests with automatic token refresh, dual auth mode support (cookie-based and header-based), and request queuing during token refresh cycles.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `apiClient` | Singleton | Pre-instantiated `ApiClient` for app-wide use |
| `ApiClient` | Class | Core HTTP client with auth lifecycle management |
| `ApiResponse<T>` | Interface | Normalized response shape with `data`, `error`, `status`, `ok` |
| `ApiRequestOptions` | Interface | Extended `RequestInit` with `skipAuth` flag and typed headers |

**`ApiClient` methods:**

| Method | Description |
|--------|-------------|
| `request<T>(path, options, isRetry?)` | Base method — handles auth headers, 401 refresh, queue drain, abort signals |
| `get / post / put / patch / delete` | HTTP verb convenience wrappers |
| `external<T>(url, options?)` | Bypasses base URL resolution for third-party endpoints |
| `me<T>()` | Shortcut for `GET /api/me` |

## Usage Example

```typescript
import { apiClient } from '@/lib/api-client';

// Basic GET
const { data, error, ok } = await apiClient.get<User[]>('/api/users');

// POST with body
const result = await apiClient.post<Ticket>('/api/tickets', {
  title: 'New ticket',
  priority: 'high',
});

// Skip auth for public endpoints
const public = await apiClient.get('/api/health', { skipAuth: true });

// External third-party API
const ext = await apiClient.external<WeatherData>('https://api.weather.com/v1/current');

// Abort long-running requests
const controller = new AbortController();
const res = await apiClient.get('/api/reports', { signal: controller.signal });
controller.abort(); // returns { error: 'Request aborted', status: 0, ok: false }
```

> **Auth behavior:** When `enableDevTicketObserver` is active, the client reads `of_access_token` from `localStorage` and injects it as a `Bearer` token. On a `401`, it attempts a single token refresh via `refreshAccessToken`, queues concurrent requests during the refresh, then either retries or calls `forceLogout`.
