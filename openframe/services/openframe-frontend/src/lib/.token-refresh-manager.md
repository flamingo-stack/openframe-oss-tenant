Centralized manager for OAuth access token refresh operations, providing deduplication of concurrent refresh calls so multiple in-flight requests share a single refresh promise rather than triggering redundant refresh attempts.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `refreshAccessToken()` | `async function` | Primary entry point — refreshes the access token, deduplicating concurrent calls via a shared promise |
| `isTokenRefreshing()` | `function` | Returns `true` if a refresh is currently in flight |
| `waitForRefresh()` | `async function` | Resolves when any in-progress refresh completes; returns `false` if none is active |

**Internal helpers:**

- `buildRefreshUrl(tenantId?)` — Constructs the `/oauth/refresh` endpoint URL using `runtimeEnv.sharedHostUrl()`
- `executeRefresh(tenantId?)` — Performs the actual `POST /oauth/refresh` fetch, handles dev-ticket token storage (via `localStorage`), and clears tokens on `401`

## Usage Example

```typescript
import {
  refreshAccessToken,
  isTokenRefreshing,
  waitForRefresh,
} from '@/lib/token-refresh-manager';

// In an API client interceptor — safe to call concurrently
const success = await refreshAccessToken();
if (!success) {
  // Tokens cleared, redirect to login
  redirectToLogin();
}

// In a request queue — wait for an in-progress refresh
if (isTokenRefreshing()) {
  const refreshed = await waitForRefresh();
  if (!refreshed) throw new Error('Session expired');
  // Retry the original request
}
```

> **Dev Ticket Mode:** When `runtimeEnv.enableDevTicketObserver()` is `true`, the manager reads/writes `localStorage` for the refresh token and injects it as a `Refresh-Token` header, supporting environments where `HttpOnly` cookies are unavailable.
