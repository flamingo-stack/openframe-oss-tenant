Centralized manager for OAuth access token refresh operations, providing deduplication of concurrent refresh calls so multiple in-flight requests share a single refresh promise.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `refreshAccessToken()` | `async function` | Triggers a token refresh; deduplicates concurrent calls by returning the existing in-flight promise |
| `isTokenRefreshing()` | `function` | Returns `true` if a refresh is currently in progress |
| `waitForRefresh()` | `async function` | Awaits any in-progress refresh, returns `false` if none is active |

### Internal Helpers

- **`buildRefreshUrl(tenantId?)`** — Constructs the `POST /oauth/refresh` endpoint URL from `runtimeEnv.sharedHostUrl()`, appending `tenantId` as a query param when available
- **`executeRefresh(tenantId?)`** — Performs the actual fetch; handles dev-ticket mode by reading/writing tokens from `localStorage` and clears stored tokens on `401`

## Usage Example

```typescript
import { refreshAccessToken, isTokenRefreshing, waitForRefresh } from './token-refresh-manager';

// Trigger a refresh (safe to call from multiple places simultaneously)
const success = await refreshAccessToken();
if (!success) {
  // Token refresh failed — user has been logged out
}

// Check if a refresh is already underway (e.g. in an Axios interceptor)
if (isTokenRefreshing()) {
  // Wait for the existing refresh to finish before retrying
  const result = await waitForRefresh();
}
```

## Behavior Notes

- **Deduplication:** Module-level `isRefreshing` / `refreshPromise` flags ensure only one refresh request is made at a time; all concurrent callers share the same `Promise<boolean>`
- **Dev-ticket mode:** When `runtimeEnv.enableDevTicketObserver()` is `true`, tokens are exchanged via `localStorage` and request/response headers instead of HTTP-only cookies
- **Auto-logout:** A `401` response from the refresh endpoint calls `clearStoredTokens()` to force a clean logout
