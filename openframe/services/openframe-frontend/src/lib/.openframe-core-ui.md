Client boundary wrapper that re-exports all UI components from `@flamingo-stack/openframe-frontend-core/components/ui`, ensuring hooks-based components are only consumed in client contexts.

## Key Components

- **Re-exports**: All UI components from `@flamingo-stack/openframe-frontend-core/components/ui`
- **`'use client'` directive**: Marks the module boundary so Next.js treats all re-exported components as client-side, preventing RSC (React Server Component) import errors caused by hook usage in the core barrel.

## Usage Example

Import UI components through this wrapper instead of the core barrel directly:

```typescript
// ✅ Safe for use in Server and Client Components
import { Button, Input, Modal } from '@/components/openframe-core-ui';

// ❌ Avoid — may break Server Components due to hooks in the barrel
import { Button } from '@flamingo-stack/openframe-frontend-core/components/ui';
```

> **Why this exists:** Next.js App Router enforces a strict server/client boundary. The core UI barrel uses React hooks internally, which are incompatible with Server Components. This thin re-export file declares `'use client'` once, so any Server Component can safely import from it without triggering RSC violations.
