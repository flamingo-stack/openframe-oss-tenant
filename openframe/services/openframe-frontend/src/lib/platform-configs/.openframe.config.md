Defines the `AppConfig` instance for the **OpenFrame** platform, wiring together branding, SEO metadata, navigation rules, header/footer layout, and social links used across the OpenFrame frontend.

## Key Components

- **`openframeConfig`** — The exported `AppConfig` object consumed by the app shell to configure the entire platform experience. Contains:
  - `brandColors` — Metadata-only color tokens (cyan primary, dark background); actual UI uses ODS CSS variables
  - `seo` — Title template, Open Graph image, Twitter card image, and keywords; URLs resolved at runtime via `getBaseUrl()`
  - `navigation` — Logo element, allowed/restricted routes, platform nav visibility flags
  - `ui.getHeaderActions` — Dynamic header button factory returning `left`/`right` action slots based on auth state (`user`, `onSignUp`)
  - `footer.sections` — Static link groups for Resources and Company
  - `contact` / `social` — Support email and GitHub/Twitter handles

## Usage Example

```typescript
// Consumed by the app shell (e.g. _app.tsx or layout.tsx)
import { openframeConfig } from './openframe.config';
import { AppShell } from '@flamingo-stack/openframe-frontend-core';

export default function RootLayout({ children }) {
  return (
    <AppShell config={openframeConfig}>
      {children}
    </AppShell>
  );
}
```

```typescript
// Accessing individual values at runtime
import { openframeConfig } from './openframe.config';

console.log(openframeConfig.seo.title);
// "OpenFrame - Open Source Framework"

console.log(openframeConfig.navigation.allowedRoutes);
// ['/docs', '/examples', '/api', '/profile', '/contact']

console.log(openframeConfig.contact.email);
// "hello@openframe.dev"
```

> **Note:** `url`, `logo`, `seo.ogImage`, and `seo.twitterImage` are defined as `get` accessors so `getBaseUrl()` is evaluated lazily at access time, ensuring the correct base URL in both SSR and client contexts.
