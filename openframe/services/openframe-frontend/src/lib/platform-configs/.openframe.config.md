Configuration object defining the OpenFrame platform's application settings, including branding, SEO metadata, navigation structure, UI behavior, and footer layout.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `openframeConfig` | `AppConfig` | Root configuration object for the OpenFrame platform |

### Configuration Sections

| Section | Purpose |
|---------|---------|
| `brandColors` | Metadata-only color tokens (UI rendering uses ODS CSS variables) |
| `seo` | Title templates, descriptions, OG/Twitter image URLs |
| `layout` | Header/footer/sidebar visibility and header type |
| `navigation` | Logo element, allowed/restricted routes, platform nav flags |
| `ui` | Header actions (user menu, sign-up, CTA), mobile nav icons, search bar |
| `footer` | Section links, logo element, waitlist toggle |
| `social` | GitHub and Twitter/X URLs |

## Usage Example

```typescript
import { openframeConfig } from './openframe.config';

// Access platform identity
console.log(openframeConfig.name);        // 'OpenFrame'
console.log(openframeConfig.platform);    // 'openframe'

// Access dynamic base URL (resolved at runtime)
console.log(openframeConfig.url);         // e.g. 'https://openframe.ai'
console.log(openframeConfig.logo);        // 'https://openframe.ai/assets/openframe/apple-touch-icon.png'

// Render header actions
const { left, right } = openframeConfig.ui.getHeaderActions({
  user: currentUser,
  router,
  pathname,
  onSignUp: handleSignUp,
});
```

> `url` and `logo` are defined as `get` accessors, so `getBaseUrl()` is evaluated lazily at access time — useful for SSR and environment-specific deployments.
