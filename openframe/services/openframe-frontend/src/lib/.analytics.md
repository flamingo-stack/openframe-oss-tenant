Fire-and-forget dashboard activity analytics module that tracks high-signal user activation events without blocking or affecting the calling flow.

## Key Components

**Constants**
- `EVENT_TYPE` — Fixed value `'DASHBOARD_ACTIVITY'` sent with every event
- `REPEAT_MODE` — Enum-style object: `SINGULAR` (one-time milestone per user) or `MULTI` (every occurrence)
- `EVENT_SUBTYPE` — Single source of truth for all trackable event subtypes, namespaced by surface (`main_dashboard`, `mingo`, `ticket_detail`)

**Types**
- `RepeatMode` — Union of `REPEAT_MODE` values
- `EventSubtype` — Union of all `EVENT_SUBTYPE` values

**Internal**
- `SINGULAR_SUBTYPES` — `ReadonlySet` of subtypes that should only be counted once per user (`SKIP_ONBOARDING`, `ADD_SSO_IDP`)
- `repeatModeFor(subtype)` — Derives the correct `RepeatMode` from a subtype; call sites never pass this manually

**Primary Export**
- `trackDashboardActivity(subtype)` — POSTs to `/api/events`, returns `void`, swallows all errors

## Usage Example

```typescript
import { trackDashboardActivity, EVENT_SUBTYPE } from './analytics';

// Inside an event handler or mutation callback — fully safe, non-blocking
function onTicketResolved() {
  trackDashboardActivity(EVENT_SUBTYPE.RESOLVE_TICKET);
  // continues immediately; analytics failure never surfaces to the user
}

// One-time onboarding milestone (auto-derived as SINGULAR)
function onOnboardingSkipped() {
  trackDashboardActivity(EVENT_SUBTYPE.SKIP_ONBOARDING);
}
```

> **Never pass raw strings** to `trackDashboardActivity`. Always use an `EVENT_SUBTYPE` constant to stay in sync with the event catalog defined in `docs/dashboard-activity-events.md`.
