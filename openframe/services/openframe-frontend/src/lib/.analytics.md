Fire-and-forget dashboard activity analytics module for tracking high-signal user activation events without blocking or affecting the calling flow.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `EVENT_TYPE` | `const` | Fixed string `'DASHBOARD_ACTIVITY'` sent with every event |
| `REPEAT_MODE` | `const object` | `SINGULAR` (one-time milestone) or `MULTI` (every occurrence) |
| `EVENT_SUBTYPE` | `const object` | Single source of truth for all tracked event subtypes |
| `trackDashboardActivity` | `function` | Fire-and-forget POST to `/api/events` — never throws |
| `RepeatMode` | `type` | Union of `REPEAT_MODE` values |
| `EventSubtype` | `type` | Union of all `EVENT_SUBTYPE` values |

**Tracked surfaces and their subtypes:**

| Surface | Subtypes |
|---------|----------|
| `/dashboard` | `ADD_DEVICE`, `ADD_SSO_IDP`, `SKIP_ONBOARDING` |
| `/mingo` | `SEND_MINGO_MESSAGE`, `APPROVE_MINGO_COMMAND`, `REJECT_MINGO_COMMAND` |
| `/tickets/dialog` | `OPEN_REMOTE_SHELL`, `OPEN_REMOTE_CONTROL`, `RESOLVE_TICKET`, `START_DIRECT_CHAT` |

`SKIP_ONBOARDING` and `ADD_SSO_IDP` are `SINGULAR` (counted once per user). All others are `MULTI`. Call sites never pass a repeat mode — it is derived automatically from the subtype.

## Usage Example

```typescript
import { trackDashboardActivity, EVENT_SUBTYPE } from './analytics';

// In an event handler or mutation success callback:
function handleSendMessage() {
  sendMessage(payload);
  trackDashboardActivity(EVENT_SUBTYPE.SEND_MINGO_MESSAGE); // non-blocking
}

// One-time activation milestone (auto-resolved as SINGULAR):
function handleSkipOnboarding() {
  skipOnboarding();
  trackDashboardActivity(EVENT_SUBTYPE.SKIP_ONBOARDING);
}
```

> Always use `EVENT_SUBTYPE` constants — never pass hand-written strings. Adding new events requires updating `EVENT_SUBTYPE` here and the event catalog in `docs/dashboard-activity-events.md`.
