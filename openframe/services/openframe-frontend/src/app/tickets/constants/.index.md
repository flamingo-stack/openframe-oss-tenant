Centralized constants and type definitions for dialog system components including chat types, message statuses, API endpoints, and network configuration.

## Key Components

**Status Enums:**
- `DIALOG_STATUS` - Dialog states (ON_HOLD, RESOLVED, ACTIVE)
- `CHAT_TYPE` - Chat categories (CLIENT, ADMIN)
- `MESSAGE_TYPE` - Message classifications including tool execution and approval flows
- `OWNER_TYPE` - Message ownership (CLIENT, ADMIN, ASSISTANT)
- `APPROVAL_STATUS` - Approval workflow states

**Configuration Objects:**
- `ASSISTANT_CONFIG` - AI assistant definitions (Fae, Mingo)
- `API_ENDPOINTS` - REST API route constants
- `NATS_TOPICS` - Message broker topic names
- `STORAGE_KEYS` - Local storage key definitions
- `NETWORK_CONFIG` - Connection timeouts and limits

**Type Definitions:**
- All const objects have corresponding TypeScript types using `typeof` patterns

## Usage Example

```typescript
import { DIALOG_STATUS, MESSAGE_TYPE, ASSISTANT_CONFIG, type DialogStatus } from './index'

// Type-safe status checking
const currentStatus: DialogStatus = DIALOG_STATUS.ACTIVE

// Message type validation
if (message.type === MESSAGE_TYPE.APPROVAL_REQUEST) {
  // Handle approval flow
}

// Assistant configuration
const faeConfig = ASSISTANT_CONFIG.FAE
console.log(`Using ${faeConfig.name} assistant`) // "Using Fae assistant"

// API endpoint usage
fetch(API_ENDPOINTS.SEND_MESSAGE, {
  method: 'POST',
  body: JSON.stringify(messageData)
})
```
