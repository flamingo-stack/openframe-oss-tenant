Centralized query key definitions for React Query caching and invalidation of dialog/ticket data, following React Query best practices for hierarchical key organization.

## Key Components

- **`DialogsQueryParams`** - Interface defining filter parameters for dialog queries (archived status, search terms, status filters, cursor pagination)
- **`dialogsQueryKeys`** - Hierarchical query key factory with base keys, list keys, and parameterized keys for specific queries
- **`invalidateAllDialogs()`** - Utility function to invalidate all dialog-related queries at once

## Usage Example

```typescript
import { useQuery } from '@tanstack/react-query'
import { dialogsQueryKeys, DialogsQueryParams } from './query-keys'

// Use query keys in React Query hooks
const queryParams: DialogsQueryParams = {
  archived: false,
  search: 'urgent',
  statusFilters: ['open', 'in-progress']
}

const { data: dialogs } = useQuery({
  queryKey: dialogsQueryKeys.list(queryParams),
  queryFn: () => fetchDialogs(queryParams)
})

// Invalidate all dialog queries after mutations
const mutation = useMutation({
  mutationFn: updateDialog,
  onSuccess: () => {
    invalidateAllDialogs(queryClient)
  }
})
```

The hierarchical structure allows for granular cache invalidation - you can invalidate all dialogs, all list queries, or specific parameterized queries as needed.
