Shellless `EmbeddableChat` surface for the OpenFrame frontend, mounted inside `AppLayoutDrawer` so the header and sidebar remain interactive while the AI chat panel is open.

## Key Components

**`OpenframeEmbeddableChatEntry`** — The sole export. Accepts `open` / `onOpenChange` props shared with the host drawer and renders `EmbeddableChat` with `shell="none"` (no floating trigger, no body scroll-lock). Wires two chat modes:

- **`modes.guide`** — SSE/Guide mode, endpoints prefixed `/guide/` and reverse-proxied to MPH.
- **`modes.mingo`** — NATS/Mingo mode, backed by OpenFrame REST + GraphQL + NATS WebSocket.

**Internal callbacks** (all `useCallback`, no business logic):

| Callback | Endpoint |
|---|---|
| `fetchDialogs` | `POST /chat/graphql` — paginated dialog list |
| `fetchDialogMessages` | `POST /chat/graphql` — messages + token usage snapshot |
| `createDialog` | `POST /chat/api/v1/dialogs` |
| `publishUserMessage` | `POST /chat/api/v1/messages` |
| `approveRequest` | `POST /chat/api/v1/approval-requests/:id/approve` |
| `rejectRequest` | `POST /chat/api/v1/approval-requests/:id/approve` |
| `stopGeneration` | `POST /chat/api/v1/dialogs/:id/stop` |

**Local type mirrors** — `FetchDialogsParams`, `FetchDialogsResult`, `FetchDialogMessagesParams`, `FetchDialogMessagesResult`, and GraphQL response shapes are declared locally until the next `@flamingo-stack/openframe-frontend-core` publish exposes them.

## Usage Example

```typescript
// Inside AppLayout — the drawer owns open state, passes it down
const [chatOpen, setChatOpen] = useState(false);

<AppLayoutDrawer open={chatOpen} onOpenChange={setChatOpen}>
  <OpenframeEmbeddableChatEntry
    open={chatOpen}
    onOpenChange={setChatOpen}
  />
</AppLayoutDrawer>
```

> **Note:** NATS WebSocket URL is resolved automatically via `useNatsAppConfig`. No manual URL wiring is required by the host. Message pages are fetched in descending order and reversed to chronological before being handed to the lib's `MessageSegmentAccumulator`.
