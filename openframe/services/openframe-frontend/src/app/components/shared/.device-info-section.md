Renders a device information card section within a dialog or log view, supporting both prop-injected device data and on-demand fetching via device ID.

## Key Components

- **`DeviceInfoSection`** — Main export; displays a labeled card with device name, OS, status, and a details button
- **`DeviceInfoSectionProps`** — Accepts `deviceId`, `userId`, and an optional partial `device` object (e.g. pre-loaded from a log entry or dialog)
- **`useDeviceDetails`** — Hook used to fetch device data when no prop data is provided; polling is disabled
- **`DeviceCard`** — UI component from `openframe-frontend-core` that renders the structured device card
- **`DeviceInfoSectionSkeleton`** — Shown during loading when no prop data is available
- **`getDeviceOperatingSystem` / `getDeviceStatusConfig`** — Utility functions that normalize OS type and map status to label/variant

## Usage Example

```typescript
// With a pre-loaded device object (no fetch triggered)
<DeviceInfoSection
  device={{
    id: 'dev-123',
    displayName: 'John Laptop',
    osType: 'windows',
    status: 'online',
  }}
/>

// With only a deviceId (triggers fetch)
<DeviceInfoSection deviceId="dev-123" />

// Renders nothing if neither deviceId nor device is provided
<DeviceInfoSection />
```

## Behavior Notes

- If `device` is passed via props, the hook fetch is skipped (`null` is passed as the ID)
- Shows the skeleton loader only when actively fetching without prop data
- Returns `null` silently when no device data or ID is available
- The "More" button is hidden; a `DeviceDetailsButton` is injected as the details action
