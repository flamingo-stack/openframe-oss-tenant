Reusable page-level panel that renders the full Devices list UI, supporting both table and grid view modes with filtering, infinite scroll, and URL-driven state.

## Key Components

- **`DevicesPanel`** — Main exported component that composes the complete devices browsing experience
- **`DevicesPanelProps`** — Configuration interface for customizing the panel when embedded in different contexts (e.g., scoped to a single organization)

### Internal Hooks Used

| Hook | Responsibility |
|------|---------------|
| `useDevicesUrlParams` | Manages URL-synchronized filter/search/view state |
| `useDevices` | Fetches paginated device data with infinite scroll support |
| `useDeviceFilters` | Loads available filter options (statuses, OS types, etc.) |
| `useTagFilterModal` | Controls the filter modal open/close state and tag management |
| `useGridInfiniteScroll` | Wires a sentinel ref to trigger `fetchNextPage` in grid mode |

## Usage Example

```typescript
// Basic usage — full devices page
<DevicesPanel />

// Scoped to a single organization (e.g., inside an org detail tab)
<DevicesPanel
  title="Organization Devices"
  addDeviceHref="/devices/new?orgId=123"
  lockedFilters={{ organizationIds: ['org-123'] }}
  hideColumns={['organization']}
  hideFilters={['organization']}
  defaultStatuses={[]}
  className=""
/>
```

## Behavior Notes

- **View modes**: Toggles between `table` (default) and `grid` via `TabSelector`; grid is automatically collapsed to table on mobile viewports
- **Locked filters**: Values in `lockedFilters` are merged over URL-driven filters and cannot be overridden by the user
- **Infinite scroll**: Table mode uses `DataTable.InfiniteFooter` with a manual "Load More" trigger; grid mode uses an intersection observer sentinel
- **Error state**: Renders `PageError` when the device fetch fails
