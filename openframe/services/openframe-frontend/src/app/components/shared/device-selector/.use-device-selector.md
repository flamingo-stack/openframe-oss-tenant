Manages state and filtering logic for a device selector component, handling search, tab switching, and device list derivation.

## Key Components

**`useDeviceSelectorParams`** — Input interface:
- `devices` — Full list of available `Device` objects
- `selectedIds` — `Set<string>` of currently selected device keys
- `getDeviceKey` — Extractor function returning a unique key per device

**`useDeviceSelector`** — Hook returns:
| Return Value | Description |
|---|---|
| `searchTerm` / `setSearchTerm` | Controlled search input state |
| `activeSubTab` / `handleTabChange` | Active sub-tab (`available` \| `selected`) with reset-on-change behavior |
| `filteredDevices` | Devices filtered by `displayName`, `hostname`, `osType`, or `operating_system` |
| `displayDevices` | Final list — further narrows `filteredDevices` to selected-only when on the `selected` tab |

## Usage Example

```typescript
const {
  searchTerm,
  setSearchTerm,
  activeSubTab,
  handleTabChange,
  displayDevices,
} = useDeviceSelector({
  devices: allDevices,
  selectedIds: new Set(['device-123', 'device-456']),
  getDeviceKey: (device) => device.id,
});

// Switching tabs clears the search term automatically
handleTabChange('selected'); // shows only selected devices
```

## Notes

- `filteredDevices` and `displayDevices` are both memoized — safe to use in render-heavy lists
- `handleTabChange` is stable via `useCallback` — suitable as a prop without triggering child re-renders
- `handleTabChange` resets `searchTerm` to `''` on every tab switch to avoid stale filter state
