A client-side, selection-oriented device list component that renders a filterable, searchable `DataTable` of devices with support for single/multi-select, infinite scroll, tag filters, and read-only modes. All filtering and selection state is managed client-side against a parent-supplied `devices` array.

## Key Components

- **`DeviceSelector`** — Main exported component; accepts pre-fetched devices and delegates selection state to the parent via `onSelectionChange`
- **`useDeviceSelector`** — Internal hook managing search term, active tab, and filtered/displayed device lists
- **`useTagFilterModal`** — Hook wiring up the tag filter modal (open/close, filter groups, tag key resolution)
- **`toggleDevice`** — Stable callback (via `useRef` + `useCallback`) toggling a single device in/out of the selection set
- **`addAllDevices`** / **`removeAllSelected`** — Bulk selection helpers supporting `merge` or `replace` behaviors
- **`clientDeviceFilters`** — Derived `DeviceFilters` object computed client-side (status/OS/org/tag counts) to drive filter dropdowns without network calls

## Usage Example

```typescript
import { DeviceSelector } from '@/app/components/shared/device-selector';

function MyModal() {
  const [selectedIds, setSelectedIds] = useState<Set<string>>(new Set());
  const { data: devices, loading } = useMyDevicesQuery();

  return (
    <DeviceSelector
      devices={devices ?? []}
      loading={loading}
      selectedIds={selectedIds}
      onSelectionChange={setSelectedIds}
      singleSelect={false}
      addAllBehavior="merge"
      isDeviceDisabled={(device) => device.status === 'archived'}
    />
  );
}
```

> **Note:** `DeviceSelector` is intentionally data-agnostic — it does not fetch devices itself. Use `DevicesPanel` when you need server-driven pagination, URL-synced filter state, or backend-sourced filter counts.
