A selection-oriented device list component that renders a filterable, searchable table of devices with client-side filtering, tab navigation (All/Selected), and single/multi-select support. Designed to be data-agnostic — consumers provide pre-fetched devices from any backend (GraphQL, REST, MDM).

## Key Components

- **`DeviceSelector`** — Main exported component; renders a `DataTable` with selection state, filter toolbar, tag chips, and optional infinite scroll
- **`useDeviceSelector`** — Hook managing search term, active tab (`all`/`selected`), and device list derivation
- **`useTagFilterModal`** — Hook driving the tag/filter modal and adapting its output back to local column filter state
- **`clientDeviceFilters`** — Client-side computed `DeviceFilters` object (status/OS/org/tag counts) built from the `devices` prop — no network call
- **`devicesForTable`** — Memoized filtered list combining tab display, column filters, and selected tag values

## Usage Example

```typescript
import { DeviceSelector } from '@/app/components/shared/device-selector';

function AssignDevicesModal({ devices, loading }) {
  const [selectedIds, setSelectedIds] = useState<Set<string>>(new Set());

  return (
    <DeviceSelector
      devices={devices}
      loading={loading}
      selectedIds={selectedIds}
      onSelectionChange={setSelectedIds}
      addAllBehavior="merge"
      singleSelect={false}
      isDeviceDisabled={(device) => device.status === 'archived'}
    />
  );
}

// Read-only / display-only mode (no selection UI)
<DeviceSelector
  devices={devices}
  loading={false}
  readOnly
/>

// Single-select with a custom key resolver
<DeviceSelector
  devices={devices}
  loading={false}
  selectedIds={selectedIds}
  onSelectionChange={setSelectedIds}
  singleSelect
  getDeviceKey={(d) => d.id}
/>
```

## Notes

- **`readOnly`** forces `disabled`, `singleSelect: true`, and hides the selection mode radio — safe for preview contexts
- **`addAllBehavior`**: `"merge"` (default) adds filtered devices to existing selection; `"replace"` clears first
- **`infiniteScroll`** is optional — most consumers fetch the full list (≤100 devices) and omit it
- Column filter state and tag state are kept local; `handleSetParams` bridges the `useTagFilterModal` adapter back to `ColumnFiltersState`
