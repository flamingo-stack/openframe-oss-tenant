A selection-oriented device list component that enables single or multi-select interactions over a pre-fetched `Device[]` array with client-side filtering, tag chips, column filters, and optional infinite scroll.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `DeviceSelector` | React Component | Main component rendering a filterable, selectable device table |
| `toggleDevice` | Callback | Adds/removes a single device from the selection set (ref-stable) |
| `addAllDevices` | Callback | Merges or replaces current selection with all visible filtered devices |
| `removeAllSelected` | Callback | Clears the entire selection set |
| `clientDeviceFilters` | Derived State | Client-side `DeviceFilters` object built from the `devices` prop without network calls |
| `devicesForTable` | Derived State | Final filtered device array combining tab, column, and tag filters |

## Usage Example

```typescript
import { DeviceSelector } from './device-selector';

const [selectedIds, setSelectedIds] = useState<Set<string>>(new Set());

<DeviceSelector
  devices={prefetchedDevices}
  loading={isLoading}
  selectedIds={selectedIds}
  onSelectionChange={setSelectedIds}
  getDeviceKey={(d) => d.machineId ?? d.id}
  singleSelect={false}
  addAllBehavior="merge"
  isDeviceDisabled={(d) => d.status === 'archived'}
  readOnly={false}
  infiniteScroll={{
    hasMore: false,
    onLoadMore: () => {},
  }}
/>
```

## Design Notes

- **Parent-owned data:** Consumers pass a pre-fetched `devices` array — no internal `useDevices` call — because different consumers fetch from GraphQL, Tactical RMM REST, or Fleet MDM.
- **Client-side filtering:** Status, OS, org, and tag filters operate purely on the passed array via `Array.filter`. Filter dropdown options are derived from the same array (no extra network call).
- **Ref-stable `toggleDevice`:** Uses `selectedIdsRef` to avoid stale closure bugs in memoized `DataTable` rows.
- **`readOnly` mode:** Forces `disabled`, hides selection UI, and switches to `singleSelect` behavior automatically.
- For server-driven listing with URL state and GraphQL pagination, use `DevicesPanel` instead.
