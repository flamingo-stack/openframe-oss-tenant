Root Next.js layout component that wraps the entire OpenFrame application, configuring global metadata, provider hierarchy, and app-level infrastructure.

## Key Components

### `metadata` (exported constant)
Full Next.js `Metadata` object defining SEO, Open Graph, Twitter cards, favicons, and PWA manifest for the OpenFrame platform.

### `RootLayout` (default export)
Root HTML shell rendered server-side for every route. Establishes the provider tree and global HTML structure.

**Provider hierarchy (outer → inner):**
- `RelayProvider` — GraphQL/Relay data layer
- `QueryClientProvider` — React Query client
- `NatsAppProvider` — NATS real-time messaging
- `FeatureFlagsGate` — Feature flag evaluation
- `NotificationsDataProvider` — App-wide notifications state
- `RouteGuard` — Auth-aware route protection

**Side-effect components mounted at root:**
| Component | Purpose |
|---|---|
| `GoogleTagManager` | Analytics |
| `EmbedShimRegistration` | Embed compatibility layer |
| `DeploymentInitializer` | Bootstrap deployment config |
| `DevTicketObserver` | Dev-only auth ticket watcher |
| `GraphQlIntrospectionInitializer` | Schema introspection setup |
| `Toaster` | Global toast notifications |

## Usage Example

```typescript
// This file is the Next.js App Router root layout.
// It is automatically applied to all routes under /app.
// No manual import needed — Next.js resolves it by convention.

// To extend metadata in child layouts or pages:
import type { Metadata } from 'next';

export const metadata: Metadata = {
  title: 'My Page', // renders as "My Page | OpenFrame" via template
};
```

## Notes

- `dynamic = 'force-dynamic'` is set globally to prevent SSG conflicts with `useSearchParams`.
- Auth-dependent providers (`DevTicketObserver`, `GraphQlIntrospectionInitializer`) are conditionally mounted via `isAuthEnabled()` and wrapped in `<Suspense fallback={null}>`.
- Fonts `azeretMono` and `dmSans` are injected as CSS variables via class names on `<html>`.
- Dark mode is forced via the `dark` class on `<html>`; hydration warnings are suppressed on both `<html>` and `<body>`.
