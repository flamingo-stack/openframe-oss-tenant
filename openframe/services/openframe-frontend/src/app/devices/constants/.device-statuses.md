This TypeScript file defines device status constants and type-safe collections for filtering devices in the Flamingo MSP platform. It provides structured status management with default visibility rules to separate active devices from archived/deleted ones.

## Key Components

- **`DEVICE_STATUS`** - Complete enum-like object containing all possible device statuses (ONLINE, OFFLINE, ACTIVE, etc.)
- **`DeviceStatus`** - Type representing all possible device status values
- **`DEFAULT_VISIBLE_STATUSES`** - Array of statuses shown in standard device views (excludes ARCHIVED/DELETED)
- **`DEFAULT_DASHBOARD_STATUSES`** - Subset of statuses displayed on dashboard (ONLINE/OFFLINE only)
- **`HIDDEN_DEVICE_STATUSES`** - Statuses excluded from default views (ARCHIVED/DELETED)
- **Type definitions** - `DefaultVisibleStatus` and `HiddenDeviceStatus` for type safety

## Usage Example

```typescript
import { DEVICE_STATUS, DEFAULT_VISIBLE_STATUSES, type DeviceStatus } from './device-statuses'

// Filter devices for main device list
const activeDevices = devices.filter(device => 
  DEFAULT_VISIBLE_STATUSES.includes(device.status as DefaultVisibleStatus)
)

// Check specific status
if (device.status === DEVICE_STATUS.MAINTENANCE) {
  showMaintenanceWarning()
}

// Type-safe status assignment
const deviceStatus: DeviceStatus = DEVICE_STATUS.ONLINE

// Query devices excluding hidden statuses
const visibleDevices = await getDevices({
  statusNotIn: HIDDEN_DEVICE_STATUSES
})
```

The file uses TypeScript's `as const` assertions and `satisfies` operator to ensure type safety while maintaining the exact string literal types for API compatibility.
