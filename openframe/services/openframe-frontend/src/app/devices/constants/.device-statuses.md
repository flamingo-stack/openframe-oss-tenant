Device status constants and type definitions for managing device visibility states across the Flamingo OpenFrame platform. This file centralizes all device statuses and provides pre-configured arrays for different UI contexts, ensuring consistent filtering of active vs. archived/deleted devices.

## Key Components

- **`DEVICE_STATUS`** - Complete enum-like object containing all possible device states
- **`DeviceStatus`** - TypeScript type derived from the status constant
- **`DEFAULT_VISIBLE_STATUSES`** - Array of statuses shown in standard device lists (excludes archived/deleted)
- **`DEFAULT_DASHBOARD_STATUSES`** - Simplified status set for dashboard views (online/offline only)
- **`HIDDEN_DEVICE_STATUSES`** - Statuses that are filtered out by default
- **`DefaultVisibleStatus`** and **`HiddenDeviceStatus`** - Refined types for specific use cases

## Usage Example

```typescript
import { 
  DEVICE_STATUS, 
  DEFAULT_VISIBLE_STATUSES, 
  type DeviceStatus 
} from './device-statuses'

// Filter devices for main listing
const activeDevices = devices.filter(device => 
  DEFAULT_VISIBLE_STATUSES.includes(device.status as DeviceStatus)
)

// Check specific status
if (device.status === DEVICE_STATUS.MAINTENANCE) {
  showMaintenanceAlert()
}

// Type-safe status assignment
const updateDeviceStatus = (status: DeviceStatus) => {
  // TypeScript ensures only valid statuses can be passed
  device.status = status
}
```

The constant arrays use `as const satisfies string[]` for type safety while maintaining literal types, and the design ensures new backend statuses must be explicitly added to appear in default views.
