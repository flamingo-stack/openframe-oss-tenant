Client-side root page component that handles initial authentication-based routing for the Flamingo/OpenFrame application.

## Key Components

- **`Home`** — Default export. Root page component that checks authentication state and redirects users to the appropriate path using `getDefaultRedirectPath`.
- **`useAuthStore`** — Zustand auth store providing `isAuthenticated` state (`true`, `false`, or `null` while loading).
- **`getDefaultRedirectPath`** — Utility that resolves the correct redirect path based on authentication status and app mode.
- **`AppShellSkeleton`** — Loading placeholder rendered while authentication state is being determined (`isAuthenticated === null`).

## Usage Example

```typescript
// This is the root "/" route — no direct usage needed.
// On load, it evaluates auth state and redirects:

// Authenticated user → redirects to dashboard or app-mode default
// Unauthenticated user → redirects to /auth/login (or equivalent)
// While resolving → renders <AppShellSkeleton /> as a loading state

// getDefaultRedirectPath example behavior:
getDefaultRedirectPath(true);  // e.g. "/dashboard"
getDefaultRedirectPath(false); // e.g. "/auth/login"
```

## Behavior Notes

- `force-dynamic` export disables static generation, ensuring auth state is always evaluated at runtime.
- Uses `router.replace` (not `push`) so the root `/` route is removed from browser history after redirect.
- The redirect fires only when `isAuthenticated` is non-null, preventing premature navigation during hydration.
