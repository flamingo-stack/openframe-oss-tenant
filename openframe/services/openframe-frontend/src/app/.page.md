Client-side root page component that handles initial authentication-based routing. On mount, it checks the user's authentication state and redirects to the appropriate default path, displaying a skeleton loader while the redirect resolves.

## Key Components

- **`Home`** — Default export; root page component (`/`) that redirects based on auth state
- **`useAuthStore`** — Zustand store hook providing `isAuthenticated` state
- **`getDefaultRedirectPath`** — Utility that resolves the correct redirect path based on auth status and app mode
- **`AppShellSkeleton`** — Placeholder UI rendered during the redirect transition

## Usage Example

```typescript
// This component is automatically rendered at the app root route "/"
// No direct usage needed — Next.js handles mounting via the file-based router.

// getDefaultRedirectPath behavior (simplified):
getDefaultRedirectPath(true);  // → "/dashboard" (or app-mode equivalent)
getDefaultRedirectPath(false); // → "/login"
getDefaultRedirectPath(null);  // → no redirect, skeleton stays visible
```

## Notes

- `dynamic = 'force-dynamic'` disables static generation, ensuring auth state is always evaluated at runtime
- Redirect is deferred until `isAuthenticated` is non-null (i.e., the store has resolved), preventing premature navigation
- Uses `router.replace` instead of `router.push` to avoid leaving the root `/` in the browser history
