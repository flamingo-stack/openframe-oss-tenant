Defines TypeScript interfaces and type guards for message handling in the Flamingo chat system, supporting both GraphQL-based messages and core message formats.

## Key Components

**Interfaces:**
- `GraphQLMessage` - Server-side message format with dialog metadata and owner information
- `CoreMessage` - Frontend message format with role-based structure and optional assistant metadata
- `MessageConnection` - GraphQL cursor-based pagination wrapper for message collections
- `MessagesResponse` - Complete GraphQL response structure for message queries
- `MessagePage` - Simplified page structure for message lists with pagination info

**Type Aliases:**
- `Message` - Alias for `CoreMessage` used throughout the application

**Type Guards:**
- `isGraphQLMessage()` - Runtime check to identify GraphQL message format
- `isCoreMessage()` - Runtime check to identify core message format

## Usage Example

```typescript
import { Message, isGraphQLMessage, isCoreMessage } from './message.types'

// Creating a core message for the UI
const userMessage: Message = {
  id: 'msg-123',
  role: 'user',
  content: { text: 'Hello, how can I help?' },
  timestamp: new Date(),
  avatar: '/avatars/user.png'
}

// Type checking messages from different sources
function processMessage(message: unknown) {
  if (isGraphQLMessage(message)) {
    // Handle server message with dialog metadata
    console.log(`Dialog: ${message.dialogId}, Owner: ${message.owner.type}`)
  } else if (isCoreMessage(message)) {
    // Handle UI-ready message
    console.log(`Role: ${message.role}, Content: ${message.content}`)
  }
}

// Working with paginated message responses
function handleMessagesResponse(response: MessagesResponse) {
  const { messages, pageInfo } = response.data.messages
  
  if (pageInfo.hasNextPage) {
    // Load more messages using endCursor
    loadMoreMessages(pageInfo.endCursor)
  }
}
```
