Client-side Next.js page component that renders the Notifications feature, gating access via a feature flag and returning a 404 if the feature is disabled.

## Key Components

- **`NotificationsPage`** — Default export; the page-level React component for the `/notifications` route
- **`featureFlags.notifications.enabled()`** — Feature flag guard; triggers `notFound()` if notifications are disabled
- **`PageLayout`** — Wrapper component from `openframe-frontend-core` providing consistent page structure
- **`NotificationsPageView`** — The main content component rendering the notifications UI
- **`dynamic = 'force-dynamic'`** — Disables static generation, ensuring the page is always server-rendered at request time

## Usage Example

```typescript
// Accessed via the /notifications route in Next.js App Router
// No direct instantiation needed — Next.js handles routing automatically

// To enable the page, ensure the feature flag is active:
// lib/feature-flags.ts
export const featureFlags = {
  notifications: {
    enabled: () => true, // toggle to false to return 404
  },
};
```

> **Note:** When `featureFlags.notifications.enabled()` returns `false`, Next.js will render the nearest `not-found.tsx` boundary instead of the notifications UI.
