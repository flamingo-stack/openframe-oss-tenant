Client-side Next.js page component for the Notifications feature, rendering the notifications view within a full-page layout while enforcing feature flag gating.

## Key Components

- **`NotificationsPage`** — Default export page component that checks the `notifications` feature flag before rendering. Returns a 404 (`notFound()`) if the feature is disabled.
- **`featureFlags.notifications.enabled()`** — Guards access to the page at render time.
- **`PageLayout`** — Wrapper layout component with header hidden and system-level padding applied.
- **`NotificationsPageView`** — The primary content component rendered inside the layout.

## Usage Example

```typescript
// Accessed via Next.js routing at /notifications
// No direct instantiation needed — Next.js handles routing automatically.

// To enable the page, ensure the feature flag is active:
// lib/feature-flags.ts
export const featureFlags = {
  notifications: {
    enabled: () => true, // toggle to false to return 404
  },
};
```

## Notes

- `'use client'` directive marks this as a Client Component.
- `export const dynamic = 'force-dynamic'` disables static caching, ensuring the page is always server-rendered on request (useful for real-time notification data).
- The layout uses CSS variable `--spacing-system-l` for padding, consistent with the OpenFrame Design System (ODS) token conventions.
