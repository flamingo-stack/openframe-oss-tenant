Client-side Next.js page component that renders the Notifications feature, guarded by a feature flag that returns a 404 if notifications are disabled.

## Key Components

- **`NotificationsPage`** — Default export page component that checks the `notifications` feature flag before rendering
- **`featureFlags.notifications.enabled()`** — Runtime feature flag check; redirects to `notFound()` if the feature is disabled
- **`PageLayout`** — Wrapper layout component with header hidden and system spacing applied
- **`NotificationsPageView`** — The primary notifications UI rendered within the layout
- **`dynamic = 'force-dynamic'`** — Disables static generation, ensuring the page is always server-rendered on request

## Usage Example

```typescript
// Navigating to this page requires the notifications flag to be enabled.
// If disabled, the route returns a 404.

// feature-flags.ts (example shape)
export const featureFlags = {
  notifications: {
    enabled: () => process.env.NEXT_PUBLIC_NOTIFICATIONS_ENABLED === 'true',
  },
};

// When enabled, renders:
<PageLayout showHeader={false} className="p-[var(--spacing-system-l)]" contentClassName="min-h-0">
  <NotificationsPageView />
</PageLayout>
```

> **Note:** This page is always dynamically rendered (`force-dynamic`) and uses the `'use client'` directive, making it a fully client-side component within the Next.js App Router.
