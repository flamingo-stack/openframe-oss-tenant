Renders the full notifications page, managing two separate Relay query loaders for unread ("New") and read ("History") notification lists, with debounced search, URL-synced params, and bulk mark-all-read mutation support.

## Key Components

| Export/Symbol | Description |
|---|---|
| `NotificationsPageView` | Main page-level component rendering two `NotificationsSection` panels |
| `PAGE_SIZE` | Constant controlling pagination batch size (50 items) |
| `SEARCH_DEBOUNCE_MS` | Debounce delay for search inputs (300ms) |

## Key Behaviors

- **Dual query loaders** — independent `useQueryLoader` instances for unread (`read: false`) and history (`read: true`) lists, each re-fetching on debounced search changes
- **URL-synced search** — `useApiParams` keeps `searchNew` / `searchHistory` in sync with URL params; local state drives the input, debounced value commits to params
- **Mutation wiring** — `useNotificationMutations` receives `filterPairs` (current filters + an unfiltered fallback) for optimistic cache updates; `markAllRead` triggers a success toast via `onMarkAllReadCompleted`
- **Retention notice** — static footer informs users that notification history is deleted after 30 days

## Usage Example

```typescript
// Rendered by the notifications route — no props required
import { NotificationsPageView } from './notifications-page-view';

export default function NotificationsPage() {
  return <NotificationsPageView />;
}
```

> **Note:** Requires Relay environment, `ToastProvider`, and `ApiParamsProvider` in the component tree. The two query loaders are disposed automatically on unmount via `useEffect` cleanup.
