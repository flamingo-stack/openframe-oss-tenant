Renders the full notifications page with two sections — **New Notifications** (unread) and **Notifications History** (read) — each with debounced search, Relay-powered pagination, and bulk action controls.

## Key Components

- **`NotificationsPageView`** — Top-level page component managing state, queries, and mutations for both notification sections
- **`useApiParams`** — Syncs `searchNew` / `searchHistory` values to URL query params
- **`useDebounce`** — Delays search query updates by 300ms to avoid excessive network requests
- **`useQueryLoader`** — Loads two independent Relay queries (`newQueryRef`, `historyQueryRef`) driven by debounced search and filter state
- **`useNotificationMutations`** — Provides `markRead`, `markAllRead`, `removeNotification`, `removeAllRead`, plus loading flags `isMarkingAllRead` / `isDeletingAllRead`
- **`NotificationsSection`** — Reusable section component rendered twice with different `rowVariant`, query refs, and bulk action buttons

## Usage Example

```typescript
// Render as a Next.js page component
import { NotificationsPageView } from './notifications-page-view';

export default function NotificationsPage() {
  return <NotificationsPageView />;
}
```

## Behavior Notes

- Search inputs are controlled locally (`useState`) and synced to URL params only after the 300ms debounce settles
- Each `useQueryLoader` effect disposes its query on cleanup to prevent memory leaks
- `filterPairs` passed to `useNotificationMutations` includes both the active filtered pair and `UNFILTERED_NOTIFICATION_PAIR`, ensuring Relay store updates apply to all relevant connection records
- A 30-day retention notice is rendered below both sections as a static footer
