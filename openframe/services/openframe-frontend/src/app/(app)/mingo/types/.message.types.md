TypeScript type definitions and type guards for chat message handling, covering both GraphQL API responses and core UI message structures used across the messaging layer.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `GraphQlMessage` | Interface | Raw message shape returned from the GraphQL API, including dialog metadata and owner info |
| `CoreMessage` | Interface | Normalized message format consumed by UI components, with role, content, and author metadata |
| `Message` | Type alias | Alias for `CoreMessage` — primary message type used throughout the app |
| `MessageConnection` | Interface | Paginated GraphQL connection wrapper with edges/cursors and `pageInfo` |
| `MessagesResponse` | Interface | Top-level GraphQL response envelope for message queries |
| `MessagePage` | Interface | Flattened, post-processed page of messages with pagination metadata |
| `isGraphQlMessage()` | Type guard | Narrows `any` to `GraphQlMessage` by checking for `messageData` property |
| `isCoreMessage()` | Type guard | Narrows `any` to `CoreMessage` by checking for `content` property |

## Usage Example

```typescript
import {
  type GraphQlMessage,
  type CoreMessage,
  isGraphQlMessage,
  isCoreMessage,
} from './message.types';

function processMessage(message: GraphQlMessage | CoreMessage) {
  if (isGraphQlMessage(message)) {
    // Access GraphQL-specific fields
    console.log(message.dialogId, message.owner.type);
  }

  if (isCoreMessage(message)) {
    // Access UI-layer fields
    console.log(message.role, message.content, message.assistantType);
  }
}

// Handling paginated GraphQL responses
function extractMessages(response: MessagesResponse): GraphQlMessage[] {
  return response.data.messages.edges.map(edge => edge.node);
}
```

## Notes

- `GraphQlMessage` uses `messageData: any` intentionally — the raw GraphQL payload is transformed before being mapped to `CoreMessage`
- The `Message` alias exists for forward-compatibility; prefer `Message` over `CoreMessage` in consumer code
- Pagination follows the [Relay cursor connection spec](https://relay.dev/graphql/connections.htm) via `MessageConnection`
