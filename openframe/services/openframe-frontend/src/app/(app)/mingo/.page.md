Client-side page component for the Mingo AI chat interface, handling dialog management, real-time subscriptions, message sending, and model display within the Flamingo MSP platform.

## Key Components

| Export/Hook | Purpose |
|---|---|
| `Mingo` (default) | Main chat page component with sidebar, message list, and composer |
| `useMingoChat` | Sends messages, creates dialogs, manages typing/compacting state |
| `useMingoDialogs` | Paginated list of chat dialogs for the sidebar |
| `useMingoDialogSelection` | Loads messages and approval state for the active dialog |
| `useMingoRealtimeSubscription` | WebSocket subscriptions for live message updates |
| `useMingoMessagesStore` | Zustand store tracking active dialog, unread counts, and token usage |
| `useMingoDialog` | Resets dialog state on new chat |
| `useMingoDialogSelection` | Handles approve/reject actions on AI tool-call confirmations |

## Usage Example

```typescript
// Rendered automatically by Next.js at /mingo
// Key interaction flows:

// 1. New chat draft (default on load with no ?dialogId)
const effectiveDraft = isDraftChat || (!activeDialogId && !urlDialogId);

// 2. Select an existing dialog
await handleDialogSelect('dialog-123');
// → Updates URL: /mingo?dialogId=dialog-123
// → Subscribes to real-time events for that dialog

// 3. Send a message (creates dialog on first message in draft)
await handleSendMessage('How do I restart the DNS service?');

// 4. Start a new chat (resets state + clears ?dialogId from URL)
handleNewChat();
```

## Notes

- **SaaS-only:** Redirects to `/dashboard` if `isSaasTenantMode()` returns `false`
- **Token usage:** Resolved from the Zustand store first (kept live by realtime frames), falling back to the dialog query result to prevent skeleton flicker on dialog switches
- **Draft state:** No empty/logo screen — `/mingo` with no `?dialogId` immediately shows a welcome message and focused input
- **Keyboard shortcuts:** `Escape` closes the sidebar, cancels draft, or removes `?dialogId` from the URL
