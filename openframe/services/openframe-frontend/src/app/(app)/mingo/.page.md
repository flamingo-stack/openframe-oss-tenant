Client-side Next.js page component for the Mingo AI chat interface, orchestrating real-time messaging, dialog management, model state, and sidebar navigation for the Flamingo MSP platform.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `Mingo` | Default export | Main page component rendering the full Mingo AI chat UI |
| `dynamic` | Config | Forces Next.js dynamic rendering (no SSG/SSR caching) |

## Key Hooks Used

| Hook | Purpose |
|------|---------|
| `useMingoChat` | Manages message sending, dialog creation, typing state, and AI approvals |
| `useMingoDialogs` | Fetches paginated dialog list for the sidebar |
| `useMingoDialogSelection` | Handles loading/switching between dialogs |
| `useMingoRealtimeSubscription` | WebSocket subscription for live message updates |
| `useMingoMessagesStore` | Zustand store for active dialog ID, unread counts, and token usage |
| `useAiModelStatus` | Resolves the current AI model config |

## State Management

```typescript
// Draft state: new chat before first message is sent
const effectiveDraft = isDraftChat || (!activeDialogId && !urlDialogId);

// Prevents token usage row from blinking on dialog switch
const tokenUsage = useMemo(() => {
  const cached = tokenUsageByDialog.get(activeDialogId);
  if (cached) return cached;
  return dialogData?.tokenUsage?.find(t => t.chatType === 'ADMIN_AI_CHAT');
}, [activeDialogId, tokenUsageByDialog, dialogData?.tokenUsage]);
```

## Usage Example

```typescript
// Rendered via Next.js routing at /mingo
// Supports URL-driven dialog selection:
// /mingo?dialogId=<uuid>

// New chat flow:
handleNewChat();          // clears URL, sets draft mode
handleSendMessage(text);  // creates dialog, then sends message

// Existing dialog flow:
handleDialogSelect(id);   // updates URL + store, fetches messages
```

## Notable Behaviors

- **Draft mode** — `/mingo` with no `dialogId` shows a welcome message and focused input instead of an empty screen
- **URL-sync** — Active dialog is mirrored to `?dialogId=` for deep-linking and back navigation
- **No input flicker** — `chatInputRef.current?.clear()` is called imperatively (not via `key` remount) on dialog switch
- **Model row stability** — `displayModel` falls back to `initialAiModel` so the model/token row never flashes empty between dialog switches
- **Escape key** — Closes sidebar → exits draft → clears dialog URL param, in that priority order
