GraphQL query definitions for the Mingo AI dialog system, providing queries to fetch dialog lists, individual dialog details, and paginated dialog messages with optional thinking data support.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `GET_MINGO_DIALOGS_QUERY` | `string` | Paginated list of dialogs with cursor-based pagination, filtering, and search |
| `GET_MINGO_DIALOG_QUERY` | `string` | Single dialog detail including owner, token usage, rating, and AI resolution metadata |
| `getMingoDialogMessagesQuery` | `function` | Returns a messages query string with optional `ThinkingData` fragment inclusion |

## Usage Example

```typescript
import {
  GET_MINGO_DIALOGS_QUERY,
  GET_MINGO_DIALOG_QUERY,
  getMingoDialogMessagesQuery,
} from './dialogs-queries';

// Fetch paginated dialogs
const result = await gqlClient.query(GET_MINGO_DIALOGS_QUERY, {
  filter: { status: 'OPEN' },
  pagination: { limit: 20 },
  search: 'printer issue',
});

// Fetch a single dialog by ID
const dialog = await gqlClient.query(GET_MINGO_DIALOG_QUERY, {
  id: 'dialog-123',
});

// Fetch messages — include AI thinking steps
const messagesQuery = getMingoDialogMessagesQuery({ includeThinking: true });
const messages = await gqlClient.query(messagesQuery, {
  dialogId: 'dialog-123',
  limit: 50,
  sortField: 'createdAt',
  sortDirection: 'ASC',
});
```

## Notes

- `getMingoDialogMessagesQuery` conditionally injects a `ThinkingData` inline fragment via the `includeThinking` option (default: `false`), keeping the payload lean for standard clients while enabling debug/dev views.
- Message `messageData` supports a union of types: `TextData`, `ExecutingToolData`, `ExecutedToolData`, `ApprovalRequestData`, `ApprovalResultData`, `ContextCompactionStartData`, `ContextCompactionEndData`, and `ErrorData`.
