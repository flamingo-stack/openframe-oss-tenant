GraphQL query definitions for fetching Mingo AI dialog data, including paginated dialog lists, individual dialog details, and dialog messages with optional thinking content.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `GET_MINGO_DIALOGS_QUERY` | `string` | Paginated list of dialogs with cursor-based pagination, filtering, and search |
| `GET_MINGO_DIALOG_QUERY` | `string` | Single dialog detail including owner, token usage, rating, and stream state |
| `getMingoDialogMessagesQuery` | `function` | Returns a messages query string with optional `ThinkingData` fragment inclusion |

## Usage Example

```typescript
import {
  GET_MINGO_DIALOGS_QUERY,
  GET_MINGO_DIALOG_QUERY,
  getMingoDialogMessagesQuery,
} from './dialogs-queries';

// Fetch paginated dialogs
const dialogsResult = await gqlClient.query(GET_MINGO_DIALOGS_QUERY, {
  filter: { status: 'OPEN' },
  pagination: { limit: 20 },
  search: 'network issue',
});

// Fetch a single dialog by ID
const dialogResult = await gqlClient.query(GET_MINGO_DIALOG_QUERY, {
  id: 'dialog-123',
});

// Fetch messages — include ThinkingData fragments for AI reasoning visibility
const messagesQuery = getMingoDialogMessagesQuery({ includeThinking: true });
const messagesResult = await gqlClient.query(messagesQuery, {
  dialogId: 'dialog-123',
  limit: 50,
  sortField: 'createdAt',
  sortDirection: 'ASC',
});
```

## Notes

- `getMingoDialogMessagesQuery` conditionally injects a `ThinkingData` fragment via the `includeThinking` option (default: `false`), allowing callers to opt into AI reasoning traces.
- Message nodes support a union `messageData` type covering tool execution, approval flows, context compaction, and error states.
- All list queries use **cursor-based pagination** via `pageInfo` (`startCursor`, `endCursor`, `hasNextPage`, `hasPreviousPage`).
