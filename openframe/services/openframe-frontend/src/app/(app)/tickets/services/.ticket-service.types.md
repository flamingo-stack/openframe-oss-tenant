Defines the TypeScript contracts for the ticket service layer, including parameter shapes, paginated response types, and the `TicketService` interface that all ticket-related data operations must implement.

## Key Components

**Paginated Response Types**
- `TicketsPage` — paginated list of dialogs with cursor-based `pageInfo` and `filteredCount`
- `MessagePage` — paginated list of messages with cursor-based `pageInfo`
- `TicketsBoardPage` — a `Record<BoardStatus, TicketsPage>` representing Kanban board columns

**Parameter Interfaces**
- `FetchTicketsParams` — filter/pagination options for list views (statuses, assignees, organizations, cursor)
- `FetchTicketsBoardParams` — lighter params for board view (no status filter needed)
- `FetchBoardColumnByStatusIdParams` — fetches a single board column by lifecycle status ID
- `FetchMessagesParams` — dialog message fetch with sort direction and `ChatType`
- `ReorderTicketParams` — drag-and-drop reorder payload with optional `status` and `statusId`

**Status & Transition Types**
- `BoardStatus` — union of `'ACTIVE' | 'TECH_REQUIRED' | 'ON_HOLD' | 'RESOLVED'`
- `TicketStatusTransition` — typed transition using `DialogStatus`
- `TicketStatusTransitionRule` — raw string-based transition rule (e.g., from external config)

**Service Interface**
- `TicketService` — the core contract defining all ticket operations
