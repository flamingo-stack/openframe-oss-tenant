Implements the `TicketService` class, which acts as a GraphQL-backed data layer for fetching and mutating ticket (dialog) data, normalizing ticket nodes into the shared `Dialog` type used across the Flamingo/OpenFrame frontend.

## Key Components

- **`TicketService`** — Main class implementing `TicketServiceInterface` with methods for tickets and dialogs
- **`normalizeTicketToDialog()`** — Transforms raw `TicketNode` GraphQL responses into the `Dialog` type
- **`mutateTicketStatus()`** — Private helper dispatching status-change GraphQL mutations
- **Status maps** — `TICKET_TO_DIALOG_STATUS`, `DIALOG_TO_TICKET_STATUS`, and `STATUS_TO_MUTATION` for bidirectional status translation

### Public Methods

| Method | Description |
|---|---|
| `fetchDialogs(params)` | Paginated ticket list with filter/search support |
| `fetchTicketsBoard(params)` | Fetches all board columns (ACTIVE, TECH_REQUIRED, ON_HOLD, RESOLVED) in one query |
| `fetchBoardColumnByStatusId(params)` | Fetches a single board column by custom status ID |
| `fetchDialog(id)` | Fetches a single ticket by ID |
| `fetchMessages(params)` | Fetches paginated dialog messages (chat history) |
| `updateStatus(ticketId, status)` | Updates ticket status, returns boolean |
| `mutateStatus(ticketId, status)` | Dispatches the appropriate GraphQL mutation for status change |

## Usage Example

```typescript
import { TicketService } from './ticket-service';

const service = new TicketService();

// Fetch paginated tickets filtered by status
const page = await service.fetchDialogs({
  limit: 20,
  statuses: ['ACTIVE', 'TECH_REQUIRED'],
  organizationIds: ['org-123'],
  search: 'printer issue',
});

// Fetch the full board view
const board = await service.fetchTicketsBoard({
  limit: 10,
  organizationIds: ['org-123'],
});

// Fetch a single ticket as a Dialog
const dialog = await service.fetchDialog('ticket-id-abc');

// Transition a ticket to ON_HOLD
await service.mutateStatus('ticket-id-abc', 'ON_HOLD');
```
