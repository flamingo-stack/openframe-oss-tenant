Defines the column configuration and table body component for rendering ticket (dialog) data in a `DataTable`, including title, source, assignee, status, and open-in-new-tab action columns.

## Key Components

- **`getTicketTableColumns(options)`** — Returns an array of `ColumnDef<Dialog>` for title, source, assignee, and status columns. Accepts `isArchived` to conditionally enable status filtering options.
- **`ticketRowHref(ticket)`** — Derives the navigation URL for a ticket row (`/tickets/dialog?id=<id>`).
- **`TICKET_OPEN_COLUMN`** — A static column definition rendering an icon button that opens the ticket in a new browser tab, bypassing row-click navigation.
- **`TicketTableBody`** — A composed table component that wires columns, data, filtering state, loading skeletons, and an optional footer into a fully rendered `DataTable`.

## Usage Example

```typescript
// Basic usage with archived tickets and custom actions column
import { TicketTableBody } from './ticket-table-columns';

function ArchivedTicketsPage({ tickets }: { tickets: Dialog[] }) {
  return (
    <TicketTableBody
      tickets={tickets}
      isLoading={false}
      isArchived={true}
      emptyMessage="No archived tickets."
      skeletonRows={5}
      stickyHeaderOffset="64px"
    />
  );
}

// Consuming column definitions directly
import { getTicketTableColumns, TICKET_OPEN_COLUMN } from './ticket-table-columns';

const columns = [
  ...getTicketTableColumns({ isArchived: false }),
  TICKET_OPEN_COLUMN,
];
```

## Notes

- The `sourceColumn` resolves device/machine info from either `ticket.deviceHostname` or a `ClientDialogOwner` owner shape.
- `statusColumn` includes a `multiSelectFilterFn` with predefined status options (`ACTIVE`, `TECH_REQUIRED`, `ON_HOLD`, `RESOLVED`) only when `isArchived` is `false`.
- Columns are responsive: `sourceColumn` hides at `md` breakpoint, `middleColumn` (assignee) hides at `lg`.
