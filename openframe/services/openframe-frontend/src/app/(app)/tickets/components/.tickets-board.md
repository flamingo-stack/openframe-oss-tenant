Kanban-style board view for tickets, rendering draggable columns by ticket status with search, organization, and assignee filtering.

## Key Components

- **`TicketsBoard`** — Main exported component that composes the full board UI inside a `PageLayout`
- **`dialogToBoardTicket`** — Maps internal `Dialog` type to the `BoardTicket` shape expected by the core `Board` component
- **`initialsOf`** — Utility that derives 1–2 character initials from a display name for assignee avatars

## Props (`TicketsBoardProps`)

| Prop | Type | Description |
|------|------|-------------|
| `selector` | `ReactNode` | Optional slot rendered in the page header |
| `organizationIds` | `string[]` | Active organization filter values |
| `assigneeIds` | `string[]` | Active assignee filter values |
| `search` | `string` | Controlled search string (debounced internally at 300 ms) |
| `onSearchChange` | `(value: string) => void` | Search input change handler |
| `onOrganizationIdsChange` | `(ids: string[]) => void` | Organization filter change handler |
| `onAssigneeIdsChange` | `(ids: string[]) => void` | Assignee filter change handler |

## Key Behaviors

- **Status transitions** — `useTicketStatusTransitions` determines which source columns are allowed to drop into each target column (`allowedFromByStatus`)
- **Drag & drop** — `BoardChange` events call `useMoveTicket` with source/target status and optional before/after ticket anchors for ordering
- **Load more** — Each column exposes a `hasMore` flag and delegates pagination to `useTicketsBoardQuery`
- **System columns** — `ACTIVE`, `TECH_REQUIRED`, and `RESOLVED` are flagged as non-deletable system columns

## Usage Example

```typescript
<TicketsBoard
  search={search}
  onSearchChange={setSearch}
  organizationIds={selectedOrgIds}
  onOrganizationIdsChange={setSelectedOrgIds}
  assigneeIds={selectedAssigneeIds}
  onAssigneeIdsChange={setSelectedAssigneeIds}
/>
```
