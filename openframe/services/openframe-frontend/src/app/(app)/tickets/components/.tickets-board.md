Kanban-style board view for ticket management, rendering tickets grouped by status columns with drag-and-drop reordering, filtering, and inline assignee picking.

## Key Components

- **`TicketsBoard`** — Main exported component. Composes the full board UI including search, filters, and the draggable `Board`.
- **`dialogToBoardTicket`** — Transforms a `Dialog` entity into a `BoardTicket` shape consumed by the core `Board` component.
- **`initialsOf`** — Derives a 1–2 character initials string from a display name for avatar fallbacks.

## Key Hooks Used

| Hook | Purpose |
|---|---|
| `useTicketsBoardQuery` | Fetches paginated ticket columns by status |
| `useMoveTicket` / `useMovingTicketIds` | Handles optimistic drag-and-drop moves |
| `useTicketStatusTransitions` | Determines which columns a ticket can move to |
| `useTicketsActions` | Provides page-level actions (e.g. archive resolved) |
| `useDebounce` | Debounces the search input (300 ms) |

## Usage Example

```typescript
'use client';
import { useState } from 'react';
import { TicketsBoard } from './tickets-board';

export default function TicketsPage() {
  const [search, setSearch] = useState('');
  const [orgIds, setOrgIds] = useState<string[]>([]);
  const [assigneeIds, setAssigneeIds] = useState<string[]>([]);

  return (
    <TicketsBoard
      search={search}
      onSearchChange={setSearch}
      organizationIds={orgIds}
      onOrganizationIdsChange={setOrgIds}
      assigneeIds={assigneeIds}
      onAssigneeIdsChange={setAssigneeIds}
    />
  );
}
```

> **Note:** `organizationIds`, `assigneeIds`, and `selector` are all optional. Omitting them renders the board without pre-filtering. The `allowedFromByStatus` map is derived from live status-transition rules, so drop targets are automatically restricted based on your workflow configuration.
