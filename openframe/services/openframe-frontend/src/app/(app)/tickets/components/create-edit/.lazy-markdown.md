Lazily loads `SimpleMarkdownRenderer` and `MarkdownEditor` from `@flamingo-stack/openframe-frontend-core` using Next.js dynamic imports, disabling SSR to prevent server-side rendering issues with rich client-side components.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `SimpleMarkdownRenderer` | Dynamic Component | Client-only markdown renderer, SSR disabled |
| `MarkdownEditor` | Dynamic Component | Client-only markdown editor, SSR disabled |

## Usage Example

```typescript
import { SimpleMarkdownRenderer, MarkdownEditor } from './lazy-markdown';

// Render markdown content
<SimpleMarkdownRenderer content="## Hello World" />

// Render an editor
<MarkdownEditor value={content} onChange={setContent} />
```

## Notes

- Both components render `null` during their loading state
- The `'use client'` directive marks this as a Next.js Client Component boundary
- Avoids SSR hydration mismatches for markdown libraries that rely on browser APIs
