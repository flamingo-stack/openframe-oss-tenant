Lazy-loads `SimpleMarkdownRenderer` and `MarkdownEditor` from the OpenFrame frontend core using Next.js dynamic imports, disabling SSR to prevent hydration issues with client-only markdown components.

## Key Components

- **`SimpleMarkdownRenderer`** — Dynamically imported markdown renderer, client-side only
- **`MarkdownEditor`** — Dynamically imported markdown editor, client-side only

## Usage Example

```typescript
import { SimpleMarkdownRenderer, MarkdownEditor } from './lazy-markdown';

// Render markdown content
<SimpleMarkdownRenderer content="## Hello World" />

// Editable markdown input
<MarkdownEditor value={markdown} onChange={setMarkdown} />
```

> Both components render `null` during loading and are never server-side rendered, making them safe to use in SSR/RSC environments without hydration mismatches.
