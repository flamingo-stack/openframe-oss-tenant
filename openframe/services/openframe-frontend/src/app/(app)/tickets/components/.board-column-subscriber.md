Headless React component that manages an infinite-scroll TanStack Query for a single Kanban board column, enabling a dynamic number of columns without violating React's rules of hooks.

## Key Components

### `BoardColumnSubscriber` (component)
A renderless component (`return null`) that owns one column's `useInfiniteQuery` instance. Communicates state upward via callbacks rather than rendering UI.

### `BoardColumnUpdate` (interface)
The payload shape passed to `onUpdate` on every query state change:
- `state` — `BoardColumnState` containing tickets, total count, cursor, pagination flags, and loading-more status
- `isLoading` — initial loading flag
- `error` — query error or `null`

### `BoardColumnSubscriberProps` (interface)
| Prop | Description |
|---|---|
| `statusId` | Identifies the column and scopes the query cache key |
| `params` | Filter params: `search`, `organizationIds`, `assigneeIds` |
| `onUpdate` | Called on every query state change with the latest `BoardColumnUpdate` |
| `registerLoadMore` | Registers a `fetchNextPage` callback keyed by `statusId` |

## Query Behavior

| Option | Value |
|---|---|
| `staleTime` | 60 s |
| `gcTime` | 5 min |
| `refetchInterval` | 15 s |
| `retry` | 2 attempts, 1 s delay |
| `pageSize` | `BOARD_PAGE_SIZE` constant |

Cache key: `dialogsQueryKeys.boardColumnLifecycle(statusId, filters)` — the same key targeted by `applyOptimisticMoveLifecycle` for optimistic updates.

## Usage Example

```typescript
// Parent board renders one subscriber per status column
{statusIds.map(statusId => (
  <BoardColumnSubscriber
    key={statusId}
    statusId={statusId}
    params={{ search, organizationIds, assigneeIds }}
    onUpdate={(id, update) => dispatch({ type: 'COLUMN_UPDATE', id, update })}
    registerLoadMore={(id, fn) => loadMoreRegistry.current.set(id, fn)}
  />
))}

// Trigger pagination from anywhere in the board
loadMoreRegistry.current.get(statusId)?.();
```
