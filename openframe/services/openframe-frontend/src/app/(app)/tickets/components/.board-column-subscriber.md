Headless React component that manages a single board column's infinite pagination query, enabling a dynamic number of columns without violating React's rules of hooks.

## Key Components

### `BoardColumnSubscriber`
A render-nothing component (`return null`) that owns one column's `useInfiniteQuery` instance. Propagates query state and load-more callbacks to the parent board via callbacks.

### `BoardColumnUpdate` (interface)
Payload emitted on every query state change, containing:
- `state` — `BoardColumnState` with accumulated tickets, pagination cursors, and loading flags
- `isLoading` — initial load indicator
- `error` — any query error or `null`

### `BoardColumnSubscriberProps` (interface)
| Prop | Description |
|---|---|
| `statusId` | Column identifier; scopes the react-query cache key |
| `params` | Filter options: `search`, `organizationIds`, `assigneeIds` |
| `onUpdate` | Called whenever query state changes |
| `registerLoadMore` | Registers a `fetchNextPage` trigger with the parent |

## Usage Example

```typescript
// Mount one subscriber per board column
columns.map(col => (
  <BoardColumnSubscriber
    key={col.statusId}
    statusId={col.statusId}
    params={{ search, organizationIds, assigneeIds }}
    onUpdate={(statusId, update) => {
      setColumnStates(prev => ({ ...prev, [statusId]: update }));
    }}
    registerLoadMore={(statusId, loadMore) => {
      loadMoreRegistry.current[statusId] = loadMore;
    }}
  />
))
```

## Query Behaviour

| Setting | Value | Purpose |
|---|---|---|
| `staleTime` | 60 s | Prevents redundant background refetches |
| `refetchInterval` | 15 s | Keeps column data reasonably fresh |
| `gcTime` | 5 min | Retains pages for optimistic move mutations |
| `retry` | 2 × (1 s delay) | Handles transient network failures |

Cache key (`boardColumnLifecycle`) is intentionally shared with `applyOptimisticMoveLifecycle` so drag-and-drop mutations update the correct paginated data in place.
