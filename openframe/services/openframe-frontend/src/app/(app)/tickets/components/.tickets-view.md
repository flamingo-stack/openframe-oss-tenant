Orchestrates the tickets view by toggling between table and board display modes, managing shared filter state (status, organizations, assignees, search) via URL params and delegating rendering to `TicketsBoard` or `CurrentTickets`.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `TicketsView` | React Component | Top-level tickets view with mode switching and shared filter state |
| `ViewMode` | Type | `'table' \| 'board'` |

**Internal dependencies:**
- `featureFlags.ticketsBoard` — gates board mode availability
- `useApiParams` — syncs filter state to URL query params
- `TabSelector` — icon-based toggle rendered only when board feature is enabled
- `TicketsBoard` / `CurrentTickets` — view-specific components receiving filtered props

## Usage Example

```typescript
// Drop-in as the main tickets page content
import { TicketsView } from './tickets-view';

export default function TicketsPage() {
  return <TicketsView />;
}
```

## Behavior Notes

- **Feature-flagged:** Board view and its `TabSelector` are only rendered when `featureFlags.ticketsBoard.enabled()` returns `true`; otherwise the component always renders the table view
- **URL-persisted state:** All filter params (`status`, `organizationIds`, `assigneeIds`, `search`, `viewMode`) are stored via `useApiParams`, making filters bookmarkable and shareable
- **Default view mode:** Defaults to `'board'` when the flag is enabled, `'table'` otherwise
- **Shared `selector`:** The `TabSelector` is passed as a `selector` prop into both child views so each can position it within its own layout
