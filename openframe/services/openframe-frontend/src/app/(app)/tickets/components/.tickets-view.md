Top-level orchestrator component for the tickets feature that conditionally renders either a table or board view based on feature flags and URL-persisted view mode state.

## Key Components

- **`TicketsView`** — Main exported component that manages view mode switching, filter state, and conditional rendering of child views
- **`ViewMode`** — Union type (`'table' | 'board'`) defining available display modes
- **Filter handlers** — Memoized callbacks for `status`, `organizationIds`, `assigneeIds`, and `search` parameters, synced to URL via `useApiParams`
- **`tabs`** — Memoized `TabSelector` rendered only when the `ticketsBoard` feature flag is enabled; provides table/board toggle icons

## Feature Flag Behavior

| Flag | Effect |
|---|---|
| `featureFlags.ticketsBoard` | Enables board view and tab switcher |
| `featureFlags.ticketStatuses` | Switches board from `TicketsBoard` to `TicketsBoardLifecycle` |

## Usage Example

```typescript
// Render the full tickets view with URL-driven state
import { TicketsView } from './tickets-view';

export default function TicketsPage() {
  return <TicketsView />;
}
```

```typescript
// View mode resolves from URL params, e.g.:
// ?viewMode=board&organizationIds[]=org1&search=vpn
// Falls back to 'board' if ticketsBoard flag is enabled, else 'table'
```

## Notes

- All filter state is persisted in URL query params via `useApiParams`, enabling shareable/bookmarkable filter combinations
- The board component variant (`TicketsBoard` vs `TicketsBoardLifecycle`) is resolved at render time from the `ticketStatuses` feature flag
