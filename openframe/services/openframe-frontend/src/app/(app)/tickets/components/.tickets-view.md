Top-level tickets view component that manages view mode switching (table vs. board) and shared filter state across the tickets feature.

## Key Components

**`TicketsView`** — Main export. Reads feature flags to determine available views, manages URL-persisted filter params, and renders either a board or table layout.

**`ViewMode`** — Union type `'table' | 'board'` controlling the active layout.

**Filter params (via `useApiParams`):**

| Param | Type | Description |
|---|---|---|
| `status` | `string[]` | Active status filters |
| `organizationIds` | `string[]` | Organization filter |
| `assigneeIds` | `string[]` | Assignee filter |
| `search` | `string` | Search query |
| `viewMode` | `string` | Active view (`'table'` or `'board'`) |

**Feature flag behavior:**
- `featureFlags.ticketsBoard` — enables the board view and `TabSelector` toggle
- `featureFlags.ticketStatuses` — switches the board component between `TicketsBoardLifecycle` (lifecycle-aware) and `TicketsBoard` (basic)

## Usage Example

```typescript
// Drop into any page that needs the full tickets interface
import { TicketsView } from './tickets-view';

export default function TicketsPage() {
  return <TicketsView />;
}
```

The component is self-contained — all filter state is stored in URL params, so filters survive page refreshes and are shareable via URL. No props are required.
