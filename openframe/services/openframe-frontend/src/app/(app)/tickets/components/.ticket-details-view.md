Renders the full ticket detail page, managing both client (Fae) and admin (Mingo AI) chat threads, ticket lifecycle, approvals, notes, attachments, and device context in a single unified view.

## Key Components

### Main Export
- **`TicketDetailsView`** — Primary page component accepting a `ticketId` prop; orchestrates all ticket sub-systems

### Helper Utilities
- **`maxLastChunkStreamSeq`** — Extracts the highest stream sequence number from paginated message pages for catchup sync
- **`withActivityTracking`** — Wraps device menu items to fire analytics events on navigation, recursively applying to submenus

### Key Hooks Consumed
| Hook | Purpose |
|---|---|
| `useTicketDetail` | Fetches ticket/dialog metadata |
| `useTicketMessages` | Loads paginated client & admin chat history |
| `useDirectChat` | Manages direct (non-AI) chat mode |
| `useSendAdminMessage` | Sends messages to the Mingo admin channel |
| `useChunkCatchup` | Buffers and replays NATS stream chunks |
| `useSideChunkProcessor` | Parses incoming AI chunks into UI messages |
| `useTicketStatus` | Controls hold/resolve/activate/archive transitions |
| `useApprovalRequests` | Handles approve/reject flows for pending AI actions |
| `useDeviceActionsMenu` | Builds contextual device action menu |

## Usage Example

```typescript
// pages/tickets/[id]/page.tsx
import { TicketDetailsView } from './ticket-details-view';

export default function TicketPage({ params }: { params: { id: string } }) {
  return <TicketDetailsView ticketId={params.id} />;
}
```

## State Management
The component uses `useTicketDetailsStore` (Zustand) to share streaming chat state — accumulator callbacks, approval statuses, and per-channel typing indicators — across client and admin chat panels without prop drilling.
