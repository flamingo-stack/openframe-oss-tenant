Renders the full ticket details view for a single support ticket, orchestrating client/admin chat tabs, AI message streaming, approval workflows, device actions, notes, attachments, and ticket lifecycle transitions.

## Key Components

### Main Export
- **`TicketDetailsView`** — Primary view component accepting a `ticketId` prop; renders a `PageLayout` with tabbed chat panels, ticket metadata, and action menus

### Helper Utilities
- **`maxLastChunkStreamSeq`** — Extracts the highest `lastChunkStreamSeq` value from paginated message history to synchronize streaming state
- **`withActivityTracking`** — Wraps `ActionsMenuItem` entries (including nested submenus) to fire `trackDashboardActivity` analytics events on click

### Key Hooks Consumed
| Hook | Purpose |
|------|---------|
| `useTicketDetail` | Fetches ticket/dialog metadata |
| `useTicketMessages` | Loads paginated client & admin chat history |
| `useDirectChat` | Manages direct-to-client chat mode |
| `useSendAdminMessage` | Sends technician (Mingo AI) messages |
| `useChunkCatchup` | Buffers and replays streaming AI chunks |
| `useSideChunkProcessor` | Routes incoming NATS chunks to client/admin state |
| `useDeviceActionsMenu` | Builds remote-action menu for the linked device |
| `useApprovalRequests` | Handles approve/reject flows for pending AI actions |
| `useTicketStatus` | Exposes `putOnHold`, `resolve`, `activate`, `archive` |

## Usage Example

```typescript
// app/tickets/[ticketId]/page.tsx
import { TicketDetailsView } from './ticket-details-view';

export default function TicketPage({ params }: { params: { ticketId: string } }) {
  return <TicketDetailsView ticketId={params.ticketId} />;
}
```

## Notes

- Supports both **Fae** (client-facing) and **Mingo** (admin/technician) AI assistants simultaneously via split chat tabs
- Detects **context compaction** in progress (`isCompacting`) to suppress duplicate streaming indicators
- `machineId` resolution prefers `owner.machineId` over `dialog.deviceId` to avoid Mongo ObjectId passthrough mismatches
- Feature-flagged lifecycle status transitions via `featureFlags.ticketStatuses`
