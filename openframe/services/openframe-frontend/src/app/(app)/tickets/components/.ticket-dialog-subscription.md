Headless React component that manages real-time NATS message subscriptions for a ticket dialog, supporting both legacy NATS core and JetStream delivery modes controlled by a feature flag.

## Key Components

### `TicketDialogSubscription`
A render-nothing (`return null`) component that encapsulates all subscription lifecycle logic for a ticket dialog.

| Prop | Description |
|------|-------------|
| `dialogId` | Active dialog identifier; changing it resets all state |
| `dispatchChunk` | Direct chunk dispatcher for JetStream messages |
| `legacyProcessChunk` | Buffered processor for legacy NATS messages |
| `catchUpChunks` | Initial catch-up on first subscription |
| `resetAndCatchUp` | Re-runs catch-up after a reconnect |
| `clientInitialOptStartSeq` | JetStream resume sequence for client topic |
| `adminInitialOptStartSeq` | JetStream resume sequence for admin topic |
| `isInitialOptStartSeqReady` | Gates JetStream consumer creation until history is loaded |

### Internal Behavior

- **Mode selection** — `featureFlags.aiStreamingJetstream.enabled()` is evaluated once at mount to choose between JetStream and legacy NATS core.
- **Deduplication** — Per-topic `lastClientStreamSeqRef` / `lastAdminStreamSeqRef` refs drop any redelivered JetStream messages already applied.
- **Catch-up guard** — `hasCaughtUpRef` ensures `catchUpChunks` runs exactly once per dialog session; `resetAndCatchUp` is triggered on legacy reconnects.
- **Stable callbacks** — `dispatchChunk` and `legacyProcessChunk` are held in refs so `useCallback` handlers never go stale without causing re-renders.

## Usage Example

```typescript
<TicketDialogSubscription
  dialogId={activeDialogId}
  dispatchChunk={dispatchChunk}
  legacyProcessChunk={processChunk}
  catchUpChunks={catchUpChunks}
  resetAndCatchUp={resetAndCatchUp}
  clientInitialOptStartSeq={clientSeq}
  adminInitialOptStartSeq={adminSeq}
  isInitialOptStartSeqReady={seqReady}
/>
```

> Both `useJetStreamDialogSubscription` hooks (client + admin topics) share the `CHAT_CHUNKS` JetStream stream and are only activated once `isInitialOptStartSeqReady` is `true`.
