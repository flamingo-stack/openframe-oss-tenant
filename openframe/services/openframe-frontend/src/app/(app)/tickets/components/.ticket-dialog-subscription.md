Headless React component that manages real-time NATS/JetStream subscriptions for a ticket dialog, routing incoming chat chunk events to the appropriate processors while handling catch-up, deduplication, and reconnection logic.

## Key Components

### `TicketDialogSubscription`
A render-less component (`return null`) that encapsulates two subscription modes controlled by the `aiStreamingJetstream` feature flag:

- **JetStream mode** — Creates two `useJetStreamDialogSubscription` hooks (client + admin topics) against the `CHAT_CHUNKS` stream, deduplicating redelivered messages via per-topic `lastStreamSeq` refs and dispatching chunks directly via `dispatchChunk`.
- **Legacy NATS mode** — Uses `useNatsDialogSubscriptionCore` for both `MESSAGE` and `ADMIN_MESSAGE` topics, routing chunks through the buffered `legacyProcessChunk` processor and triggering `catchUpChunks` on first subscribe.

**Reconnect handling:**
- Legacy: monitors `legacyReconnectionCount` and calls `resetAndCatchUp()` on re-connection.
- JetStream: consumers resume from `clientInitialOptStartSeq` / `adminInitialOptStartSeq`, gated by `isInitialOptStartSeqReady`.

**State resets on `dialogId` change:** clears `hasCaughtUpRef` and both stream sequence refs.

## Usage Example

```typescript
<TicketDialogSubscription
  dialogId={activeDialogId}
  dispatchChunk={(chunk, type) => sideProcessor.handle(chunk, type)}
  legacyProcessChunk={(chunk, type) => chunkCatchup.process(chunk, type)}
  catchUpChunks={chunkCatchup.catchUp}
  resetAndCatchUp={chunkCatchup.resetAndCatchUp}
  clientInitialOptStartSeq={clientSeq}
  adminInitialOptStartSeq={adminSeq}
  isInitialOptStartSeqReady={historyLoaded}
/>
```

> This component should be mounted once per active dialog. It produces no DOM output and relies entirely on side effects.
