Headless React component that manages real-time NATS message subscriptions for a ticket dialog, supporting both legacy NATS core and JetStream delivery modes based on a feature flag.

## Key Components

**`TicketDialogSubscription`** — Render-nothing (`return null`) component that wires up streaming subscriptions for a given `dialogId`.

- **Legacy mode** (`useNatsDialogSubscriptionCore`) — subscribes to `MESSAGE` and `ADMIN_MESSAGE` topics via NATS core; triggers catch-up on initial subscribe and re-runs it on reconnect via `resetAndCatchUp`.
- **JetStream mode** (`useJetStreamDialogSubscription`) — creates two durable consumers on `CHAT_CHUNKS` stream (client + admin topics), each resuming from a provided sequence number (`optStartSeq`). Duplicate redeliveries are dropped using per-topic `lastStreamSeqRef` guards.
- **Feature flag gate** — `featureFlags.aiStreamingJetstream.enabled()` is evaluated once on mount via `useState` to select the active transport.
- **Ref-stabilized callbacks** — `dispatchChunk` and `legacyProcessChunk` are kept in refs so event handlers never need to be re-created, avoiding unnecessary subscription teardowns.
- **Reset on dialog change** — `hasCaughtUpRef` and stream sequence refs are cleared whenever `dialogId` changes, ensuring clean state for each conversation.

## Usage Example

```typescript
<TicketDialogSubscription
  dialogId={activeTicketId}
  dispatchChunk={(chunk, type) => sideProcessor.handle(chunk, type)}
  legacyProcessChunk={(chunk, type) => chunkBuffer.process(chunk, type)}
  catchUpChunks={async () => await loadMissedChunks()}
  resetAndCatchUp={async () => await resetAndReload()}
  clientInitialOptStartSeq={clientSeq}
  adminInitialOptStartSeq={adminSeq}
  isInitialOptStartSeqReady={historyLoaded}
/>
```

> `isInitialOptStartSeqReady` gates JetStream consumer creation — set it to `true` only after both client and admin message history has fully loaded to avoid replaying already-rendered chunks.
