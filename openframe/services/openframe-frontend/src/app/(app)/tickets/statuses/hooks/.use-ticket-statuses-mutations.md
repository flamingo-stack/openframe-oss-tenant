React Query mutation hooks for managing ticket status CRUD operations — create, update, reorder, and delete — via GraphQL, with toast notifications and query cache invalidation.

## Key Components

### `useSaveTicketStatusesMutation`
Wraps the `saveTicketStatuses` function in a `useMutation` hook. Diffs the current form state against a server snapshot and dispatches the minimal sequence of create → update → reorder GraphQL mutations. On success, invalidates the statuses query cache and shows a success toast.

### `useDeleteTicketStatusMutation`
Standalone mutation hook for deleting a single ticket status. Accepts an optional `replacementStatusId` to reassign tickets before deletion. Invalidates the cache and toasts on completion.

### `saveTicketStatuses` (internal)
Core diffing logic executed in three ordered phases:
1. **Creates** — rows with no matching snapshot ID
2. **Updates** — persisted rows where `name` or `color` changed
3. **Reorders** — only when order changed or new rows were created; uses `precedingSystemId` to anchor the custom group beneath the correct system status

### `precedingSystemId` (internal)
Resolves the system status ID directly preceding the custom group, used as a positional anchor during reorder operations.

## Usage Example

```typescript
// Save (create/update/reorder) ticket statuses
const { mutate: saveStatuses } = useSaveTicketStatusesMutation();

saveStatuses({
  customStatuses: formState.statuses,
  snapshot: serverSnapshot,
});

// Delete a ticket status with reassignment
const { mutate: deleteStatus } = useDeleteTicketStatusMutation();

deleteStatus({
  id: 'status-123',
  replacementStatusId: 'status-456', // optional: reassign open tickets
});
```

## Types

| Type | Description |
|------|-------------|
| `SaveTicketStatusesInput` | `{ customStatuses, snapshot }` passed to the save mutation |
| `DeleteTicketStatusInput` | `{ id, replacementStatusId? }` passed to the delete mutation |
