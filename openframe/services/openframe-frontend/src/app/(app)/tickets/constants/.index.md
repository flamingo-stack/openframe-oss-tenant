Defines shared constants and TypeScript types for the dialog/chat system, covering statuses, message types, assistant configurations, API endpoints, and network settings used across the platform.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `DIALOG_STATUS` | `const` | Dialog lifecycle states: `ON_HOLD`, `RESOLVED`, `ACTIVE`, `ARCHIVED` |
| `TICKET_STATUS` | `const` | Ticket states mirroring the backend `TicketStatus` enum |
| `DIALOG_MODE` | `const` | Interaction mode — `AI` or `DIRECT` |
| `CHAT_TYPE` | `const` | Chat context — `CLIENT_CHAT` or `ADMIN_AI_CHAT` |
| `MESSAGE_TYPE` | `const` | Full message lifecycle types including tool execution and approval flow |
| `OWNER_TYPE` | `const` | Message ownership — `CLIENT`, `ADMIN`, or `ASSISTANT` |
| `APPROVAL_STATUS` | `const` | Approval workflow states: `pending`, `approved`, `rejected` |
| `ASSISTANT_CONFIG` | `const` | AI assistant definitions for **Fae** (client-facing) and **Mingo** (technician-facing) |
| `CREATION_SOURCE` | `const` | Origin of a ticket/dialog — form, dialog, or dashboard |
| `API_ENDPOINTS` | `const` | Chat service REST and GraphQL route constants |
| `NATS_TOPICS` | `const` | NATS pub/sub topic identifiers for real-time messaging |
| `STORAGE_KEYS` | `const` | Browser storage key for the access token |
| `NETWORK_CONFIG` | `const` | Timeouts, reconnect delays, ping intervals, and message pagination limits |

## Usage Example

  DIALOG_STATUS,
  MESSAGE_TYPE,
  ASSISTANT_CONFIG,
  NETWORK_CONFIG,

  type MessageType,
  type AssistantType,

// Type-safe status comparison
function isActive(status: DialogStatus): boolean {
  return status === DIALOG_STATUS.ACTIVE;
}

// Route a message based on type
function handleMessage(type: MessageType) {
  if (type === MESSAGE_TYPE.APPROVAL_REQUEST) {
    // prompt user for approval
  }
}

// Identify the assistant in use
const assistant: AssistantType = ASSISTANT_CONFIG.MINGO.type; // 'mingo'

// Apply network config for SSE/NATS connections
