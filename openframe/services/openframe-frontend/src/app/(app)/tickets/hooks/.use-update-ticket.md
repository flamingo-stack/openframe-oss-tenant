React Query mutation hook for updating tickets, handling field-level GraphQL mutations (assign, unassign, link/unlink device and organization) and navigating on success.

## Key Components

- **`runTicketMutation<K>`** — Generic helper that executes a GraphQL mutation via `apiClient`, extracts the response payload, and throws on `userErrors`.
- **`updateTicketApi`** — Orchestrates multiple conditional GraphQL mutations based on which fields are present in `UpdateTicketInput` (null = unlink/unassign, string = assign/link, omitted = skip).
- **`useUpdateTicket`** — Exported React Query `useMutation` hook that wires up `updateTicketApi` with toast notifications, query cache invalidation, and post-save navigation.

## Usage Example

```typescript
import { useUpdateTicket } from '@/features/tickets/hooks/use-update-ticket';

function TicketEditForm({ ticketId }: { ticketId: string }) {
  const { mutate: updateTicket, isPending } = useUpdateTicket();

  const handleSubmit = (values: FormValues) => {
    updateTicket({
      id: ticketId,
      title: values.title,
      assigneeId: values.assigneeId ?? null, // null = unassign
      deviceId: values.deviceId ?? null,     // null = unlink device
      organizationId: values.organizationId, // undefined = leave unchanged
    });
  };

  return <button disabled={isPending}>Save</button>;
}
```

## Mutation Field Behaviour

| Field value | Action triggered |
|---|---|
| `null` | Unlink/unassign via dedicated mutation |
| `string` | Assign/link via dedicated mutation |
| `undefined` | Field is skipped entirely |

On success, `tickets` and `dialogs` query caches are invalidated and the user is redirected to the ticket dialog or `/tickets` if no ticket ID is returned.
