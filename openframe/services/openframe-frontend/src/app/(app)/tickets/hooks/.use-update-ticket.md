React Query mutation hook for updating tickets, handling assignment, device/organization linking, and field updates via sequential GraphQL mutations.

## Key Components

- **`runTicketMutation<K>`** — Generic helper that executes a single GraphQL mutation via `apiClient`, extracts the response data, and throws on `userErrors`.
- **`updateTicketApi`** — Orchestrates up to four sequential mutations based on which fields are present in the input:
  - `null` values trigger unlink/unassign mutations (`unlinkOrganizationFromTicket`, `unlinkDeviceFromTicket`, `unassignTicket`)
  - `string` values trigger assign/link mutations (`assignTicket`)
  - Remaining fields are batched into a single `updateTicket` mutation
- **`useUpdateTicket`** — Exported React Query `useMutation` hook that wraps `updateTicketApi` with toast notifications, query cache invalidation, and post-save navigation.

## Usage Example

```typescript
import { useUpdateTicket } from '@/features/tickets/hooks/use-update-ticket';

function TicketForm({ ticketId }: { ticketId: string }) {
  const { mutate: updateTicket, isPending } = useUpdateTicket();

  const handleSubmit = () => {
    updateTicket({
      id: ticketId,
      title: 'Updated Title',
      assigneeId: 'user-123',   // assign → triggers assignTicket mutation
      organizationId: null,      // null  → triggers unlink mutation
      deviceId: 'device-456',   // string → included in updateTicket mutation
    });
  };

  return <button disabled={isPending} onClick={handleSubmit}>Save</button>;
}
```

## Behavior Notes

| Input Value | Action |
|-------------|--------|
| `null` | Triggers dedicated unlink/unassign mutation |
| `string` | Triggers assign mutation or includes in general update |
| `undefined` | Field is ignored entirely |

On success, invalidates both `ticketsQueryKeys.all` and `dialogsQueryKeys.all`, then navigates back or to the ticket dialog.
