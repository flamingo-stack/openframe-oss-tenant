Manages paginated, infinite-scroll data fetching for the Kanban-style tickets board, creating one `useInfiniteQuery` per board column and exposing a unified state object for all columns.

## Key Components

- **`BOARD_PAGE_SIZE`** — Page size constant (20 tickets per fetch)
- **`BOARD_STATUSES`** — Ordered tuple of valid column statuses: `ACTIVE`, `TECH_REQUIRED`, `ON_HOLD`, `RESOLVED`
- **`BoardColumnState`** — Shape of a single column's derived state (tickets, total, pagination metadata, loading flag)
- **`BoardColumnsState`** — `Record<BoardStatus, BoardColumnState>` aggregating all four columns
- **`useBoardColumnQuery`** *(internal)* — Wraps `useInfiniteQuery` for a single status with 15s auto-refetch, 60s stale time, and cursor-based pagination
- **`toColumnState`** *(internal)* — Flattens paginated pages into a single `BoardColumnState`
- **`useTicketsBoardQuery`** — Primary export; composes all four column queries, surfaces errors via toast, and returns `columns`, `loadMore`, `refetch`, and `isLoading`

## Usage Example

```typescript
const { columns, loadMore, refetch, isLoading } = useTicketsBoardQuery({
  search: 'network',
  organizationIds: ['org-123'],
  assigneeIds: ['user-456'],
});

// Render a column
const activeColumn = columns.ACTIVE;
console.log(activeColumn.tickets);   // Dialog[]
console.log(activeColumn.hasMore);   // boolean

// Load next page for a column
loadMore('ACTIVE');

// Invalidate and refetch all board columns
refetch();
```

## Notes

- Each column is independently paginated — `loadMore(columnId)` is a no-op if the column has no next page or is already fetching
- Errors from any column trigger a destructive toast notification and are surfaced as `error: string | null` on the return value
- Filter params (`search`, `organizationIds`, `assigneeIds`) are included in the React Query cache key, so changing them triggers fresh fetches per column
