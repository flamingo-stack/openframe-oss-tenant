Manages temporary file attachment state for ticket forms, handling upload, removal, and lifecycle tracking of both new and existing attachments via GraphQL mutations and presigned S3 URLs.

## Key Components

### Types

| Type | Description |
|------|-------------|
| `TempFileStatus` | Union: `'uploading' \| 'uploaded' \| 'error' \| 'existing'` |
| `TempFileEntry` | File entry with `id`, `fileName`, `fileSize`, `contentType`, `status`, and optional `error` |

### Internal Helpers

- **`createTempAttachment(file)`** — Requests a presigned upload URL via GraphQL, then PUTs the file directly to storage
- **`deleteTempAttachment(id)`** — Removes a temporary (unlinked) attachment via GraphQL
- **`deleteTicketAttachment(id)`** — Removes an attachment already linked to a saved ticket

### `useTempAttachments()` Hook

| Return Value | Description |
|---|---|
| `files` | Current `TempFileEntry[]` state |
| `uploadFile(file)` | Adds a placeholder entry then uploads; resolves to real `id` on success |
| `removeFile(id)` | Deletes temp attachments immediately; defers deletion of `existing` attachments |
| `initializeExisting(attachments)` | Seeds the file list with already-saved ticket attachments (idempotent) |
| `getTempAttachmentIds()` | Returns IDs of successfully uploaded (not yet saved) files |
| `deleteRemovedAttachments()` | Flushes deferred deletions for existing attachments on form submit |
| `hasPendingDeletes` | `true` when existing attachments are queued for deletion |
| `isUploading` | `true` while any upload mutation is in flight |
| `reset()` | Clears all file and pending-delete state |

## Usage Example

```typescript
const {
  files,
  uploadFile,
  removeFile,
  initializeExisting,
  getTempAttachmentIds,
  deleteRemovedAttachments,
  isUploading,
  reset,
} = useTempAttachments();

// Seed existing attachments when editing a ticket
useEffect(() => {
  if (ticket?.attachments) {
    initializeExisting(ticket.attachments);
  }
}, [ticket]);

// On file input change
const handleFileChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  for (const file of Array.from(e.target.files ?? [])) {
    uploadFile(file);
  }
};

// On form submit — flush deferred deletes, then collect new IDs
const handleSubmit = async () => {
  await deleteRemovedAttachments();
  const tempIds = getTempAttachmentIds();
  await saveTicket({ tempAttachmentIds: tempIds });
  reset();
};
```

> **Note:** Pending uploads use a `pending-{timestamp}` placeholder ID that is swapped for the real server ID on success. The `removeFile` call on a `pending-` ID skips the API call entirely, while `existing` removals are batched and sent only on `deleteRemovedAttachments()`.
