Synchronizes paginated historical ticket messages into the ticket-details store, handling approval statuses, pagination boundaries, and real-time message deduplication.

## Key Components

### `useHistoricalMessages(options)`
Primary hook that processes fetched message pages and syncs them to the store.

**Options (`UseHistoricalMessageSyncOptions`):**

| Option | Type | Description |
|---|---|---|
| `side` | `ChatSide` | Which chat panel (e.g., client/technician) |
| `messageDialogId` | `string \| null` | Active dialog identifier; resets processing on change |
| `chatType` | `ChatType` | Filters messages by chat type |
| `assistantConfig` | `{ name, type }` | Assistant metadata for message processing |
| `pages` | `MessagePage[]` | Paginated message pages from the ticket service |
| `isFetched` | `boolean` | Guard flag to defer processing until data is ready |
| `onApprove` / `onReject` | `function` | Approval action callbacks (stabilized via `useRef`) |

### Internal Behaviors

- **Dialog reset** — clears the processed page counter when `messageDialogId` changes
- **Approval resolution extraction** — scans `APPROVAL_RESULT` message data and merges statuses into the store via `mergeApprovalStatuses`
- **Initial load vs. pagination** — on first load, merges processed messages with any existing real-time/optimistic messages; on pagination, prepends only new messages and optionally patches the boundary message if its content changed
- **Optimistic message preservation** — retains user-authored optimistic messages not yet confirmed in historical data

## Usage Example

```typescript
useHistoricalMessages({
  side: 'technician',
  messageDialogId: ticket.dialogId,
  chatType: 'TECHNICIAN',
  assistantConfig: { name: 'Mingo', type: 'MINGO' },
  pages: messagePages,
  isFetched: isMessagesFetched,
  onApprove: (requestId) => approveAction(requestId),
  onReject: (requestId) => rejectAction(requestId),
});
```
