Synchronizes paginated historical ticket messages into the ticket-details-store by processing each fetched page, resolving approval statuses, and merging real-time messages without overwriting optimistic updates.

## Key Components

### `useHistoricalMessages(options)`
The primary exported hook. Accepts a `UseHistoricalMessageSyncOptions` object and manages:

- **Page change detection** — resets the internal page counter when `messageDialogId` changes
- **Historical resolution extraction** — scans message data for `APPROVAL_RESULT` entries and syncs them into the store via `mergeApprovalStatuses`
- **Message processing** — delegates to `processHistoricalMessagesWithErrors` from `openframe-frontend-core`, applying assistant config, chat type filters, and approval callbacks
- **Approval envelope folding** — calls `foldPendingApprovalsEnvelope` to group pending approvals before writing to the store
- **Pagination vs. initial load** — on first load, merges with existing real-time/optimistic messages; on pagination, prepends new pages using `prependWithBoundaryMerge` and patches boundary message content if it changed

### `UseHistoricalMessageSyncOptions`
Interface defining the hook's configuration, including `side`, `messageDialogId`, `chatType`, `assistantConfig`, `pages`, `isFetched`, `onApprove`, and `onReject`.

## Usage Example

```typescript
useHistoricalMessages({
  side: 'mingo',
  messageDialogId: ticket.dialogId,
  chatType: 'MINGO',
  assistantConfig: { name: 'Mingo', type: 'MINGO' },
  pages: messagePages,
  isFetched: isMessagesFetched,
  onApprove: async (requestId) => {
    await approveAction(requestId);
  },
  onReject: async (requestId) => {
    await rejectAction(requestId);
  },
});
```

> **Note:** `onApprove` and `onReject` are stored in refs internally, so passing new function references on re-render does not trigger re-processing of historical messages.
