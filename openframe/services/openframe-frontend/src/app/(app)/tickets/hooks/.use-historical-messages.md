Synchronizes paginated historical ticket messages into the ticket-details-store by processing each fetched page, resolving approval statuses, and merging results with any existing real-time messages.

## Key Components

**`useHistoricalMessages(options)`**
The sole export. A React hook that:
- Watches paginated `MessagePage[]` data and re-runs whenever pages or the active `messageDialogId` change
- Delegates message transformation to `processHistoricalMessagesWithErrors` from `@flamingo-stack/openframe-frontend-core`
- Extracts `APPROVAL_RESULT` entries from raw message data and syncs them into the store via `mergeApprovalStatuses`
- Applies `foldPendingApprovalsEnvelope` to consolidate pending approval messages before storage
- Distinguishes between **initial load** and **pagination**: initial load merges with live/optimistic messages already in the store; pagination prepends older messages via `prependWithBoundaryMerge`, patching the boundary message if its content changed
- Uses stable `useRef` refs for `onApprove`/`onReject` callbacks and approval statuses to avoid stale closure issues

**`UseHistoricalMessageSyncOptions`**
Interface defining the hook's input contract — chat side, dialog ID, chat type, assistant config, pages, fetch state, and approval callbacks.

## Usage Example

```typescript
useHistoricalMessages({
  side: 'mingo',
  messageDialogId: ticket.dialogId,
  chatType: 'MINGO',
  assistantConfig: { name: 'Mingo', type: 'mingo' },
  pages: messagesQuery.data?.pages,
  isFetched: messagesQuery.isFetched,
  onApprove: (requestId) => approveAction(requestId),
  onReject: (requestId) => rejectAction(requestId),
});
```

> Optimistic user messages already rendered in the store are preserved during initial load: a message is kept if its `id` starts with `"optimistic-"` and no processed message shares the same content.
