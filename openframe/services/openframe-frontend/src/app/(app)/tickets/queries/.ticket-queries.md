GraphQL query and mutation definitions for ticket management operations, targeting the `openframe-saas-ai-agent` service via `/chat/graphql`.

## Key Components

### Queries
| Export | Description |
|--------|-------------|
| `GET_TICKET_QUERY` | Fetch a single ticket by ID with full detail (notes, attachments, dialog, transitions) |
| `GET_TICKETS_QUERY` | Paginated ticket list with cursor-based pagination, filtering, and search |
| `GET_TICKETS_BOARD_QUERY` | Kanban board view — fetches tickets grouped into `active`, `techRequired`, `onHold`, `resolved` columns |
| `GET_BOARD_COLUMN_TICKETS_QUERY` | Paginated tickets for a single lifecycle board column (custom status, gated by `featureFlags.ticketStatuses`) |
| `GET_TICKET_LABELS_QUERY` | All available ticket labels |
| `GET_TICKET_STATUS_TRANSITION_RULES_QUERY` | Valid from/to status transition rules |
| `GET_TICKET_ATTACHMENT_DOWNLOAD_URL` | Pre-signed download URL for a ticket attachment |

### Mutations
| Export | Description |
|--------|-------------|
| `CREATE_TICKET_MUTATION` | Create a new ticket with owner, device, and organization context |
| `UPDATE_TICKET_MUTATION` | Update ticket fields (title, description, assignee, labels, etc.) |
| `TRANSITION_TICKET_MUTATION` | Move a ticket to a new status via a defined transition |
| `PUT_TICKET_ON_HOLD_MUTATION` | Shortcut mutation to set status to `ON_HOLD` |
| `RESOLVE_TICKET_MUTATION` | Shortcut mutation to resolve a ticket |
| `ADD_TICKET_NOTE_MUTATION` | Add an internal note to a ticket |
| `UPDATE_TICKET_NOTE_MUTATION` | Edit an existing ticket note |
| `DELETE_TICKET_NOTE_MUTATION` | Delete a ticket note by ID |
| `CREATE_TEMP_ATTACHMENT_UPLOAD_URL` | Generate a pre-signed upload URL for a temporary attachment |
| `DELETE_TEMP_ATTACHMENT` | Remove a temporary (pre-commit) attachment |
| `DELETE_TICKET_ATTACHMENT` | Remove a committed ticket attachment |

### Internal Fragments
- `BOARD_CARD_TICKET_FRAGMENT` — Shared fields for standard board cards
- `BOARD_CARD_TICKET_LIFECYCLE_FRAGMENT` — Board card fields extended with `statusDefinition` for custom-status boards
- `BOARD_COLUMN_CONNECTION_FRAGMENT` — Reusable paginated connection structure for board columns

## Usage Example

```typescript
import {
  GET_TICKETS_BOARD_QUERY,
  CREATE_TICKET_MUTATION,
  TRANSITION_TICKET_MUTATION,
} from './ticket-queries';

// Fetch Kanban board data
const boardData = await graphqlClient.query({
  query: GET_TICKETS_BOARD_QUERY,
  variables: {
    limit: 20,
    search: 'vpn',
    organizationIds: ['org_123'],
    assigneeIds: ['user_456'],
  },
});

// Create a new ticket
const result = await graphqlClient.mutate({
  mutation: CREATE_TICKET_MUTATION,
  variables: {
    input: {
      title: 'VPN not connecting',
      description: 'Client cannot connect after update',
      organizationId: 'org_123',
      deviceId: 'dev_789',
    },
  },
});

// Transition ticket to a new status
await graphqlClient.mutate({
  mutation: TRANSITION_TICKET_MUTATION,
  variables: {
    input: { ticketId: 'ticket_001', toStatusId: 'status_resolved' },
  },
});
```

> **Note:** `GET_TICKETS_BOARD_QUERY` uses the standard four-status model (`ACTIVE`, `TECH_REQUIRED`, `ON_HOLD`, `RESOLVED`). For custom lifecycle statuses, use `GET_BOARD_COLUMN_TICKETS_QUERY` per column, which is gated by `featureFlags.ticketStatuses`.
