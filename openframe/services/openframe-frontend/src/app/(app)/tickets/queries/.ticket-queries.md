GraphQL query and mutation string constants for the ticket management domain, targeting the `openframe-saas-ai-agent` service via `/chat/graphql`.

## Key Components

### Queries
| Export | Description |
|--------|-------------|
| `GET_TICKET_QUERY` | Fetch a single ticket by ID with full detail (notes, attachments, dialog, owner) |
| `GET_TICKETS_QUERY` | Paginated, filterable ticket list with cursor-based pagination |
| `GET_TICKETS_BOARD_QUERY` | Kanban board view — fetches all four status columns in a single request using fragments |
| `GET_TICKET_LABELS_QUERY` | All available ticket labels |
| `GET_TICKET_ATTACHMENT_DOWNLOAD_URL` | Presigned download URL for a ticket attachment |
| `GET_TICKET_STATUS_TRANSITIONS_QUERY` | Valid status transition pairs |
| `GET_TICKET_STATISTICS_QUERY` | Aggregate stats: counts, resolution time, average rating |

### Mutations
| Export | Description |
|--------|-------------|
| `CREATE_TICKET_MUTATION` | Create a new ticket |
| `UPDATE_TICKET_MUTATION` | Update ticket fields |
| `PUT_TICKET_ON_HOLD_MUTATION` | Transition ticket to `ON_HOLD` |
| `RESOLVE_TICKET_MUTATION` | Transition ticket to `RESOLVED` |
| `ARCHIVE_TICKET_MUTATION` | Archive a single ticket |
| `REOPEN_TICKET_MUTATION` | Reopen a ticket |
| `REORDER_TICKET_MUTATION` | Update ticket sort order on the board |
| `ASSIGN_TICKET_MUTATION` / `UNASSIGN_TICKET_MUTATION` | Manage ticket assignee |
| `UNLINK_DEVICE_FROM_TICKET_MUTATION` | Detach device association |
| `UNLINK_ORGANIZATION_FROM_TICKET_MUTATION` | Detach organization association |
| `ADD_TICKET_NOTE_MUTATION` / `UPDATE_TICKET_NOTE_MUTATION` / `DELETE_TICKET_NOTE_MUTATION` | Internal note CRUD |
| `CREATE_TEMP_ATTACHMENT_UPLOAD_URL` | Generate a presigned upload URL for a temp attachment |
| `DELETE_TEMP_ATTACHMENT` / `DELETE_TICKET_ATTACHMENT` | Remove attachments |
| `ARCHIVE_RESOLVED_TICKETS_MUTATION` | Bulk-archive all resolved tickets |

### Internal Fragments (not exported)
- `BOARD_CARD_TICKET_FRAGMENT` — reusable ticket fields for board cards
- `BOARD_COLUMN_CONNECTION_FRAGMENT` — wraps a `TicketConnection` with pagination for board columns; composed into `GET_TICKETS_BOARD_QUERY`

## Usage Example

```typescript
import {
  GET_TICKETS_BOARD_QUERY,
  CREATE_TICKET_MUTATION,
  RESOLVE_TICKET_MUTATION,
} from './ticket-queries';

// Fetch Kanban board columns in one request
const boardData = await graphqlClient.request(GET_TICKETS_BOARD_QUERY, {
  limit: 50,
  search: 'vpn',
  organizationIds: ['org_123'],
  assigneeIds: ['user_456'],
});
// boardData.active / .techRequired / .onHold / .resolved

// Create a ticket
const { createTicket } = await graphqlClient.request(CREATE_TICKET_MUTATION, {
  input: {
    title: 'VPN not connecting',
    description: 'User cannot connect to VPN since update.',
    organizationId: 'org_123',
  },
});

// Resolve a ticket
const { resolveTicket } = await graphqlClient.request(RESOLVE_TICKET_MUTATION, {
  input: { id: 'ticket_789' },
});
```

> **Note:** The `owner` field uses a GraphQL union type — responses will be either `ClientTicketOwner` (with `machineId`) or `AdminTicketOwner` (with `userId`). Handle both variants when consuming ticket data.
