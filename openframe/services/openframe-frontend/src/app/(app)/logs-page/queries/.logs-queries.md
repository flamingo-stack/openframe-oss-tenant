GraphQL query definitions for fetching log data, including filter metadata, paginated log listings, and detailed log records.

## Key Components

| Export | Description |
|--------|-------------|
| `GET_LOG_FILTERS_QUERY` | Retrieves available filter options (tool types, event types, severities, organizations) for populating log filter UI |
| `GET_LOGS_QUERY` | Fetches a paginated list of logs with optional filtering and search; returns cursor-based `pageInfo` |
| `GET_LOG_DETAILS_QUERY` | Fetches full details for a single log entry by composite key (`toolEventId`, `ingestDay`, `toolType`, `eventType`, `timestamp`) |

## Usage Example

```typescript
import {
  GET_LOG_FILTERS_QUERY,
  GET_LOGS_QUERY,
  GET_LOG_DETAILS_QUERY,
} from './logs-queries';

// Fetch available filter options
const filtersResult = await gqlClient.query(GET_LOG_FILTERS_QUERY, {
  filter: { organizationId: 'org_123' },
});

// Fetch paginated logs with search
const logsResult = await gqlClient.query(GET_LOGS_QUERY, {
  filter: { severity: 'ERROR', toolType: 'endpoint' },
  first: 25,
  after: 'cursor_abc',
  search: 'disk failure',
});

// Fetch full details for a specific log entry
const detailsResult = await gqlClient.query(GET_LOG_DETAILS_QUERY, {
  logId: 'evt_xyz',
  ingestDay: '2025-01-15',
  toolType: 'endpoint',
  eventType: 'alert',
  timestamp: '2025-01-15T10:30:00Z',
});
```

> **Note:** `GET_LOG_DETAILS_QUERY` requires a composite key of five fields — all are mandatory (`!`) — as logs are stored in a partitioned structure requiring `ingestDay`, `toolType`, `eventType`, and `timestamp` alongside the event ID.
