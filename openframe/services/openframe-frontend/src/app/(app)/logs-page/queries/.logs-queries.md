GraphQL query definitions for fetching log data, including filter options, paginated log listings, and detailed log entry retrieval.

## Key Components

| Export | Description |
|--------|-------------|
| `GET_LOG_FILTERS_QUERY` | Fetches available filter options (tool types, event types, severities, organizations) for the logs UI |
| `GET_LOGS_QUERY` | Paginated log listing with cursor-based pagination and optional search/filter parameters |
| `GET_LOG_DETAILS_QUERY` | Retrieves full details for a single log entry, including raw `message` and `details` fields |

## Usage Example

```typescript
import {
  GET_LOG_FILTERS_QUERY,
  GET_LOGS_QUERY,
  GET_LOG_DETAILS_QUERY
} from './logs-queries';

// Fetch available filter options
const filters = await graphqlClient.query(GET_LOG_FILTERS_QUERY, {
  filter: { organizationId: 'org_123' }
});

// Fetch paginated logs
const logs = await graphqlClient.query(GET_LOGS_QUERY, {
  filter: { severity: 'ERROR', toolType: 'endpoint' },
  first: 25,
  after: 'cursor_abc',
  search: 'disk full'
});

// Fetch a single log entry's full details
const detail = await graphqlClient.query(GET_LOG_DETAILS_QUERY, {
  logId: 'evt_xyz',
  ingestDay: '2024-01-15',
  toolType: 'endpoint',
  eventType: 'alert',
  timestamp: '2024-01-15T10:30:00Z'
});
```

> `GET_LOG_DETAILS_QUERY` requires five mandatory arguments (`toolEventId`, `ingestDay`, `toolType`, `eventType`, `timestamp`) that together uniquely identify a log entry in the underlying storage layer. The response includes the full `message` and `details` fields not returned by the list query.
