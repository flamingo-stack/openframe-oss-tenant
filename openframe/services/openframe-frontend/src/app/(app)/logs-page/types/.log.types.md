Defines TypeScript interfaces for the log management system, covering log entries, edge wrappers, and filter structures used across the Flamingo platform's logging pipeline.

## Key Components

| Interface | Description |
|-----------|-------------|
| `LogEntry` | Core log record with severity levels, device context, and optional metadata |
| `LogEdge` | GraphQL-style edge wrapper containing a `LogEntry` node |
| `LogFilters` | Available filter options for the log viewer UI |
| `LogFilterInput` | Query input shape for filtering logs by severity, tool type, org, device, or user |

### Severity Levels

`LogEntry.severity` is a strict union type:

```text
'DEBUG' | 'INFO' | 'WARNING' | 'ERROR' | 'CRITICAL'
```

## Usage Example

```typescript
import type { LogEntry, LogFilterInput } from './log.types';

// Constructing a log entry
const entry: LogEntry = {
  toolEventId: 'evt_123',
  eventType: 'agent.action',
  ingestDay: '2025-01-15',
  toolType: 'mingo',
  severity: 'INFO',
  summary: 'Ticket auto-resolved by Mingo AI',
  timestamp: new Date().toISOString(),
  deviceId: 'dev_abc',
  hostname: 'workstation-01',
  organizationId: 'org_xyz',
};

// Building a filter query
const filters: LogFilterInput = {
  severities: ['ERROR', 'CRITICAL'],
  toolTypes: ['mingo'],
  organizationIds: ['org_xyz'],
};
```

## Notes

- `device` is typed as `Partial<Device>` to accommodate partial hydration from the backend transform layer
- `metadata` accepts an open `Record<string, any>` for tool-specific payload extensions
- `LogEdge` follows the GraphQL connection pattern, making it compatible with paginated log queries
