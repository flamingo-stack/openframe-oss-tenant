A form page component for creating and editing Fleet monitoring policies, supporting SQL query authoring, device assignment, and live policy testing.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `EditPolicyPage` | React component | Main page component accepting a `policyId` prop (`null` for new, numeric string for edit) |
| `policyFormSchema` | Zod schema | Validates `name` (required), `description`, and `query` fields |
| `PolicyFormData` | Type | Inferred form data type from the Zod schema |
| `getDeviceKey` | Helper function | Extracts Fleet host ID from a `Device` as a string key for the selector |

### Internal Hooks Used

- `usePolicyDetails` — fetches existing policy data
- `usePolicies` — provides `createPolicy` / `updatePolicy` mutations
- `usePolicyHosts` / `useReplacePolicyHosts` — manages device-to-policy host assignments
- `usePolicyDevices` — lists available devices for selection
- `useLiveCampaign` — manages live test execution state

## Usage Example

```typescript
// In a Next.js page (e.g., app/monitoring/policy/edit/page.tsx)
import { EditPolicyPage } from './edit-policy-page';

// Create new policy
export default function NewPolicyPage() {
  return <EditPolicyPage policyId={null} />;
}

// Edit existing policy
export default function UpdatePolicyPage({ params }: { params: { id: string } }) {
  return <EditPolicyPage policyId={params.id} />;
}
```

## Behavior Notes

- Renders `CardLoader` while fetching, `LoadError` or `NotFoundError` on failure
- **Test Policy** button triggers a live osquery campaign against selected devices; results appear in `LiveTestPanel`
- **Save Policy** writes form data then atomically replaces host assignments via `replacePolicyHostsMutation`
- Device rows with no Fleet agent installed are disabled with a tooltip message
- Links to the [osquery schema reference](https://osquery.io/schema) inline below the SQL editor
