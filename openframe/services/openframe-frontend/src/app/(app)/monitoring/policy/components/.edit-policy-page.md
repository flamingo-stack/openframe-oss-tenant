A full-page form component for creating and editing Fleet monitoring policies, supporting name/description/query fields, device assignment, and live policy testing.

## Key Components

- **`EditPolicyPage`** — Main exported component accepting a `policyId` prop (`string | null`); `null` triggers create mode, a valid numeric string triggers edit mode
- **`policyFormSchema`** — Zod schema validating `name` (required), `description`, and `query` fields
- **`PolicyFormData`** — TypeScript type inferred from the Zod schema
- **`getDeviceKey`** — Helper that resolves a Fleet host ID from a `Device` object into a string key for the selector

## Key Hooks Used

| Hook | Purpose |
|------|---------|
| `usePolicyDetails` | Fetches existing policy data in edit mode |
| `usePolicies` | Provides `createPolicy` / `updatePolicy` mutations |
| `usePolicyHosts` / `useReplacePolicyHosts` | Loads and replaces host assignments |
| `usePolicyDevices` | Fetches all available devices for selection |
| `useLiveCampaign` | Manages live osquery test execution state |

## Usage Example

```typescript
// In a Next.js page or parent component
import { EditPolicyPage } from './edit-policy-page';

// Create mode
<EditPolicyPage policyId={null} />

// Edit mode — pass the policy's numeric ID as a string
<EditPolicyPage policyId="42" />
```

## Behavior Notes

- **Loading states**: Renders `<CardLoader>` while fetching, `<LoadError>` on failure, `<NotFoundError>` if the policy ID resolves to nothing
- **Device assignment**: Uses numeric Fleet host IDs internally; converts to/from strings for the `DeviceSelector`; devices without a Fleet agent are disabled with an inline tooltip
- **Live testing**: Clicking "Test Policy" launches `useLiveCampaign` with the current query and selected hosts, revealing `<LiveTestPanel>` inline
- **Navigation**: Uses `useSafeBack` to return to the policy detail page (edit) or the policies tab (create)
