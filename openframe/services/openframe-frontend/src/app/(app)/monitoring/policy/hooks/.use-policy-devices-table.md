Builds and returns a sorted, compliance-annotated table of devices for a given policy by combining paginated Fleet device data with passing/failing/pending host status information.

## Key Components

- **`fetchDevicesPage(cursor)`** — Fetches a single page of devices via GraphQL with a fixed page size of 100, returning devices, pagination info, and the next cursor.
- **`fetchAllDevices()`** — Iterates through all pages using `fetchDevicesPage` until all Fleet-connected devices are collected.
- **`usePolicyDevicesTable(policyId, assignedHostIds)`** — Primary hook that orchestrates device fetching, compliance status resolution, and row construction.

### Compliance Status Priority

| Status | Source |
|---|---|
| `non-compliant` | `failingHosts` from `usePolicyResponseHosts` |
| `passing` | `passingHosts` from `usePolicyResponseHosts` |
| `pending` | `assignedHostIds` prop (not yet evaluated) |

Rows are sorted by compliance status (`non-compliant` → `pending` → `passing`), then alphabetically by `displayName`.

## Usage Example

```typescript
const { rows, isLoading, error } = usePolicyDevicesTable(
  42,
  [{ id: 7, hostname: 'workstation-01' }]
);

if (isLoading) return <Spinner />;
if (error) return <ErrorMessage message={error} />;

return <DeviceTable rows={rows} />;
```

## Notes

- Device deduplication by Fleet host ID is handled by preferring the most recently seen device when duplicates exist.
- The hook returns a `null` error when no error is present, safe for direct conditional rendering.
- Depends on `usePolicyResponseHosts` for live compliance state per policy.
