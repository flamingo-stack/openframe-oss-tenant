Renders the full detail view for a single monitoring policy, displaying its metadata, SQL query, and associated devices, with edit and delete actions.

## Key Components

- **`PolicyStatusTag`** — Internal component that renders a styled `Tag` based on computed policy status using `POLICY_STATUS_CONFIG`
- **`PolicyDetailsView`** — Main export; accepts a `policyId` string, parses it to a numeric ID, and orchestrates data fetching and UI rendering
- **`usePolicyDetails`** — Hook that fetches policy data; guards against invalid IDs by passing `null`
- **`usePolicies`** — Hook providing `deletePolicy` and `isDeleting` for delete operations
- **`ScriptEditor`** — Read-only SQL editor rendered when `policyDetails.query` is present
- **`PolicyDevicesTable`** — Displays devices assigned to the policy via `hosts_include_any`
- **`ConfirmDeleteMonitoringModal`** — Confirmation dialog gating the delete action

## Usage Example

```typescript
// app/monitoring/policy/[id]/page.tsx
import { PolicyDetailsView } from './components/policy-details-view';

export default function PolicyPage({ params }: { params: { id: string } }) {
  return <PolicyDetailsView policyId={params.id} />;
}
```

## States Handled

| State | Rendered Output |
|---|---|
| Loading | `<CardLoader items={4} />` |
| Fetch error | `<LoadError message={...} />` |
| Not found / invalid ID | `<NotFoundError message="Policy not found" />` |
| Success | Full detail layout |

## Navigation

- **Back** — Returns to `/monitoring?tab=policies` via `useSafeBack` fallback
- **Edit** — Pushes to `/monitoring/policy/edit/:policyId`
- **Delete** — Confirms via modal, then redirects to `/monitoring?tab=policies` on success
