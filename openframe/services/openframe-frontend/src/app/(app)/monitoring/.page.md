Renders the top-level monitoring page route, wrapping the `MonitoringView` component inside a full-width `ContentPageContainer` with system-level padding and no header.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `Monitoring` | Default export | Page component that renders the monitoring layout |
| `dynamic` | Named export | Set to `'force-dynamic'` to disable static caching for this route |

## Usage Example

```typescript
// Automatically rendered by Next.js App Router at the /monitoring route.
// No direct instantiation needed — the framework calls this default export.

export default function Monitoring() {
  return (
    <ContentPageContainer className="p-[var(--spacing-system-l)]" padding="none" showHeader={false}>
      <MonitoringView />
    </ContentPageContainer>
  );
}
```

## Notes

- `'use client'` directive marks this as a Client Component.
- `force-dynamic` ensures the page is always server-rendered on request, preventing stale cached data in monitoring contexts.
- `ContentPageContainer` is sourced from `@flamingo-stack/openframe-frontend-core` and provides consistent layout scaffolding.
- All monitoring UI logic is delegated to `MonitoringView` via `./components/monitoring-view`.
