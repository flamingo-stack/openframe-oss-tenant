Renders the Monitoring section of the OpenFrame UI, managing tab navigation between **Policies** and **Queries** views with URL-driven tab state.

## Key Components

- **`MonitoringView`** — Main exported component that orchestrates tab navigation using Next.js router and search params as the single source of truth for active tab state
- **`TAB_IDS`** — Constant tuple defining valid tab identifiers: `'policies'` and `'queries'`
- **`DEFAULT_TAB`** — Fallback tab (`'policies'`) used when no valid `?tab=` param is present
- **`handleTabChange`** — URL-controlled tab switch callback; replaces the current route with updated `?tab=` param using `router.replace` (no scroll reset, no history entry)

## Usage Example

```typescript
// Renders automatically when mounted at the /monitoring route.
// Tab state is read from and written to the URL search params:
// /monitoring?tab=policies  → shows Policies tab
// /monitoring?tab=queries   → shows Queries tab

import { MonitoringView } from './monitoring-view';

export default function MonitoringPage() {
  return <MonitoringView />;
}
```

## Notes

- Uses **controlled mode** for `TabNavigation` (explicit `activeTab` + `onTabChange`) instead of `urlSync` mode to avoid a flicker bug where the internal sync effect briefly resets the active tab during navigation
- Invalid or missing `?tab=` values silently fall back to `'policies'`
- Tab components are resolved lazily via `getTabComponent` from `@flamingo-stack/openframe-frontend-core`
