Renders the Monitoring section's tabbed layout, wiring URL search params (`?tab=`) as the single source of truth for active tab state.

## Key Components

- **`MonitoringView`** — Primary export. Reads the `tab` query param to determine the active tab, falls back to `'policies'` if the param is missing or invalid.
- **`TAB_IDS`** — Allowlist of valid tab identifiers: `'policies'` and `'queries'`.
- **`DEFAULT_TAB`** — Fallback tab (`'policies'`) used when no valid `tab` param is present.
- **`handleTabChange`** — Callback that updates the URL via `router.replace` without a scroll reset, keeping the URL as the authoritative tab state and avoiding a flicker bug in `TabNavigation`'s internal `urlSync` mode.

## Usage Example

```typescript
// app/monitoring/page.tsx
import { MonitoringView } from './monitoring-view';

export default function MonitoringPage() {
  return <MonitoringView />;
}

// Navigating to /monitoring?tab=queries activates the "queries" tab.
// Navigating to /monitoring?tab=invalid falls back to "policies".
```

## Notes

- Tab components are resolved lazily via `getTabComponent` from `@flamingo-stack/openframe-frontend-core`.
- The controlled URL pattern (`router.replace`) prevents a race condition where `TabNavigation`'s internal sync effect would briefly revert to the previous tab during client-side navigation.
- Adding a new tab requires registering it in both `MONITORING_TABS` and the `TAB_IDS` tuple.
