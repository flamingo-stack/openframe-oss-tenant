Defines TypeScript interfaces for policy data structures used across the MSP platform's policy management features.

## Key Components

- **`Policy`** — Core interface representing a compliance/monitoring policy, including metadata, author info, host counts, and scheduling configuration
- **`PolicyFilters`** — Filter criteria interface for querying/narrowing policy lists by status and source

## Usage Example

```typescript
import { Policy, PolicyFilters } from './policies.types';

const policy: Policy = {
  id: 1,
  name: 'Disk Encryption Required',
  query: 'SELECT 1 FROM disk_encryption WHERE encrypted = 1;',
  category: 'security',
  enabled: true,
  critical: true,
  description: 'Ensures full disk encryption is active on all endpoints',
  author_id: 42,
  author_name: 'Jane Doe',
  author_email: 'jane@example.com',
  resolution: 'Enable FileVault or BitLocker on the affected host',
  platform: 'darwin',
  calendar_events_enabled: false,
  created_at: '2024-01-01T00:00:00Z',
  updated_at: '2024-06-01T00:00:00Z',
  passing_host_count: 198,
  failing_host_count: 4,
};

const filters: PolicyFilters = {
  status: ['failing'],
  source: ['fleet'],
};
```

## Notes

- `hosts_include_any` allows scoping a policy to specific hosts by `id` and `hostname`
- `calendar_events_enabled` supports scheduling policy-related calendar notifications
- Optional fields (`category`, `enabled`, `team_id`, `host_count_updated_at`) support both global and team-scoped policy contexts
