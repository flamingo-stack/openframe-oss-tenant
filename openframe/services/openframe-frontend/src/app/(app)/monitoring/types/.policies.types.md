Defines TypeScript interfaces for fleet policy management, including full policy details and filtering options.

## Key Components

- **`Policy`** — Core interface representing a fleet compliance policy with metadata, author info, platform targeting, host pass/fail counts, and optional team/calendar associations
- **`PolicyFilters`** — Lightweight interface for filtering policies by status and source arrays

## Usage Example

```typescript
import { Policy, PolicyFilters } from './policies.types';

const policy: Policy = {
  id: 1,
  name: 'Disk Encryption Required',
  query: 'SELECT 1 FROM disk_encryption WHERE encrypted = 1;',
  critical: true,
  description: 'Ensures all disks are encrypted.',
  author_id: 42,
  author_name: 'Jane Doe',
  author_email: 'jane@example.com',
  resolution: 'Enable FileVault or BitLocker.',
  platform: 'darwin',
  calendar_events_enabled: false,
  created_at: '2024-01-01T00:00:00Z',
  updated_at: '2024-06-01T00:00:00Z',
  passing_host_count: 120,
  failing_host_count: 5,
};

const filters: PolicyFilters = {
  status: ['failing'],
  source: ['team'],
};
```

## Notes

- `team_id`, `category`, `enabled`, `host_count_updated_at`, and `hosts_include_any` are optional fields
- `hosts_include_any` scopes a policy to specific hosts by `id` and `hostname`
- Timestamps (`created_at`, `updated_at`) follow ISO 8601 string format
