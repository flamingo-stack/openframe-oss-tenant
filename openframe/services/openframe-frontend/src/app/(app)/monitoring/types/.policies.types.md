Defines TypeScript interfaces for policy management, representing policy records and their associated filter options.

## Key Components

- **`Policy`** — Core interface representing a compliance/monitoring policy with metadata, ownership, platform targeting, and host pass/fail statistics
- **`PolicyFilters`** — Lightweight filter interface for querying policies by status and source

## Usage Example

```typescript
import { Policy, PolicyFilters } from './policies.types';

const policy: Policy = {
  id: 1,
  name: 'Disk Encryption Enabled',
  query: 'SELECT 1 FROM disk_encryption WHERE enabled = 1;',
  category: 'security',
  enabled: true,
  critical: true,
  description: 'Ensures full disk encryption is active on all hosts.',
  author_id: 42,
  author_name: 'Jane Doe',
  author_email: 'jane@example.com',
  resolution: 'Enable FileVault or BitLocker on the affected host.',
  platform: 'darwin',
  calendar_events_enabled: false,
  created_at: '2024-01-01T00:00:00Z',
  updated_at: '2024-06-01T00:00:00Z',
  passing_host_count: 198,
  failing_host_count: 4,
};

const filters: PolicyFilters = {
  status: ['failing'],
  source: ['fleet'],
};
```

## Field Notes

| Field | Notes |
|---|---|
| `critical` | Flags high-priority policies for escalation |
| `calendar_events_enabled` | Links policy failures to calendar-based remediation workflows |
| `hosts_include_any` | Scopes the policy to a subset of hosts by ID and hostname |
| `host_count_updated_at` | Timestamp of the last host compliance count refresh |
