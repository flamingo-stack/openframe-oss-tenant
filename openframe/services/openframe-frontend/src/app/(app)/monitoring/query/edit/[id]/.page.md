Client-side Next.js page component that handles routing for the query editor, resolving the dynamic `[id]` URL parameter and delegating rendering to `EditQueryPage`.

## Key Components

- **`EditQueryPageWrapper`** — Default export page component that reads the `id` route param and passes a normalized `queryId` to the editor. Maps the special `"new"` slug to `null` (indicating a new query), and passes a string ID for existing queries.

## Usage Example

```typescript
// Route: /queries/new → queryId = null (new query)
// Route: /queries/abc123 → queryId = "abc123" (existing query)

// Next.js dynamic route: app/queries/[id]/page.tsx
// Automatically invoked by the router; no direct usage required.

// The resolved queryId is forwarded to EditQueryPage:
<EditQueryPage queryId={null} />       // creating a new query
<EditQueryPage queryId="abc123" />     // editing an existing query
```

## Parameter Resolution Logic

| URL Segment | `queryId` Passed |
|-------------|-----------------|
| `new` | `null` |
| `"abc123"` (string) | `"abc123"` |
| Missing / non-string | `null` |
