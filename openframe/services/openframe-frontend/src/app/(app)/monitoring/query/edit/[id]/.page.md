Client-side Next.js page component that handles routing for the edit/create query workflow, resolving the dynamic `[id]` route param and delegating rendering to `EditQueryPage`.

## Key Components

- **`EditQueryPageWrapper`** — Default export page component that reads the `id` route parameter and passes a normalized `queryId` to the underlying `EditQueryPage` component.
  - `id === 'new'` → passes `null` (create mode)
  - `id === <string>` → passes the string (edit mode)
  - `id === undefined` → passes `null` (fallback)

## Usage Example

```typescript
// Rendered automatically by Next.js App Router at:
// /queries/new          → EditQueryPage with queryId={null}
// /queries/abc123       → EditQueryPage with queryId="abc123"
// /queries/[id]/page.tsx is the file path convention
```

```typescript
// EditQueryPage receives the resolved prop:
<EditQueryPage queryId={null} />     // create mode
<EditQueryPage queryId="abc123" />   // edit mode
```

## Notes

- Uses `'use client'` directive — runs in the browser, enabling `useParams` hook usage.
- Acts purely as a thin routing adapter; all business logic lives in `EditQueryPage`.
