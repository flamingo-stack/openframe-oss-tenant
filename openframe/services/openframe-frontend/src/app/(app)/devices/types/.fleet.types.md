Defines TypeScript interfaces for Fleet MDM API responses, modeling the complete structure of host data including hardware, software, network, MDM enrollment, and vulnerability information.

## Key Components

| Interface | Description |
|-----------|-------------|
| `FleetHost` | Primary host model with 50+ fields covering identity, hardware, network, storage, and status |
| `FleetSoftware` | Installed software with CVE vulnerabilities, source type union, and signature metadata |
| `FleetVulnerability` | CVE entry with detail link and discovery timestamp |
| `FleetMdmInfo` | MDM enrollment status, DEP profile state, and Fleet connectivity |
| `FleetLabel` | Fleet label with osquery definition and membership type |
| `FleetUser` | Local system user with UID, group, and shell |
| `FleetBattery` | Battery health and cycle count |
| `FleetIssues` | Aggregated policy failure counts |
| `FleetHostResponse` | Top-level API response wrapper containing a `FleetHost` |

## Usage Example

```typescript
import { FleetHostResponse, FleetHost, FleetSoftware } from './fleet.types';

async function getHostDetails(hostId: number): Promise<FleetHost> {
  const res = await fetch(`/api/fleet/hosts/${hostId}`);
  const data: FleetHostResponse = await res.json();
  return data.host;
}

// Filter software with known vulnerabilities
function getVulnerableSoftware(host: FleetHost): FleetSoftware[] {
  return (host.software ?? []).filter(
    (pkg) => pkg.vulnerabilities && pkg.vulnerabilities.length > 0
  );
}

// Check MDM enrollment and disk encryption
function isCompliant(host: FleetHost): boolean {
  return (
    host.mdm.enrollment_status === 'On (automatic)' &&
    host.disk_encryption_enabled &&
    host.issues.failing_policies_count === 0
  );
}
```

> **Note:** Several fields (`policies`, `packs`, `pack_stats`, `profiles`) are typed as `any[]` — consider narrowing these with dedicated interfaces as Fleet API coverage expands.
