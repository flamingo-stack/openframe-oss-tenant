React hook for managing device lifecycle actions (archive and delete) with built-in loading state tracking and toast notifications.

## Key Components

- **`useDeviceActions(options?)`** — Main hook export that returns device action handlers and loading states
- **`archiveDevice(deviceId, deviceName?)`** — Sets device status to `ARCHIVED` via `PATCH /api/devices/:id`, returns `Promise<boolean>`
- **`deleteDevice(deviceId, deviceName?)`** — Sets device status to `DELETED` via `PATCH /api/devices/:id`, returns `Promise<boolean>`
- **`isArchiving`** / **`isDeleting`** — Granular loading flags per action
- **`isProcessing`** — Combined loading flag (`isArchiving || isDeleting`)
- **`UseDeviceActionsOptions`** — Optional `onSuccess` callback fired after any successful action

## Usage Example

```typescript
import { useDeviceActions } from '@/hooks/use-device-actions';

function DeviceRow({ device }) {
  const { archiveDevice, deleteDevice, isProcessing } = useDeviceActions({
    onSuccess: () => router.push('/devices'),
  });

  return (
    <>
      <button
        disabled={isProcessing}
        onClick={() => archiveDevice(device.id, device.name)}
      >
        Archive
      </button>
      <button
        disabled={isProcessing}
        onClick={() => deleteDevice(device.id, device.name)}
      >
        Delete
      </button>
    </>
  );
}
```

## Behavior Notes

- Both actions call `PATCH /api/devices/:id` with a `status` payload — archive and delete are soft operations, not destructive HTTP calls
- Toast notifications are shown on both success and failure using the `useToast` hook
- Loading state is reset in `finally` to ensure cleanup even on error
- Returns `true` on success, `false` on failure — callers can branch on the return value without catching exceptions
