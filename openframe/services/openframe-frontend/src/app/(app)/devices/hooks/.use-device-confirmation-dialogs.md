Provides archive and delete confirmation dialog logic for a device, including generating and copying a platform-specific uninstall command during deletion flow.

## Key Components

### `useDeviceConfirmationDialogs(device, options)`

Main hook that manages two confirmation dialogs and returns controls to open them.

**Parameters:**
- `device` — `Device | null | undefined` — Target device object
- `options.onArchived` — Optional callback fired after successful archive
- `options.onDeleted` — Optional callback fired after successful deletion

**Returns (`UseDeviceConfirmationDialogsResult`):**

| Property | Type | Description |
|---|---|---|
| `openArchive` | `() => void` | Opens the archive confirmation dialog |
| `openDelete` | `() => void` | Opens the delete/uninstall confirmation dialog |
| `dialogs` | `ReactNode` | Pre-rendered dialog pair to mount in the component tree |
| `isArchiving` | `boolean` | True while archive mutation is in-flight |
| `isDeleting` | `boolean` | True while delete mutation is in-flight |

**Internal dependencies:**
- `useDeviceActions` — Executes `archiveDevice` / `deleteDevice` mutations
- `useReleaseVersion` — Lazily fetches the current agent release version (only when the delete dialog is open)
- `buildUninstallCommand` / `normalizeDevicePlatform` — Derives the correct platform-specific uninstall shell command
- `useCopyToClipboard` — Handles copying the uninstall command with success/error toasts

## Usage Example

```typescript
function DeviceActions({ device }: { device: Device }) {
  const { openArchive, openDelete, dialogs, isArchiving, isDeleting } =
    useDeviceConfirmationDialogs(device, {
      onArchived: () => router.push('/devices'),
      onDeleted: () => router.push('/devices'),
    });

  return (
    <>
      <button onClick={openArchive} disabled={isArchiving}>
        Archive
      </button>
      <button onClick={openDelete} disabled={isDeleting}>
        Delete
      </button>
      {dialogs}
    </>
  );
}
```

> **Note:** Mount `dialogs` anywhere in the same component tree — the dialogs are self-contained and require no additional state from the parent.
