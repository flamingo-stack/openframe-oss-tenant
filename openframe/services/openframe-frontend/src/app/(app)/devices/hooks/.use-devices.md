Infinite-scroll data fetching hook for paginated device lists, using TanStack Query's `useInfiniteQuery` to load devices from a GraphQL endpoint with filtering, search, and cursor-based pagination.

## Key Components

**`devicesQueryKeys`**
Cache key factory for TanStack Query. Scopes all device queries under `['devices']` and generates stable list keys from active filters and search terms.

**`useDevices(filters, search)`**
Primary hook that fetches and accumulates paginated device data. Handles GraphQL response parsing, error toasting, and flattens paginated results into a single array.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `filters` | `DeviceFilterInput` | `{}` | Field-level filter criteria |
| `search` | `string` | `''` | Full-text search string |

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `devices` | `Device[]` | Flattened list across all loaded pages |
| `isLoading` | `boolean` | True on initial fetch |
| `isFetchingNextPage` | `boolean` | True while loading next page |
| `hasNextPage` | `boolean` | Whether more pages exist |
| `fetchNextPage` | `function` | Trigger next page load |
| `filteredCount` | `number` | Total matched records from server |
| `error` | `string \| null` | Error message if fetch failed |
| `refetch` | `function` | Manually re-trigger the query |

## Usage Example

```typescript
import { useDevices } from './use-devices';

function DeviceList() {
  const {
    devices,
    isLoading,
    hasNextPage,
    fetchNextPage,
    isFetchingNextPage,
    filteredCount,
  } = useDevices({ status: 'online' }, 'workstation');

  if (isLoading) return <Spinner />;

  return (
    <>
      <p>{filteredCount} devices found</p>
      {devices.map(device => (
        <DeviceRow key={device.id} device={device} />
      ))}
      {hasNextPage && (
        <button onClick={() => fetchNextPage()} disabled={isFetchingNextPage}>
          Load more
        </button>
      )}
    </>
  );
}
```

> Results are sorted by `status DESC` server-side and cached for 30 seconds. Errors automatically surface as destructive toast notifications.
