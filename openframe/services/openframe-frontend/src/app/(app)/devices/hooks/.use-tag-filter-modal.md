Manages state and logic for a tag-based device filter modal, coordinating column filters and tag filters into a single batched `setParams` call.

## Key Components

- **`isCompleteTag(tag)`** — Guard utility that validates a tag string contains a non-empty key and value separated by `:`.
- **`useTagFilterModal(params)`** — Primary hook that encapsulates modal open/close state, filter group construction, tag key grouping, and two-phase filter change buffering.

### Returned Values

| Property | Type | Description |
|---|---|---|
| `isOpen` | `boolean` | Modal open/close state |
| `open` / `close` | `() => void` | Modal toggle handlers |
| `isMdUp` | `boolean` | Breakpoint flag — hides filter groups on `md+` screens |
| `filterGroups` | `array` | Column-based filter groups, only populated below `md` breakpoint |
| `tagFilterKeys` | `array` | Tag keys grouped with their distinct values from `deviceFilters` |
| `handleFilterChange` | `fn` | Buffers column filters into a ref (Phase 1) |
| `handleTagsChange` | `fn` | Flushes buffered column filters + tags in one `setParams` call (Phase 2) |
| `selectedTags` | `string[]` | Currently applied tag filter values |

## Usage Example

```typescript
const {
  isOpen,
  open,
  close,
  isMdUp,
  filterGroups,
  tagFilterKeys,
  handleFilterChange,
  handleTagsChange,
  selectedTags,
} = useTagFilterModal({
  tags: currentTags,
  deviceFilters,
  columns,
  setParams,
});
```

## Notes

- **Two-phase buffering:** `FilterModal` calls `onFilterChange` before `onTagsChange`. Column filters are held in `pendingFiltersRef` and flushed only when `handleTagsChange` fires, ensuring a single atomic `setParams` update.
- After applying filters, the hook scrolls `<main>` back to the top via `scrollTo({ top: 0, behavior: 'instant' })`.
- Tags with `key === 'null'` or `value === 'null'` are silently excluded from `tagFilterKeys`.
