Manages state and logic for a tag-based device filter modal, coordinating column filters and tag filters into a single batched `setParams` call.

## Key Components

- **`isCompleteTag(tag)`** — Helper that validates a tag string contains a non-empty key and value separated by `:`.
- **`useTagFilterModal(params)`** — Primary hook exposing all modal state and handlers.
- **`pendingFiltersRef`** — A `useRef` buffer that holds column filters temporarily, since `FilterModal` calls `onFilterChange` before `onTagsChange`.
- **`filterGroups`** — Derived from `columns`; only populated on screens below `md` breakpoint (mobile/tablet), returns filterable column groups for the modal.
- **`tagFilterKeys`** — Groups `deviceFilters.tagKeys` by key, filtering out `"null"` keys/values, and formats them for display.
- **`handleFilterChange`** — Step 1 handler; buffers column filter selections into `pendingFiltersRef`.
- **`handleTagsChange`** — Step 2 handler; merges buffered column filters with tag selections and flushes everything via `setParams`, then resets the scroll position.

## Usage Example

```typescript
const {
  isOpen,
  open,
  close,
  isMdUp,
  filterGroups,
  tagFilterKeys,
  handleFilterChange,
  handleTagsChange,
  selectedTags,
} = useTagFilterModal({
  tags: activeTags,
  deviceFilters: filters,
  columns: tableColumns,
  setParams: (params) => router.push({ query: params }),
});

return (
  <FilterModal
    isOpen={isOpen}
    onClose={close}
    filterGroups={filterGroups}
    tagFilterKeys={tagFilterKeys}
    selectedTags={selectedTags}
    onFilterChange={handleFilterChange}
    onTagsChange={handleTagsChange}
  />
);
```

> **Note:** `handleFilterChange` and `handleTagsChange` must be wired in order — the modal calls filter change first, tags change second — ensuring both are merged into a single `setParams` call.
