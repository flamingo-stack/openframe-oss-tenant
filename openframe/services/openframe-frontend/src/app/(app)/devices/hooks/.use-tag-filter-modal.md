Custom hook that manages state and logic for a device tag filter modal, including column-based filters and tag-based filters with a two-phase flush pattern.

## Key Components

**`useTagFilterModal(params)`** — Main hook export accepting:
- `tags` — currently selected tag filters
- `deviceFilters` — available filter options including tag keys
- `columns` — table column definitions (used to build mobile filter groups)
- `setParams` — callback to apply combined filters

**`isCompleteTag(tag)`** — Internal helper that validates a tag string contains both a key and value (e.g., `"env:prod"`), rejecting partial entries like `"env:"` or `":prod"`.

**`pendingFiltersRef`** — A `useRef` buffer that holds column filters between the two-phase flush. `FilterModal` calls `onFilterChange` before `onTagsChange`, so column filters are staged here until tags arrive, then both are flushed together in a single `setParams` call.

**`filterGroups`** — Derived from filterable columns; only populated on mobile (`!isMdUp`) to avoid redundant desktop filter UI.

**`tagFilterKeys`** — Normalizes raw `deviceFilters.tagKeys` into grouped `{ key, label, values[] }` structures, skipping `"null"` keys and values.

## Usage Example

```typescript
const {
  isOpen,
  open,
  close,
  isMdUp,
  filterGroups,
  tagFilterKeys,
  handleFilterChange,
  handleTagsChange,
  selectedTags,
} = useTagFilterModal({
  tags: activeTagFilters,
  deviceFilters,
  columns: tableColumns,
  setParams,
});

// Wire into your FilterModal component
<FilterModal
  open={isOpen}
  onClose={close}
  filterGroups={filterGroups}
  tagFilterKeys={tagFilterKeys}
  selectedTags={selectedTags}
  onFilterChange={handleFilterChange}
  onTagsChange={handleTagsChange}
/>
```

> **Two-phase flush:** `handleFilterChange` buffers column filter state; `handleTagsChange` merges it with tag state and calls `setParams` once, preventing redundant re-renders or partial filter application.
