Builds a structured, availability-aware actions menu for a device, wiring together navigation, confirmation dialogs, and per-action enable/disable logic into a single reusable hook.

## Key Components

**`useDeviceActionsMenu(device, options)`** — Primary hook that composes all device action menu state.

**`UseDeviceActionsMenuOptions`** — Configuration interface:
- `onRunScript` — Custom handler for the Run Script action (falls back to navigation)
- `onActionComplete` — Callback fired after archive/delete succeeds
- `deviceId` — Override for when `device` is still loading
- `iconSize` — Tailwind size classes for icons (default: `w-6 h-6`)
- `navigateOnDestructive` — Auto-navigate to `/devices` after archive/delete

**`DeviceActionsMenuItems`** — Typed shape of all returned menu items:
`deviceDetails` · `remoteShell` · `remoteControl` · `manageFiles` · `runScript` · `deviceLogs` · `archive` · `delete`

**`UseDeviceActionsMenuResult`** — Return type exposing `items`, `dialogs` (confirmation dialog nodes), and `actionAvailability`.

## Usage Example

```typescript
import { useDeviceActionsMenu } from './use-device-actions-menu';

function DeviceCard({ device }: { device: Device }) {
  const { items, dialogs, actionAvailability } = useDeviceActionsMenu(device, {
    iconSize: 'w-5 h-5',
    navigateOnDestructive: true,
    onActionComplete: () => refetchDeviceList(),
  });

  const menuItems = [
    items.deviceDetails,
    items.remoteShell,
    items.runScript,
    items.archive,
    items.delete,
  ].filter(Boolean);

  return (
    <>
      <ActionsMenu items={menuItems} />
      {dialogs}
    </>
  );
}
```

> `archive` and `delete` items are `null` when unavailable — filter before rendering. The hook internally uses `useDeviceConfirmationDialogs`, so always render the returned `dialogs` node alongside the menu.
