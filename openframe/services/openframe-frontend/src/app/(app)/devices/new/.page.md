Client-side page component that renders the "New Device" registration UI, wrapping the content in a `Suspense` boundary to display a skeleton loader during async operations.

## Key Components

- **`NewDevicePage`** — Default export; the top-level page component that composes the Suspense boundary with its fallback and content.
- **`NewDeviceContent`** — The main content component rendered inside `Suspense` (imported from `./new-device-content`).
- **`NewDeviceSkeleton`** — Fallback UI displayed while `NewDeviceContent` is loading (imported from `./new-device-skeleton`).
- **`dynamic = 'force-dynamic'`** — Next.js segment config forcing dynamic rendering on every request, required because a parent layout (`AppLayout`) uses `useSearchParams`.

## Usage Example

This file is a Next.js App Router page and is automatically rendered when navigating to its route (e.g. `/devices/new`). No direct invocation is needed:

```typescript
// Next.js resolves and renders this automatically at the matching route.
// The Suspense boundary handles async child rendering:

<Suspense fallback={<NewDeviceSkeleton />}>
  <NewDeviceContent />
</Suspense>
```

> **Note:** The `'use client'` directive is required here because `useSearchParams` (used in a parent layout) cannot be used in Server Components without wrapping the consumer in a client-side `Suspense` boundary. Removing `dynamic = 'force-dynamic'` or the `Suspense` wrapper may cause build-time errors in Next.js static generation.
