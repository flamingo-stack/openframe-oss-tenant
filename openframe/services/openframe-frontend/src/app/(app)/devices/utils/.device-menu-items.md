Builds and returns a typed set of device action menu items from a given context, serving as the single source of truth for labels, icons, hrefs, and disabled states across all views that render device action menus.

## Key Components

### Interfaces

- **`DeviceMenuItemContext`** — Input context describing the target device and rendering options (device ID, availability, icon size, OS type, new-tab action toggle)
- **`DeviceMenuItems`** — Output shape containing five `ActionsMenuItem` entries: `deviceDetails`, `remoteShell`, `remoteControl`, `manageFiles`, `deviceLogs`

### Functions

- **`buildDeviceMenuItems(ctx)`** — Main export; constructs all five menu items using the provided context
- **`buildRemoteShellItem(ctx)`** — Internal builder; handles three shell variants:
  - `isWindows === true` → submenu with CMD and PowerShell entries
  - `isWindows === false` → direct link with `?shellType=bash`
  - `isWindows === undefined` → plain link without shell param (Tickets-style)
- **`maybeNewTabAction(ctx, href, label, disabled?)`** — Conditionally appends an `iconAction` (arrow icon) when `ctx.withNewTabAction` is `true`

## Usage Example

```typescript
// Devices table dropdown (Windows machine, with new-tab icons)
const items = buildDeviceMenuItems({
  deviceId: 'abc-123',
  availability: getDeviceActionAvailability(device),
  iconSize: 'w-6 h-6',
  isWindows: true,
  withNewTabAction: true,
});

// Render only the items needed for this view
<ActionsMenu items={[
  items.remoteShell,
  items.remoteControl,
  items.manageFiles,
]} />

// Tickets view (minimal context, no new-tab icons)
const ticketItems = buildDeviceMenuItems({
  deviceId: machineId,
  availability: null, // device not yet loaded — remote actions auto-disabled
});
```

> **Note:** `Run Script` is intentionally excluded — its handler opens a React-stateful modal owned by the parent component and cannot be expressed as a pure config item.
