Builds and returns a typed set of device action menu items (Device Details, Remote Shell, Remote Control, Manage Files, Device Logs) from a shared context, serving as the single source of truth for each action's label, icon, href, and disabled state.

## Key Components

### `DeviceMenuItemContext` (interface)
Configuration passed by the consuming view:
- `deviceId` — machine/device ID used in route hrefs
- `availability` — derived from `getDeviceActionAvailability`; `null` disables remote actions
- `iconSize?` — Tailwind size class (e.g. `'w-6 h-6'`), omitted for compact/ticket views
- `isWindows?` — controls Remote Shell rendering (`true` = CMD/PowerShell submenu, `false` = bash link, `undefined` = plain link)
- `withNewTabAction?` — appends an "open in new tab" icon-action to each item

### `DeviceMenuItems` (interface)
Typed record of all built `ActionsMenuItem` entries: `deviceDetails`, `remoteShell`, `remoteControl`, `manageFiles`, `deviceLogs`.

> **Note:** `Run Script` is intentionally excluded — its `onClick` opens a React-stateful modal owned by the parent and cannot be expressed as pure config.

### `buildDeviceMenuItems(ctx)` (exported function)
Primary factory. Accepts a `DeviceMenuItemContext` and returns the full `DeviceMenuItems` record. Views destructure only the items they need.

## Usage Example

```typescript
// Devices table row dropdown (Windows machine, with new-tab actions)
const items = buildDeviceMenuItems({
  deviceId: machine.id,
  availability: getDeviceActionAvailability(machine),
  iconSize: 'w-6 h-6',
  isWindows: machine.os === 'windows',
  withNewTabAction: true,
});

const menuItems = [
  items.deviceDetails,
  items.remoteShell,   // renders CMD / PowerShell submenu on Windows
  items.remoteControl,
  items.manageFiles,
  items.deviceLogs,
];

// Ticket sidebar (compact, no new-tab, OS unknown)
const ticketItems = buildDeviceMenuItems({
  deviceId: ticket.machineId,
  availability: null, // device not yet loaded — remote actions stay disabled
});
```
