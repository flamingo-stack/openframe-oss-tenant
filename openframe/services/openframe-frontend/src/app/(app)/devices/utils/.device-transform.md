Transforms a GraphQL node into a normalized `Device` list item for lightweight display in device list views, avoiding external API calls.

## Key Components

**`createDeviceListItem(node: DevicesGraphQlNode): Device`**
Maps a `DevicesGraphQlNode` to a `Device` object, populating only fields available from the GraphQL response. Fields requiring external API calls (CPU, memory, storage, software, MDM, etc.) are explicitly set to `undefined`, making the data-availability contract clear at a glance.

Notable mapping behaviors:
- **Hostname fallback:** `node.hostname || node.displayName`
- **Tactical RMM agent ID:** Extracted by scanning `toolConnections` for `toolType === 'TACTICAL_RMM'`
- **Local IPs:** Constructed as `[node.ip]` if present, otherwise `[]`
- **Organization image:** Falls back to `null` if unavailable
- Fields are mapped to both camelCase aliases (`lastSeen`/`last_seen`, `osType`/`operating_system`) for cross-consumer compatibility

## Usage Example

```typescript
import { createDeviceListItem } from './device-transform';
import { DevicesGraphQlNode } from '../types/device.types';

const node: DevicesGraphQlNode = {
  id: 'abc-123',
  hostname: 'workstation-01',
  ip: '192.168.1.50',
  status: 'online',
  osType: 'windows',
  osVersion: '11',
  toolConnections: [
    { toolType: 'TACTICAL_RMM', agentToolId: 'tac-999' }
  ],
  // ...other GraphQL fields
};

const device = createDeviceListItem(node);
console.log(device.hostname);        // 'workstation-01'
console.log(device.tacticalAgentId); // 'tac-999'
console.log(device.memory);          // undefined (not in list view)
```

> **Note:** This transform is intended for list views only. Detail views should use a separate transform that hydrates `undefined` fields via dedicated API calls.
