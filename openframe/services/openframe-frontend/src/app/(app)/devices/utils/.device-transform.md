Maps a `DevicesGraphQlNode` GraphQL response to a normalized `Device` object for list view rendering, omitting fields that require additional API calls (CPU, memory, storage, MDM, etc.).

## Key Components

### `createDeviceListItem(node: DevicesGraphQlNode): Device`

Transforms a raw GraphQL node into a lightweight `Device` list item. Fields unavailable at the list level (e.g., `cpu_brand`, `memory`, `disks`, `mdm`, `software`) are explicitly set to `undefined` to maintain a consistent shape across list and detail views.

**Notable mappings:**

| Source (`DevicesGraphQlNode`) | Target (`Device`) |
|---|---|
| `node.hostname \|\| node.displayName` | `hostname` |
| `node.serialNumber` | `hardware_serial`, `serial_number` |
| `node.osType` | `platform`, `operating_system`, `osType` |
| `node.ip` | `primary_ip`, `ip`, `local_ips` |
| `toolConnections` (TACTICAL_RMM) | `tacticalAgentId` |
| `node.organization.organizationId` | `organizationId` |

## Usage Example

```typescript
import { createDeviceListItem } from './device-transform';

const devices = graphQlNodes.map(node => createDeviceListItem(node));

// Result: normalized Device[] ready for list rendering
// Detail-only fields (cpu, memory, disks, mdm) are undefined
// until a full device fetch is performed
```

> **Note:** This transform is intentionally lightweight — detail-view fields should be populated separately via a full device fetch to avoid unnecessary API calls during list rendering.
