React page component that renders a live remote shell session (CMD or PowerShell) for a managed device using MeshCentral tunneling and an embedded xterm.js terminal.

## Key Components

- **`RemoteShellPage`** — Default export; full-page component mounted at `/devices/[deviceId]/remote-shell`
- **`WINDOWS_POWERSHELL_CMD`** — Fallback chain that attempts several PowerShell executable paths on Windows
- **`MeshTunnel`** / **`MeshControlClient`** — WebSocket tunnel and control session abstractions for MeshCentral agent communication
- **Terminal lifecycle** — Lazily imports `@xterm/xterm` and `@xterm/addon-fit`, opens a terminal in a `<div>` ref, handles resize, data I/O, and cleanup
- **State machine** — `TunnelState` (0–3: Idle → Connecting → Open → Connected) drives status display and PowerShell bootstrap timing
- **Shell type** — Resolved from `?shellType=powershell` query param; defaults to `cmd`

## Usage Example

```typescript
// Navigate to this page from a device detail view:
router.push(`/devices/details/${deviceId}/remote-shell?shellType=powershell`);

// The page will:
// 1. Load device details to resolve the MeshCentral agentToolId
// 2. Initialize an xterm.js terminal in the DOM
// 3. Open a MeshControlClient session and start a MeshTunnel (protocol=1 → shell)
// 4. For PowerShell, auto-send the WINDOWS_POWERSHELL_CMD once data is received
// 5. Render connection status, Disconnect button, and Back navigation
```

## States & Error Handling

| Condition | Rendered Output |
|---|---|
| `isDeviceLoading` | Animated skeleton layout |
| `deviceError` | Error message + Back button |
| `!meshcentralAgentId` | "Agent not available" message + Back button |
| Ready | Full terminal UI with status indicator |
