Renders an interactive browser-based remote shell terminal for a specific device, establishing a MeshCentral tunnel and embedding an xterm.js terminal emulator with support for both `cmd` and `powershell` shell types.

## Key Components

- **`RemoteShellPage`** — Default export; full-page Next.js Client Component managing terminal lifecycle, tunnel state, and device metadata
- **`MeshTunnel`** — WebSocket tunnel abstraction handling connect/disconnect, binary data relay, and pairing handshake
- **`MeshControlClient`** — Auth cookie management and relay session coordination with MeshCentral
- **`xterm.js` (dynamic import)** — Terminal emulator loaded lazily via `@xterm/xterm` + `@xterm/addon-fit` for responsive sizing
- **`WINDOWS_POWERSHELL_CMD`** — Fallback chain constant that auto-discovers and launches PowerShell on Windows endpoints

## Usage Example

```typescript
// Navigate to the page with optional shellType param:
// /devices/[deviceId]/remote-shell?shellType=powershell
// /devices/[deviceId]/remote-shell?shellType=cmd

// The page resolves the device's MeshCentral agentToolId automatically:
const meshcentralAgentId = deviceDetails?.toolConnections
  ?.find(tc => tc.toolType === 'MESHCENTRAL')
  ?.agentToolId;

// Tunnel state values map to UI status labels:
// 0 → "Idle" | 1 → "Connecting" | 2 → "Open" | 3 → "Connected"
```

## Behavior Notes

- Terminal initializes only after `meshcentralAgentId` is resolved (`isPageReady` gate)
- PowerShell command is sent once on first data receipt when `shellType === 'powershell'`
- Resize events propagate terminal dimensions to the remote session via `ctrlChannel 102938`
- Displays loading skeleton during device fetch, error states for fetch failures or missing MeshCentral agent
