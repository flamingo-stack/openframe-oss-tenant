Next.js page component for the device File Manager feature, handling loading, error, and missing-agent states before rendering the file browser UI.

## Key Components

- **`FileManagerPage`** — Default export; resolves the `deviceId` route param, fetches device details, extracts the MeshCentral agent ID, and gates rendering behind three guard states (loading → error → no agent).
- **`FileManagerPageSkeleton`** — Internal skeleton component rendered during device details fetch, wrapping `FileManagerSkeleton` inside `DetailPageContainer`.
- **`useDeviceDetails`** — Hook (polling disabled) that fetches device metadata including the MeshCentral agent connection.
- **`getMeshCentralAgentId`** — Utility that extracts the MeshCentral agent ID from device details; required for file manager functionality.
- **`useSafeBack`** — Hook providing a back-navigation handler that falls back to `/devices/details/[deviceId]`.

## Render States

| State | Output |
|---|---|
| Loading | `FileManagerPageSkeleton` |
| Error | Error message + "Return to Device Details" button |
| No MeshCentral agent | Warning message explaining agent requirement |
| Ready | `FileManagerContainer` with `deviceId`, `meshcentralAgentId`, and `hostname` |

## Usage Example

```typescript
// Accessed via Next.js route:
// /devices/details/[deviceId]/file-manager

// FileManagerContainer receives resolved props:
<FileManagerContainer
  deviceId="device-123"
  meshcentralAgentId="agent-abc"
  hostname="WORKSTATION-01"
  className="pt-4 px-4 md:pt-6 md:px-6"
/>
```

> **Note:** File manager functionality requires an active MeshCentral agent on the target device. If the agent ID cannot be resolved from device details, the page renders an informational error state rather than attempting to load the file browser.
