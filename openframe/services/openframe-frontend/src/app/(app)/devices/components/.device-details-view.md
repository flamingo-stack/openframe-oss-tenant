Full-page view component for displaying detailed information about a single device, including status, tags, tabbed content sections, and device action menus.

## Key Components

- **`DeviceDetailsView`** — Main export. Renders the complete device detail page with header actions, status tags, info section, and tab navigation.
- **`DeviceStatusAndTags`** — Internal component displaying the device's status badge and associated key/value tags with tooltips.
- **`DEVICE_TAB_IDS`** — Constant tuple defining valid tab identifiers: `hardware`, `network`, `security`, `compliance`, `agents`, `users`, `software`, `vulnerabilities`, `logs`.
- **`DEFAULT_DEVICE_TAB`** — Defaults to `'hardware'` when no valid tab is present in the URL.

## Key Behaviors

- **URL-driven tab state** — Active tab is read from the `?tab=` search param; changes are written back via `router.replace()` to avoid flicker.
- **URL action handling** — Supports `?action=runScript` param (e.g., navigated from a table dropdown) to auto-open the scripts modal on load.
- **Relative time refresh** — Forces a re-render every second to keep relative timestamps current.
- **Action menu** — Builds grouped `ActionsMenuGroup[]` from `useDeviceActionsMenu`, separating primary actions (run script, manage files) from destructive ones (archive, delete).

## Usage Example

```typescript
// Render device detail page for a given device ID
import { DeviceDetailsView } from './device-details-view';

export default function DevicePage({ params }: { params: { id: string } }) {
  return <DeviceDetailsView deviceId={params.id} />;
}
```

> **Note:** Renders `DeviceDetailsSkeleton` during load, `LoadError` on fetch failure, and `NotFoundError` when the device is not found — no additional error boundary required.
