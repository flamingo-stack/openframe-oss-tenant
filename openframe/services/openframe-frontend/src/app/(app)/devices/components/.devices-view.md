Client-side page component that renders the full Devices list view, supporting both table and grid display modes with search, tag filtering, column filtering, and infinite scroll pagination.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `DevicesView` | React Component | Root page component orchestrating device listing UI |

**Internal hooks consumed:**

| Hook | Purpose |
|------|---------|
| `useDevicesUrlParams` | Syncs search/filter/viewMode state with URL params |
| `useDevices` | Fetches paginated device data with infinite scroll |
| `useDeviceFilters` | Fetches available filter options (status, OS, org) |
| `useTagFilterModal` | Manages the filter modal open state and tag selection |
| `useGridInfiniteScroll` | Triggers `fetchNextPage` via Intersection Observer in grid mode |

## Usage Example

```typescript
// app/devices/page.tsx
import { DevicesView } from '@/features/devices/components/devices-view';

export default function DevicesPage() {
  return <DevicesView />;
}
```

## Behavior Notes

- **View toggle** — `TabSelector` switches between `table` and `grid` modes; persisted in URL via `viewMode` param.
- **Sticky search bar** — `TagSearchInput` + filter button remain fixed at the top while scrolling.
- **Filter modal** — Responsive: shows a labeled "Device Tags" button on `md+` screens, icon-only on mobile.
- **Infinite scroll** — Table mode uses `DataTable.InfiniteFooter` with a manual "load more" trigger; grid mode uses a sentinel `ref` for automatic scroll-based loading.
- **Column filters** — Status, OS type, and organization filters are derived from URL params and synced back via `onColumnFiltersChange`.
- **Error state** — Renders `<PageError>` if the devices fetch returns an error.
