Defines the column structure, filter metadata, and table composition for the devices data table, including cell renderers, filter options, and row-level actions.

## Key Components

- **`getDeviceTableRowActions`** — Returns a render function that wraps `DeviceActionsDropdown` for use as a row-level actions menu (three-dot menu).
- **`deviceRowHref`** — Derives the navigation URL for a device row using `machineId` or `id`.
- **`DEVICE_OPEN_COLUMN`** — Static column definition rendering an "open in new tab" button, pinned to the right side of the table.
- **`DevicesTableBody`** — Full table component composing columns, filters, skeleton loading, sticky headers, and footer slots via `DataTable`.
- **`getDeviceFilterColumns`** — Returns filter metadata (`DeviceFilterColumn[]`) for external filter modals (e.g. mobile tag filter modal), independent of `ColumnDef`.
- **`getDeviceTableColumns`** — Returns the core `ColumnDef<Device>[]` array covering device name/icon, status+last-seen, OS badge, and organization columns — each with optional filter options derived from `DeviceFilters`.

## Usage Example

```typescript
// Basic table with org column hidden and refresh-aware row actions
const actionsColumn = {
  id: 'actions',
  cell: ({ row }) => getDeviceTableRowActions(refetch)(row.original),
};

<DevicesTableBody
  devices={devices}
  isLoading={isLoading}
  deviceFilters={filters}
  hideColumns={['organization']}
  actionsColumn={actionsColumn}
  columnFilters={columnFilters}
  onColumnFiltersChange={setColumnFilters}
  totalCount={totalCount}
  stickyHeaderOffset="64px"
/>
```

## Notes

- `getDeviceFilterColumns` and `getDeviceTableColumns` both derive filter options from the same `DeviceFilters` source but serve different consumers — the DataTable header vs. an external modal.
- `ARCHIVED` and `DELETED` statuses are excluded from filter options via `DEFAULT_VISIBLE_STATUSES`.
- The `hideColumns` prop on `DevicesTableBody` accepts column `id` strings to drop from the base column set at render time, useful for scoped views (e.g. single-org context).
