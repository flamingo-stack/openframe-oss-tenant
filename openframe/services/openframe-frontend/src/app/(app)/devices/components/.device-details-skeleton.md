Renders loading placeholder UI for the device details page, providing pixel-accurate skeleton screens that mirror the layout of each tab and section before real data loads.

## Key Components

| Component | Description |
|-----------|-------------|
| `SectionHeadingSkeleton` | Reusable heading placeholder matching `h3.text-h5` section titles |
| `InfoCardSkeleton` | Card placeholder with configurable item count, optional title, subtitle, and progress bar |
| `TableSkeleton` | Table placeholder with configurable columns and row count |
| `InfoFieldSkeleton` | Single field placeholder matching label + value layout used in `DeviceInfoSection` |
| `DeviceInfoSectionSkeleton` | Three-row grid of 4 fields each, matching the device info panel |
| `DeviceStatusAndTagsSkeleton` | Status tag + chip row placeholder |
| `TabNavigationSkeleton` | Full-width tab bar with icon + label slots for all 9 tabs |
| `HardwareTabSkeleton` | Disk (4-col), RAM (3-col), and CPU section skeletons |
| `NetworkTabSkeleton` | Public IP card + 2-col IPv4/IPv6 grid skeleton |
| `SecurityTabSkeleton` | Six security sections: posture, sessions, agents, network, alerts, boot info |
| `ComplianceTabSkeleton` | Patch management, policy compliance, and compliance checks sections |
| `AgentsTabSkeleton` | 3-col grid of agent cards with absolute-positioned tool badge and info icon |

## Usage Example

```typescript
import { DeviceInfoSectionSkeleton, TabNavigationSkeleton } from './device-details-skeleton';

export default function DeviceDetailsPage({ isLoading, device }) {
  if (isLoading) {
    return (
      <>
        <DeviceStatusAndTagsSkeleton />
        <DeviceInfoSectionSkeleton />
        <TabNavigationSkeleton />
        <HardwareTabSkeleton />
      </>
    );
  }

  return <DeviceDetails device={device} />;
}
```

Each skeleton component is self-contained and can be rendered independently per tab, allowing progressive loading states as individual sections resolve.
