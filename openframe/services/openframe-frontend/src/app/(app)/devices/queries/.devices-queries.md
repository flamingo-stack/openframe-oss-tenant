GraphQL query definitions for device-related operations, providing queries for fetching device lists, individual devices, filter metadata, and lightweight overview data.

## Key Components

| Export | Operation | Description |
|--------|-----------|-------------|
| `GET_DEVICE_FILTERS_QUERY` | `GetDeviceFilters` | Fetches available filter facets (statuses, OS types, organizations, tags) with counts |
| `GET_DEVICES_QUERY` | `GetDevices` | Paginated device list with full details, sorting, searching, and filtering |
| `GET_DEVICE_QUERY` | `GetDevice` | Single device lookup by `machineId` including installed agents |
| `GET_DEVICES_OVERVIEW_QUERY` | `GetDevicesOverview` | Lightweight paginated query returning only device status (for dashboards/summaries) |

## Usage Example

```typescript
import {
  GET_DEVICES_QUERY,
  GET_DEVICE_QUERY,
  GET_DEVICE_FILTERS_QUERY,
  GET_DEVICES_OVERVIEW_QUERY,
} from './devices-queries';

// Paginated device list with filter + search
const devicesResult = await gqlClient.query({
  query: GET_DEVICES_QUERY,
  variables: {
    filter: { osType: 'WINDOWS', organizationIds: ['org-123'] },
    first: 25,
    after: null,
    search: 'workstation',
    sort: { field: 'lastSeen', direction: 'DESC' },
  },
});

// Fetch a single device by machineId
const deviceResult = await gqlClient.query({
  query: GET_DEVICE_QUERY,
  variables: { machineId: 'machine-abc-456' },
});

// Load filter facets for a filter panel
const filtersResult = await gqlClient.query({
  query: GET_DEVICE_FILTERS_QUERY,
  variables: { filter: {} },
});
```

## Notes

- `GET_DEVICES_QUERY` and `GET_DEVICES_OVERVIEW_QUERY` both use cursor-based pagination via `pageInfo.endCursor` / `hasNextPage`.
- `GET_DEVICE_QUERY` additionally returns `installedAgents`, which is omitted from the list query for performance.
- `GET_DEVICES_OVERVIEW_QUERY` intentionally omits heavy fields — use it for status aggregation or polling scenarios where bandwidth matters.
