Hook that provides server-side script autocomplete functionality, managing search state, debouncing, lazy query execution, and edit-mode pre-selection for script dropdown components.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `useScriptsAutocomplete` | Hook | Main hook returning scripts list, loading state, and input/lifecycle handlers |
| `fetchScriptsV2` | Internal | Fetches paginated scripts from `/v2/scripts/` with optional search and platform filters |
| `fetchScriptById` | Internal | Fetches a single script by ID for edit-mode pre-population |

**Parameters:**

| Param | Type | Description |
|-------|------|-------------|
| `supportedPlatforms` | `string[]` | Platform filters passed to the API |
| `selectedScriptId` | `number?` | Pre-selected script ID for edit mode |

**Return values:**

| Key | Type | Description |
|-----|------|-------------|
| `scripts` | `ScriptEntry[]` | Deduplicated options list, pre-selected item prepended when no active search |
| `isLoading` | `boolean` | `true` while the search query is fetching |
| `inputValue` | `string` | Controlled input state |
| `onInputChange` | `fn` | Updates input, triggers debounced search after 500ms |
| `onOpen` | `fn` | Activates the lazy query |
| `onClose` | `fn` | Deactivates query and resets input |
| `onClear` | `fn` | Immediately resets input, bypassing debounce |

## Usage Example

```typescript
import { useScriptsAutocomplete } from './use-scripts-autocomplete';

function ScriptSelector({ scriptId }: { scriptId?: number }) {
  const {
    scripts,
    isLoading,
    inputValue,
    onInputChange,
    onOpen,
    onClose,
    onClear,
  } = useScriptsAutocomplete(['windows', 'linux'], scriptId);

  return (
    <Autocomplete
      options={scripts}
      loading={isLoading}
      inputValue={inputValue}
      onInputChange={(_, val) => onInputChange(val)}
      onOpen={onOpen}
      onClose={onClose}
      onClear={onClear}
      getOptionLabel={(s) => s.name}
    />
  );
}
```

> **Loading strategy:** The search query is lazy — it only fires while the dropdown is open (`isActive: true`), avoiding redundant requests when multiple cards are mounted simultaneously. On close, the input resets so the next open always starts with an unfiltered list.
