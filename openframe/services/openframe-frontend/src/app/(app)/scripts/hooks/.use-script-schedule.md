React Query hooks for fetching script schedule data from the Tactical RMM API, including list, detail, assigned agents, and execution history.

## Key Components

### Query Keys
`scriptScheduleQueryKeys` — structured cache key factory for TanStack Query:
- `list()` — all schedules
- `detail(id)` — single schedule by ID
- `agents(id)` — agents assigned to a schedule
- `history(id, limit, offset)` — paginated execution history

### Hooks

| Hook | Returns | Notes |
|---|---|---|
| `useScriptSchedules()` | `schedules[]` | Full schedule list |
| `useScriptSchedule(id)` | `schedule \| null` | Single detail; skips fetch if no `id` |
| `useScriptScheduleAgents(id)` | `agents[]` | Agents assigned to schedule |
| `useScriptScheduleHistory(id, options?)` | `history[]`, `total` | Paginated; defaults `limit=50, offset=0` |

All hooks return a consistent shape: `{ data, isLoading, error, refetch }`.

## Usage Example

```typescript
// List all schedules
const { schedules, isLoading, error } = useScriptSchedules();

// Fetch a single schedule with its agents
const { schedule } = useScriptSchedule('schedule-123');
const { agents } = useScriptScheduleAgents('schedule-123');

// Paginated execution history
const { history, total } = useScriptScheduleHistory('schedule-123', {
  limit: 25,
  offset: 0,
});
```

> All hooks are client-side only (`'use client'`). Queries with an `id` parameter are automatically disabled when `id` is falsy, preventing unnecessary API calls. Stable empty array/object constants (`EMPTY_SCHEDULES`, `EMPTY_AGENTS`, `EMPTY_HISTORY`) are used as fallbacks to avoid reference-equality churn on re-renders.
