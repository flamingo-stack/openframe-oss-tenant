Manages form state and submission logic for creating or editing a script, handling validation, API mutations, cache invalidation, and navigation.

## Key Components

- **`useEditScriptForm`** — Primary hook that orchestrates the full create/edit script workflow
- **`createScriptApi`** — Calls `tacticalApiClient.createScript` and throws on error
- **`updateScriptApi`** — Calls `tacticalApiClient.updateScript` with script ID and throws on error
- **`UseEditScriptFormOptions`** — Input interface accepting `scriptId`, `scriptDetails`, and `isEditMode`

## Usage Example

```typescript
import { useEditScriptForm } from './use-edit-script-form';

function ScriptFormPage({ scriptId, scriptDetails, isEditMode }) {
  const { form, isSubmitting, handleSave } = useEditScriptForm({
    scriptId,
    scriptDetails,
    isEditMode,
  });

  return (
    <Form {...form}>
      <input {...form.register('name')} placeholder="Script name" />
      <button onClick={handleSave} disabled={isSubmitting}>
        {isSubmitting ? 'Saving...' : 'Save'}
      </button>
    </Form>
  );
}
```

## Behavior Notes

- In **edit mode**, the form is pre-populated from `scriptDetails` via a `useEffect` reset whenever the details change
- `args` are parsed from space-separated strings (e.g. `"key value"` → `{ key, value }`) and serialized back on submit
- `env_vars` are parsed from `KEY=VALUE` format and re-serialized on submit; entries with empty keys are filtered out before submission
- On **create success**, navigates to `/scripts/details/:id` (or `/scripts` as fallback)
- On **update success**, uses `safeBackOrReplace` to return to the script detail page
- Both mutations invalidate `scriptsQueryKeys.all`; updates also invalidate the specific script detail query
