Client-side Next.js page component that renders the Scripts management interface within the OpenFrame platform layout.

## Key Components

- **`Scripts`** (default export) — Page component that wraps `ScriptsView` inside a full-width `ContentPageContainer` with system-level spacing and no default header.
- **`ContentPageContainer`** — Layout wrapper from `@flamingo-stack/openframe-frontend-core` providing consistent page structure.
- **`ScriptsView`** — Feature component rendering the scripts list and management UI.

## Usage Example

```typescript
// Rendered automatically by Next.js App Router at the /scripts route.
// No manual instantiation required.

// ContentPageContainer props used:
<ContentPageContainer
  className="p-[var(--spacing-system-l)]"
  padding="none"
  showHeader={false}
>
  <ScriptsView />
</ContentPageContainer>
```

## Notes

- Marked `'use client'` — runs exclusively in the browser context.
- `dynamic = 'force-dynamic'` disables static generation, ensuring the page is always server-rendered fresh on each request (useful for live script data).
- Header is hidden (`showHeader={false}`); `ScriptsView` is expected to manage its own heading/toolbar.
