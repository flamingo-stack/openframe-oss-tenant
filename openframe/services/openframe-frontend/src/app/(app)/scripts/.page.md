A Next.js client-side page component that renders the Scripts management view within a standardized content container.

## Key Components

- **`Scripts`** (default export) — Page component that wraps `ScriptsView` inside `ContentPageContainer` with system-level padding and no header.
- **`ContentPageContainer`** — Layout wrapper from `@flamingo-stack/openframe-frontend-core` providing consistent page structure.
- **`ScriptsView`** — The primary scripts management UI component rendered within the container.

## Usage Example

```typescript
// This page is rendered automatically by Next.js at the /scripts route.
// No direct instantiation needed — it is the default export consumed by the router.

import Scripts from './page';

// Internally renders:
// <ContentPageContainer className="p-[var(--spacing-system-l)]" padding="none" showHeader={false}>
//   <ScriptsView />
// </ContentPageContainer>
```

## Notes

- `'use client'` directive enables client-side rendering for this page.
- `dynamic = 'force-dynamic'` disables static generation, ensuring the page is always server-rendered at request time (no caching).
- Header is explicitly hidden via `showHeader={false}`, delegating navigation/title rendering to `ScriptsView` or a parent layout.
