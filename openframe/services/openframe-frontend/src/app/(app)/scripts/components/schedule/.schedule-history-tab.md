Displays a paginated execution history table for a script schedule, with a slide-out log drawer for viewing detailed run output per entry.

## Key Components

- **`ScheduleHistoryTab`** — Main exported component that renders the history data table, pagination controls, and log detail drawer
- **`getStatusVariant(status)`** — Maps execution status strings (`'passing'`, `'failing'`) to UI tag color variants
- **`getStatusLabel(entry)`** — Derives a human-readable status label from a history entry's `retcode` and `status` fields
- **`useScriptScheduleHistory`** — Hook that fetches paginated history data for a given `scheduleId`
- **`LogDrawer`** — Shared drawer component populated with metadata fields (device, platform, return code, sync status, execution time) and raw stdout/stderr output
- **`DataTable` + `useDataTable`** — Table infrastructure with columns for Log ID, Status, Device, and Log Details

## Usage Example

```typescript
import { ScheduleHistoryTab } from './schedule-history-tab';

<ScheduleHistoryTab
  scheduleId="sched_abc123"
  schedule={scheduleDetail}
/>
```

## Column Layout

| Column | Description | Responsive |
|---|---|---|
| `LOG ID` | Zero-padded ID + run timestamp | Always visible |
| `STATUS` | Color-coded tag (passing/failing) | Always visible |
| `DEVICE` | Agent hostname | Hidden at `md` |
| `LOG DETAILS` | Truncated stdout/stderr + exec time | Hidden at `md` |

## Pagination

Fetches 50 records per page using `offset`/`limit` state. Previous/Next controls render only when `total > 50`.

> **Note:** A `console.log(history)` debug statement is present in the component and should be removed before production use.
