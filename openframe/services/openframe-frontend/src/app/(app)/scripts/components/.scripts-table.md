A client-side React component that renders a paginated, filterable table of automation scripts for the Flamingo/OpenFrame MSP platform, with URL-persisted search/filter state and row-level actions.

## Key Components

- **`ScriptsTable`** — Main exported component; renders the full scripts list page with search, multi-select filters, and row actions
- **`UiScriptEntry`** — Interface defining the normalized shape of a script row (id, name, shellType, supportedPlatforms, category, etc.)
- **URL State** — Search, shell type, category, and platform filters persist in the URL via `useApiParams`
- **`filteredScripts`** — Client-side filtering logic across name, description, shellType, category, and supportedPlatforms
- **`renderRowActions`** — Renders a dropdown with **Run**, **Edit**, and **Details** actions, each supporting new-tab navigation
- **`columns`** — TanStack Table column definitions for Name, Shell Type, OS, Added By, Category, Description, and Actions; responsive visibility via `hideAt` meta
- **`handleColumnFiltersChange`** — Syncs TanStack column filter state back to URL params and resets pagination
- **Load More** — Simple slice-based pagination (`visibleCount`) incremented on user request

## Usage Example

```typescript
// Mount inside a scripts page route
import { ScriptsTable } from './components/scripts-table';

export default function ScriptsPage() {
  return <ScriptsTable />;
}
```

```typescript
// URL params managed automatically:
// /scripts?search=backup&shellType=powershell&category=Security

// Row navigation targets:
// Details → /scripts/details/:id
// Edit    → /scripts/edit/:id
// Run     → /scripts/details/:id/run
```

## Notes

- Debounced search (300 ms) prevents excessive URL writes
- `useRef` pattern keeps `handleColumnFiltersChange` referentially stable while reading latest filter state
- `data-no-row-click` on action cells prevents row-click navigation conflicts
- `addedBy` is hardcoded to `'tactical'` (TacticalRMM as the data source)
