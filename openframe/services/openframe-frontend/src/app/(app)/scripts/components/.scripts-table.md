A client-side React table component for displaying, filtering, searching, and navigating scripts in the Flamingo/OpenFrame MSP platform.

## Key Components

### `ScriptsTable` (exported function)
The main component rendering a filterable, searchable data table of automation scripts.

### `UiScriptEntry` (interface)
Local UI model representing a script row with fields: `id`, `name`, `description`, `shellType`, `addedBy`, `supportedPlatforms`, `category`, `timeout`.

### Key Behaviors

| Feature | Details |
|---|---|
| **URL-persisted state** | Search, filters, and pagination sync to URL via `useApiParams` |
| **Debounced search** | 300ms debounce on search input before URL update |
| **Client-side filtering** | Filters by `search`, `shellType`, `category`, `supportedPlatforms` |
| **Incremental loading** | Renders 10 rows initially, "load more" appends 10 at a time |
| **Row actions** | Run, Edit, Details — each with an open-in-new-tab icon action |
| **Responsive columns** | Columns hide at `md`/`lg` breakpoints via `meta.hideAt` |

### Column Definitions
`name` · `shellType` · `supportedPlatforms` · `addedBy` · `category` · `description` · `actions` · `open`

## Usage Example

```typescript
// Render the scripts table in a page component
import { ScriptsTable } from '@/features/scripts/components/scripts-table';

export default function ScriptsPage() {
  return <ScriptsTable />;
}
```

```typescript
// URL params automatically managed — filters are shareable:
// /scripts?search=backup&shellType=powershell&category=Security
```

> **Note:** `ScriptsTable` depends on the `useScripts` hook for data fetching and `useApiParams` for URL state. Ensure the route context and API layer are configured before rendering.
