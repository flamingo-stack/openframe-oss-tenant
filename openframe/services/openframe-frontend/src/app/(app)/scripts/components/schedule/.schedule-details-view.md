Renders the full detail view for a single script schedule, composing tab navigation, action buttons, and schedule metadata into a unified page layout.

## Key Components

- **`ScheduleDetailView`** — Main exported component; accepts `scheduleId` and orchestrates data fetching, error states, and tab routing
- **`SCHEDULE_TABS`** — Static tab configuration defining three tabs: `schedule-scripts`, `schedule-devices`, and `schedule-history`
- **`handleTabChange`** — URL-controlled tab sync using `router.replace`; avoids flicker by treating the URL as the single source of truth instead of relying on `urlSync` mode
- **`actions`** — Memoized array of `Edit Devices` and `Edit Schedule` action buttons rendered as icon-buttons in the page header

## Tab Structure

| Tab ID | Label | Component |
|---|---|---|
| `schedule-scripts` | Scheduled Scripts | `ScheduleScriptsTab` |
| `schedule-devices` | Assigned Devices | `ScheduleDevicesTab` |
| `schedule-history` | Execution History | `ScheduleHistoryTab` |

## Usage Example

```typescript
// Render the schedule detail view for a given schedule ID
import { ScheduleDetailView } from './schedule-details-view';

export default function SchedulePage({ params }: { params: { id: string } }) {
  return <ScheduleDetailView scheduleId={params.id} />;
}
```

## State & Error Handling

Uses `useScriptSchedule(scheduleId)` to fetch data with three possible render outcomes:

- **Loading** → `ScheduleDetailSkeleton`
- **Error** → `LoadError` with message
- **Not found** → `NotFoundError`

Active tab defaults to `schedule-scripts` and falls back to it if an unrecognized `?tab=` query param is provided.
