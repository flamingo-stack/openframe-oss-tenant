Loading skeleton for the Schedule Create/Edit page that mirrors the exact layout of `ScheduleCreateView`, preventing layout shift during data fetch.

## Key Components

| Component | Description |
|-----------|-------------|
| `ScheduleCreateSkeleton` | Main exported skeleton — full page loader matching the create/edit schedule layout |
| `NameFieldSkeleton` | Skeleton for the schedule name label + input field |
| `DateRepeatSkeleton` | Skeleton for the date picker and repeat checkbox row |
| `PlatformsSkeleton` | Skeleton for the supported platforms row (3 platform buttons) |
| `ActionCardSkeleton` | Skeleton for a `ScheduleActionFormCard` including header, action selector, and parameter fields |

## Usage Example

```typescript
import { ScheduleCreateSkeleton } from './schedule-create-skeleton';

// Render while schedule data or form config is loading
function ScheduleCreatePage() {
  const { data, isLoading } = useSchedule();

  if (isLoading) return <ScheduleCreateSkeleton />;

  return <ScheduleCreateView data={data} />;
}
```

## Notes

- Marked `'use client'` — renders exclusively on the client side.
- Uses `Skeleton` from `@flamingo-stack/openframe-frontend-core` to stay consistent with ODS design tokens (`bg-ods-bg`, `bg-ods-card`, `border-ods-border`).
- Sub-skeletons (`NameFieldSkeleton`, etc.) are intentionally unexported — they are internal layout fragments composed only by `ScheduleCreateSkeleton`.
