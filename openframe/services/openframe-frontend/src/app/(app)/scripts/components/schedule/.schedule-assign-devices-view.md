View component for assigning devices to a script schedule, handling device fetching, selection state, and saving agent assignments.

## Key Components

**`ScheduleAssignDevicesView`** — Main exported component that renders a device selector interface for a given `scheduleId`. Orchestrates data fetching, selection initialization, and mutation submission.

**`fetchDevicesByPlatforms`** — Async utility that queries the GraphQL API for online/offline devices filtered by OS platform types, returning up to 100 results sorted by status.

**`getDeviceKey`** — Alias for `getDevicePrimaryId`, used as the device identity key in the selector.

## Usage Example

```typescript
import { ScheduleAssignDevicesView } from './schedule-assign-devices-view';

// In a Next.js page or parent component
export default function AssignDevicesPage({ params }: { params: { id: string } }) {
  return <ScheduleAssignDevicesView scheduleId={params.id} />;
}
```

## Behavior Notes

- **Initialization**: Pre-selects devices by mapping existing schedule `agent_id` values back to device primary IDs via the Tactical agent ID field.
- **Platform filtering**: Only fetches devices whose OS types match the schedule's `task_supported_platforms`, converted via `mapPlatformsToOsTypes`.
- **Device ordering**: Devices with a Tactical agent installed are sorted first; unsupported devices render as disabled with a tooltip.
- **Save flow**: Extracts Tactical agent IDs from selected devices and calls `useReplaceScheduleAgents`, then redirects to the schedule's `schedule-devices` tab on success.
- **Loading/error states**: Renders `ScheduleAssignDevicesSkeleton`, `LoadError`, or `NotFoundError` from `openframe-frontend-core` depending on fetch state.
