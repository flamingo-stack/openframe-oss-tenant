View component for assigning devices to a script schedule, handling device fetching, selection state, and persisting agent assignments via mutation.

## Key Components

- **`ScheduleAssignDevicesView`** — Main exported component that renders a device selector UI for a given `scheduleId`, initialized with currently assigned agents
- **`fetchDevicesByPlatforms`** — Async helper that queries the GraphQL API for online/offline devices filtered by OS type, returning up to 100 results sorted by status
- **`getDeviceKey`** — Alias for `getDevicePrimaryId`, used as the stable key function for the device selector

## Usage Example

```typescript
// Render the assign-devices view for a specific schedule
import { ScheduleAssignDevicesView } from './schedule-assign-devices-view';

export default function Page({ params }: { params: { id: string } }) {
  return <ScheduleAssignDevicesView scheduleId={params.id} />;
}
```

## Behavior Notes

- Devices are split into two groups on load: those with a Tactical agent ID (selectable) and those without (shown but disabled with tooltip `"Tactical agent is not installed"`)
- Selection state is initialized once from the existing schedule agent list, mapping Tactical agent IDs back to device primary IDs
- On **Save**, selected devices are resolved to Tactical agent IDs and passed to `useReplaceScheduleAgents`; on success, navigates to the schedule's `?tab=schedule-devices` tab
- Displays a `ScheduleInfoBarFromData` header inside the selector showing schedule name, date/time, repeat cadence, and supported platforms
- Handles loading (`ScheduleAssignDevicesSkeleton`), error (`LoadError`), and not-found (`NotFoundError`) states
