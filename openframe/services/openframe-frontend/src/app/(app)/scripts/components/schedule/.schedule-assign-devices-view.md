View component for assigning devices to a script schedule. Fetches compatible devices by platform, initializes selection from existing agent assignments, and persists changes via a replace-agents mutation.

## Key Components

- **`ScheduleAssignDevicesView`** — Main exported component. Renders a `DeviceSelector` inside a `DetailPageContainer`, wired to schedule-specific state and save logic.
- **`fetchDevicesByPlatforms`** — Async helper that queries the GraphQL API for online/offline devices filtered by OS type, returning up to 100 results sorted by status.
- **`getDeviceKey`** — Alias for `getDevicePrimaryId`, used as the stable key function for device list items.

## Usage Example

```typescript
// In a Next.js page/route segment
import { ScheduleAssignDevicesView } from './schedule-assign-devices-view';

export default function Page({ params }: { params: { scheduleId: string } }) {
  return <ScheduleAssignDevicesView scheduleId={params.scheduleId} />;
}
```

## Behavior Notes

- **Initialization guard** — `isInitialized` prevents overwriting user selection after the first render; maps tactical agent IDs back to device primary IDs to pre-check rows.
- **Platform filtering** — `mapPlatformsToOsTypes` converts `task_supported_platforms` from the schedule into OS type strings used as a GraphQL filter variable.
- **Device ordering** — Devices with a Tactical agent ID are surfaced first; others are appended at the end.
- **Save flow** — Calls `useReplaceScheduleAgents` with resolved Tactical agent IDs, then navigates to the `schedule-devices` tab on success.
- **Disabled state** — Devices lacking a Tactical agent ID render as disabled with a tooltip message inside `DeviceSelector`.
- **Loading/error states** — Returns `ScheduleAssignDevicesSkeleton`, `LoadError`, or `NotFoundError` based on schedule fetch state.
