Async Next.js page component that validates and routes log detail view requests, redirecting to the logs listing page if required query parameters are missing.

## Key Components

- **`LogDetailsPage`** — Default async page export that resolves `searchParams` and enforces presence of all required log identifiers before rendering
- **`LogDetailsView`** — Imported child component that receives validated log parameters as props
- **`dynamic = 'force-dynamic'`** — Next.js segment config forcing dynamic rendering, required due to `useSearchParams` usage in the layout

## Required Search Parameters

| Parameter | Description |
|-----------|-------------|
| `id` | Unique log entry identifier |
| `ingestDay` | Day partition the log was ingested |
| `toolType` | Source tool type for the log |
| `eventType` | Classification of the log event |
| `timestamp` | Event timestamp |

If any parameter is missing, the user is redirected to `/logs-page`.

## Usage Example

```typescript
// Navigate to this page with all required params:
const params = new URLSearchParams({
  id: 'abc123',
  ingestDay: '2024-01-15',
  toolType: 'zabbix',
  eventType: 'alert',
  timestamp: '1705324800000',
});

router.push(`/logs-page/details?${params.toString()}`);
```
