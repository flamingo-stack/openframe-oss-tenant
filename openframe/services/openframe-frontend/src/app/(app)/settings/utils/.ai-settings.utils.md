Utility functions for transforming and managing AI policy rules into structured permission category groups used by the AI settings UI.

## Key Components

| Export | Description |
|--------|-------------|
| `buildPolicyGroups` | Transforms a flat array of `PolicyRule` objects into a nested `Map` of policy groups → `PermissionCategory[]`, sorted alphabetically by category name |
| `clonePolicyGroups` | Deep-clones a policy groups `Map` to prevent mutation of shared state |
| `mapToObject` | Converts a `Map<string, T>` to a plain `Record<string, T>` object |
| `slugify` *(internal)* | Normalizes strings into URL-safe slugs used as stable category IDs |

## Usage Example

```typescript
import {
  buildPolicyGroups,
  clonePolicyGroups,
  mapToObject,
} from './ai-settings.utils';

// Transform raw policy rules into grouped UI structure
const rules: PolicyRule[] = [
  {
    naturalKey: 'read:tickets',
    operation: 'Read Tickets',
    category: 'Tickets',
    policyGroup: 'ConnectWise',
    tool: 'connectwise_psa',
    approvalLevel: 'auto',
    commandPattern: undefined,
  },
];

const groups = buildPolicyGroups(rules);
// Map { 'ConnectWise' => [{ id: 'connectwise:tickets', name: 'Tickets', policies: [...] }] }

// Deep clone before mutation
const editableCopy = clonePolicyGroups(groups);

// Serialize to plain object for API payload
const payload = mapToObject(editableCopy);
// { ConnectWise: [{ id: 'connectwise:tickets', ... }] }
```

## Notes

- Categories without a `policyGroup` fall back to `'General'`; those without a `category` fall back to `'Other'`
- Each category is assigned a `<Shield />` icon by default
- `buildPolicyGroups` delegates tool name normalization to `normalizeToolTypeWithFallback` from the core package
