URL-synchronized settings view component that manages tab navigation state, syncing the active tab with the `?tab=` query parameter to support browser back/forward navigation.

## Key Components

- **`SettingsView`** — Main exported component that composes tab navigation and content
- **`TabId`** — Union type for valid tab identifiers: `ai-settings`, `architecture`, `company-and-users`, `api-keys`, `sso-configuration`, `profile`
- **`DEFAULT_TAB`** — Fallback tab (`ai-settings`) used when no valid `?tab=` param is present
- **`handleTabChange`** — Updates both local state and the URL via `router.replace` without adding a history entry

## Usage Example

```typescript
// Renders inside a Next.js App Router page
import { SettingsView } from './settings-view';

export default function SettingsPage() {
  return <SettingsView />;
}

// Navigating to ?tab=api-keys will activate the API Keys tab
// e.g. /settings?tab=api-keys
```

## Behavior Notes

- On mount, reads `?tab=` from the URL; falls back to `ai-settings` if the value is missing or invalid
- A `useEffect` keeps `activeTab` state in sync with URL changes (e.g., browser back/forward)
- Tab changes call `router.replace` (not `push`) to avoid polluting the browser history stack
- Valid tab IDs are derived dynamically from `getSettingsTabs()` via a memoized `Set` for O(1) validation
