A confirmation modal component for regenerating API keys, wrapping the shared `ConfirmDialog` with regeneration-specific messaging and async loading state management.

## Key Components

**`RegenerateApiKeyModal`** — Named export, client-side React component

**Props (`RegenerateApiKeyModalProps`):**

| Prop | Type | Description |
|------|------|-------------|
| `isOpen` | `boolean` | Controls modal visibility |
| `onClose` | `() => void` | Callback when modal is dismissed |
| `apiKeyName` | `string?` | Display name of the key being regenerated |
| `onConfirm` | `() => Promise<void>` | Async handler executed on confirmation |

**Behavior:**
- Displays a warning-styled `ConfirmDialog` with the key name highlighted
- Manages `loading` state during the async `onConfirm` call
- Resets loading state when the modal closes (via `useEffect`)
- Falls back to `"this API Key"` if no `apiKeyName` is provided

## Usage Example

```typescript
import { RegenerateApiKeyModal } from './regenerate-api-key-modal';

function ApiKeySettings() {
  const [modalOpen, setModalOpen] = useState(false);

  const handleRegenerate = async () => {
    await regenerateKey('my-service-key');
    setModalOpen(false);
  };

  return (
    <>
      <button onClick={() => setModalOpen(true)}>Regenerate Key</button>
      <RegenerateApiKeyModal
        isOpen={modalOpen}
        onClose={() => setModalOpen(false)}
        apiKeyName="my-service-key"
        onConfirm={handleRegenerate}
      />
    </>
  );
}
```

> **Note:** The current API key becomes invalid **immediately** upon confirmation — ensure users are warned before triggering this action.
