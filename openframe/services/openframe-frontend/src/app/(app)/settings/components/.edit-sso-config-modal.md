Modal component for editing SSO (Single Sign-On) provider OAuth configuration, supporting Client ID/Secret setup, Microsoft single-tenant mode, and domain-based auto-provisioning.

## Key Components

- **`SsoConfigModal`** — Primary export. Renders a two-column modal with OAuth credentials on the left and a domain allowlist on the right.
- **`EditSsoConfigModal`** — Re-export alias for backwards compatibility.
- **`SsoConfigModalProps`** — Interface defining all configurable props including initial field values and async `onSubmit`/`onDisable` callbacks.

### Internal State

| State | Purpose |
|---|---|
| `clientId` / `clientSecret` | OAuth credentials |
| `isSingleTenant` / `msTenantId` | Microsoft-specific tenant config |
| `autoProvisionUsers` / `allowedDomains` | Domain-based account provisioning |
| `showSecret` | Toggle secret field visibility |
| `isSubmitting` | Prevents duplicate submissions |

## Usage Example

```typescript
<SsoConfigModal
  isOpen={isModalOpen}
  onClose={() => setIsModalOpen(false)}
  providerKey="microsoft"
  providerDisplayName="Microsoft"
  isEnabled={true}
  initialClientId="my-client-id"
  initialClientSecret="my-secret"
  initialAutoProvisionUsers={true}
  initialAllowedDomains={['openframe.com']}
  onSubmit={async (data) => {
    await saveSsoConfig(data);
  }}
  onDisable={async () => {
    await disableSsoProvider('microsoft');
  }}
/>
```

### Validation Rules

- `clientId` and `clientSecret` are always required.
- `msTenantId` is required when Microsoft + single-tenant mode is active.
- At least one `allowedDomain` is required when `autoProvisionUsers` is enabled.
- The OAuth redirect URL (`/sas/login/oauth2/code/{providerKey}`) is auto-generated from `runtimeEnv.sharedHostUrl()` and copyable to clipboard.
