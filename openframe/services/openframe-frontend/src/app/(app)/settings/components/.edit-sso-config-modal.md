Modal component for editing SSO (Single Sign-On) OAuth provider configurations, supporting credential management, Microsoft-specific tenant settings, and domain-based auto-provisioning.

## Key Components

- **`SsoConfigModal`** — Main modal component (also exported as `EditSsoConfigModal` for backwards compatibility)
- **`SsoConfigModalProps`** — Interface defining all configurable props including initial values and async callbacks
- **`canSubmit`** — Memoized validation logic ensuring required fields are filled; enforces domain requirement when auto-provisioning is enabled
- **`handleSubmit`** — Saves OAuth credentials, conditionally includes Microsoft tenant ID, clears allowed domains when auto-provision is disabled
- **`handleDisable`** — Invokes the `onDisable` callback and closes the modal with a success/error toast

## Usage Example

```typescript
<SsoConfigModal
  isOpen={isModalOpen}
  onClose={() => setIsModalOpen(false)}
  providerKey="microsoft"
  providerDisplayName="Microsoft"
  isEnabled={true}
  initialClientId="your-client-id"
  initialClientSecret="your-client-secret"
  initialMsTenantId="your-tenant-id"
  initialAutoProvisionUsers={true}
  initialAllowedDomains={['openframe.com']}
  onSubmit={async (data) => {
    await updateSsoConfig(data);
  }}
  onDisable={async () => {
    await disableSsoProvider('microsoft');
  }}
/>
```

## Notes

- Redirect URL is auto-generated from `runtimeEnv.sharedHostUrl()` using the pattern `/sas/login/oauth2/code/{providerKey}`
- Microsoft provider unlocks an additional **Single Tenant** toggle that conditionally requires a Tenant ID
- Client secret visibility is toggled with a show/hide button
- Auto-provisioning requires at least one allowed domain before the form can be submitted
