Renders the subscription settings page, allowing users to configure managed device plans and AI assistant add-ons, then submit package updates or initiate a Stripe Checkout flow.

## Key Components

- **`SubscriptionSettingsView`** — Public entry point; wraps content in `Suspense` with a skeleton fallback
- **`SubscriptionSettingsContent`** — Core component that fetches billing plan and subscription data via Relay (`subscriptionSettingsViewQuery`), manages local state, and renders the full settings UI
- **`PRODUCT_DISPLAY`** — Static display config mapping `OpenframeProduct` keys (`MANAGED_DEVICES`, `AI_ASSISTANCE`) to titles, descriptions, labels, and optional help text
- **`subscriptionSettingsViewQuery`** — Relay GraphQL query fetching `billingPlan.products` and `subscription.products` with their associated fragments
- **AI toggle logic** — `aiEnabled` state gates whether `AI_ASSISTANCE` is included in updates; when disabled, `buildProductCancelUpdates` generates cancellation diffs automatically
- **`SubscriptionSubmitButton`** — Receives computed `packageUpdates`, `checkoutProducts`, `hasInvalidCustom`, and `needsCheckout` (true when subscription status is `TRIAL`, `TRIAL_EXPIRED`, or `CANCELED`)

## Usage Example

```typescript
// Rendered within a billing settings route
import { SubscriptionSettingsView } from './subscription-settings-view';

export default function BillingSettingsPage() {
  return <SubscriptionSettingsView />;
}
```

## Behavior Notes

- **Checkout vs. update** — `needsCheckout` redirects to Stripe Checkout when no active paid subscription exists (trial, expired, or canceled states)
- **Responsive layout** — Submit button is sticky on mobile (`md:hidden`) and inline on desktop (`hidden md:flex`)
- **Locked state** — When `isLocked` is true, hides the page header/back button and renders `TrialEndedBanner` instead
