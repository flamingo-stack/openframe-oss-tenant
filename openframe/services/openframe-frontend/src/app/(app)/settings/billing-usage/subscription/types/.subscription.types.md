Defines shared TypeScript types and re-exports for the subscription management feature, centralizing billing-related type definitions used across checkout and subscription update flows.

## Key Components

| Export | Kind | Description |
|--------|------|-------------|
| `BillingPeriod` | Re-export | Billing cycle enum (`MONTHLY` / `ANNUAL`) from generated GraphQL fragment |
| `SubscriptionProductStatus` | Re-export | Product status enum from generated subscription GraphQL fragment |
| `OpenframeProduct` | Re-export | Product identifier enum from generated settings query |
| `UpdateAction` | Type | Union literal — `'ADD'` or `'CANCEL'` |
| `ProductSelectionState` | Interface | UI state snapshot for a product selection (billing period, package, quantity) |
| `ProductUpdates` | Interface | Computed diff payload ready to hand off to `updateSubscription` or `createCheckoutSession` |

## Usage Example

```typescript
import type {
  BillingPeriod,
  ProductSelectionState,
  ProductUpdates,
} from './subscription.types';

const selectionState: ProductSelectionState = {
  payAsYouGoEnabled: false,
  billingPeriod: 'MONTHLY',
  selectedPackageId: 'pkg_basic',
  customQuantity: null,
};

const updates: ProductUpdates = {
  packageUpdates: [{ packageId: 'pkg_basic', action: 'ADD' }],
  checkout: { productId: 'prod_123', billingPeriod: 'MONTHLY' },
  valid: true,
};
```

## Notes

- `ProductUpdates.packageUpdates` targets the `updateSubscription` mutation — used only for **active paid** subscriptions.
- `ProductUpdates.checkout` targets `createCheckoutSession` — used for `TRIAL`, `TRIAL_EXPIRED`, and `CANCELED` states.
- `ProductUpdates.valid` gates form submission; it is `false` when **Custom Amount** is selected but the quantity field is empty or invalid.
