A modal dialog component for collecting cancellation reason and displaying data-loss warnings before confirming a subscription cancellation.

## Key Components

- **`CancelSubscriptionModal`** — Main exported component; manages reason/comment state, resets on close, and gates confirmation behind a selected reason
- **`CancelReason`** — Union type of valid cancellation reason codes (`TOO_EXPENSIVE` | `NOT_USING_ENOUGH` | `MISSING_FEATURE` | `TECHNICAL_ISSUES` | `OTHER`)
- **`DataLossStats`** — Interface describing counts of resources (devices, tickets, KB articles, monitoring policies, saved queries) that will become inaccessible
- **`DataLossBox`** — Renders a warning card listing only non-zero resource counts; returns `null` when all counts are zero
- **`DataLossSkeleton`** — Mirrors `DataLossBox` layout with skeleton placeholders during stats loading
- **`formatCount`** — Formats large numbers with a `+` suffix rounded to the nearest hundred (e.g. `1,200+`)

## Usage Example

```typescript
import {
  CancelSubscriptionModal,
  type CancelReason,
  type DataLossStats,
} from './cancel-subscription-modal';

const stats: DataLossStats = {
  activeDevices: 42,
  tickets: 1500,
  kbArticles: 87,
  monitoringPolicies: 12,
  savedQueries: 5,
};

<CancelSubscriptionModal
  isOpen={isOpen}
  endDate="2025-12-31T23:59:59Z"
  stats={stats}
  isStatsLoading={false}
  isPending={isCancelling}
  onClose={() => setIsOpen(false)}
  onConfirm={(reason: CancelReason, comment: string) => {
    cancelSubscription({ reason, comment });
  }}
/>
```

> When `reason` is `OTHER`, a free-text `Textarea` is revealed for additional feedback. The **Continue** button remains disabled until a reason is selected.
