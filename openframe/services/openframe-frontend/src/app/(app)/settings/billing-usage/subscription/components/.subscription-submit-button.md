A client-side React component that renders the appropriate subscription action button based on the current subscription state — either initiating a Stripe Checkout session or updating an existing active subscription.

## Key Components

**`SubscriptionSubmitButton`** — Primary export. Conditionally renders one of two action buttons:
- **"Proceed to Payment"** — shown when `needsCheckout` is `true` (e.g., TRIAL, TRIAL_EXPIRED, or CANCELED states); triggers `useCreateCheckoutSession`
- **"Update Subscription"** — shown for active paid subscriptions; triggers `useUpdateSubscription`, disabled when no diff exists or a custom amount is invalid

**Props (`SubscriptionSubmitButtonProps`):**

| Prop | Type | Description |
|---|---|---|
| `needsCheckout` | `boolean` | Switches between checkout vs. update flow |
| `packageUpdates` | `PackageUpdateInput[]` | ADD/CANCEL diff for update flow |
| `checkoutProducts` | `ProductCheckoutInput[]` | Desired end-state for checkout flow |
| `hasInvalidCustom` | `boolean` | Blocks update if a custom amount is invalid |

## Usage Example

```typescript
<SubscriptionSubmitButton
  needsCheckout={subscriptionStatus === 'TRIAL_EXPIRED'}
  checkoutProducts={[{ productId: 'prod_abc', quantity: 1 }]}
  packageUpdates={[{ packageId: 'pkg_xyz', action: 'ADD' }]}
  hasInvalidCustom={false}
/>
```

## Notes

- Both mutation hooks share a unified `isPending` state — the button shows a loading spinner and is disabled during any in-flight request
- The update flow validates custom package quantities before mutating; an invalid amount surfaces a destructive toast instead of submitting
- Empty `checkoutProducts` or `packageUpdates` arrays are early-exited silently without triggering mutations
