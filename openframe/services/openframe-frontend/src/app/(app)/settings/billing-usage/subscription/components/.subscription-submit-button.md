Renders the correct subscription submit button based on the current subscription state — either initiating a new Stripe Checkout session or updating an existing active subscription.

## Key Components

### `SubscriptionSubmitButton`
A client-side React component that conditionally renders one of two action buttons:

| Mode | Condition | Button Label | Behavior |
|------|-----------|--------------|----------|
| Checkout | `needsCheckout: true` | **Proceed to Payment** | Calls `createCheckout.mutate` with `checkoutProducts` |
| Update | `needsCheckout: false` | **Update Subscription** | Calls `updateSubscription.mutate` with `packageUpdates` |

### Props (`SubscriptionSubmitButtonProps`)

| Prop | Type | Description |
|------|------|-------------|
| `needsCheckout` | `boolean` | When `true`, routes to Stripe Checkout (TRIAL / TRIAL_EXPIRED / CANCELED states) |
| `packageUpdates` | `PackageUpdateInput[]` | ADD/CANCEL diff payload for the update flow |
| `checkoutProducts` | `ProductCheckoutInput[]` | Desired end-state for new checkout flow |
| `hasInvalidCustom` | `boolean` | Blocks update submission when a Custom Amount quantity is empty/invalid |

## Usage Example

```typescript
<SubscriptionSubmitButton
  needsCheckout={subscriptionStatus === 'TRIAL_EXPIRED'}
  checkoutProducts={[{ productId: 'prod_abc', quantity: 1 }]}
  packageUpdates={[{ packageId: 'pkg_xyz', action: 'ADD' }]}
  hasInvalidCustom={false}
/>
```

> The update button is automatically disabled when `packageUpdates` is empty (no diff from the current plan) or while either mutation is pending. Invalid custom amounts surface a destructive toast instead of submitting.
