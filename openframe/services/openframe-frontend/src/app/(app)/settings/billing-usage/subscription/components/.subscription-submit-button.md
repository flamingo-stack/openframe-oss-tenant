A smart submit button component that conditionally renders either a "Proceed to Payment" (Stripe Checkout) or "Update Subscription" action based on the current subscription state.

## Key Components

- **`SubscriptionSubmitButton`** — Main exported component that switches between two submission flows:
  - **Checkout flow** (`needsCheckout: true`) — Triggers `useCreateCheckoutSession` for new/expired/canceled subscriptions
  - **Update flow** (`needsCheckout: false`) — Triggers `useUpdateSubscription` for active paid subscriptions
- **`SubscriptionSubmitButtonProps`** — Interface defining the four required props
- **Validation** — Blocks submission when `hasInvalidCustom` is `true` (update flow) or when no products/updates are queued

## Usage Example

```typescript
import { SubscriptionSubmitButton } from './subscription-submit-button';

// New / trial / expired subscription → Stripe Checkout
<SubscriptionSubmitButton
  needsCheckout={true}
  checkoutProducts={[{ productId: 'prod_abc', quantity: 1 }]}
  packageUpdates={[]}
  hasInvalidCustom={false}
/>

// Active subscription → update diff
<SubscriptionSubmitButton
  needsCheckout={false}
  checkoutProducts={[]}
  packageUpdates={[
    { packageId: 'pkg_123', action: 'ADD' },
    { packageId: 'pkg_456', action: 'CANCEL' },
  ]}
  hasInvalidCustom={false}
/>
```

## Notes

- Both actions share a unified `isPending` state derived from either mutation, preventing double-submits
- The update button is automatically `disabled` when `packageUpdates` is empty (no diff from current plan)
- Invalid custom quantities show a destructive toast before blocking the mutation call
- Two `console.log` statements are present for debugging and should be removed before production
