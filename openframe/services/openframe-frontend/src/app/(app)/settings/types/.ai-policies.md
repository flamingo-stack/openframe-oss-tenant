Defines shared TypeScript types and constants for AI policy management within the Flamingo/OpenFrame platform, covering policy templates, rules, and customization requests.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `CUSTOM_CREATION_TEMPLATE_ID` | `const` | Sentinel ID (`'CUSTOM_CREATION'`) used to identify custom policy creation workflows |
| `PolicyTemplateSummary` | `interface` | Lightweight summary of a policy template for list/overview views |
| `PolicyRule` | `interface` | Represents a single AI approval rule, mapping a tool/function to an `ApprovalLevel` |
| `PolicyTemplateDetail` | `interface` | Full policy template detail including all rules and custom overrides |
| `CustomPolicyRequest` | `interface` | Payload for applying custom approval-level overrides to an existing template |

## Usage Example

```typescript
import {
  CUSTOM_CREATION_TEMPLATE_ID,
  type PolicyRule,
  type PolicyTemplateDetail,
  type CustomPolicyRequest,
} from './ai-policies';

// Check if a template is a custom creation
const isCustom = (templateId: string) =>
  templateId === CUSTOM_CREATION_TEMPLATE_ID;

// Build a custom policy override request
const request: CustomPolicyRequest = {
  templateId: 'template-abc123',
  overrides: {
    'reboot-server': 'REQUIRE_APPROVAL',
    'read-logs':     'AUTO_APPROVE',
  },
};

// Inspect a rule from a loaded template detail
const template: PolicyTemplateDetail = await fetchPolicyTemplate('template-abc123');
template.rules.forEach((rule: PolicyRule) => {
  console.log(`${rule.tool}::${rule.function} → ${rule.approvalLevel}`);
});
```

## Notes

- `ApprovalLevel` is imported from `@flamingo-stack/openframe-frontend-core` and drives Mingo AI's autonomy boundaries per operation.
- `PolicyTemplateDetail.customOverrides` is typed as `Record<string, unknown>` for forward-compatibility as the override schema evolves.
