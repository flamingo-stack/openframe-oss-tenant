React hook for fetching integrated tools via GraphQL, exposing loading state, error handling, and toast notifications on failure.

## Key Components

**`useIntegratedTools()`** — Primary hook returning:
- `tools` — `IntegratedTool[]` state array populated after a successful fetch
- `isLoading` — `boolean` fetch-in-progress flag
- `error` — `string | null` last error message
- `fetchIntegratedTools(filter?, search?)` — `async` function that POSTs the `GetIntegratedTools` GraphQL query to `/api/graphql`

**Exported Types**
| Type | Description |
|------|-------------|
| `IntegratedTool` | Full tool entity including URLs, credentials, layer config, and health check settings |
| `Credentials` | Username/password + optional `ApiKey` shape |
| `ToolUrl` | URL entry with optional `port` and `type` |
| `ApiKey` | API key with optional `type` and `keyName` |

## Usage Example

```typescript
import { useIntegratedTools } from '@/hooks/use-integrated-tools';

export function ToolList() {
  const { tools, isLoading, error, fetchIntegratedTools } = useIntegratedTools();

  useEffect(() => {
    // Fetch only enabled monitoring tools
    fetchIntegratedTools({ enabled: true, category: 'monitoring' }, 'zabbix');
  }, [fetchIntegratedTools]);

  if (isLoading) return <Spinner />;
  if (error) return <p>Error: {error}</p>;

  return (
    <ul>
      {tools.map(tool => (
        <li key={tool.id}>{tool.name}</li>
      ))}
    </ul>
  );
}
```

> `fetchIntegratedTools` defaults to `{ enabled: true, category: null }` with an empty search string when called with no arguments. Errors are surfaced both via the returned `error` string and a destructive toast notification.
