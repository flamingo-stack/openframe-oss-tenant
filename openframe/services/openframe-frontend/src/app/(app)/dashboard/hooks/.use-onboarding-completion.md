Provides onboarding completion status by aggregating data from multiple sources to determine which setup steps have been completed.

## Key Components

### Internal Hooks

| Hook | Purpose |
|------|---------|
| `useActiveSsoProviderCount` | Fetches and counts enabled SSO providers via `api/sso/providers/available` |
| `useUsersCount` | Retrieves total user count via GraphQL query |

### Exported Hook

**`useOnboardingCompletion()`** — Combines device, organization, SSO, and user data to compute a completion status map for each onboarding step.

#### Returns

| Field | Type | Description |
|-------|------|-------------|
| `completionStatus` | `Record<string, boolean>` | Keyed completion flags per step |
| `isLoading` | `boolean` | `true` while any data source is loading |

#### Completion Steps

| Key | Condition |
|-----|-----------|
| `sso-configuration` | At least 1 enabled SSO provider |
| `organizations-setup` | More than 1 organization |
| `device-management` | At least 1 device registered |
| `company-and-team` | More than 1 user account |

## Usage Example

```typescript
import { useOnboardingCompletion } from './use-onboarding-completion';

function OnboardingChecklist() {
  const { completionStatus, isLoading } = useOnboardingCompletion();

  if (isLoading) return <Spinner />;

  return (
    <ul>
      {Object.entries(completionStatus).map(([step, done]) => (
        <li key={step}>
          {step}: {done ? '✅' : '⬜'}
        </li>
      ))}
    </ul>
  );
}
```

> **Note:** All sub-queries are gated on `isAuthenticated` from `useAuthStore` and use staggered `staleTime`/`gcTime` values to reduce redundant API calls.
