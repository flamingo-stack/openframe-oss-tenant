Next.js route-level loading skeleton for the `/dashboard` route, rendering placeholder UI that mirrors the exact layout and structure of the actual dashboard components during data fetch.

## Key Components

| Component | Description |
|-----------|-------------|
| `DashboardLoading` | Default export; root skeleton container with `role="status"` accessibility attribute |
| `OnboardingSkeleton` | Matches `OnboardingWalkthrough` — header row + 5 vertical `OnboardingStepCardSkeleton` items |
| `DevicesSkeleton` | Matches `DevicesOverviewSection` — title, subtitle, and 2-card grid |
| `TicketsSkeleton` | Matches `TicketsOverviewSection` — title, subtitle, and 4-card grid; conditionally rendered in SaaS tenant mode only |
| `CustomersSkeleton` | Matches `CustomersOverviewSection` — title, subtitle, and 3 rows of `[CustomerCardSkeleton, InfoCardSkeleton, InfoCardSkeleton]` |
| `InfoCardSkeleton` | Reusable card with content column (title + value/percentage) and circular progress placeholder |
| `OnboardingStepCardSkeleton` | Step row with title, description, and two action button placeholders |
| `CustomerCardSkeleton` | Org card with name, detail, and device count badge placeholders |

## Usage Example

This file is automatically consumed by Next.js as a route segment loading UI — no manual import needed:

```text
app/
└── dashboard/
    ├── page.tsx        ← actual dashboard
    └── loading.tsx     ← this file (auto-used by Next.js)
```

The `TicketsSkeleton` section renders conditionally based on deployment mode:

```typescript
// Tickets section only appears for SaaS tenant deployments
const showTickets = isSaasTenantMode();

return (
  <div className="space-y-10 pt-6" role="status" aria-label="Loading dashboard">
    <OnboardingSkeleton />
    <DevicesSkeleton />
    {showTickets && <TicketsSkeleton />}
    <CustomersSkeleton />
  </div>
);
```
