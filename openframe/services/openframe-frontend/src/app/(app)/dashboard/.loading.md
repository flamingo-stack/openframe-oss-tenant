Next.js route-level loading skeleton for the `/dashboard` route, rendering placeholder UI that mirrors the exact layout and structure of the live dashboard to prevent layout shift during data fetching.

## Key Components

| Component | Description |
|---|---|
| `DashboardLoading` | Default export; root skeleton shell, conditionally renders `TicketsSkeleton` based on SaaS tenant mode |
| `InfoCardSkeleton` | Matches `DashboardInfoCard` — icon area, title, value/percentage row, circular progress |
| `OnboardingStepCardSkeleton` | Matches `OnboardingStepCard` — title, description, and two action button placeholders |
| `OnboardingSkeleton` | Matches `OnboardingWalkthrough` — header row + 5 vertical step card skeletons |
| `DevicesSkeleton` | Matches `DevicesOverviewSection` — title, subtitle, 2-column `InfoCardSkeleton` grid |
| `TicketsSkeleton` | Matches `TicketsOverviewSection` — title, subtitle, 4-column `InfoCardSkeleton` grid (SaaS tenant only) |
| `CustomerCardSkeleton` | Matches `OrganizationCard` — org name, details, device count badge |
| `CustomersSkeleton` | Matches `CustomersOverviewSection` — title, subtitle, rows of `[CustomerCardSkeleton, InfoCardSkeleton, InfoCardSkeleton]` |

## Usage Example

This file is automatically consumed by Next.js as a route segment loading state. No manual imports are needed:

```text
app/
└── dashboard/
    ├── page.tsx          ← actual dashboard
    └── loading.tsx       ← this file (auto-used by Next.js)
```

The `isSaasTenantMode()` check gates the tickets section at skeleton render time, keeping it consistent with the real page:

```typescript
export default function DashboardLoading() {
  const showTickets = isSaasTenantMode();

  return (
    <div className="space-y-10 pt-6" role="status" aria-label="Loading dashboard">
      <OnboardingSkeleton />
      <DevicesSkeleton />
      {showTickets && <TicketsSkeleton />}
      <CustomersSkeleton />
    </div>
  );
}
```

> Each skeleton sub-component is intentionally scoped to its matching real component — dimension classes (`h-`, `w-`, grid columns) are kept in sync with the live layout to eliminate cumulative layout shift (CLS) on hydration.
