Singleton service that fetches and normalizes device and ticket statistics for the dashboard, using GraphQL queries via the shared API client.

## Key Components

### Exported Types

| Type | Description |
|------|-------------|
| `DashboardDeviceStats` | Device counts with active/inactive totals and percentages |
| `DashboardTicketStats` | Ticket counts, resolution time, Fae rating, and status percentages |

### `DashboardApiService` (Singleton)

| Method | Returns | Description |
|--------|---------|-------------|
| `fetchDeviceStats()` | `Promise<DashboardDeviceStats>` | Queries `GET_DEVICE_FILTERS_QUERY` for online/offline device counts and computes percentages |
| `fetchTicketStats()` | `Promise<DashboardTicketStats>` | Queries `GET_TICKET_STATISTICS_QUERY` for active/resolved counts, avg resolution time, and avg Fae rating |

### `dashboardApiService`

Pre-instantiated singleton exported for direct import across the dashboard.

## Usage Example

```typescript
import { dashboardApiService } from './dashboard-api-service';

// Fetch device statistics
const deviceStats = await dashboardApiService.fetchDeviceStats();
console.log(deviceStats.total);           // e.g. 120
console.log(deviceStats.activePercentage); // e.g. 85

// Fetch ticket statistics
const ticketStats = await dashboardApiService.fetchTicketStats();
console.log(ticketStats.avgResolveTime); // e.g. "2h 15m"
console.log(ticketStats.avgFaeRate);     // e.g. 4.7
```

> **Note:** `fetchTicketStats` targets the `ticketStatistics` GraphQL query. The legacy `dialogStatistics` query was replaced after the backend separated tickets from dialogs.
