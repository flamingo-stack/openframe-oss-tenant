Singleton service that fetches and transforms device and ticket statistics for the dashboard, exposing two GraphQL-backed methods that return normalized stat objects with counts and percentages.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `DashboardDeviceStats` | Interface | Device counts with `total`, `active`, `inactive`, and derived percentages |
| `DashboardTicketStats` | Interface | Ticket counts with `total`, `active`, `resolved`, `avgResolveTime`, and `avgFaeRate` |
| `dashboardApiService` | Singleton | Pre-instantiated `DashboardApiService` instance for app-wide use |
| `fetchDeviceStats()` | Method | Queries `GET_DEVICE_FILTERS_QUERY` and returns `DashboardDeviceStats` |
| `fetchTicketStats()` | Method | Queries `GET_TICKET_STATISTICS_QUERY` and returns `DashboardTicketStats` |

## Usage Example

```typescript
import { dashboardApiService } from './dashboard-api-service';

// Fetch device statistics
const deviceStats = await dashboardApiService.fetchDeviceStats();
console.log(deviceStats.total);           // e.g. 120
console.log(deviceStats.activePercentage); // e.g. 85

// Fetch ticket statistics
const ticketStats = await dashboardApiService.fetchTicketStats();
console.log(ticketStats.avgResolveTime); // e.g. "2h 15m"
console.log(ticketStats.avgFaeRate);     // e.g. 4.7
```

## Notes

- Both methods normalize missing or malformed API responses to safe defaults (`0`, `'—'`).
- `fetchTicketStats()` uses `resolvedCountFromStatistics` to aggregate resolved counts across multiple terminal statuses.
- All errors are re-thrown as typed `Error` instances with descriptive operation context via `handleApiError`.
