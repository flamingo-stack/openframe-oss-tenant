Root application group layout component that wraps authenticated routes with the OpenFrame chat runtime context and app shell, while applying route-specific padding overrides for specialized views.

## Key Components

- **`getMainClassNameOverride(pathname)`** — Pure function that returns Tailwind class overrides based on the current route: removes padding for `/mingo`, `/tickets`, and device file-manager routes to allow full-bleed layouts
- **`AppGroupLayout`** — Default export; composes `OpenframeChatRuntimeProvider` + `AppLayout` as the shell for all child routes
- **`OpenframeChatRuntimeProvider`** — Supplies `ChatRuntime` context supporting both Guide (SSE → MPH via `/guide` proxy) and Mingo (NATS → OpenFrame backend) chat modes simultaneously
- **`AppLayout`** — Renders the full app shell (header, sidebar, main content area) with an embedded `AppLayoutDrawer` for the AI chat panel

## Usage Example

```typescript
// This layout is automatically applied to all routes in the (app) route group.
// Next.js picks it up via the file-system layout convention.

// Route-specific padding behavior:
// /mingo            → 'p-0 md:p-0'       (full-bleed AI surface)
// /tickets          → 'pb-0 md:pb-0'     (full-height ticket list)
// /devices/.../file-manager → 'pb-0 md:pb-0'  (full-height file browser)
// all other routes  → 'pb-14'            (default bottom padding)

// Children are rendered inside AppLayout's main content slot:
<AppGroupLayout>
  <TicketsPage /> {/* receives correct padding via mainClassName */}
</AppGroupLayout>
```

## Notes

- The `/mingo` standalone route coexists with the in-layout drawer chat during migration; both are active until validation is complete
- Chat drawer occupies only the main content area — header and sidebar remain visible and interactive when the AI panel is open
