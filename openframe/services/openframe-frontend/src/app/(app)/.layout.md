Client-side layout wrapper that applies route-aware padding overrides to the `AppLayout` component.

## Key Components

- **`getMainClassNameOverride(pathname)`** — Pure function that returns a CSS class override string based on the current route:
  - `/mingo/*` → removes all padding (`p-0 md:p-0`)
  - `/devices/details/[id]/file-manager` → removes bottom padding (`pb-0 md:pb-0`)
  - `/tickets/*` → removes bottom padding (`pb-0 md:pb-0`)
  - All other routes → `undefined` (falls back to default)

- **`AppGroupLayout`** — Default export. Reads the current pathname via `usePathname()` and passes the resolved `mainClassName` to `AppLayout`. Defaults to `pb-14` to prevent content overlap with the app's fixed bottom navigation bar.

## Usage Example

```typescript
// Automatically applied as a Next.js route group layout.
// No direct usage required — Next.js picks this up via the filesystem.

// Effective rendering for /tickets/123:
<AppLayout mainClassName="pb-0 md:pb-0">
  {children}
</AppLayout>

// Effective rendering for /dashboard:
<AppLayout mainClassName="pb-14">
  {children}
</AppLayout>
```

> The `pb-14` default accounts for the fixed bottom bar in `AppLayout`, preventing page content from being obscured by it on routes that don't require custom spacing.
