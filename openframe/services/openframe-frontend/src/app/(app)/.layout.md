Root application group layout component that wraps all child routes with the shared app shell and AI chat runtime context, applying route-specific CSS overrides for padding/spacing.

## Key Components

- **`getMainClassNameOverride(pathname)`** — Pure helper that maps specific route patterns to Tailwind class overrides:
  - `/mingo` → removes all padding (`p-0 md:p-0`)
  - `/devices/details/[id]/file-manager` → removes bottom padding (`pb-0 md:pb-0`)
  - `/tickets` → removes bottom padding (`pb-0 md:pb-0`)
  - All other routes → falls back to `pb-14`

- **`AppGroupLayout`** — Default export; Next.js layout component that composes:
  - [`OpenframeChatRuntimeProvider`](../components/openframe-chat-runtime-provider) — Supplies `ChatRuntime` context for both **Guide** (SSE → MPH via `/guide` proxy) and **Mingo** (NATS → OpenFrame backend) AI modes simultaneously, with an in-panel toggle
  - [`AppLayout`](../components/app-layout) — App shell rendering the header, sidebar, and main content area; hosts `AppLayoutDrawer` for the embedded chat panel

## Usage Example

```typescript
// Next.js automatically applies this as the group layout.
// No manual usage required — place page components as children:

// app/(group)/tickets/page.tsx
export default function TicketsPage() {
  return <div>Tickets content</div>;
  // Rendered inside AppGroupLayout → AppLayout with pb-0 md:pb-0
}
```

## Notes

- The embedded chat (`EmbeddableChat`) lives inside `AppLayout` as a drawer — leaving the header and sidebar interactive — rather than as a floating body-level button
- The `/mingo` route coexists with the in-layout chat during migration; both surfaces remain active until validation is complete
- Uses `'use client'` directive since `usePathname` requires a client component context
