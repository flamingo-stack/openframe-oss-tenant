Entry point for the Knowledge Base page route, guarding access behind a feature flag and rendering the root-level knowledge base view.

## Key Components

- **`KnowledgeBasePage`** — Default page component that checks the `knowledgeBase` feature flag; redirects to a 404 if disabled, otherwise renders `KnowledgeBaseView` with no folder context (`folderId={null}`)
- **`featureFlags.knowledgeBase.enabled()`** — Runtime feature flag check controlling page availability
- **`KnowledgeBaseView`** — Child component responsible for rendering the knowledge base UI
- **`dynamic = 'force-dynamic'`** — Disables static generation, ensuring the page is always server-rendered at request time

## Usage Example

```typescript
// Automatically rendered by Next.js App Router at /knowledge-base
// No manual invocation needed

// To enable/disable the page, toggle the feature flag:
// lib/feature-flags.ts
export const featureFlags = {
  knowledgeBase: {
    enabled: () => process.env.NEXT_PUBLIC_FEATURE_KNOWLEDGE_BASE === 'true',
  },
};
```

> **Note:** When the feature flag is disabled, Next.js will serve a 404 for this route. The `folderId={null}` prop signals `KnowledgeBaseView` to render the root folder context rather than a specific subfolder.
