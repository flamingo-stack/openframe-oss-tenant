Unified form hook for creating and editing Knowledge Base articles, handling validation, tag management, attachment linking, assignment diffing, and publish/unpublish lifecycle transitions.

## Key Components

- **`useEditArticleForm(options)`** — Main exported hook accepting `articleId`, `initialFolderId`, and `initialArticle`
- **`handleSave(targetStatus, options)`** — Submits the form, branching between create and update flows; manages tag diffs, attachment linking, assignment changes, and status transitions (`DRAFT` → `PUBLISHED` / `ARCHIVED`)
- **`resolveTagIds(keys, availableTags)`** — Resolves tag keys to IDs, creating new tags via `createTag` when no match exists
- **`SaveStatus`** — Exported union type `'DRAFT' | 'PUBLISHED'` representing the intended article state after save
- **Form initialization** — Resets `react-hook-form` state when `initialArticle` or `assignedItems` become ready; pre-populates existing attachments via `tempAttachments.initializeExisting`

## Usage Example

```typescript
const { form, isEditMode, isSubmitting, handleSave, tempAttachments } =
  useEditArticleForm({
    articleId: 'article-123',          // null for create mode
    initialFolderId: 'folder-456',
    initialArticle: fetchedArticle,
  });

// Save as published
handleSave('PUBLISHED', { availableTags: tagList });

// Save as draft
handleSave('DRAFT', { availableTags: tagList });

// Check pending attachment state
if (tempAttachments.hasPendingDeletes) { /* ... */ }
```

## Notes

- In **edit mode**, tag changes are computed as a diff (`toAdd` / `toRemove`) and applied in parallel alongside article update, assignment diff, and attachment mutations.
- In **create mode**, tags and assignments are passed directly on article creation, with attachments linked post-creation.
- Status transitions handle the `ARCHIVED` → `PUBLISHED`/`DRAFT` path by calling `unarchiveArticle` first.
- After attachment mutations, a `network-only` Relay `fetchQuery` is triggered to keep the cache consistent.
