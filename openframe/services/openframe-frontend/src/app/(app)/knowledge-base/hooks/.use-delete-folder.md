React hook that executes a GraphQL mutation to delete a knowledge base folder, handling optimistic Relay store updates and error notifications.

## Key Components

- **`deleteFolderMutation`** — GraphQL mutation (`useDeleteFolderMutation`) accepting a `DeleteFolderInput` with folder ID and children disposition strategy
- **`FolderChildrenAction`** — Union type `'MOVE' | 'ARCHIVE'` defining what happens to child items when the folder is deleted
- **`DeleteFolderArgs`** — Interface describing required parameters: `id`, `childrenAction`, optional `moveTargetFolderId`, Relay `connections`, and an optional `onCompleted` callback
- **`useDeleteFolder()`** — Primary exported hook returning `deleteFolder` and `isPending`

### Relay Store Updater

After mutation, the updater performs two cleanup steps:
1. Removes the deleted node from all provided Relay connection IDs via `ConnectionHandler.deleteNode`
2. Filters the deleted folder out of the root-level `KNOWLEDGE_BASE_FOLDER_TREE_FIELD` linked records

## Usage Example

```typescript
import { useDeleteFolder } from './use-delete-folder';

function FolderActions({ folderId, connectionId }) {
  const { deleteFolder, isPending } = useDeleteFolder();

  const handleDelete = () => {
    deleteFolder({
      id: folderId,
      childrenAction: 'MOVE',
      moveTargetFolderId: 'target-folder-id',
      connections: [connectionId],
      onCompleted: () => console.log('Folder deleted'),
    });
  };

  return (
    <button onClick={handleDelete} disabled={isPending}>
      {isPending ? 'Deleting...' : 'Delete Folder'}
    </button>
  );
}
```

> **Note:** When `childrenAction` is `'ARCHIVE'`, `moveTargetFolderId` is automatically set to `null` regardless of what is passed in.
