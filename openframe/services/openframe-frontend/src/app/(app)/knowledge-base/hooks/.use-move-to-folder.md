Encapsulates the GraphQL mutation logic for moving a knowledge base item into a different folder, with optimistic Relay store updates and error toast notifications.

## Key Components

- **`moveToFolderMutation`** — GraphQL mutation that accepts an item `id` and optional `parentId`, returning the updated item's `id`, `parentId`, and `updatedAt`
- **`MoveToFolderArgs`** — Interface defining mutation inputs:
  - `id` / `parentId` — target item and destination folder
  - `removeFromConnections` — Relay connection IDs to remove the item from
  - `appendToConnections` — optional Relay connection IDs to insert the item into
  - `onCompleted` — optional success callback
- **`useMoveToFolder`** — Hook exposing `moveToFolder` (returns a `Promise<void>`) and `isPending` (in-flight state)

## Usage Example

```typescript
const { moveToFolder, isPending } = useMoveToFolder();

await moveToFolder({
  id: 'item-123',
  parentId: 'folder-456',         // null to move to root
  removeFromConnections: [sourceConnectionId],
  appendToConnections: [targetConnectionId],
  onCompleted: () => console.log('Moved successfully'),
});
```

## Notes

- Uses `ConnectionHandler.deleteNode` and `ConnectionHandler.insertEdgeAfter` to keep the Relay store consistent without a refetch
- On error, a destructive toast is shown via `useToast` and the promise is rejected with the original error
- `isPending` mirrors Relay's `isInFlight`, useful for disabling UI during the mutation
