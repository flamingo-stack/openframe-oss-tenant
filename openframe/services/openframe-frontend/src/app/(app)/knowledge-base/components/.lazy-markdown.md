Lazy-loads `SimpleMarkdownRenderer` and `MarkdownEditor` from `@flamingo-stack/openframe-frontend-core` using Next.js dynamic imports, disabling SSR to prevent hydration issues with client-side-only markdown components.

## Key Components

- **`SimpleMarkdownRenderer`** — Dynamically imported markdown renderer, client-side only, renders `null` during loading
- **`MarkdownEditor`** — Dynamically imported markdown editor sourced from the `/components/ui` subpath, client-side only, renders `null` during loading

## Usage Example

```typescript
import { SimpleMarkdownRenderer, MarkdownEditor } from '@/components/lazy-markdown';

// Render markdown content
<SimpleMarkdownRenderer content="## Hello World" />

// Render a markdown editor
<MarkdownEditor
  value={markdownContent}
  onChange={(val) => setMarkdownContent(val)}
/>
```

> Both exports are drop-in replacements for their core counterparts — prop types are preserved via `ComponentProps`, so no type changes are required at the call site.
