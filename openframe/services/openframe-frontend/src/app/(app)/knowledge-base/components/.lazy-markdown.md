Lazy-loads `SimpleMarkdownRenderer` and `MarkdownEditor` from `@flamingo-stack/openframe-frontend-core` using Next.js dynamic imports with SSR disabled, preventing hydration issues for client-only markdown components.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `SimpleMarkdownRenderer` | Dynamic Component | Client-only markdown renderer, SSR disabled |
| `MarkdownEditor` | Dynamic Component | Client-only markdown editor, SSR disabled |

## Usage Example

```typescript
import { SimpleMarkdownRenderer, MarkdownEditor } from '@/components/lazy-markdown';

// Render markdown content
<SimpleMarkdownRenderer content="# Hello World" />

// Render an editor
<MarkdownEditor value={markdown} onChange={setMarkdown} />
```

> Both components render `null` during their loading state and will never be server-side rendered, making them safe to use in layouts that require browser-only APIs (e.g., CodeMirror, highlight.js).
