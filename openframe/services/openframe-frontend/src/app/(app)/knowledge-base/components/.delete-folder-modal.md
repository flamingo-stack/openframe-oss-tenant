A confirmation modal for deleting a knowledge base folder, with an inline folder picker that lets users choose whether to archive or move the folder's child articles before deletion.

## Key Components

- **`DeleteFolderModal`** — Primary export. Renders a `ConfirmDialog` that handles the full delete flow, including pending state, toast feedback, and post-deletion callbacks.
- **`FolderPicker`** — Internal dropdown built on `ActionsMenuDropdown` that presents a list of destination folders plus an "archive" option. Excludes the folder being deleted from valid move targets.
- **`FolderPickerSkeleton`** — Pulse placeholder rendered via `Suspense` while folder data loads.
- **`DeleteSelection`** — Discriminated union (`{ kind: 'archive' } | { kind: 'move'; target: FolderMenuTarget }`) tracking the user's child-article disposition choice.
- **`DeleteFolderTarget`** — Exported interface describing the minimal folder shape (`id`, `name`) required by the modal.

## Usage Example

```typescript
import { DeleteFolderModal, type DeleteFolderTarget } from './delete-folder-modal';

const folder: DeleteFolderTarget = { id: 'folder-123', name: 'Support Articles' };

<DeleteFolderModal
  isOpen={isModalOpen}
  onClose={() => setIsModalOpen(false)}
  folder={folder}
  sourceConnectionId="conn-abc"
  onDeleted={() => refetchFolders()}
/>
```

## Behavior Notes

- Selection resets to `archive` (default) each time the modal closes via the `isOpen` effect.
- `handleConfirm` maps the `DeleteSelection` state to a `FolderChildrenAction` (`'ARCHIVE'` or `'MOVE'`) passed to the `useDeleteFolder` hook.
- The confirm button and folder picker are both disabled while the delete mutation is in-flight (`isPending`).
