Customer details page view component that renders a full-page layout for a single customer (organization), including tabbed navigation, archive/restore actions, and loading/error states.

## Key Components

- **`CustomerDetailsView`** — Main page component accepting a customer `id` prop
- **Tab management** — URL-driven tab state (`devices`, `tickets`, `logs`, `details`) using `useSearchParams` + `router.replace` to avoid flicker from `urlSync` mode
- **`useCustomerDetails`** — Fetches customer/organization data by ID
- **`useCustomerArchive`** — Provides `checkCanArchive`, `archiveOrganization`, and `restoreOrganization` mutations
- **Action buttons** — Context-aware `Edit Customer` and `Archive`/`Restore Customer` buttons rendered via `PageLayout`
- **`ArchiveCustomerModal` / `RestoreCustomerModal`** — Confirmation dialogs for destructive/restorative operations
- **`CustomerDetailsSkeleton`** — Loading placeholder rendered while data is in flight

## Usage Example

```typescript
// Typically rendered by a Next.js page at /customers/[id]
import { CustomerDetailsView } from './customer-details-view';

export default function CustomerPage({ params }: { params: { id: string } }) {
  return <CustomerDetailsView id={params.id} />;
}
```

## Behavior Notes

- **Archive flow**: Checks archivability first (`checkCanArchive`), then opens confirmation modal; on confirm, invalidates both the customers list and detail query caches, then redirects to `/customers?tab=archived`
- **Restore flow**: Confirms via modal, invalidates caches, redirects to `/customers`
- **Default organizations** (`isDefault: true`) have archive/restore disabled
- **Error states**: Renders `<LoadError>` on fetch failure and `<NotFoundError>` when organization is `null` after loading
