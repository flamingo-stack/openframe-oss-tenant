Loading skeleton components for the `CustomerDetailsView` page, providing pixel-accurate placeholder UI that mirrors the real layout during data fetching.

## Key Components

| Export | Description |
|--------|-------------|
| `CustomerDetailsSkeleton` | Root skeleton — composes header, tab nav, and active tab content into the full-page layout |
| `CustomerHeaderSkeleton` | Mirrors `TitleBlock` with logo, title, subtitle, back button, and responsive action buttons |
| `CustomerTabNavigationSkeleton` | Four-tab navigation bar with icon + label placeholders and bottom border |
| `CustomerDetailsTabSkeleton` | Info card skeleton for the Details tab (website row + physical/mailing address cells) |
| `CustomerDevicesTabSkeleton` | Data table skeleton for the Devices tab (3 columns + open action) |
| `CustomerTicketsTabSkeleton` | Data table skeleton for the Tickets tab (5 columns + open action) |
| `CustomerLogsTabSkeleton` | Data table skeleton for the Logs tab (6 columns + open action) |
| `getCustomerTabSkeleton` | Helper that returns the correct tab skeleton component based on the active tab string |
| `makeTableTabSkeleton` | Internal factory function that generates a `DataTable`-backed skeleton with `loading=true` for accurate column layout matching |

## Usage Example

```typescript
// Render the full-page skeleton while customer data loads
import { CustomerDetailsSkeleton } from './customer-details-skeleton';

// Default to devices tab skeleton
<CustomerDetailsSkeleton />

// Match skeleton to the currently active tab
<CustomerDetailsSkeleton activeTab="tickets" />

// Supported activeTab values: 'devices' | 'tickets' | 'logs' | 'details'
```

> **Note:** Table tab skeletons use real `DataTable` column definitions via `makeTableTabSkeleton`, ensuring skeleton column widths are always in sync with the live table layout — no manual measurement required.
