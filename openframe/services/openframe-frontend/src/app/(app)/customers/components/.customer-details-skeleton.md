Loading skeleton components for the `CustomerDetailsView` page, providing placeholder UI while customer data is being fetched.

## Key Components

| Export | Description |
|--------|-------------|
| `CustomerDetailsSkeleton` | Root skeleton matching the full `CustomerDetailsView` PageLayout structure |
| `CustomerHeaderSkeleton` | Mirrors `TitleBlock` with logo, title, subtitle, and action buttons |
| `CustomerTabNavigationSkeleton` | Four-tab navigation bar with icon + label placeholders |
| `CustomerDetailsTabSkeleton` | Info card skeleton for the Details tab (website + address rows) |
| `CustomerDevicesTabSkeleton` | Table skeleton with Devices column layout |
| `CustomerTicketsTabSkeleton` | Table skeleton with Tickets column layout |
| `CustomerLogsTabSkeleton` | Table skeleton with Logs column layout |
| `getCustomerTabSkeleton` | Helper that returns the correct tab skeleton given an `activeTab` string |

The internal `makeTableTabSkeleton` factory generates reusable table-tab skeletons by accepting a column definition array and rendering an empty `DataTable` with `loading=true`, ensuring column widths match the real table 1:1.

## Usage Example

```typescript
// Full-page skeleton for the customer details route
<CustomerDetailsSkeleton activeTab="devices" />

// Tab-specific skeleton (e.g. inside a Suspense boundary or loading state)
<CustomerTicketsTabSkeleton />

// Dynamic tab skeleton from router state
const skeleton = getCustomerTabSkeleton(activeTab); // 'devices' | 'tickets' | 'logs' | 'details'
```

**Supported `activeTab` values:** `"devices"` (default), `"tickets"`, `"logs"`, `"details"`.

All skeletons are fully responsive — layouts shift between mobile (stacked/card), `md` (column), and `lg` (row) breakpoints to match the live view's PageLayout behaviour.
