Full-page loading skeleton for the `CustomerDetailsView`, mirroring its `PageLayout` structure across header, tab navigation, and tab-specific content panels.

## Key Components

| Export | Description |
|--------|-------------|
| `CustomerDetailsSkeleton` | Root skeleton component; composes all sub-skeletons into the full page layout |
| `CustomerHeaderSkeleton` | Mirrors `TitleBlock` with logo, title, subtitle, back button, and action buttons |
| `CustomerTabNavigationSkeleton` | Four-tab navigation bar with icon + label placeholders |
| `CustomerDetailsTabSkeleton` | Info card skeleton for the Details tab (website + address rows) |
| `CustomerDevicesTabSkeleton` | Data table skeleton with Device / Status / OS columns |
| `CustomerTicketsTabSkeleton` | Data table skeleton with Title / Source / Created / Status columns |
| `CustomerLogsTabSkeleton` | Data table skeleton with Log ID / Status / Tool / Source / Details columns |
| `getCustomerTabSkeleton` | Returns the correct tab skeleton component given an `activeTab` string |
| `makeTableTabSkeleton` | Factory function that produces a `DataTable`-based skeleton for any column config |

## Usage Example

```typescript
// Full-page skeleton with active tab awareness
import { CustomerDetailsSkeleton } from './customer-details-skeleton';

// Default (devices tab)
<CustomerDetailsSkeleton />

// With active tab
<CustomerDetailsSkeleton activeTab="tickets" />

// Individual sub-skeletons
import {
  CustomerHeaderSkeleton,
  CustomerTabNavigationSkeleton,
  getCustomerTabSkeleton,
} from './customer-details-skeleton';

<CustomerHeaderSkeleton />
<CustomerTabNavigationSkeleton />
{getCustomerTabSkeleton('logs')}
```

> **Note:** Table tab skeletons render an actual `DataTable` with `loading=true` and an empty dataset, ensuring the skeleton column layout matches the real table 1:1.
