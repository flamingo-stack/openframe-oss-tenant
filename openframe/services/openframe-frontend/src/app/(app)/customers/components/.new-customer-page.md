Unified create/edit page component for customer (organization) records, handling form state, image upload, and navigation for both new and existing customers.

## Key Components

### `NewCustomerPage`
The primary exported component accepting `organizationId` (nullable) to toggle between create and edit modes.

### Form State Interfaces
- **`FormState`** — Core editable fields: name, website, notes, addresses, logo URL
- **`PreservedFields`** — Fields managed elsewhere (contacts, revenue, contract dates) retained across edits to avoid data loss
- **`NewCustomerPageProps`** — Component props interface

### Key Helpers
| Function | Purpose |
|---|---|
| `buildAddressDto` | Converts a raw address string to the backend DTO shape |
| `stripPlaceholder` | Normalises `-` placeholder values to empty strings |
| `contactToDto` | Maps contact objects to backend contact DTO format |

## Usage Example

```typescript
// New customer creation
<NewCustomerPage organizationId={null} />

// Edit existing customer
<NewCustomerPage organizationId="org_abc123" />
```

## Behaviour Notes

- **Prefill on edit** — Loads existing organization data via `useCustomerDetails`, populates form once (`didPrefill` guard prevents re-hydration loops)
- **Mailing address sync** — When `mailingSameAsPhysical` is checked, mailing address mirrors physical address automatically
- **Deferred image upload** — For new customers, the logo file is held in memory and uploaded only after the organization is created; blob URLs are revoked on unmount
- **Image uploader visibility** — Only shown in `saas-tenant` app mode
- **Safe navigation** — Uses `useSafeBack` to return to customer detail or list after save/cancel
