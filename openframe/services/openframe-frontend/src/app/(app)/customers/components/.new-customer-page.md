Brief description of the file's purpose: This is a client-side Next.js page component for creating and editing customer (organization) records, handling form state, image uploads, and navigation.

## Key Components

- **`NewCustomerPage`** — Main exported component; renders a form for creating or editing a customer organization
- **`FormState`** — Interface defining editable fields: name, website, notes, addresses, and image URL
- **`PreservedFields`** — Interface holding fields fetched from existing records that are passed through unchanged (contacts, revenue, contract dates)
- **`buildAddressDto`** — Helper that maps a raw address string into the API address DTO shape
- **`stripPlaceholder`** — Utility that normalizes placeholder/empty values (e.g., `"-"` → `""`)
- **`contactToDto`** — Maps a contact object to the API-expected shape

**Hooks used:**
- `useCreateCustomer` / `useUpdateCustomer` — Mutations for POST/PATCH organization
- `useCustomerDetails` — Fetches existing organization data for edit mode
- `useSafeBack` / `safeBackOrReplace` — Safe navigation fallback

## Usage Example

```typescript
// Create mode (no organizationId)
<NewCustomerPage organizationId={null} />

// Edit mode (prefills form from existing organization)
<NewCustomerPage organizationId="org_abc123" />
```

## Behavior Notes

- In **create mode**, logo file is held in memory (`pendingFile`) and uploaded after the organization is successfully created
- In **edit mode**, logo is uploaded immediately on file selection via `PATCH /api/organizations/:id/image`
- The **mailing address** mirrors the physical address when `mailingSameAsPhysical` is `true`
- The `ImageUploader` is only shown in `saas-tenant` app mode (`showImageUploader`)
- On save, `organizations` React Query cache is invalidated to trigger a refresh
