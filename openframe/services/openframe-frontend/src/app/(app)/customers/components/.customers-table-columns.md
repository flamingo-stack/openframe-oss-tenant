Defines the column configuration, cell renderers, and table body component for the Customers data table, including search input and device count integration.

## Key Components

- **`UiCustomerEntry`** — Normalized interface representing a customer row for UI rendering
- **`CUSTOMERS_COLUMNS`** — `ColumnDef<UiCustomerEntry>[]` array defining the five table columns: Name, Tier, Devices, Last Activity, and an open-in-new-tab action
- **`CustomerNameCell`** — Cell renderer displaying the customer's avatar, name, and email
- **`transformCustomerToEntry`** — Utility that maps a raw `Customer` object and its device count into a `UiCustomerEntry`
- **`customerRowHref`** — Row-level navigation function returning `/customers/details/:organizationId`
- **`CustomersSearchInput`** — Controlled search input component with a leading search icon
- **`CustomersTableBody`** — Fully composed table component that fetches device counts, transforms customer data, and renders the `DataTable` with header, body, and optional footer slot

## Usage Example

```typescript
import {
  CustomersTableBody,
  CustomersSearchInput,
} from './customers-table-columns';

function CustomersPage({ customers, isLoading }) {
  const [search, setSearch] = useState('');

  return (
    <>
      <CustomersSearchInput value={search} onChange={setSearch} />
      <CustomersTableBody
        customers={customers}
        isLoading={isLoading}
        skeletonRows={8}
        stickyHeaderOffset="64px"
        emptyMessage="No customers found."
      />
    </>
  );
}
```

## Notes

- Device counts are resolved asynchronously via `useCustomerDeviceCounts`, keyed by `organizationId`; rows show `—` until counts are available
- The open action button uses `data-no-row-click` to prevent row-level navigation from triggering on click
- Tier, Devices, and Last Activity columns are hidden below `md` breakpoint via the `hideAt` meta property
