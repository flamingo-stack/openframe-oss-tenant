React Query hook for fetching and normalizing a single customer (organization) record by ID from the GraphQL API.

## Key Components

- **`CustomerDetails`** — Interface defining the normalized shape of a customer record, including contact roles (primary, billing, technical), contract dates, MRR, and addresses
- **`customerDetailsQueryKeys`** — Query key factory for cache management (`all` and `detail(id)`)
- **`formatAddress(addr)`** — Utility that joins address fields into a single comma-separated string
- **`mapOrganization(org)`** — Transforms raw GraphQL organization response into a typed `CustomerDetails` object; maps the first three contacts array entries to primary/billing/technical roles
- **`fetchCustomer(id)`** — Posts the `GET_ORGANIZATION_BY_ORGANIZATION_ID_QUERY` GraphQL query and throws on missing or failed responses
- **`useCustomerDetails(id?)`** — Primary exported hook; returns `{ organization, isLoading, error, refetch }`; query is disabled when `id` is falsy

## Usage Example

```typescript
import { useCustomerDetails } from '@/features/customers/hooks/use-customer-details';

function CustomerProfile({ organizationId }: { organizationId: string }) {
  const { organization, isLoading, error } = useCustomerDetails(organizationId);

  if (isLoading) return <Spinner />;
  if (error) return <ErrorBanner message={error} />;

  return (
    <div>
      <h1>{organization?.name}</h1>
      <p>MRR: ${organization?.mrrUsd ?? 0}</p>
      <p>Primary: {organization?.primary.name} — {organization?.primary.email}</p>
    </div>
  );
}
```

> **Note:** The hook is safe to call with a `null` or `undefined` `id` — the query will remain idle until a valid ID is provided, making it suitable for conditionally loaded detail views.
