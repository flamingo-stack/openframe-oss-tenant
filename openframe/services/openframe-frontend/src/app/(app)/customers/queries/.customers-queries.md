GraphQL query definitions for fetching customer organization data, supporting both paginated list views and single-record lookups.

## Key Components

| Export | Description |
|--------|-------------|
| `GET_ORGANIZATIONS_QUERY` | Paginated list of organizations with full details, filtering, and cursor-based pagination |
| `GET_ORGANIZATIONS_MIN_QUERY` | Lightweight organization list returning only `id`, `organizationId`, `name`, `isDefault`, and `image` |
| `GET_ORGANIZATION_BY_ORGANIZATION_ID_QUERY` | Full organization detail lookup by business-level `organizationId` (string) |
| `GET_ORGANIZATION_BY_ID_QUERY` | Full organization detail lookup by internal GraphQL `id` (ID scalar) |

## Usage Example

```typescript
import {
  GET_ORGANIZATIONS_QUERY,
  GET_ORGANIZATION_BY_ORGANIZATION_ID_QUERY,
} from './customers-queries';

// Paginated list with search and filter
const { data } = await apolloClient.query({
  query: gql(GET_ORGANIZATIONS_QUERY),
  variables: {
    search: 'Acme',
    first: 20,
    after: 'cursor123',
    filter: { status: 'ACTIVE' },
  },
});

// Full detail by organizationId
const { data: orgData } = await apolloClient.query({
  query: gql(GET_ORGANIZATION_BY_ORGANIZATION_ID_QUERY),
  variables: { organizationId: 'ORG-001' },
});
```

## Notes

- `GET_ORGANIZATIONS_QUERY` returns `pageInfo` and `filteredCount` for pagination UI support.
- Full-detail queries (`BY_ID` / `BY_ORGANIZATION_ID`) include nested `contactInformation` with physical/mailing addresses, contacts, and the `mailingAddressSameAsPhysical` flag.
- `GET_ORGANIZATIONS_MIN_QUERY` is suited for dropdowns and autocomplete where minimal payload is preferred.
