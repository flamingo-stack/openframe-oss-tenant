A Next.js loading skeleton component for the authentication page that provides a pixel-accurate placeholder UI while auth content loads, matching the exact layout of `AuthLayout`, `AuthChoiceSection`, and `AuthBenefitsSection`.

## Key Components

- **`AuthLoading`** — Default export; a `'use client'` React component using `Skeleton` primitives from `@flamingo-stack/openframe-frontend-core` to mirror the full auth page structure with proper ARIA attributes (`role="status"`, `aria-label`).

## Layout Structure

```text
min-h-screen (flex-col → lg:flex-row)
├── Left Side (lg:w-1/2)
│   ├── Create Organization Card (bg-ods-card, p-10)
│   │   ├── Header skeletons (h1 + subtitle)
│   │   ├── Two-column form fields (name + org)
│   │   └── Button row (right-aligned)
│   └── Already Have Account Card (bg-ods-bg, p-10)
│       ├── Header skeletons
│       ├── Email field (full width)
│       └── Button row (two buttons)
└── Right Side (lg:w-1/2)
    └── Benefits Section (bg-ods-card, border-l)
        ├── Logo row (icon + wordmark)
        └── 3× BenefitCard rows (icon + title + description)
```

## Usage Example

Next.js automatically renders this file as the loading state for the `/auth` route segment — no manual import needed:

```typescript
// app/auth/loading.tsx  ← Next.js App Router convention
// Automatically displayed while app/auth/page.tsx suspends

export default function AuthLoading() { /* ... */ }
```

To use the `Skeleton` primitive independently:

```typescript
import { Skeleton } from '@flamingo-stack/openframe-frontend-core/components/ui';

<Skeleton className="h-10 w-56" />
```

> This component relies on the `ods-*` design token CSS classes (`bg-ods-bg`, `bg-ods-card`, `border-ods-border`) from the OpenFrame design system for dark-mode-safe theming.
