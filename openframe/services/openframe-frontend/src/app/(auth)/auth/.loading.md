Skeleton loading screen for the authentication page, rendered during Next.js route transitions while the auth content loads.

## Key Components

- **`AuthLoading`** — Default export. A pixel-accurate skeleton that mirrors the `AuthLayout` structure, including both the left-side form cards and the right-side benefits panel.

## Layout Structure

```text
┌─────────────────────┬─────────────────────┐
│  Left (50%)         │  Right (50%)         │
│  ┌───────────────┐  │  Logo skeleton       │
│  │ Create Org    │  │  ┌───────────────┐   │
│  │ Card skeleton │  │  │ Benefit 1     │   │
│  └───────────────┘  │  │ Benefit 2     │   │
│  ┌───────────────┐  │  │ Benefit 3     │   │
│  │ Sign In       │  │  └───────────────┘   │
│  │ Card skeleton │  │                      │
│  └───────────────┘  │                      │
└─────────────────────┴─────────────────────┘
```

## Usage Example

This component is auto-invoked by Next.js App Router when placed as `loading.tsx` alongside a `page.tsx` in the same route segment — no manual import needed.

```typescript
// app/auth/loading.tsx  ← Next.js picks this up automatically
export { default } from './loading';
```

To test the skeleton in isolation:

```typescript
import AuthLoading from '@/app/auth/loading';

export default function PreviewPage() {
  return <AuthLoading />;
}
```

## Notes

- Uses `Skeleton` from `@flamingo-stack/openframe-frontend-core` for consistent shimmer styling with ODS design tokens (`bg-ods-bg`, `bg-ods-card`, `border-ods-border`).
- Includes `role="status"` and `aria-label` for screen reader accessibility.
- Responsive: stacks vertically on mobile (`flex-col`), side-by-side on `lg+` breakpoints.
