Client-side login route entry point that dynamically imports the `LoginPage` component with SSR disabled, preventing server-side rendering of the authentication UI.

## Key Components

- **`Login`** — Default export; a thin wrapper that renders the dynamically loaded `LoginPage`.
- **`LoginPage`** (dynamic import) — The actual login UI, lazy-loaded from `@/app/(auth)/auth/pages/login-page` with `ssr: false`.

## Usage Example

```typescript
// Rendered automatically by Next.js when navigating to /auth/login (or equivalent route).
// No manual instantiation required — Next.js resolves this as the page component.

import Login from './page';

// Equivalent to:
<Login /> // → lazy-loads <LoginPage /> on the client only
```

> `ssr: false` ensures auth-related client state (e.g. tokens, browser storage) is only accessed in the browser, avoiding hydration mismatches.
