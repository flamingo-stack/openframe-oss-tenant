Client-side entry point for the login route that lazy-loads the full `LoginPage` component with SSR disabled.

## Key Components

- **`Login`** — Default export; a thin wrapper that renders the dynamically imported `LoginPage`.
- **`LoginPage`** — Dynamically imported from `@/app/(auth)/auth/pages/login-page` with `ssr: false`, deferring auth-related rendering entirely to the client.

## Usage Example

```typescript
// Automatically rendered by Next.js when navigating to /auth or /login.
// No manual instantiation needed; the route maps directly to this component.
export default function Login() {
  return <LoginPage />;
}
```

> **Why `ssr: false`?** Authentication pages often rely on browser-only APIs (e.g., `localStorage`, cookies, OAuth redirects). Disabling SSR prevents hydration mismatches and avoids leaking session state during server rendering.
