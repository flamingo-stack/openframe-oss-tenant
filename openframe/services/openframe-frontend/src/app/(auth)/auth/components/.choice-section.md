Renders the authentication landing page with two side-by-side forms: **Create Organization** and **Sign In**, handling SaaS shared-mode access code validation, subdomain availability checks, and domain suggestions.

## Key Components

### `AuthChoiceSection`

**Props** (`AuthChoiceSectionProps`):

| Prop | Type | Description |
|------|------|-------------|
| `onCreateOrganization` | `(orgName, domain, accessCode, email) => void` | Callback fired after successful validation |
| `onSignIn` | `(email: string) => Promise<void>` | Callback for the sign-in flow |
| `isLoading` | `boolean?` | Disables all inputs/buttons when truthy |

**Internal state:**

- `orgName`, `domain`, `orgEmail`, `signInEmail`, `accessCode` — form field values
- `accessCodeError` — inline error message for access code field
- `suggestedDomains` — alternative subdomain suggestions when chosen domain is taken
- `isSigningIn`, `isCheckingDomain`, `isValidatingAccessCode` — per-action loading flags
- `showForgotPassword` — controls the `ForgotPasswordModal`

**Key handlers:**

- `handleCreateOrganization()` — validates org name regex + email format, then (in SaaS shared mode) calls `authApiClient.validateAccessCode` → `authApiClient.checkDomainAvailability` before invoking `onCreateOrganization`
- `handleSignIn()` — guards against double-submit, delegates to the `onSignIn` prop

## Usage Example

```typescript
<AuthChoiceSection
  isLoading={isSubmitting}
  onCreateOrganization={(orgName, domain, accessCode, email) => {
    createOrg({ orgName, domain, accessCode, email });
  }}
  onSignIn={async (email) => {
    await initiateSignIn(email);
  }}
/>
```

> **SaaS shared mode** (`isSaasSharedMode() === true`) enables the **Access Code** field and appends `SAAS_DOMAIN_SUFFIX` to the chosen subdomain. In self-hosted mode, the domain field accepts any freeform string and skips access-code validation.
