A client-side React component that renders the benefits/branding panel on the authentication page, with conditional rendering based on app mode — showing either a waitlist signup form (`saas-shared` mode) or a static benefits overview with feature cards.

## Key Components

- **`AuthBenefitsSection`** — Main exported component with two rendering modes:
  - **`saas-shared` mode** — Renders an early access waitlist form with Reddit click ID tracking, duplicate email handling, and toast notifications
  - **Default mode** — Renders three static `BenefitCard` entries: *Cut Vendor Costs*, *Automate Everything*, and *Reclaim Your Profits*

- **`handleRegister`** — Async callback that POSTs to `https://content-api.openframe.ai/api/waitlist`, attaches Reddit click ID (`rdt_cid`) if present, handles `DUPLICATE_EMAIL` gracefully, and clears stored Reddit click ID on success

## Usage Example

```typescript
// Typically rendered as the right-hand panel on an auth/login page
import { AuthBenefitsSection } from '@/components/auth/benefits-section';

export default function LoginPage() {
  return (
    <div className="flex min-h-screen">
      {/* Left: login form */}
      <LoginForm />
      {/* Right: benefits panel */}
      <AuthBenefitsSection />
    </div>
  );
}
```

## Behavior Notes

- `appMode` is read from `runtimeEnv.appMode()` — set to `"saas-shared"` to display the waitlist flow
- Reddit click ID is read via `getStoredRedditClickId()` and cleared on successful or duplicate submission
- Toast variants used: `success`, `info`, `destructive`
- Waitlist endpoint: `https://content-api.openframe.ai/api/waitlist` (platform: `"openframe"`)
