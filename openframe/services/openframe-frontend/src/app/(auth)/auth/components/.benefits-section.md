A client-side React component that renders the authentication page's right-hand benefits panel, adapting its content based on the application mode — showing a waitlist signup form in `saas-shared` mode or a three-card feature highlights layout otherwise.

## Key Components

- **`AuthBenefitsSection`** — Main exported component with two rendering paths:
  - **`saas-shared` mode** — Displays the OpenFrame logo + a waitlist registration form with Reddit click ID tracking, duplicate email handling, and toast notifications.
  - **Default mode** — Displays the OpenFrame logo + three `BenefitCard` components highlighting cost savings, automation, and profit reclamation.
- **`handleRegister`** — Async callback that POSTs to the OpenFrame content API, handles `DUPLICATE_EMAIL` gracefully, tracks Reddit conversion via `rdt_cid`, and clears stored click IDs on success.

## Usage Example

```typescript
// Render inside an auth layout (e.g., login or signup page)
import { AuthBenefitsSection } from '@/components/auth/benefits-section';

export default function AuthLayout({ children }: { children: React.ReactNode }) {
  return (
    <div className="flex min-h-screen">
      {/* Left: Auth form */}
      <main className="flex-1">{children}</main>

      {/* Right: Benefits panel — adapts to appMode */}
      <aside className="hidden lg:flex w-1/2">
        <AuthBenefitsSection />
      </aside>
    </div>
  );
}
```

> **Note:** The component reads `runtimeEnv.appMode()` at render time. In `saas-shared` deployments, it renders the waitlist form. All other modes render the static benefits cards. Reddit conversion tracking is handled automatically via `getStoredRedditClickId` / `clearStoredRedditClickId`.
