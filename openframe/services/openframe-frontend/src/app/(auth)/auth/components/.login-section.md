Renders the login UI section for authenticated users, presenting SSO provider options (including OpenFrame SSO as a primary option) and an email/password fallback for organization access.

## Key Components

### `AuthLoginSection`
Main exported component that displays available authentication methods based on discovered providers.

**Props (`AuthLoginSectionProps`):**

| Prop | Type | Description |
|------|------|-------------|
| `availableProviders` | `string[]` | List of provider keys (e.g., `'google'`, `'openframe-sso'`) |
| `onSso` | `(provider: string) => Promise<void>` | Callback triggered on SSO provider click |
| `onBack` | `() => void` | Callback to navigate back |
| `isLoading` | `boolean` | Disables/shows loading state on buttons |
| `onEmailPasswordLogin` | `(email, password) => Promise<void>` | Optional email/password handler |

### Supporting Interfaces

- **`TenantInfo`** — Holds `tenantName` and `tenantDomain` for the resolved organization
- **`SsoProvider`** — Normalizes a provider key into `{ provider, enabled, displayName }`

### Internal Logic

- **OpenFrame SSO isolation** — `openframe-sso` is separated from standard providers and rendered as the primary `accent` button
- **Display name normalization** — Maps known provider keys (`google`, `microsoft`, `slack`, `github`) to human-readable labels; falls back to capitalized key
- **`loginMethod` state** — Tracks active method (`'sso'` | `'email'`) for scoped loading indicators

## Usage Example

```typescript
<AuthLoginSection
  email="user@acme.com"
  tenantInfo={{ tenantName: 'Acme Corp', tenantDomain: 'acme.com' }}
  hasDiscoveredTenants={true}
  availableProviders={['openframe-sso', 'google', 'microsoft']}
  onSso={async (provider) => {
    await initiateOAuthFlow(provider);
  }}
  onBack={() => setStep('email-entry')}
  isLoading={false}
  onEmailPasswordLogin={async (email, password) => {
    await signIn(email, password);
  }}
/>
```

> **Note:** The `email`, `tenantInfo`, `hasDiscoveredTenants`, and `onEmailPasswordLogin` props are declared in `AuthLoginSectionProps` but not currently destructured by the component — they are reserved for future expansion of the login flow.
