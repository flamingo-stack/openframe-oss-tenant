React client component that renders the login interface for authenticated users, supporting OpenFrame SSO and standard OAuth providers (Google, Microsoft, Slack, GitHub) with a fallback email/password option.

## Key Components

**`AuthLoginSection`** — Main exported component accepting:
- `availableProviders` — Array of provider strings to render
- `onSso` — Async callback triggered on SSO provider click
- `onBack` — Navigation callback for the back button
- `isLoading` — Loading state flag

**`SsoProvider`** — Internal interface mapping provider keys to display metadata

**Provider Resolution Logic** — Separates `openframe-sso` from standard OAuth providers, mapping raw provider strings to human-readable display names

## Usage Example

```typescript
import { AuthLoginSection } from './login-section';

<AuthLoginSection
  email="user@example.com"
  tenantInfo={{ tenantName: 'Acme Corp', tenantDomain: 'acme.com' }}
  hasDiscoveredTenants={true}
  availableProviders={['openframe-sso', 'google', 'microsoft']}
  onSso={async (provider) => {
    await initiateOAuthFlow(provider);
  }}
  onBack={() => router.push('/auth')}
  isLoading={false}
/>
```

## Notes

- `openframe-sso` renders as a primary accent `Button`; all other providers are delegated to `AuthProvidersList` with vertical orientation
- An `or continue with` divider is injected between OpenFrame SSO and standard providers only when both are present
- Several props defined in `AuthLoginSectionProps` (`email`, `tenantInfo`, `hasDiscoveredTenants`, `onEmailPasswordLogin`) are accepted by the interface but not yet consumed by the component body
