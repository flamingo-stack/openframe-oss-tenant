A client-side React component that renders the final user registration form during the OpenFrame onboarding flow, handling both email/password signup and SSO provider options.

## Key Components

**`AuthSignupSection`** — Main exported component accepting:

| Prop | Type | Description |
|------|------|-------------|
| `orgName` | `string` | Pre-filled organization name (read-only) |
| `domain` | `string` | Pre-filled tenant domain (read-only) |
| `accessCode` | `string` | Invitation/access code passed to submission |
| `email` | `string?` | Optional pre-filled email (locks field if provided) |
| `onSubmit` | `(data: RegisterRequest) => void` | Fires with full registration payload on form submit |
| `onSso` | `(provider: string) => void?` | Fires when user selects an SSO provider |
| `onBack` | `() => void` | Navigates back to previous step |
| `isLoading` | `boolean` | Disables inputs and shows loading state |

**`RegisterRequest`** — Payload shape sent via `onSubmit`, containing `tenantName`, `tenantDomain`, `firstName`, `lastName`, `email`, `password`, and `accessCode`.

**Internal hooks used:**
- `useRegistrationProviders` — fetches available SSO providers for the registration flow
- `isSaasSharedMode` — toggles SaaS-specific UI copy and password length validation

## Usage Example

```typescript
<AuthSignupSection
  orgName="Acme Corp"
  domain="acme.openframe.ai"
  accessCode="INV-XYZ"
  email="jane@acme.com"
  isLoading={submitting}
  onSubmit={(data) => registerTenant(data)}
  onSso={(provider) => initiateSsoFlow(provider)}
  onBack={() => setStep('org-details')}
/>
```

**Validation behavior:**
- Submit is blocked unless all fields are filled, email passes regex, and passwords match
- In SaaS shared mode, passwords shorter than 8 characters show an inline error
- `Enter` key triggers submission when the form is valid
