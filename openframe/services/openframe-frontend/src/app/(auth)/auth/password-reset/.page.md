Password reset page component that handles token-validated password updates, including client-side validation, API submission via `authApiClient`, and redirect logic on success or missing token.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `PasswordResetPage` | Default export | Client component rendering the password reset form |

**Internal logic:**

- **Token guard** — reads `token` from URL search params on mount; redirects to `/auth` with a destructive toast if absent
- **`handleSubmit`** — validates field presence, password match, and minimum length (8 chars) before calling `authApiClient.confirmPasswordReset`
- **Success flow** — shows a success toast and redirects to `/auth` after a 2-second delay
- **Error flow** — surfaces API or network error messages via destructive toast

## Usage Example

```typescript
// Route: /auth/password-reset?token=<reset_token>
// Next.js will automatically render this page when navigating to that path.

// The token is expected as a query param, typically from a password reset email link:
// https://your-app.com/auth/password-reset?token=abc123xyz

// Minimal manual test (e2e / integration):
const url = `/auth/password-reset?token=${validResetToken}`;
router.push(url);
// User fills in new password + confirmation, clicks "Reset Password"
// On success → redirected to /auth after 2s
// On missing token → immediately redirected to /auth
```

> **Validation rules enforced client-side:** both fields required · passwords must match · minimum 8 characters. The submit button is disabled until all conditions pass.
