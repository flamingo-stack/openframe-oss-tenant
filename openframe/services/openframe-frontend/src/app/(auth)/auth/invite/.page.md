Invitation acceptance page that allows users to complete their registration via an email invitation link, supporting both form-based signup (name + password) and SSO provider authentication.

## Key Components

- **`InvitePage`** — Default export; main page component handling the full invitation acceptance flow
- **`useInviteProviders`** — Custom hook that fetches available SSO providers for the given invitation ID
- **`handleSubmit`** — Validates form fields and calls `authApiClient.acceptInvitation`, handling tenant-switch conflicts
- **`handleSsoSignup`** — Initiates SSO-based registration via `authApiClient.acceptInvitationSso`
- **`handleTenantSwitch`** — Confirms switching the user's active tenant when a `USER_IS_ACTIVE_IN_ANOTHER_TENANT` conflict is detected
- **`ConfirmDialog`** — Modal shown when the user belongs to another tenant and must confirm switching
- **`AuthProvidersList`** — Renders available SSO provider buttons (Google, Microsoft, etc.)

## Usage Example

```typescript
// Accessed via: /auth/invite?id=<invitationId>
// The component reads the invitation ID from search params automatically.

// Typical flow:
// 1. User clicks invite link → /auth/invite?id=abc123
// 2. SSO providers are loaded for that invitation
// 3. User fills in First Name, Last Name, Password (or clicks an SSO button)
// 4. On submit, authApiClient.acceptInvitation is called
// 5. On success, user is redirected to /auth after 2 seconds

// Edge cases handled:
// - Missing ?id param → toast + redirect to /auth
// - Expired/invalid invitation → "Invite link isn't valid" card
// - USER_IS_ACTIVE_IN_ANOTHER_TENANT → ConfirmDialog for tenant switch
```

## States & Rendering

| State | UI Rendered |
|---|---|
| `loadingProviders` | Animated skeleton card |
| `invitationNotFound` | Error card with "Back to Login" button |
| Default | Full registration form with optional SSO providers |
