Handles email verification redirect by extracting a token from the URL query string and forwarding the user to the shared authentication service's verification endpoint.

## Key Components

- **`VerifyEmailPage`** — Default export; a Next.js client component that orchestrates the verification flow
- **Token extraction** — Reads the `token` query parameter via `useSearchParams()`
- **Redirect logic** — On mount, validates the token and either:
  - Redirects to `/auth/error` if the token is missing
  - Performs a hard navigation (`window.location.href`) to the SAS email verification URL built from `runtimeEnv.sharedHostUrl()`
- **Loading UI** — Renders an animated three-dot pulse indicator while the redirect is in progress
- **Branding** — Displays the OpenFrame logo at the top and a "Powered by Flamingo" footer link

## Usage Example

This page is typically reached via a verification email link in the format:

```text
https://<app-host>/auth/verify-email?token=<verification-token>
```

On load, the component constructs and navigates to:

```text
<sharedHostUrl>/sas/email/verify?token=<verification-token>
```

If no token is present, the user is redirected to:

```text
/auth/error?error=Invalid%20verification%20link.%20Please%20try%20again.
```

The runtime destination is resolved via `runtimeEnv.sharedHostUrl()`, so no hardcoded backend URL is required at build time.
