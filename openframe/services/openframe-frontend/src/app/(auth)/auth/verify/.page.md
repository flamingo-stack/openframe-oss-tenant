Handles email verification by extracting a token from URL search params and redirecting the user to the shared authentication service's verification endpoint.

## Key Components

- **`VerifyEmailPage`** — Default export; a client-side Next.js page component that:
  - Reads the `token` query parameter via `useSearchParams`
  - Redirects to `/auth/error` if no token is present
  - Constructs the full verification URL using `runtimeEnv.sharedHostUrl()` and performs a hard redirect via `window.location.href`
  - Renders a branded loading screen with an animated dot indicator while the redirect is in progress

## Usage Example

```typescript
// Accessed via: /auth/verify-email?token=<jwt_or_verification_token>

// On mount, the component resolves the shared host URL and redirects to:
// https://<sharedHostUrl>/sas/email/verify?token=<encoded_token>

// If the token is missing, the user is redirected to:
// /auth/error?error=Invalid%20verification%20link.%20Please%20try%20again.
```

## Notes

- Uses `window.location.href` (hard redirect) rather than Next.js `router.push` to ensure the external SAS endpoint receives the full navigation request
- The loading UI displays the OpenFrame branding and a pulsing three-dot animation during the async redirect
- Requires `runtimeEnv.sharedHostUrl()` to be correctly configured in `@/lib/runtime-config`
