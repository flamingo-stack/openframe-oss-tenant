Handles email verification redirect by extracting a token from URL search params and forwarding the user to the shared authentication service's email verification endpoint, or redirecting to an error page if the token is missing.

## Key Components

- **`VerifyEmailPage`** — Default export; a Next.js client component that orchestrates the verification flow
- **`useEffect` redirect logic** — Validates the `token` query param; redirects to `/auth/error` if absent, otherwise constructs the full `sharedHostUrl`-based verification URL and performs a hard navigation via `window.location.href`
- **`runtimeEnv.sharedHostUrl()`** — Runtime config helper used to resolve the base URL for the SAS email verification endpoint
- **Loading UI** — Animated three-dot indicator displayed while the redirect is in progress
- **Flamingo branding footer** — `FlamingoLogo` link to `flamingo.run` shown at the bottom of the page

## Usage Example

This page is rendered automatically when a user clicks an email verification link. The expected URL shape is:

```text
/auth/verify-email?token=<verification_token>
```

```typescript
// Internally constructs and navigates to:
const verifyUrl = `${runtimeEnv.sharedHostUrl()}/sas/email/verify?token=${encodeURIComponent(token)}`;
window.location.href = verifyUrl;

// Missing token triggers:
router.replace(`/auth/error?error=${encodeURIComponent('Invalid verification link. Please try again.')}`);
```

No props are accepted; all input is consumed from the URL's `searchParams`.
