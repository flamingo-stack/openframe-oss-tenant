Renders the login page for authenticated tenant discovery, handling SSO provider selection and redirecting users based on authentication state and app mode.

## Key Components

- **`LoginPage`** — Default export; a Next.js client component that orchestrates the login flow
- **`useAuth`** — Hook providing tenant discovery, SSO login, and auth state (email, providers, loading)
- **`useAuthStore`** — Zustand store for checking `isAuthenticated` status
- **`AuthLoginSection`** — UI component rendering the login form with SSO options
- **`AuthLayout`** — Wrapper layout for all auth pages
- **`useSafeBack`** — Hook for safe back navigation, defaulting to `/auth/`
- **`isAuthOnlyMode`** — Utility that skips dashboard redirect in auth-only deployments

## Behavior

| Condition | Action |
|-----------|--------|
| Authenticated + not auth-only mode | Redirect to `/dashboard` |
| No email in state | Redirect to `/auth` |
| Email present, tenants not yet discovered | Calls `discoverTenants(email)` |

## Usage Example

```typescript
// Rendered automatically by Next.js at the /auth/login route.
// The page reads email from auth state set by the preceding /auth step.

// SSO flow triggered internally:
const handleSso = async (provider: string) => {
  await loginWithSso(provider); // e.g., provider = 'google' | 'azure-ad'
};

// Back navigation falls back to /auth/ if no browser history exists
const handleBack = useSafeBack('/auth/');
```

> **Note:** This page expects `email` to already be stored in auth state from the previous `/auth` step. If absent, it immediately redirects back to `/auth`.
