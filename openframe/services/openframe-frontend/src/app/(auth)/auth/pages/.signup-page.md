Renders the organization signup page, handling both standard registration and SSO-based organization creation with pre-populated session data and post-authentication redirects.

## Key Components

- **`SignupPage`** — Default export; Next.js client page component that orchestrates the signup flow
- **`useAuth`** — Provides `registerOrganization`, `registerOrganizationSso`, and `loginWithSso` actions
- **`useAuthStore`** — Reads `isAuthenticated` to redirect already-authenticated users to `/dashboard`
- **`AuthSignupSection`** — UI section component receiving pre-filled form values and event handlers
- **`AuthLayout`** — Wraps the page in the shared authentication layout shell
- **`useSafeBack`** — Returns a safe back-navigation handler defaulting to `/auth/`
- **`isAuthOnlyMode`** — Guards the redirect; skips dashboard push in auth-only deployments

## Session Storage Keys

| Key | Purpose |
|-----|---------|
| `auth:org_name` | Pre-fills organization name |
| `auth:domain` | Pre-fills tenant domain (defaults to `localhost`) |
| `auth:access_code` | Pre-fills invite/access code |
| `auth:email` | Pre-fills user email |

## Usage Example

```typescript
// Accessed via route: /auth/signup
// Session storage is pre-populated by a prior onboarding step, e.g.:
sessionStorage.setItem('auth:org_name', 'Acme IT');
sessionStorage.setItem('auth:domain', 'acme.com');
sessionStorage.setItem('auth:access_code', 'INVITE123');
sessionStorage.setItem('auth:email', 'admin@acme.com');

// SSO signup flow — if all three keys exist, registers the org via SSO directly;
// otherwise stores org info and redirects to the provider OAuth flow.
await handleSsoSignup('google');
```
