Client-side Next.js page component that handles new organization registration, supporting both standard credential-based signup and SSO (Google/Microsoft) flows. Redirects authenticated users to `/dashboard` unless running in auth-only mode.

## Key Components

| Element | Description |
|---|---|
| `SignupPage` | Default export; top-level page component rendered at the signup route |
| `useAuth` | Provides `registerOrganization`, `registerOrganizationSso`, and `loginWithSso` actions |
| `useAuthStore` | Reads `isAuthenticated` to guard against redundant signup access |
| `sessionStorage` reads | Hydrates pre-filled form values (`auth:org_name`, `auth:domain`, `auth:access_code`, `auth:email`) from session |
| `handleSsoSignup` | Branches between full SSO org registration (when stored context is present) and a generic SSO login initiation |
| `useSafeBack` | Provides a safe fallback navigation to `/auth/` when browser history is unavailable |
| `isAuthOnlyMode` | Feature flag that suppresses the dashboard redirect in restricted deployments |

## Usage Example

```typescript
// Rendered automatically by Next.js at the /auth/signup route.
// Pre-populate session before navigating to pre-fill the form:

sessionStorage.setItem('auth:org_name', 'Acme IT');
sessionStorage.setItem('auth:domain', 'acme.com');
sessionStorage.setItem('auth:access_code', 'ABC123');
sessionStorage.setItem('auth:email', 'admin@acme.com');

router.push('/auth/signup');

// SSO flow with stored context triggers full org registration:
// registerOrganizationSso({ tenantName, tenantDomain, email, provider, redirectTo, accessCode })

// SSO flow without stored context falls back to:
// loginWithSso(provider)
```

> **Note:** If `isAuthenticated` is `true` and `isAuthOnlyMode()` returns `false`, the user is immediately redirected to `/dashboard` on mount.
