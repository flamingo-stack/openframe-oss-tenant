Entry point page component for the authentication flow, handling both sign-in and organization creation routing logic.

## Key Components

- **`AuthPage`** — Default export page component that orchestrates the initial auth screen
- **`useAuthStore`** — Reads `isAuthenticated` state to redirect already-authenticated users to `/dashboard`
- **`useAuth`** — Provides `discoverTenants` to check if an email has existing accounts before proceeding to login
- **`handleCreateOrganization`** — Persists org details (`org_name`, `domain`, `access_code`, `email`) to `sessionStorage` then navigates to `/auth/signup/`
- **`handleSignIn`** — Calls `discoverTenants`; redirects to `/auth/login` if accounts exist, otherwise shows a destructive toast

## Usage Example

```typescript
// This is a Next.js page — rendered automatically at /auth
// No direct import needed; routed via the filesystem

// Org creation flow:
// 1. User fills out org form → handleCreateOrganization fires
// 2. Org data is stored in sessionStorage
// 3. Router pushes to /auth/signup/

// Sign-in flow:
// 1. User enters email → handleSignIn fires
// 2. discoverTenants checks for existing accounts
// 3. Redirects to /auth/login or shows "Account Not Found" toast

// Auth-only mode bypass:
// If isAuthOnlyMode() returns true, authenticated users are NOT
// redirected to /dashboard (useful for embedded/standalone auth contexts)
```

## Notes

- Authenticated users are automatically redirected to `/dashboard` via a `useEffect`, unless `isAuthOnlyMode()` is active
- `sessionStorage` keys are namespaced under `auth:` to avoid collisions
- Relies on `AuthLayout` and `AuthChoiceSection` for all UI rendering; this component is purely behavioral
