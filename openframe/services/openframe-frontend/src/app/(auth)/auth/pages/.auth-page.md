Entry point page component for the authentication flow, handling initial routing logic and user action dispatch for sign-in or organization creation.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `AuthPage` | Default Export | Root auth page component managing sign-in and org creation flows |
| `handleCreateOrganization` | Handler | Persists org details to `sessionStorage` and redirects to `/auth/signup/` |
| `handleSignIn` | Async Handler | Runs tenant discovery and routes to `/auth/login` or shows a destructive toast |

## Usage Example

```typescript
// Rendered automatically via Next.js App Router at /auth
// No manual instantiation required.

// sessionStorage keys written on org creation:
// auth:org_name, auth:domain, auth:access_code, auth:email

// Redirects:
// - Authenticated (non-auth-only mode) → /dashboard
// - Existing account found             → /auth/login
// - No account found                   → toast error
```

## Behavior Notes

- **Auto-redirect**: If `isAuthenticated` is `true` and the app is **not** in `authOnlyMode`, the user is immediately pushed to `/dashboard` via a `useEffect`.
- **Tenant discovery**: `handleSignIn` calls `discoverTenants(email)`. If `has_existing_accounts` is `false`, a destructive toast prompts the user to create an organization instead.
- **Session handoff**: `handleCreateOrganization` writes four keys to `sessionStorage` so the `/auth/signup` page can pre-populate its form without prop-drilling or global state.
- **Layout**: Wraps content in `AuthLayout` and delegates UI rendering entirely to `AuthChoiceSection`.
