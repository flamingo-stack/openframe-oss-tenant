Client-side authentication page entry point that dynamically imports the main auth page component with SSR disabled.

## Key Components

- **`Auth`** — Default export; root component that renders the dynamically loaded auth page
- **`AuthPage`** — Lazy-loaded via `next/dynamic` from `@/app/(auth)/auth/pages/auth-page`, with SSR explicitly disabled and a fallback loading state
- **`dynamic = 'force-dynamic'`** — Exported route segment config that opts the route out of static rendering

## Usage Example

```typescript
// This component is automatically used by Next.js
// as the route handler for the /auth path.
// No manual instantiation required.

// Dynamic import config (as defined in the file):
const AuthPage = nextDynamic(() => import('@/app/(auth)/auth/pages/auth-page'), {
  ssr: false,                     // Disables server-side rendering
  loading: () => <AuthLoading />, // Shown while the bundle is loading
});
```

## Notes

- `ssr: false` ensures auth-related browser APIs (e.g. `localStorage`, OAuth redirects) are available before the component mounts
- `AuthLoading` provides a consistent loading skeleton during the dynamic import, preventing layout shift
- `force-dynamic` prevents Next.js from caching this route at build time, ensuring fresh renders on every request
