Client-side entry point for the authentication route that dynamically imports the auth page component with SSR disabled.

## Key Components

- **`dynamic` export** — Forces Next.js to opt out of static generation for this route (`force-dynamic`)
- **`AuthPage`** — Lazily loaded via `next/dynamic` with `ssr: false`, preventing server-side rendering of the auth UI
- **`Auth`** — Default export; the route component that renders the dynamically imported `AuthPage`

## Usage Example

```typescript
// Rendered automatically by Next.js at the /auth route.
// The auth page is loaded client-side only, with a fallback
// spinner/skeleton from AuthLoading during the lazy import.

export default function Auth() {
  return <AuthPage />;
}
```

## Notes

- `ssr: false` ensures auth logic (tokens, browser APIs, etc.) only runs in the browser
- `AuthLoading` is shown as a fallback while the dynamic import resolves
- The actual UI lives in `@/app/(auth)/auth/pages/auth-page`
