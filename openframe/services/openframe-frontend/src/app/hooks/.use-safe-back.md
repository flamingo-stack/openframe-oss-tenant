Safe navigation utilities for Next.js apps that prevent unsafe `router.back()` calls by checking the Navigation API before navigating, with deterministic fallbacks when history state is unknown.

## Key Components

- **`navCanGoBack()`** — Probes `window.navigation.canGoBack` (Chrome/Edge 102+, Safari 16.4+) defensively via `unknown` cast to avoid TS `lib.dom` version conflicts. Returns `false` for SSR, unsupported browsers, or when no safe back entry exists.
- **`useSafeBack(fallback)`** — React hook returning a memoized handler that calls `router.back()` when safe, otherwise `router.push(fallback)`. Use for general back-navigation (e.g. cancel buttons).
- **`safeBackOrReplace(router, fallback)`** — Non-hook utility for post-save/submit flows. Uses `router.replace(fallback)` instead of `push` to keep the submitted form out of history.

## Usage Example

```typescript
// Hook usage — cancel button
function EditForm() {
  const handleCancel = useSafeBack('/dashboard');
  return <button onClick={handleCancel}>Cancel</button>;
}

// Post-submit — remove form from history stack
async function handleSubmit(router: AppRouter) {
  await saveData();
  safeBackOrReplace(router, '/dashboard');
}

// Standalone check
if (navCanGoBack()) {
  router.back();
}
```

## When to Use Which

| Scenario | Function |
|---|---|
| Cancel / close button | `useSafeBack` |
| After form save/submit | `safeBackOrReplace` |
| Raw API check only | `navCanGoBack` |
