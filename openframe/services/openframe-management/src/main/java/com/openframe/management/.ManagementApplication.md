Entry point for the OpenFrame Management Spring Boot microservice. Bootstraps the application context and configures component scanning across the core management, data, and shared packages while explicitly excluding the `CassandraHealthIndicator` to avoid conflicts with the management module's own health check configuration.

## Key Components

| Element | Description |
|---|---|
| `@SpringBootApplication` | Enables auto-configuration, component scanning, and configuration properties |
| `@ComponentScan` | Scans `com.openframe.management`, `com.openframe.data`, and `com.openframe.core` packages |
| `excludeFilters` | Suppresses `CassandraHealthIndicator` registration to prevent duplicate/conflicting health beans |
| `main()` | Standard Spring Boot launcher via `SpringApplication.run()` |

## Usage Example

```bash
# Build and run the management service
./mvnw spring-boot:run -pl management

# Or run the packaged JAR directly
java -jar management/target/management-application.jar
```

```java
// The application starts automatically — no manual wiring required.
// To override Cassandra health behavior, register a custom HealthIndicator bean:
@Bean
public HealthIndicator cassandraHealth(CassandraOperations ops) {
    return () -> {
        // custom check logic
        return Health.up().build();
    };
}
```

## Notes

- The `CassandraHealthIndicator` exclusion is intentional — if Cassandra connectivity checks are needed, a replacement bean should be defined within the `com.openframe.management` package to maintain explicit control over health endpoint behavior.
- See the full source at [`ManagementApplication.java`](https://github.com/flamingo-stack/openframe-oss-tenant/blob/main/management/src/main/java/com/openframe/management/ManagementApplication.java).
